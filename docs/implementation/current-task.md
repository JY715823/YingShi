# Current Task: 上传定位、去重与长视频上传

## 背景

上传/导入任务已经只在传输中心展示，并具备进度、失败保留、取消、重试和基础重复媒体跳过能力。本轮继续修复两个实际验收问题：较长视频仍可能上传失败，同一系统媒体重复上传/导入仍会在照片流生成挨着的重复媒体。

## 目标

1. 单个媒体上传成功后立即发布第一个成功媒体的定位事件，不再等整批任务全部成功/失败。
2. 传输中心成功任务点击“查看”时，进入照片流并定位到该任务的 `resultMediaId` 附近。
3. 从传输中心返回时恢复进入前照片流的滚动位置，不回到照片流顶部。
4. Android 上传较长视频时只读取元数据和文件大小，实际文件内容通过 `InputStream` 分块写入 multipart，避免把整个视频读成 `ByteArray`。
5. 流式上传不声明固定 Content-Length，避免系统 URI 提供的大小与真实读取长度不一致导致长视频上传失败。
6. 上传请求携带稳定的 `sourceFingerprint`；Server 命中已有媒体时直接返回已有 `mediaId`，不再重复创建媒体记录。
7. Server 上传时对文件大小和 mimeType 做容错记录，不因为系统返回值差异直接拒绝。
8. 上传 API 继续使用独立长超时 OkHttp 客户端；Server 本地开发 multipart 限制保持 `1024MB / 1100MB`。
9. 上传失败仍保留真实错误信息到传输中心，不假成功、不静默丢任务。

## 范围

- Android App 根导航的上传成功定位事件处理。
- Android 传输中心“查看”跳转和照片流返回位置恢复。
- Android 上传请求仓库和上传任务的数据读取方式。
- Android 上传请求携带系统媒体来源指纹。
- Server 上传去重和上传校验容错。
- Server 本地开发 multipart 上传大小配置。
- 当前文档。

## 不做内容

- 不恢复底部任务弹窗。
- 不改 Viewer、回收站、分页、封面质量等无关模块。
- 不做视频转码、HLS、OSS 或数据库字段扩展之外的大改。

## 验收

1. 真机批量上传/导入时，第一个媒体成功后照片流会刷新并定位到该媒体或对应时间分组附近。
2. 真机在传输中心点击成功任务的“查看”，能跳转到对应媒体或其所在时间分组附近。
3. 真机从传输中心返回后，能回到进入传输中心前的照片流位置。
4. 失败、取消、重复跳过任务不会误跳转。
5. 真机上传 30 秒以上、数分钟视频不再因为 Android 端整文件读入内存或固定 Content-Length 不一致而直接失败；如仍失败，传输中心能显示明确失败原因。
6. 真机重复上传/导入同一系统媒体时，后端返回已有媒体，不在照片流生成挨着的重复媒体。
7. 上传/导入任务进度、重试、取消、清理正常。
8. Android `assembleDebug` 通过；Server 测试通过。
