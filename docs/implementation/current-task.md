# Current Task: 上传/导入元数据稳定性精修

## 背景

系统媒体导入 App、从系统媒体发新帖、加入已有帖已经具备任务进度、失败保留、重试和取消能力。第二步需要把媒体元数据链路补稳：上传前尽量读准图片/视频的类型、宽高、时间、文件大小和视频时长，避免导入后照片流排序异常、视频时长缺失或宽高比例异常。

## 目标

1. 图片上传前读取并保存稳定的 `mimeType`、文件大小、宽高、拍摄/显示时间，并根据 EXIF 方向修正宽高。
2. 视频上传前读取并保存稳定的 `mimeType`、文件大小、旋转后的宽高、视频时长和显示时间。
3. 元数据读取失败时不让整批任务卡死：宽高和时间使用安全兜底，真正无法读取文件字节时才让单个任务失败并保留可重试。
4. 上传请求继续复用现有后端字段，不扩 OSS/HLS/转码，不做大接口重构。
5. 不破坏第一步已经补齐的进度、失败重试、取消和传输中心状态展示。

## 范围

- Android 系统媒体导入/上传元数据读取。
- Android 上传 token payload 的显示时间、拍摄时间、文件大小、宽高、视频时长传递。
- 当前文档。

## 不做内容

- 不处理重复导入、上传后定位、分页、回收站、封面质量等后续任务。
- 不做 OSS/HLS/转码。
- 不重构无关页面和后端接口。
- 后端当前已有 `mimeType`、`sizeBytes`、`width`、`height`、`aspectRatio`、`durationMillis`、`displayTimeMillis`、`capturedAtMillis`、`importedAtMillis` 字段，本轮优先使用现有字段。

## 验收

1. 真机导入图片后，照片流宽高比例、时间分组、排序基本正常。
2. 真机导入视频后，照片流能显示视频时长，Viewer 能正常播放。
3. 遇到个别元数据读取失败的媒体，不会导致整批任务卡死。
4. 上传/导入任务进度、失败重试、取消能力不被破坏。
5. Android `assembleDebug` 通过；Server 如无实际改动需说明。
