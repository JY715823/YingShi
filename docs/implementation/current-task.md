# Current Task: 上传/导入成功后的照片流刷新与定位

## 背景

上传/导入闭环已经补齐了任务进度、失败保留、取消、重试和基础元数据读取。第三步需要把“任务成功”与“照片流可见”接起来：系统媒体导入 App、发新帖上传、加入已有帖上传完成后，新媒体应尽快出现在照片流，并尽量滚动到新媒体所在的行或时间分组附近。

## 目标

1. 上传/导入任务成功汇总事件携带成功生成的 App 媒体 ID，供照片流定位使用。
2. App 根层收到全量成功的任务事件后，触发照片流刷新，并记录待定位媒体 ID。
3. 照片流只有在刷新后的数据中真正找到目标媒体时才清空待定位目标，避免事件早于数据刷新导致定位丢失。
4. REAL 照片流在刷新触发递增时主动重新拉取后端数据；FAKE 照片流继续使用本地仓库数据和现有模式切换逻辑。
5. 批量成功时使用成功任务列表里的第一项媒体作为定位目标，规则简单稳定。

## 范围

- Android 上传/导入任务完成事件。
- Android App 根层的任务成功处理。
- Android 照片流刷新触发与滚动定位。
- 当前文档。

## 不做内容

- 不处理重复导入、分页、回收站、封面质量等后续任务。
- 不改变失败、取消、部分成功任务的重试和保留逻辑。
- 不改帖子详情、回收站、上传中心、后端接口等无关模块。
- 不做 OSS/HLS/转码或数据库相关改造。

## 验收

1. 真机从系统媒体导入 App 成功后，回到照片流能立即看到新媒体。
2. 真机发新帖上传成功后，照片流会刷新，并能定位到新媒体或对应时间分组附近。
3. 真机加入已有帖上传成功后，照片流会刷新，新媒体可见。
4. 上传/导入失败、取消、重试逻辑不被破坏。
5. FAKE / REAL 模式下照片流基本可用。
6. Android `assembleDebug` 通过；Server 本轮未改动。
