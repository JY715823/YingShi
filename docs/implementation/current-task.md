# Current Task: 上传/导入任务闭环精修

## 背景

系统媒体导入 App、从系统媒体发新帖、加入已有帖都已经接到上传链路，但早期实现更偏“一次性流程”：任务要等本地文件读取和 token 创建后才出现，REAL 上传过程只有粗略阶段进度，取消只是改 UI 状态，失败保留和重试能力还需要更稳定地显式化。

## 目标

1. 导入/上传一开始就生成可见任务，覆盖等待读取、读取中、创建上传任务、上传中、处理中、成功、失败、取消状态。
2. REAL multipart 上传上报客户端发送进度，任务列表展示明确百分比。
3. 失败和取消任务保留在传输中心/任务面板中，用户可以重试或清理。
4. 正在进行的 REAL 上传支持按任务取消，取消后协程停止，UI 不再残留“上传中”。
5. 重试复用原始操作请求和媒体信息，不要求用户重新选择媒体。

## 范围

- Android 上传仓库接口与 REAL multipart 上传进度回调。
- `LocalSystemMediaBridgeRepository` 的上传任务生命周期、取消、重试保留逻辑。
- 照片页和系统媒体页的轻量上传任务面板展示。
- 当前文档。

## 不做内容

- 不处理重复导入、照片流刷新定位、分页、回收站、封面质量等后续任务。
- 不改帖子详情、回收站、上传中心以外的业务模块。
- 不修改 Server；当前后端仍没有独立 upload cancel/status endpoint，Android 端本轮做客户端侧任务取消和请求协程取消。

## 验收

1. 从系统媒体导入 App、发新帖上传、加入已有帖时，能看到任务进度。
2. 上传/导入失败后任务保留，可重试或清理。
3. 正在进行的任务可以取消，取消后不会卡住或继续显示上传中。
4. 成功任务仍能进入完成汇总或结果媒体入口。
5. 上传中心 badge 与任务列表状态正常。
6. Android `assembleDebug` 通过；Server 本轮未改动。
