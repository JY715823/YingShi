# 已实现功能清单

更新时间：2026-05-09

本文档按当前代码状态整理 YingShi Android 已经完成的功能，用于后续精修、验收和联调。若实现与早期 PRD 或 roadmap 描述不一致，以本文档和当前代码为准。

## 1. 全局壳层

- 一级导航包含 `主页`、`照片`、`生活`、`我的`。
- 底部导航中间提供 `添加` 入口。
- 全屏业务页打开时自动隐藏底部导航，包括 Viewer、系统媒体、帖子详情、编辑页、回收站详情、通知、设置、缓存管理、后端诊断等。
- 使用 Compose 状态维护轻量路由，不依赖 Navigation Component。
- 支持多层返回：Viewer、系统媒体 Viewer、新建帖子、帖子详情、Gear Edit、媒体管理、通知详情等都有独立 BackHandler。
- 主页和生活页目前是结构占位页，用于保留后续信息架构入口。
- 我的页提供设置和缓存管理入口。

## 2. 照片模块总览

- 照片模块顶部有三个二级页签：`照片`、`相册`、`回收站`。
- 顶部工具区包含系统媒体入口、传输中心入口和通知中心入口。
- 传输中心入口显示剩余任务 badge。
- 通知中心入口显示未读 badge。
- 照片页多选时顶部切换为选择上下文：取消、已选数量、空选择提示。

## 3. 照片流

- 支持 FAKE / REAL 两套数据来源。
- REAL 模式通过后端 media feed 获取 App 内容区媒体。
- FAKE 模式使用本地 FakePhotoFeedRepository，便于离线调试。
- 全局照片流按媒体维度去重，同一媒体可归属于多个帖子但只显示一次。
- 媒体按展示时间倒序排列。
- 支持图片和视频类型。
- 缩略图支持本地 URI、远端 URL、占位渐变和视频标识。
- 按时间分组展示月份和日期。
- 支持密度切换：2 列、3 列、4 列、8 列、16 列。
- 支持时间滑条快速定位，滑条随自然滚动同步。
- 时间滑条只在拖动滑块时控制列表，点击轨道空白不跳转。
- 支持长按进入多选模式。
- 支持点击右下角选择圆点选择/取消选择。
- 支持横向滑动范围多选，降低纵向滚动误触；拖到顶部/底部会自动滚动并继续更新选择范围。
- 多选新增时会显示选择序号闪现反馈。
- 多选状态下可发成新帖子、加入已有帖子、移入回收站。
- 选择为空但仍处于选择模式时，界面显示“请选择媒体”，避免误清空上下文。

## 4. Viewer

- 可从照片流、帖子详情、传输中心、系统媒体等入口打开。
- 支持图片和视频混排查看。
- 支持左右切换当前媒体。
- 支持图片缩放、拖动和离散缩放手势。
- 支持长图查看适配。
- 支持视频封面/缩略图和播放状态 UI。
- 支持原图按需加载。
- 支持全帖原图加载。
- REAL 模式下通过后端媒体文件接口加载原图。
- FAKE 模式下使用本地模拟原图加载状态。
- 支持查看媒体评论。
- 支持从媒体打开所属帖子。
- 支持从 Viewer 发成新帖子。
- 支持打开缓存管理。
- 支持 Viewer 内删除媒体并进入回收站语义。

## 5. 相册与帖子

- 相册页展示相册列表和帖子目录。
- 帖子卡片展示标题、摘要、时间、媒体预览、评论/媒体数量等信息。
- 支持打开帖子详情。
- 帖子详情包含基础信息、媒体区、评论区和管理入口。
- 支持帖子评论列表和评论输入。
- 支持媒体评论与帖子评论分流。
- 支持评论创建、编辑和删除。
- 支持从帖子详情打开 Gear Edit。
- 支持从帖子详情进入缓存管理。
- REAL 模式使用后端 album、post、comment API。
- FAKE 模式使用本地 FakeAlbumRepository 和 FakeCommentRepository。

## 6. Gear Edit 与媒体管理

- Gear Edit 支持帖子基础信息编辑。
- 支持修改标题、摘要、时间等基础字段。
- 支持修改帖子所属相册。
- 支持进入媒体管理页。
- 媒体管理页支持帖子内媒体排序。
- 支持设置封面。
- 支持从当前帖子移除媒体。
- 支持删除当前帖子。
- 删除帖子时可选择是否系统删帖子内媒体。
- REAL 模式通过 post API 更新基础信息、封面、排序、媒体关系和删除。
- FAKE 模式同步更新本地帖子、照片流和回收站状态。

## 7. 新建帖子

- 底部中央 `添加` 可打开新建帖子。
- 照片流多选可发成新帖子。
- 系统媒体多选可发成新帖子。
- 系统媒体 Viewer 可发成新帖子。
- 支持标题、摘要、展示时间、相册选择和封面选择。
- 支持从 App 已有媒体创建帖子。
- 支持从系统媒体创建帖子并进入上传任务。
- REAL 模式会走 upload + post 链路。
- 支持后台提交，提交后通过传输中心和 toast 汇报进度。
- 创建成功后可跳转到新帖子详情。

## 8. 系统媒体工具区

- 通过 MediaStore 查询设备本地图片和视频。
- 支持 Android 图片/视频权限与系统选择器相关流程。
- 支持筛选：全部、相机、截图、视频、已发帖、未发帖。
- 支持按时间倒序展示。
- 支持月份/日期分区。
- 支持时间滑条定位，交互规则与 App 照片流一致。
- 支持多选模式。
- 支持横向滑动范围多选、边缘自动滚动和选择序号闪现。
- 多选模式下点击缩略图主体仍可打开媒体，右下角圆点负责选择。
- 支持系统媒体 Viewer。
- 支持导入 App 照片流。
- 支持发成新帖子。
- 支持加入已有帖子。
- 支持将系统媒体移入 Android 系统回收站。
- 支持系统回收站请求结果回写本地状态。
- 支持已发帖状态标记，便于判断系统媒体是否已进入 App 内容区。

## 9. 上传与传输中心

- 系统媒体导入、发帖、加入已有帖子会生成上传任务。
- 支持 REAL 模式上传 token、multipart 文件上传和上传确认。
- 支持 FAKE 模式模拟上传任务。
- 上传任务包含 pending、uploading、succeeded、failed、cancelled 等状态。
- 传输中心展示任务列表、状态、来源、目标和结果媒体。
- 顶部传输中心入口显示剩余待处理任务数量。
- 上传任务完成后剩余任务数减少。
- 批量任务完成后显示汇总提示。
- 支持失败任务清理和重试入口。
- 支持从传输中心打开结果媒体；找不到媒体时回到照片页查看最新内容。

## 10. 回收站

- 回收站包含三类删除语义：
  - 帖子删除：恢复帖子本体、帖子评论和帖子媒体关系。
  - 媒体移除：只恢复当前帖子与媒体的关系，不影响媒体本体。
  - 媒体系统删：恢复媒体本体、相关帖子关系和媒体评论入口。
- 回收站列表支持 chip 分类切换。
- 24h 可撤销项目作为同页分类展示，不再进入独立全屏。
- 支持回收站详情。
- 支持恢复条目。
- 支持移出回收站并进入 24h 可撤销区域。
- 支持在 24h 内撤销移出。
- 支持永久清理语义占位。
- REAL 模式对接 trash API。
- FAKE 模式保留完整本地快照，能恢复帖子、媒体和关系。

## 11. 通知中心

- 顶部通知按钮显示未读数量。
- 通知中心支持分类与列表展示。
- 通知详情页展示单条通知内容。
- 通知可跳转到相关目标：
  - 评论/帖子更新跳到帖子或相册页。
  - 相册更新跳到相册页。
  - 回收站通知跳到回收站页。
  - 恢复通知跳到 24h 可撤销分类。
  - 缓存通知跳到缓存管理。
- 当前通知数据主要来自 FAKE 仓库，用于验证导航和信息结构。

## 12. 设置、缓存和后端诊断

- 我的页提供设置入口。
- 设置页包含浏览偏好、工具项和后端联调诊断入口。
- 后端联调诊断页支持查看/修改 baseUrl。
- 支持切换 FAKE / REAL Repository 模式。
- 支持登录、保存会话和查看当前用户。
- 支持 health、albums、media、comments、trash、upload 等 smoke check。
- 支持清理或观察当前阶段的调试状态。
- 缓存管理页展示预览、原图、视频缓存占位。
- 支持执行本地缓存清理。

## 13. 后端接入

- 已定义 Retrofit API：
  - `AuthApi`
  - `AlbumApi`
  - `PostApi`
  - `MediaApi`
  - `CommentApi`
  - `TrashApi`
  - `UploadApi`
  - `HealthApi`
- 已定义 DTO 和 mapper。
- 已实现 Repository 契约：
  - `MediaRepository`
  - `AlbumRepository`
  - `PostRepository`
  - `CommentRepository`
  - `TrashRepository`
  - `UploadRepository`
  - `AuthRepository`
- `RepositoryProvider` 按 FAKE / REAL 模式分发实现。
- `AuthSessionManager` 保存 token 并配合 `AuthInterceptor` 注入认证头。
- `RemoteServiceFactory` 根据当前 baseUrl 重建 Retrofit graph。
- REAL ViewModel 已覆盖照片流、帖子详情、编辑、媒体管理、评论、回收站、系统媒体目标加载等主要链路。

## 14. 当前保留的占位或限制

- 主页和生活页仍是入口占位，尚未接真实业务。
- 通知数据主要是本地模拟。
- 缓存管理目前偏状态占位和清理入口，不是完整缓存统计系统。
- 没有引入 Room，本地状态主要由内存仓库和系统数据源承担。
- 上传仍是本地后端联调链路，不包含 OSS、云存储、转码或 CDN。
- 真实大数据分页、离线缓存、冲突合并和发布级错误治理仍待后续阶段补强。
