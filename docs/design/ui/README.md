# 映世 UI 原型文档

Updated: 2026-05-29

这组文档只服务于当前阶段的两件事：

1. 把首轮核心页面整理成可直接设计的页面规格。
2. 为 `image2` 生成适合首轮出图的逐页提示词，并统一首版颜色系统。

本目录的职责就是把已有产品事实收束成：

- 清晰的首轮页面范围
- 可直接落到 Figma 和 Compose 的首版颜色系统

- 适合导入 `即时设计` 继续细修的设计工作流

## 2. 本轮固定原则

- 目标平台：中文 Android 移动端 app
- 原型精度：中高保真，稍微精美一点，不做低保真线框
- 设计工具默认对接：`即时设计`
- 本轮只做文档，不改 Android 代码，不改现有 token 实现
- 页面原型必须贴当前 app 的真实功能范围，不能擅自扩成功能大改版
- 登录页允许比当前实现更产品化，但不能反向定义新业务逻辑
- 首版对外产品文案优先使用 `相册 / 小相册`，不走社交流“帖子流”语言

## 3. 首轮范围

首轮只覆盖 9 个核心页：

1. 登录页
2. 主页
3. 照片首页
4. 相册页
5. 小相册详情页
6. Viewer
7. 生活页
8. 我的页
9. 设置页

首轮不纳入：

- 通知中心
- 回收站详情
- 创建帖子
- 传输中心
- 系统媒体详情页
- 各类复杂编辑页

这些页面后续仍会继续设计，但不进入第一批出图。

## 4. 颜色系统策略

本轮颜色方向已经收成一套首版可用系统，不再只停在模糊风格锚点：

- 主文档见：[03-color-system-v1.1.md](E:/Study/App/YingShi/docs/design/ui/03-color-system-v1.1.md)
- 首版主方案固定为：`奶雾天青 · 目录感增强版`
- 允许受控发散，但不能离开这套浅蓝壳层 + 深蓝结构 + 浅绿辅助 + 少量金色点缀的系统骨架

### 4.1 主方案

主方案继承 [light-color-system-v1.md](E:/Study/App/YingShi/docs/design/light-color-system-v1.md) 并在 [03-color-system-v1.1.md](E:/Study/App/YingShi/docs/design/ui/03-color-system-v1.1.md) 里进一步收口：

- 浅蓝整页背景
- 暖白卡片
- 深蓝结构与主按钮
- 浅绿辅助分区
- 少量香槟金点缀
- Viewer 使用雾夜蓝深色沉浸

### 4.2 两条可控发散

本轮允许两条扩展，但都不能离开 `奶雾天青` 的品牌骨架：

- `奶雾天青 · 显色层次版`
  - 首轮优先试图方向
  - 蓝绿分区更可见
  - 卡片层级更清楚
  - 金色点缀稍微更容易被注意到
  - 目标是让页面一眼看出有完整设计系统，但不能花

- `奶雾天青 · 轻透清亮版`
  - 更亮、更轻、更透
  - 更偏空气感和清透感
  - 目标是测试页面亮度上限，同时避免结构发飘

### 4.3 发散边界

允许发散：

- 浅蓝背景深浅变化
- 卡片白度和暖度变化
- 蓝绿分区显色程度变化
- 点缀色存在感变化
- 阴影、描边、表面层次变化

不允许发散：

- 跳成完全不同品牌方向
- 变成营销落地页风格
- 变成企业后台风格
- 变成紫色主导或高饱和赛博风
- 变成甜腻恋爱粉色风

## 5. 推荐工作流

推荐顺序如下：

1. 先读 [03-color-system-v1.1.md](E:/Study/App/YingShi/docs/design/ui/03-color-system-v1.1.md)，锁住颜色系统和 Compose 映射口径。
2. 再读 [01-core-page-specs.md](E:/Study/App/YingShi/docs/design/ui/01-core-page-specs.md)，确认页面边界和首轮范围。
3. 再从 [02-image2-page-prompts.md](E:/Study/App/YingShi/docs/design/ui/02-image2-page-prompts.md) 选页面级提示词喂给 `image2`。
3. 每页先生成 2 到 3 个方向，优先比较：
   - 结构是否清楚
   - 功能入口是否完整
   - 气质是否像同一 app
4. 首轮优先试图顺序建议是：
   - 登录页
   - 照片首页
   - 相册页
   - 小相册详情页
   - 主页
5. 选中结果后导入 `即时设计`。
6. 在 `即时设计` 里继续做：
   - 布局微调
   - 卡片层次统一
   - 字号与间距统一
   - 图标、标签、按钮精修
7. 等页面方向稳定后，再把设计稿交给我做 Compose 落地。

一句话版本：

`颜色系统 v1.1` -> `image2` 出图 -> 导入即时设计 -> 手动细修 -> 再交给我落代码

## 6. 使用提醒

- 单页提示词比整套提示词更适合你当前阶段，因为更容易反复试图和局部改图。
- 登录页、主页这类产品气质页可以更产品化，但照片、相册、帖子、Viewer 这些核心页必须尊重当前真实功能。
- 如果某一页看起来“很高级”，但功能入口不清楚、模块关系混乱、无法映射到真实前端，就不要选。

## 7. 当前迭代记录

### 7.1 登录页

当前登录页已经形成 5 步渐进式迭代思路：

- `v1 brand-atmosphere`
  - 优点：背景氛围感和品牌感最强
  - 风险：更接近展示海报，不够产品化
- `v2 productized`
  - 优点：更像真实产品
  - 风险：容易长出当前项目没有的登录分支
- `v3 project-aligned`
  - 优点：功能边界最接近当前项目
  - 风险：整体有点保守
- `v4 blended-background-minimal-advanced`
  - 优点：极简结构已收稳，没有大白卡，也没有多余文案
  - 风险：背景和标题仍偏素，精致度不够
- `v5 light-luxe-song-title`
  - 当前推荐方向
  - 目标：保留 `v4` 的结构骨架，吸收 `v1` 的设计存在感
  - 强化点：现代宋感标题、蓝绿雾层背景、极淡相册意象、克制点金
- `v6 sculpted-luxe-product-limit`
  - 最终冲刺方向
  - 目标：在 `v5` 稳定结构上，推到“惊艳但仍像真实产品”的产品上限
  - 强化点：雕塑感轻奢背景、高定字标、蓝绿流光、微金细节、按钮与中段结构轻度雕塑化
- `v7 sculpted-luxe-light-blue-balance`
  - 色彩回正方向
  - 目标：保留 `v6` 的雕塑感和高级感，但把标题蓝和按钮蓝拉回浅色系主系统口径
  - 强化点：标题更通透、按钮更青蓝、更轻、更平衡

### 7.2 当前登录页推荐口径

如果继续迭代登录页，不要回到“大白卡包住全部内容”的方案，默认沿着下面这个方向走：

- 结构参考：`v5`
- 风格母体：`雕塑感轻奢`
- 关键词：`雕塑感 / 轻奢 / 蓝绿流光 / 微金点缀 / 高定字标 / 产品上限`
- 固定内容：`映世 / 邮箱 / 密码 / 高级功能 / 登录`
- 固定禁区：注册、找回密码、第三方登录、协议文案、邀请说明、调试信息、手机状态栏
