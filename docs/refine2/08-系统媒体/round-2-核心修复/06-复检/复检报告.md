## 三、发现的 Bug（已全部修复）

### BUG-1: SystemMediaUploadReal.kt 主上传成功路径缺失 invalidate 调用

- **严重度**: P0（阻塞，功能性缺口）
- **问题**: `enqueueRealUploadTask` 的上传成功分支（line 441-446）在 `finalizeRealOperationIfReady` 之后、`OperationBus.publishOperationSummaryIfReady` 之前缺失 `invalidateSystemMediaMetadataCache(clearDisk = true)` 调用。同时 `finalizeRealOperationIfReady` 的 `ApiResult.Success` 分支（line 715-744）也缺失。
- **根因**: 实施时仅在复用路径 `finalizeRealOperationWithKnownMedia`（line 821）添加了 invalidate，遗漏了主上传路径。
- **影响**: REAL 模式下上传成功后磁盘缓存未失效，5 分钟内重新进入页面会读取旧缓存，导致"已导入"徽标不显示。影响 TC-13、TC-22、TC-50。
- **修复**:
  1. `enqueueRealUploadTask` 上传成功分支：`finalizeRealOperationIfReady` 之后添加 `invalidateSystemMediaMetadataCache(clearDisk = true)`（line 446）
  2. `finalizeRealOperationIfReady` Success 分支：`notifyRealBackendContentChanged` 之后添加 `invalidateSystemMediaMetadataCache(clearDisk = true)`（line 725）
- **验证**: 编译通过（`BUILD SUCCESSFUL`）

### BUG-2: ContentObserver 未从 ContentResolver 注销（内存泄漏）

- **严重度**: P1（重要，内存泄漏）
- **问题**: `SystemMediaContentObserver.unregister()` 仅取消了 `debounceScope`，未调用 `contentResolver.unregisterContentObserver(this)`。ContentResolver 持续持有 observer 强引用，observer 持有 `onChangeCallback` lambda（捕获 ViewModel 的 `startBackgroundRefresh`），导致 ViewModel 销毁后无法 GC。
- **根因**: 实施时遗漏了 ContentResolver 注销。
- **修复**:
  - 构造函数新增 `contentResolver: ContentResolver` 参数
  - `create()` 中保存 `appContext.contentResolver` 引用并传入
  - `unregister()` 末尾添加 `runCatching { contentResolver.unregisterContentObserver(this) }`
- **验证**: 编译通过

### BUG-3: refresh() 的 pendingForceRefresh 递归调用逻辑错误

- **严重度**: P1（重要，功能错误）
- **问题**: `refresh()` 协程末尾 `if (pendingForceRefresh) { refresh(forceRefresh = true) }` 递归调用时，当前 `refreshJob` 仍处于 active 状态，进入 `refresh()` 后命中 `refreshJob?.isActive == true` 守卫直接 return，导致强制刷新请求丢失。
- **根因**: 递归调用与 Job 守卫冲突。
- **修复**: 改为 `do-while` 循环在协程内部重试：
  ```kotlin
  refreshJob = viewModelScope.launch {
      var shouldForceRefresh = forceRefresh || pendingForceRefresh
      pendingForceRefresh = false
      do {
          val currentForceRefresh = shouldForceRefresh
          shouldForceRefresh = false
          // ... 加载逻辑（用 currentForceRefresh）...
          if (pendingForceRefresh) {
              shouldForceRefresh = true
              pendingForceRefresh = false
          }
      } while (shouldForceRefresh)
  }
  ```
- **验证**: 编译通过

### BUG-4: LocalSystemMediaQueryCache 字段线程不安全

- **严重度**: P1（重要，并发安全）
- **问题**: `memoryItems`、`memoryStoredAtMillis`、`cachedContext` 是普通可变 `var`，无同步保护。`peek()` 从 main 线程和 IO 线程并发调用，`store()` 从 IO 线程写入，存在脏读风险。
- **根因**: 实施时未考虑跨线程访问。
- **修复**: 给 `peek()`、`store()`、`invalidate()` 添加 `@Synchronized` 注解。
- **验证**: 编译通过
