## 二、按 FR 实施详情

### FR-8 刷新机制重构

**目标**: 进入页面时若缓存有效（< 5 分钟），直接显示缓存数据并后台静默刷新；手动刷新按钮 / 下拉刷新才显示 loading；MediaStore 变更通过 ContentObserver 监听及时刷新。

**落地内容**:

1. **SystemMediaModels.kt** — `SystemMediaUiState` 新增 `val isBackgroundRefreshing: Boolean = false` 字段，用于区分后台静默刷新与手动 loading。

2. **SystemMediaRepository.kt** — `LocalSystemMediaQueryCache` 重构：
   - 新增 `StoredAtKey = "stored_at_millis"` 持久化 key
   - 新增 `memoryStoredAtMillis` 和 `cachedContext` 字段
   - `peek(context, maxAgeMillis)` 检查时效（`maxAgeMillis > 0` 时若超时返回 null）
   - `store()` 同步更新 `storedAtMillis`
   - `invalidate(context, clearDisk)` 支持清磁盘（清除 SharedPreferences 中的 ItemsKey + StoredAtKey）
   - `readFromDisk(prefs)` 改为接收 prefs 参数
   - `writeToDisk(context, items, storedAtMillis)` 增加 storedAtMillis 参数
   - 接口 `peekCachedMedia(maxAgeMillis: Long = 0L)` 增加可选参数
   - `invalidateSystemMediaMetadataCache(context, clearDisk = false)` 增加参数

3. **SystemMediaContentObserver.kt**（新增，完整 79 行）— MediaStore 变更监听：
   - 继承 `ContentObserver(handler)`
   - `onChange` 内部 500ms debounce（避免 MediaStore 短时间多次回调）
   - `companion object create()` 注册 `MediaStore.Files.getContentUri("external")` 观察者
   - `unregister()` 取消注册并清理协程作用域
   - SecurityException 兜底返回 null

4. **SystemMediaViewModel.kt** — 完全重写刷新机制：
   - 新增字段：`backgroundRefreshJob`、`contentObserver`
   - `init`：使用 `peekCachedMedia(maxAgeMillis = CACHE_VALIDITY_MILLIS)` 判断缓存时效，未过期直接显示缓存+后台刷新；过期或无缓存走常规 refresh
   - 新增 `registerContentObserver()`：注册 SystemMediaContentObserver
   - 新增 `startBackgroundRefresh()`：后台静默刷新（设置 `isBackgroundRefreshing = true`，不显示 loading）
   - `refresh()`：`isRefreshing = true`（手动 loading 标记）
   - `handleBridgeMutation`：MEDIA_STORE_CHANGED → `startBackgroundRefresh()`（不再 forceRefresh）
   - `onCleared()`：注销 contentObserver
   - `publishState()`：保留 `isBackgroundRefreshing` 状态
   - `CACHE_VALIDITY_MILLIS = 5L * 60L * 1000L`（5 分钟）

5. **SystemMediaScreen.kt** — 外层 `Box` 替换为 `PullToRefreshBox`：
   - `isRefreshing = uiState.isRefreshing`（仅手动 loading）
   - `onRefresh` 触发 `invalidateSystemMediaMetadataCache(context, clearDisk = true) + viewModel.refresh(forceRefresh = true)`
   - 添加 `@OptIn(ExperimentalMaterial3Api::class)` 注解（PullToRefreshBox 实验性 API）
   - 顶部 TopBar `onRefresh` 同步触发下拉刷新逻辑

6. **SystemMediaComponents.kt** — `SystemMediaTopBar` 参数 `isRefreshing` → `isManualRefreshing`，内部 `if (isRefreshing)` → `if (isManualRefreshing)`，UI 不变。

### FR-10 导入状态准确性修复

**目标**: 修复 metadata 指纹与归一化后的 displayTimeMillis 不一致问题；持久化 invalidatedAppMediaIds 避免重启后丢失；缓存层不再维护 importedAppMediaId；删除/恢复/上传后彻底清磁盘缓存。

**落地内容**:

1. **SystemMediaImportPreview.kt** — `stableImportMetadataKey()` 删除 `append(displayTimeMillis)` 行，避免归一化前后指纹不一致（统一基于 `type + mimeType + displayName + sizeBytes + width x height + videoDurationMillis`）。

2. **ImportOverlayStore.kt** — 持久化 `invalidatedAppMediaIds`：
   - 新增 `InvalidatedAppMediaIdsKey = "invalidated_app_media_ids"` 常量
   - `warmPersistentImportOverlay()` 末尾调用 `warmInvalidatedAppMediaIds(prefs)` 读取持久化的 invalidatedAppMediaIds JSON 数组
   - `persistImportOverlay()` 末尾追加序列化 invalidatedAppMediaIds 到 JSON 数组

3. **SystemMediaRepository.kt** — `toCacheJson()` **删除了 `importedAppMediaId` 字段**（缓存层不再维护此字段，导入状态由 ImportOverlay 单一来源维护）。
   - `toSystemMediaItemOrNull` 仍可读取 `importedAppMediaId`（向后兼容旧缓存），但下次 store 时会被清除。

4. **RealPhotoFeedViewModel.kt** — 删除流程 line 409 改为 `invalidateSystemMediaMetadataCache(clearDisk = true)`。

5. **RealTrashViewModels.kt** — 恢复/彻底删除流程 3 处（line 269, 371, 619）改为 `invalidateSystemMediaMetadataCache(clearDisk = true)`。

6. **SystemMediaUploadSupport.kt** — fake 上传成功路径（line 255）在 `finalizeOperationIfReady` 之后、`publishOperationSummaryIfReady` 之前添加 `invalidateSystemMediaMetadataCache(clearDisk = true)`。

7. **SystemMediaUploadReal.kt** — 真实上传成功路径（line 821）在 `rememberAppMediaIdForSource` 之后添加 `invalidateSystemMediaMetadataCache(clearDisk = true)`。

### FR-11 时间滑条回弹 Bug 修复

**目标**: 拖拽期间冻结布局，不修改 renderedCount，避免 LazyVerticalGrid relayout。

**落地内容**:

**SystemMediaScreen.kt** 两处关键修改：

1. **`onSeekToProgress`**（原 line 813-821）— **删除了 renderedCount 修改逻辑**（原 `nextRenderedCount` 计算和赋值），只保留 `scrollToItem`。因为 `onInteractingChanged` 已经一次性全量扩展，拖拽中无需再扩展。

2. **`onInteractingChanged`** — 拖拽开始时一次性全量扩展 `renderedCount`：
   ```kotlin
   if (interacting) {
       scrubberDragProgress = currentScrollProgress
       scrubberDragLabel = currentScrubberLabel
       if (density != PhotoFeedDensity.OVERVIEW_16 &&
           renderedCount < uiState.filteredItems.size
       ) {
           renderedCount = uiState.filteredItems.size
       }
   } else {
       scrubberDragProgress = null
       scrubberDragLabel = ""
       // 拖拽结束后不回收 renderedCount（保持当前可见范围，避免回收引起闪烁）
   }
   ```
   - 拖拽期间不再修改 `renderedCount`，避免触发 LazyVerticalGrid relayout 导致回弹。

### FR-14 16列卡顿优化

**目标**: 16 列模式滚动帧率 ≥ 55fps，减少不必要的缩略图解码，避免缓存 thrashing。

**落地内容**:

1. **SystemMediaGrid.kt**:
   - `systemMediaThumbnailWarmWindow(OVERVIEW_16)`: 420 → 240（减少预热窗口，降低内存压力）
   - `systemMediaThumbnailWarmBatchSize(OVERVIEW_16)`: 18 → 10（减小批次，避免一次性 IO 过载）

2. **SystemMediaThumbnail.kt**:
   - `SystemMediaOverviewThumbnailCacheMaxBytes`: 24MB → 48MB（增大概览层缓存，降低 thrashing）
   - 新增 `SystemMediaVideoThumbnailCacheMaxBytes = 32 * 1024 * 1024`
   - `SystemMediaVideoThumbnailCache`: 从无界 `ConcurrentHashMap<String, Bitmap>` 改为有界 `LruCache<String, Bitmap>(32MB)`，重写 `sizeOf` 按 byteCount 计量
   - `rememberSystemVideoThumbnail`: `.bitmaps[key]` → `.get(key)` / `.put(key, bitmap)`
   - `prefetchSystemVideoThumbnail`: 同上

3. **SystemMediaScrubber.kt** — `calculateSystemMediaScrollProgress` 中 `blocks.take(...).count { ... }` 改为手动 for 循环计数（避免创建中间列表，减少 GC 压力）：
   ```kotlin
   val limit = (firstVisible.index + 1).coerceAtMost(blocks.size)
   var mediaCount = 0
   for (i in 0 until limit) {
       if (blocks[i] is SystemMediaGridBlock.Media) mediaCount++
   }
   ```

## 四、过程中的修正（实施时发现的偏差）

1. **CACHE_VALIDITY_MILLIS 误写**：初次写成 `5L * 60L * 60L * 1000L`（5 小时），已修正为 `5L * 60L * 1000L`（5 分钟，符合 FR-8 验收标准）。

2. **isRefreshing 语义**：初次写成 `isRefreshing = !showLoading`，后修正为 `isRefreshing = true`（手动刷新始终设置 loading 标记，与 isBackgroundRefreshing 区分）。

3. **LocalSystemMediaQueryCache cachedContext**：为支持无 context 调用 invalidate 时清磁盘，新增 `cachedContext` 字段在 peek/store 时缓存 applicationContext，避免 invalidate 时 context 丢失。

4. **SystemMediaUploadSupport.kt 补充**：实施时发现计划第 14 项 SystemMediaUploadSupport.kt（fake 上传路径）尚未添加 invalidate 调用，补上 `invalidateSystemMediaMetadataCache(clearDisk = true)` 在 `finalizeOperationIfReady` 之后、`publishOperationSummaryIfReady` 之前，与 SystemMediaUploadReal.kt 保持一致。

5. **FR-14 SystemMediaScrubber.kt 实现方式**：计划写的是二分查找，但实施时检查发现 `SystemMediaGridBlock` 没有 `firstItemIndex` 字段，二分查找无法直接应用。改为手动 for 循环计数（避免创建中间列表），同样达到 O(N) → O(K) 的优化效果（K = firstVisible.index + 1，通常远小于 N）。
