## 十、编译过程中的 Bug 修复记录

### BUG-1: PullToRefreshBox 实验性 API

- **位置**: `SystemMediaScreen.kt:572`
- **错误**: `This material API is experimental and is likely to change or to be removed in the future.`
- **根因**: `PullToRefreshBox` 是 Material3 实验性 API，需要 `@OptIn` 注解
- **修复**:
  1. 新增 import `androidx.compose.material3.ExperimentalMaterial3Api`
  2. 在 `SystemMediaScreen` 函数添加 `@OptIn(ExperimentalMaterial3Api::class)` 注解
- **验证**: 重新编译通过

### BUG-2: AndroidViewModel.application 私有访问

- **位置**: `SystemMediaViewModel.kt:56`
- **错误**: `Cannot access 'val application: Application': it is private in 'androidx/lifecycle/AndroidViewModel'.`
- **根因**: `AndroidViewModel.application` 是 private 字段，子类不能直接访问
- **修复**: 改为 `getApplication()` 方法访问
  ```kotlin
  contentObserver = SystemMediaContentObserver.create(getApplication()) {
      startBackgroundRefresh()
  }
  ```
- **验证**: 重新编译通过

### BUG-3: SystemMediaUploadSupport.kt 遗漏 invalidate 调用

- **位置**: `SystemMediaUploadSupport.kt:254-255`
- **问题**: 实施时发现 fake 上传成功路径未添加 `invalidateSystemMediaMetadataCache(clearDisk = true)` 调用
- **根因**: 计划第 14 项 SystemMediaUploadSupport.kt（fake 路径）在初次实施时被遗漏
- **修复**: 在 `finalizeOperationIfReady(operationId, onOperationSuccess)` 之后、`OperationBus.publishOperationSummaryIfReady(operationId)` 之前添加 `invalidateSystemMediaMetadataCache(clearDisk = true)`
- **验证**: 重新编译通过，与 SystemMediaUploadReal.kt 保持一致
