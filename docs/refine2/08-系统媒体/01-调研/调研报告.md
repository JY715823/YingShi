## 二、用户流程

### 流程1: 打开系统媒体页浏览
用户点击照片模块"系统媒体"入口 → SystemMediaScreen → 检查权限 → 从缓存恢复(冷启动)或直接查询 MediaStore → 后台查询远程导入状态 → 合并 overlay → 按筛选条件过滤 → 渲染网格 → 缩略图异步加载+预热。

涉及: `SystemMediaScreen`, `SystemMediaViewModel`, `SystemMediaRepository`, `LocalSystemMediaBridgeRepository`, `LocalSystemMediaQueryCache`

### 流程2: 导入照片到 App 媒体库
用户多选媒体 → 点击"导入" → ImportPreviewDialog 查重+时间校验 → 确认后入队上传 → 2并发上传(MediaStore读取→创建token→multipart上传→确认) → 上传成功后标记已导入 → 通知照片流刷新。

涉及: `LocalSystemMediaBridgeRepository.enqueueImportToAppUpload()`, `SystemMediaImportPreviewDialog`, `UploadRepository`, `RealBackendMutationBus`

### 流程3: 新建小相册
用户多选媒体 → 点击"新建" → 跳转 CreatePostRoute → 上传新媒体+复用已导入媒体 → 创建小相册+关联 → 成功后跳转小相册详情。

涉及: `LocalSystemMediaBridgeRepository.enqueueCreatePostUpload()`, `PostRepository.createPost()`

### 流程4: 加入已有小相册
用户多选媒体 → 点击"加入" → PostDestinationDialog 选择目标小相册 → 跳过已关联媒体 → 上传新媒体 → 追加关联 → 成功通知。

涉及: `LocalSystemMediaBridgeRepository.enqueueAddToExistingPostUpload()`, `SystemMediaPostDestinationDialog`, `PostRepository.addMediaToPost()`

### 流程5: 删除系统媒体
用户多选媒体 → 点击"删除" → 系统回收站确认 dialog (API 30+) → 用户确认 → 标记隐藏 → 触发全量刷新 → 仅影响本地 MediaStore，不影响 App 媒体库。

涉及: `SystemMediaTrashRequests`, `LocalSystemMediaBridgeRepository.markMovedToSystemTrash()`

### 流程6: 查看系统媒体
用户点击网格中某媒体 → SystemMediaViewerScreen → HorizontalPager 翻页 → 缩放/双击/长图/视频播放 → 底部信息卡 → 菜单操作(导入/加入/删除)。

涉及: `SystemMediaViewerScreen`, `SystemViewerZoomState`, `SystemMediaViewerCanvas`

## 三、数据流向

### 前后端数据流
```
[MediaStore] → SystemMediaRepository.queryMedia() → SystemMediaItem 列表
                                              ↓
                              withAppImportStatus() 批量查询指纹
                                              ↓
                              POST /api/media/import-status (Server)
                                              ↓
                              合并导入状态 → overlay → 渲染网格

[用户操作: 导入/新建/加入]
  → LocalSystemMediaBridgeRepository 上传队列
  → POST /api/uploads/token → POST /api/uploads/{id}/file → POST /api/uploads/{id}/confirm
  → Server: UploadService → MediaEntity 创建
  → 成功后 → RealBackendMutationBus → 照片流刷新
```

### sourceFingerprint 双指纹策略
1. **sourceFingerprint**: `store:${type}:${mediaStoreId}` 的 SHA-256 — 基于 MediaStore 原生 ID，稳定但仅限本机
2. **metadataFingerprint**: `meta:${type}|${mimeType}|${displayName}|${size}|${time}|${WxH}|${duration}` 的 SHA-256 — 基于文件元数据，跨设备可匹配

查询时优先匹配 source，回退到 metadata。上传时只存 metadata 指纹。

## 七、UI/视觉现状评估

### Theme Token使用
- 所有 SystemMedia UI 文件均正确使用 `YingShiThemeTokens`
- Viewer 使用独立深色 token (viewerBackground/viewerSurface/viewerAccent等)
- 唯一硬编码颜色在 `paletteForSystemMediaId()` — 缩略图占位渐变背景，属于有意设计

### 视觉层
- 网格卡片：缩略图 + 选中框/光泽 + 已导入标记 + 视频时长badge + 内联视频播放器
- 密度切换：Ghost Overlay 交叉淡出过渡(520ms alpha + 0.998f scale)
- 16列模式：简化卡片(无覆盖层)、年份头、96px缩略图、禁用animateItem
- 时间滑条：复用 PhotoFeedTimeScrubber，自绘拖拽手柄(胶囊+三角)
- 上传面板：最近3个任务进度条

### 与设计计划的差距
- 系统媒体页面整体视觉风格与照片流保持一致，符合"工具区"定位
- 网格卡片的选中框/光泽效果已有，但可能缺乏 design-plan 要求的"材质光影"层次
- 16列概览模式的视觉丰富度较低（有意为之的性能取舍）

## 八、总结

系统媒体模块是映世App中**功能最完整、代码量最大**的模块之一（15文件/9700行）。上轮精修(2026-06-18 closed)已完成了核心功能闭环：MediaStore查询、导入状态管理、上传调度、密度切换、时间滑条、Viewer等。

**当前主要问题集中在三方面**：

1. **代码架构**：`LocalSystemMediaBridgeRepository` 3273行巨型单例，`SystemMediaScreen.kt` 2547行，`SystemMediaViewerScreen.kt` 1611行。可维护性和可测试性差。
2. **测试覆盖**：几乎为零（仅1个测试），回归风险极高。
3. **代码重复**：`paletteForSystemMediaId()` 双份副本，`SystemViewerZoomState` 与共享 `ViewerZoomState` 完全重复。

**服务端完全就绪**，所有系统媒体需要的 API 已完整实现，无需新增端点。
