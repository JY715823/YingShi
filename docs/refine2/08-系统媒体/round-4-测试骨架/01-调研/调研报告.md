### 核心查重函数

- **位置**: [SystemMediaImportPreview.kt#L55-L123](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/SystemMediaImportPreview.kt#L55-L123)
- **签名**: `internal fun buildSystemMediaImportPreview(mediaItems, preference, importedAtBaseMillis, knownAppMediaIdForSource): SystemMediaImportPreview`
- **特性**: 纯函数，所有依赖通过参数注入，是理想的单元测试对象

### 三态判定逻辑

| 状态 | 判定条件 | reason |
|------|---------|--------|
| **已导入** | `knownAppMediaIdForSource(groupFirst) != null` → 整组标记 | `ALREADY_IMPORTED` |
| **新媒体** | `knownAppMediaIdForSource == null` 且组内首个 | 进入 `importableItems` |
| **重复** | `knownAppMediaIdForSource == null` 且非组内首个 | `DUPLICATE_IN_SELECTION` |

- **判定单元是分组**：同一 sourceKey 的所有 item 命运一致
- **守恒律**: `requestedCount == importableCount + duplicateCount`
- **sourceKey 优先级**: mediaStoreId > picked 路径 > uri > metadata

## 五、关键发现与测试策略

### 关键发现

1. **applyFilter 可见性障碍**: 当前是 private 顶层函数，需改为 internal（一处改动）才能测试
2. **ViewModel 无法直接构造**: AndroidViewModel + init 块强依赖 Android 框架，测试应针对 applyFilter 纯函数
3. **buildSystemMediaImportPreview 已是 internal**: 无需改可见性，直接可测
4. **无需引入新依赖**: JUnit4 + 现有 UriTestDouble + sampleSystemMediaItem helper 足够
5. **现有 ImportPreview 测试应扩展而非新建**: 已有 5 个用例和完整 helper
