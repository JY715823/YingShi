## 四、数据流依赖

### 4.1 FR-2 数据流（改动后）

```
deleteLargeAlbum(albumId, currentUser)
│
├── 查询 smallAlbums（PostRepository）
├── 提取 smallAlbumIds
├── 查询 mediaIds（PostMediaRepository，去重）
│
├── 软删 Album + SmallAlbums
│
└── createTrashItem(...)
    ├── relatedPostIds = smallAlbumIds（全量，<2000 字符）
    ├── relatedMediaIds = truncateMediaIdsForColumn(mediaIds)（前 20 个）
    └── snapshotJson = {
            "albumId": albumId,
            "smallAlbumIds": [...全量...],
            "mediaIds": [...全量...]    ← 新增
        }

purgeLargeAlbumDeleted(item, libraryId)
│
├── readLargeAlbumDeletedSnapshot(item)
│   └── Jackson 反序列化 → mediaIds 可能 null（历史数据）
│
├── resolveMediaIdsForPurge(snapshot, item)
│   ├── snapshot.mediaIds() 非空 → 用 snapshot mediaIds
│   └── snapshot.mediaIds() 为空 → fallback 到 item.relatedMediaIds（split）
│
├── 按 smallAlbumId 维度清理（既有逻辑）
│   ├── purgeMediaRemovedItemsForSmallAlbum
│   ├── postMediaRepository.deleteByLibraryIdAndPostId
│   ├── commentRepository.deleteByLibraryIdAndPostId
│   └── postRepository.delete
│
├── 按 mediaId 维度清理（新增）
│   ├── postMediaRepository.deleteByLibraryIdAndMediaId
│   └── commentRepository.deleteByLibraryIdAndMediaId
│
└── albumRepository.delete
```

## 五、不可协商项与约束

| # | 约束 | 说明 | 本轮影响 |
|---|------|------|---------|
| 1 | 删除大相册不删除媒体本体 | purge 只删 postMedia 关系 + post + album，不删 media | FR-2 mediaIds 维度清理仅删 postMedia + comment，不删 media |
| 2 | relatedMediaIds 列长度 2000 | varchar(2000)，约 66 条 mediaId 触发截断 | FR-2 截断为前 20 条（约 720 字符） |
| 3 | snapshotJson 无长度限制 | text 列，可存任意长度 JSON | FR-2 完整 mediaIds 存入 snapshot |
| 4 | Testcontainers JVM 级复用 | 测试间共享容器，数据不清空 | FR-1 测试用唯一标识避免冲突 |
| 5 | Flyway ddl-auto=validate | JPA 不自动建表，依赖 Flyway 迁移 | FR-2 无需迁移 |
| 6 | 种子数据无大相册 | TestSeedDataInitializer 只预置用户和库 | FR-1 测试通过 API 自建大相册 |
