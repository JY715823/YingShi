#### 改动点 3：TrashService.java 新增私有方法 truncateMediaIdsForColumn

**新增代码**（放在 createTrashItem 方法附近）:
```java
private static final int RELATED_MEDIA_IDS_SUMMARY_LIMIT = 20;

private List<String> truncateMediaIdsForColumn(List<String> mediaIds) {
    if (mediaIds == null || mediaIds.size() <= RELATED_MEDIA_IDS_SUMMARY_LIMIT) {
        return mediaIds;
    }
    return mediaIds.subList(0, RELATED_MEDIA_IDS_SUMMARY_LIMIT);
}
```

**说明**:
- 仅对 LARGE_ALBUM_DELETED 场景的 mediaIds 截断
- createTrashItem 保持通用性，不内部截断
- 前 20 个媒体 ID 作为摘要写入 relatedMediaIds 列（约 720 字符，远低于 2000 限制）

#### 改动点 4：TrashService.java L519-528 — purgeLargeAlbumDeleted 从 snapshot 读取 mediaIds + fallback

**当前代码**:

**改动后**:
```java
private void purgeLargeAlbumDeleted(TrashItemEntity item, String libraryId) {
    TrashSnapshotHelper.LargeAlbumDeletedSnapshot snapshot = snapshotHelper.readLargeAlbumDeletedSnapshot(item);
    // mediaIds 完整列表优先从 snapshot 读取，历史数据 fallback 到 relatedMediaIds 列
    List<String> mediaIds = resolveMediaIdsForPurge(snapshot, item);
    for (String smallAlbumId : snapshot.smallAlbumIds()) {
        purgeMediaRemovedItemsForSmallAlbum(libraryId, smallAlbumId);
        postMediaRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
        commentRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
        postRepository.findByIdAndLibraryId(smallAlbumId, libraryId).ifPresent(postRepository::delete);
    }
    // 额外保障：按 mediaIds 维度清理（覆盖无 smallAlbum 关联的孤儿媒体关系）
    if (mediaIds != null && !mediaIds.isEmpty()) {
        for (String mediaId : mediaIds) {
            postMediaRepository.deleteByLibraryIdAndMediaId(libraryId, mediaId);
            commentRepository.deleteByLibraryIdAndMediaId(libraryId, mediaId);
        }
    }
    albumRepository.findByIdAndLibraryId(snapshot.albumId(), libraryId).ifPresent(albumRepository::delete);
}
```

**新增私有方法**:
```java
private List<String> resolveMediaIdsForPurge(
        TrashSnapshotHelper.LargeAlbumDeletedSnapshot snapshot,
        TrashItemEntity item
) {
    List<String> snapshotMediaIds = snapshot.mediaIds();
    if (snapshotMediaIds != null && !snapshotMediaIds.isEmpty()) {
        return snapshotMediaIds;
    }
    // 历史数据 fallback：relatedMediaIds 列可能被截断，但仍尽可能清理
    String relatedMediaIds = item.getRelatedMediaIds();
    if (relatedMediaIds == null || relatedMediaIds.isBlank()) {
        return List.of();
    }
    return Arrays.stream(relatedMediaIds.split(","))
            .map(String::trim)
            .filter(s -> !s.isEmpty())
            .toList();
}
```

**说明**:
- 新增 mediaIds 维度清理逻辑（双重保障）
- 历史 snapshot 无 mediaIds 字段时 fallback 到 relatedMediaIds 列
- 使用 Arrays.stream（Arrays 已在 import 中，L39）

### 1.3 边界条件与防御

| # | 边界场景 | 处理策略 |
|---|---------|---------|
| 1 | 大相册无小相册（smallAlbumIds 为空） | mediaIds 也为空，snapshot 存空 List，relatedMediaIds 存空字符串 |
| 2 | 大相册有 100+ 媒体 | snapshot.mediaIds 存全量 100+，relatedMediaIds 截断为前 20 |
| 3 | 历史 trash 数据（无 mediaIds 字段） | snapshot.mediaIds 反序列化为 null，purgeLargeAlbumDeleted fallback 到 relatedMediaIds |
| 4 | relatedMediaIds 列为 null/空 | resolveMediaIdsForPurge 返回 List.of()，跳过 mediaIds 维度清理 |
| 5 | smallAlbumIds 为 null（异常情况） | 当前代码直接 NPE，不在本次修复范围（历史无此问题） |

### 1.4 编译验证点

- `TrashSnapshotHelper.LargeAlbumDeletedSnapshot` 构造器签名变更，所有调用点需同步更新
- 调用点仅 1 处：`TrashService.java` L126
- `Arrays` 已在 TrashService.java import（L39），无需新增 import

@Test
void largeAlbumDeletedFullLifecycle() throws Exception {
    String token = loginAndGetAccessToken();

    String albumId = createLargeAlbum(token, "Lifecycle Album");

            .andExpect(status().isOk())
            .andReturn();

    mockMvc.perform(post("/api/trash/items/{trashItemId}/purge", trashItemId2)
                    .header("Authorization", "Bearer " + token))
            .andExpect(status().isOk());
    
    // 7. 验证物理删除
    mockMvc.perform(get("/api/albums")
                    .header("Authorization", "Bearer " + token))
            .andExpect(jsonPath("$.data[?(@.albumId == '%s')]".formatted(albumId)).doesNotExist());
}
