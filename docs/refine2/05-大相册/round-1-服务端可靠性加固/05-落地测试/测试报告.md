# Round 1 落地测试报告

> 测试时间: 2026-07-10
> 测试环境: Windows + Docker Desktop 29.4.3 + Testcontainers 1.21.4 + PostgreSQL 16-alpine
> 测试命令: `mvnw.cmd test -Dtest=AlbumIntegrationTest,TrashIntegrationTest`

## 一、测试环境准备

### 1.1 Testcontainers 兼容性修复

**问题**: Testcontainers 1.20.4 与 Docker Desktop 29.4.3 不兼容，连接 Docker API 返回 400 BadRequest。

**修复**: 升级 Testcontainers 至 1.21.4（pom.xml 中 3 个依赖同步升级）。

**验证**: Testcontainers 1.21.4 成功连接 Docker Desktop 29.4.3，API Version 1.54。

### 1.2 Ryuk 镜像拉取禁用

**问题**: Docker 镜像源 `dockerproxy.com` 超时，`testcontainers/ryuk:0.12.0` 拉取失败。

**修复**: 设置环境变量 `TESTCONTAINERS_RYUK_DISABLED=true`（Ryuk 非测试必需组件）。

### 1.3 单例容器模式

**问题**: `@Container` 注解的容器在每个测试类之间重启，导致 Spring 上下文缓存中的 datasource URL 过期，引发 `CannotCreateTransactionException`。

**修复**: 改为单例容器模式 — 静态初始化块中 `postgres.start()`，所有测试类共享同一容器实例。

## 二、Spring Boot 4.0 兼容性修复

### 2.1 `@TestConfiguration` 显式导入

**问题**: Spring Boot 4.0 不再自动检测 `@TestConfiguration` 内部类，`AbstractPostgresIntegrationTest.TestCapturingConfig` 被忽略。

**修复**: 在基类上添加 `@Import(AbstractPostgresIntegrationTest.TestCapturingConfig.class)`。

### 2.2 Spring Data JPA 4.0 返回类型约束

**问题**: `MediaRepository.findTopByLibraryIdOrderByUpdatedAtDesc(String, Pageable)` 返回 `Optional<MediaEntity>`，Spring Data JPA 4.0 禁止 `Optional` + `Pageable` 组合。

**修复**: 返回类型从 `Optional<MediaEntity>` 改为 `List<MediaEntity>`（2个方法，均为未使用遗留代码）。

### 2.3 `ImportedMessageSearchEntity` ID 属性映射

**问题**: `ImportedMessageSearchRepository` 使用 `findByIdAndLibraryId` 等方法名，但 `@Id` 注解在 `messageId` 字段上（非 `id`），Spring Data JPA 4.0 不再自动映射。

**修复**: 重命名 Repository 方法：`Id` → `MessageId`（3个方法），同步更新调用方 `ChatImportedSyncService`。

### 2.4 `ObjectMapper` Bean 缺失

**问题**: `ChatImportedZipService` 构造函数注入 `ObjectMapper`，但 Spring Boot 4.0 + `spring-boot-starter-webmvc` 不自动注册 Jackson `ObjectMapper` Bean。

**修复**: 改为 `private final ObjectMapper objectMapper = new ObjectMapper()`（与 `TrashSnapshotHelper`、`ChatSnapshotService` 保持一致）。

## 三、UploadService FK 约束修复

**问题**: V24 迁移在 `upload_tasks.media_id` 上添加了外键约束（→ `media(id)`），但 `createUploadToken` 在创建 UploadTask 时设置了 `mediaId`，而 Media 实体尚未创建，导致 `DataIntegrityViolationException`。

**修复**: 移除 `createUploadToken` 中的 `task.setMediaId(mediaId)`，`mediaId` 在 `uploadFile`/`confirmUpload` 阶段从 `task.getMediaId()`（null → 生成新 ID）解析。

## 四、测试用例修正

### 4.1 上传请求格式

**问题**: 测试使用 `fileSize` 字段，但 `UploadTokenRequest` record 的字段名是 `fileSizeBytes`。缺少 `mediaType`、`width`、`height`、`displayTimeMillis` 必填字段。

**修复**: 更新 `AlbumIntegrationTest` 和 `TrashIntegrationTest` 的 `uploadAndConfirmMedia` 辅助方法，使用正确的 DTO 字段名。

### 4.2 枚举值序列化格式

**问题**: 测试期望 `IN_TRASH`、`RESTORED` 等大写枚举值，但实际序列化为 `inTrash`、`restored`（驼峰）。

**修复**: 更新断言为驼峰格式。

### 4.3 Trash 列表响应路径

**问题**: 测试期望 `$.data.content`，但 `TrashPageResponse` record 使用 `items` 字段。

**修复**: 更新为 `$.data.items`。

### 4.4 软删除后端点行为

**问题**: `largeAlbumDeletedCascadeRestoreRestoresSmallAlbums` 期望大相册软删除后访问 `/api/albums/{albumId}/small-albums` 返回 200 + 空列表，但 `requireAlbum` 使用 `deletedAtIsNull` 过滤，软删除后返回 404。

**修复**: 更新断言为期望 404（证明大相册已被软删除）。

### 4.5 测试数据隔离

**问题**: `listTrashInitiallyEmpty` 期望空列表，但多个测试类共享同一数据库，前面的测试创建的 trash items 残留。

**修复**: 改为验证响应结构有效性（`isArray` + 分页字段存在），不再期望空。
