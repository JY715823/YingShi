## 二、发现的 Bug

### BUG-1: purgeLargeAlbumDeleted 误删跨相册媒体关联（HIGH）

**问题**: `purgeLargeAlbumDeleted` 中新增的 mediaId 维度清理循环（L528-533）通过 `postMediaRepository.deleteByLibraryIdAndMediaId(libraryId, mediaId)` 跨所有 post 删除关联。如果同一媒体被添加到不同大相册下的小相册，purge 大相册 A 会误删大相册 B 中小相册对该媒体的引用和评论。

**根因**: FR-2 实施时过度设计了 purge 逻辑。原 `purgeLargeAlbumDeleted` 只按 postId 维度清理（足够），新增的 mediaId 维度清理是多余的，且会跨相册误删。对比 `purgeSmallAlbumDeleted`（只按 postId 清理），两个方法策略不一致。

**修复**: 移除 mediaId 维度清理循环（L528-533），保留按 postId 维度的清理。同时移除因此变成死代码的 `resolveMediaIdsForPurge` 方法。

**验证**: 14/14 测试全部通过，`largeAlbumDeletedFullLifecycle` 的 purge 步骤验证物理删除成功。

### BUG-2: readLargeAlbumDeletedSnapshot 未处理空快照（MEDIUM）

**问题**: `readLargeAlbumDeletedSnapshot` 直接调用 `readSnapshot(item.getSnapshotJson(), ...)`，未经过 `normalizeLegacySnapshotJson` 守卫。当 `snapshotJson` 为 null 时会抛出未包装的 `IllegalArgumentException`。

**根因**: FR-2 扩展 `LargeAlbumDeletedSnapshot` 时遗漏了对读取方法的空值守卫。其他三个读取方法都有 `normalizeLegacySnapshotJson` 调用。

**修复**: 改为 `readSnapshot(normalizeLegacySnapshotJson(item), LargeAlbumDeletedSnapshot.class)`。

**验证**: 编译通过，14/14 测试通过。
