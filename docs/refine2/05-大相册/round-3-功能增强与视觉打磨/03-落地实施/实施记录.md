## 四、计划外变更说明

### `FakeRepositories.kt` — `FakeAlbumRepositoryShell`

- **原因**: `AlbumRepository` 接口新增 `moveSmallAlbums` 方法后，所有实现该接口的类都必须实现新方法。`FakeAlbumRepositoryShell` 是 FAKE 模式下的接口实现类（委托 `FakeAlbumRepository` object），实施计划中遗漏了此文件。
- **影响**: 仅 FAKE 模式，REAL 模式不受影响。
- **实现**: 委托 `FakeAlbumRepository.moveSmallAlbums` + `.map { it.toRemotePostSummary() }` 转换为 `ApiResult<List<RemotePostSummary>>`。
- **风险评估**: 低风险。`FakeAlbumRepositoryShell` 仅在 FAKE 模式使用，且实现逻辑与 `RealAlbumRepository` 保持一致。

## 五、编译问题与修复记录

### 问题 1: `combinedClickable` 实验性 API

- **错误**: `YingShiInteractions.kt:81:14 This foundation API is experimental and is likely to change or be removed in the future.`
- **根因**: `combinedClickable` 标注了 `@ExperimentalFoundationApi`，使用时需要显式 OptIn
- **修复**: 在 `yingShiClickable` 函数上添加 `@OptIn(ExperimentalFoundationApi::class)` 注解 + 新增 `import ExperimentalFoundationApi`
- **验证**: 重新编译通过

### 问题 2: `FakeAlbumRepositoryShell` 未实现接口方法

- **错误**: `Class 'FakeAlbumRepositoryShell' is not abstract and does not implement abstract member: suspend fun moveSmallAlbums(...)`
- **根因**: `Contracts.kt` 的 `AlbumRepository` 接口新增 `moveSmallAlbums` 方法后，`FakeAlbumRepositoryShell` 也需要实现
- **修复**: 在 `FakeAlbumRepositoryShell` 中新增 `moveSmallAlbums` 实现，委托 `FakeAlbumRepository`
- **验证**: 重新编译通过
