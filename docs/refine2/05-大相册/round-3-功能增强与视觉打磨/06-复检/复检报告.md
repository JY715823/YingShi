## 二、发现的 Bug（已修复）

### BUG-1: shouldAutoDismiss 遗漏移动消息 [HIGH]

**问题**: `RealPhotoViewModels.kt` 的 `shouldAutoDismiss()` 函数白名单不包含移动成功消息"已将 X 个小相册移动到目标大相册。"，导致 `AlbumPageScreen.kt` 的 `LaunchedEffect(uiState.statusMessage)` 在 2800ms 后调用 `clearStatusMessage()` 时，`shouldAutoDismiss()` 返回 false，消息**永久停留**在屏幕上。

**根因**: `moveSmallAlbums` 方法新增的状态消息未同步更新到 `shouldAutoDismiss()` 白名单。

**修复**: 在 `shouldAutoDismiss()` 中添加 `endsWith("个小相册移动到目标大相册。")` 条件。

**验证**: 编译通过，消息将在 2800ms 后自动消失。

**代码位置**: `RealPhotoViewModels.kt` L913

---

### BUG-2: moveSmallAlbums 竞态条件导致显示错误相册帖子 [HIGH]

**问题**: `moveSmallAlbums` 成功后无条件调用 `loadAlbumPosts(sourceAlbumId)`。移动操作是异步的（`viewModelScope.launch`），在 mutation 期间用户可以切换到另一个大相册（AlbumSwitchChip 点击不受 `isAlbumMutating` 限制）。当 mutation 完成后，`loadAlbumPosts(sourceAlbumId)` 会覆盖用户已切换到的新相册的帖子列表，导致 UI 显示相册 B 被选中但帖子列表却是相册 A 的内容。

**根因**: 第 462 行的 `loadAlbumPosts(sourceAlbumId)` 调用缺少与第 453 行 posts 更新相同的 `if (sourceAlbumId == it.selectedAlbumId)` 保护。

**修复**: 在 `loadAlbumPosts` 调用前增加 `if (sourceAlbumId == _uiState.value.selectedAlbumId)` 保护。若用户已切换相册，不刷新 source 列表（mutation bus 通知会触发 `refresh()` 修正数据）。

**验证**: 编译通过，用户切换相册后不再被覆盖。

**代码位置**: `RealPhotoViewModels.kt` L462-467

---

### BUG-3: MoveSmallAlbumsPayload 死代码 [MEDIUM]

**问题**: `PostAlbumRepositoryModels.kt` 中定义的 `MoveSmallAlbumsPayload` data class 从未被任何文件 import 或使用。`AlbumRepository.moveSmallAlbums` 方法直接接收 `targetAlbumId` 和 `smallAlbumIds` 两个参数，而非包装在 Payload 对象中。

**根因**: 实施计划中设计了 Payload 包装类，但实际实现时 VM 直接传参，Payload 成为死代码。

**修复**: 删除 `MoveSmallAlbumsPayload` data class。

**验证**: 编译通过，无引用错误。

**代码位置**: `PostAlbumRepositoryModels.kt` 原 L115-118（已删除）
