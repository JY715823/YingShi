### FR-2: relatedMediaIds 截断风险修复

**描述**: `TrashService.deleteLargeAlbum()` 将所有子小相册的媒体 ID 逗号分隔存入 `TrashItemEntity.relatedMediaIds` 字段（长度限制 2000 字符）。大相册包含大量媒体时可能被截断，导致 purge 时无法正确清理。修复：将完整媒体 ID 列表移入 `snapshotJson`（JSON 无长度限制），`relatedMediaIds` 仅保留前 20 个 ID 作为摘要。

**端**: Server
**优先级**: P0
**验收标准**:
- AC-1: `LargeAlbumDeletedSnapshot` JSON 新增 `mediaIds: List<String>` 字段
- AC-2: `deleteLargeAlbum` 将完整 mediaIds 写入 snapshotJson，relatedMediaIds 截断为前 20 个
- AC-3: `purgeLargeAlbumDeleted` 从 snapshotJson 读取完整 mediaIds（如有），否则 fallback 到 relatedMediaIds
- AC-4: 现有测试 + 新增测试全部通过
**涉及文件**:
- `E:/Study/App/YingShi-Server/src/main/java/com/yingshi/server/service/trash/TrashSnapshotHelper.java` — LargeAlbumDeletedSnapshot 扩展
- `E:/Study/App/YingShi-Server/src/main/java/com/yingshi/server/service/trash/TrashService.java` — deleteLargeAlbum + purgeLargeAlbumDeleted

### FR-5: RealTrashMemoryCache 内存泄漏修复

**描述**: `RealTrashMemoryCache` 使用 `mutableMapOf<String, TrashListState>` 和 `mutableMapOf<String, TrashDetailState>` 存储状态，不会清理旧条目。长时间使用后可能积累大量条目。修复：添加 LRU 淘汰策略，最大保留 20 个 listStates 和 50 个 detailStates。

**端**: Android
**优先级**: P1
**验收标准**:
- AC-1: `RealTrashMemoryCache` 添加 `maxListStates = 20` 和 `maxDetailStates = 50` 限制
- AC-2: 超出限制时淘汰最早写入的条目（LRU 策略）
- AC-3: `gradlew.bat assembleDebug` 编译通过
**涉及文件**:
- `E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/RealTrashViewModels.kt` — RealTrashMemoryCache

### FR-8: 切换小相册所属大相册

**描述**: 实现"将小相册从一个大大相册移动到另一个大相册"功能。前后端一起实现。

**Server 端**:
- 新增端点 `PATCH /api/albums/{targetAlbumId}/move-small-albums`
- 请求体: `MoveSmallAlbumsRequest { smallAlbumIds: List<String> }`
- 逻辑: 将指定的 PostEntity 的 `albumId` 更新为 `targetAlbumId`
- 返回: `ApiResponse<List<PostSummaryDto>>`（移动后的小相册列表）
- 校验: targetAlbum 存在且未删除；所有 smallAlbum 存在且未删除；所有 smallAlbum 当前属于同一 library

**Android 端**:
- `AlbumApi.kt` 新增 `moveSmallAlbums()` 方法
- `AlbumRepository` 接口新增 `moveSmallAlbums(targetAlbumId, smallAlbumIds)`
- `RealAlbumRepository` 实现
- `AlbumPageRealViewModel` 新增 `moveSmallAlbums()` 方法（调 API → 更新缓存 → mutation bus 通知）
- `AlbumDirectoryDialog` 中为每个小相册添加"移动到其他大相册"操作（长按或菜单项）→ 弹出目标大相册选择器 → 确认后执行移动

**端**: Both
**优先级**: P1
**验收标准**:
- AC-1: Server 端 `PATCH /api/albums/{targetAlbumId}/move-small-albums` 端点可用
- AC-2: 移动后 source 大相册的 smallAlbumCount 减少，target 的增加
- AC-3: Android 端小相册卡片有"移动到"操作入口
- AC-4: 移动成功后 source/target 大相册的小相册列表即时刷新
- AC-5: 移动成功后 mutation bus 通知照片流、目的地列表等模块刷新
- AC-6: `gradlew.bat assembleDebug` + `mvnw.cmd compile` 编译通过
- AC-7: 测试覆盖 move-small-albums 主链路

- 服务端测试覆盖补齐（album CRUD + largeAlbumDeleted）

### 不在范围内

- FAKE/REAL 两套行为尽量一致
