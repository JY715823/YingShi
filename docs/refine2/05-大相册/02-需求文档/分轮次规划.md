## Round 1: 服务端可靠性加固

**预估**: 中
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 服务端测试覆盖补齐 | Server | P0 | AlbumIntegrationTest 新建 + TrashIntegrationTest 扩展 |
| FR-2 | relatedMediaIds 截断风险修复 | Server | P0 | snapshotJson 存完整 mediaIds + relatedMediaIds 截断 |

**本轮重点**:
- FR-1 和 FR-2 可并行实施：FR-1 写测试，FR-2 改 TrashService/TrashSnapshotHelper
- FR-2 改完后 FR-1 的新测试可以覆盖 FR-2 的变更
- 实施顺序：先 FR-2（改代码）→ 再 FR-1（写测试覆盖 FR-2 + 原有链路）→ 最后 `mvnw.cmd test` 全量验证
- FR-1 的 AlbumIntegrationTest 需独立于 TrashIntegrationTest，因为 Album CRUD 不涉及回收站

**前置条件**:
- 确认 TrashIntegrationTest 的 Testcontainers 配置可复用
- 确认 AlbumService 的依赖注入方式（直接构造 vs Spring @Autowired）

**实施顺序**:
1. TrashSnapshotHelper.java — LargeAlbumDeletedSnapshot 新增 mediaIds 字段
2. TrashService.java — deleteLargeAlbum 写入完整 mediaIds 到 snapshot，relatedMediaIds 截断
3. TrashService.java — purgeLargeAlbumDeleted 从 snapshot 读取 mediaIds（含 fallback）
4. mvnw.cmd compile — 验证编译
5. AlbumIntegrationTest.java — 新建，覆盖 5 端点
6. TrashIntegrationTest.java — 扩展 largeAlbumDeleted 测试 + systemKey 冲突 + 子小相册级联
7. mvnw.cmd test — 全量验证
