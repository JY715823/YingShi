## FR-5: RealTrashMemoryCache 内存泄漏修复

**目标**: 为 `RealTrashMemoryCache` 添加 LRU 淘汰策略。

### 变更文件清单

| 文件路径 | 端 | 变更类型 | 变更内容 |
|---------|-----|---------|---------|
| `E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/RealTrashViewModels.kt` | Android | 修改 | RealTrashMemoryCache 改用 LRU 淘汰 |

### 变更详情

**当前代码**（L47-72）:
```kotlin
private object RealTrashMemoryCache {
    private val listStates = mutableMapOf<String, RealTrashListUiState>()
    private val detailStates = mutableMapOf<String, RealTrashDetailUiState>()
    // ... 读写方法无淘汰逻辑
}
```

**修改后**:
```kotlin
private object RealTrashMemoryCache {
    private const val MAX_LIST_STATES = 20
    private const val MAX_DETAIL_STATES = 50

    private val listStates = object : LinkedHashMap<String, RealTrashListUiState>(16, 0.75f, true) {
        override fun removeEldestEntry(eldest: MutableMap.MutableEntry<String, RealTrashListUiState>?): Boolean {
            return size > MAX_LIST_STATES
        }
    }
    private val detailStates = object : LinkedHashMap<String, RealTrashDetailUiState>(16, 0.75f, true) {
        override fun removeEldestEntry(eldest: MutableMap.MutableEntry<String, RealTrashDetailUiState>?): Boolean {
            return size > MAX_DETAIL_STATES
        }
    }
    // 读写方法保持不变（LinkedHashMap 兼容 mutableMapOf 接口）
}
```

**逻辑伪代码**:
- `MAX_LIST_STATES = 20`、`MAX_DETAIL_STATES = 50`
- 使用 `LinkedHashMap(accessOrder=true)` — 每次 read/write 都将条目移到末尾
- 重写 `removeEldestEntry` — 当 size > max 时自动移除头部（最久未访问）
- `readListState`、`writeListState`、`readDetailState`、`writeDetailState` 方法签名不变

**边界条件**:
- `readListState` 触发 accessOrder 更新（LRU 关键）
- `writeListState` 写入新条目时，若超限自动淘汰
- `hasListState` 不更新 accessOrder（仅检查存在性，不影响 LRU 顺序）

**编译验证**: `gradlew.bat :app:compileDebugKotlin`
