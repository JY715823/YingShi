## FR-5: RealTrashMemoryCache 内存泄漏修复

### 变更文件

| 文件路径 | 变更类型 | 变更内容 |
|---------|---------|---------|
| `RealTrashViewModels.kt` L47-81 | 修改 | RealTrashMemoryCache 改用 LRU 淘汰 |

### 实施详情

**修改前**:
```kotlin
private object RealTrashMemoryCache {
    private val listStates = mutableMapOf<String, RealTrashListUiState>()
    private val detailStates = mutableMapOf<String, RealTrashDetailUiState>()
    // ... 读写方法无淘汰逻辑
}
```

**修改后**:
```kotlin
private object RealTrashMemoryCache {
    private const val MAX_LIST_STATES = 20
    private const val MAX_DETAIL_STATES = 50

    private val listStates = object : LinkedHashMap<String, RealTrashListUiState>(16, 0.75f, true) {
        override fun removeEldestEntry(eldest: MutableMap.MutableEntry<String, RealTrashListUiState>?): Boolean =
            size > MAX_LIST_STATES
    }
    private val detailStates = object : LinkedHashMap<String, RealTrashDetailUiState>(16, 0.75f, true) {
        override fun removeEldestEntry(eldest: MutableMap.MutableEntry<String, RealTrashDetailUiState>?): Boolean =
            size > MAX_DETAIL_STATES
    }
    // ... 读写方法签名不变
}
```

**关键点**:
- `LinkedHashMap(accessOrder=true)` — 每次 read/write 都将条目移到末尾
- `removeEldestEntry` — 当 size > max 时自动移除头部（最久未访问）
- `readListState`/`readDetailState` 通过 `map[key]` 访问，触发 accessOrder 更新
- `hasListState` 使用 `containsKey`，不更新 accessOrder（仅检查存在性）
- 方法签名完全不变，对 RealTrashListViewModel/RealTrashDetailViewModel 透明
