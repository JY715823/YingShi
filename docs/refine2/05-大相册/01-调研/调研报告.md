## 二、用户流程

### 流程1: 浏览大相册目录

用户切换到 ALBUMS tab → AlbumPageScreen 渲染 → REAL 模式进入 RealAlbumPageScreen → AlbumPageRealViewModel.init 调用 refresh() → 先读磁盘缓存填充 cachedDirectorySnapshot → 调 albumRepository.getAlbums() 拉取远端列表 → 成功后映射为 AlbumSummaryUiModel 列表 → 默认选中第一个大相册 → AlbumSwitchSection 渲染横滑 chip（最多 3+1 个）+ 新建小相册按钮 + 全部菜单按钮。

涉及: AlbumPageScreen.kt, RealPhotoViewModels.kt (AlbumPageRealViewModel L80-814), AlbumApi.kt, AppReadCacheStore.kt

### 流程2: 切换大相册（cold vs warm）

用户点击 chip 或弹窗中的 AlbumDirectoryRow → viewModel.selectAlbum(albumId) → 先查 albumPostCardCacheByAlbumId（内存 L1）→ 再查 CachedAlbumDirectory.postsByAlbumId（磁盘 L2）→ 有缓存则立即填充 posts，isPostsLoading=false（warm switch）→ 无缓存则 posts=emptyList()，调 loadAlbumPosts(showBlockingIndicator=true)（cold switch）→ 成功后 rememberAlbumPostCards() 写入 L1 缓存 → persistAlbumDirectory() 更新 L2 缓存 → prefetchAlbumPostCovers() 异步预取前 6 个封面。

涉及: RealPhotoViewModels.kt (selectAlbum L251-305, loadAlbumPosts L500-560)

### 流程3: 重命名大相册

在 AlbumDirectoryDialog 的 AlbumDirectoryManagementCard 点击"重命名" → AlertDialog 输入标题+简介 → 保存 → viewModel.renameAlbum(albumId, payload) → albumRepository.updateAlbum() → 成功后写入 pendingAlbumOverrides[albumId]（乐观更新）→ 更新磁盘缓存 → notifyRealBackendAlbumsChanged() → statusMessage 2800ms 自动消失。

涉及: AlbumPageScreen.kt (AlbumDirectoryDialog), RealPhotoViewModels.kt (renameAlbum L307-401), AlbumApi.kt (PATCH)

### 流程4: 删除大相册

在管理卡片点击"删除" → 确认弹窗（文案说明"小相册一起进回收站，媒体本体不删除"）→ 确认后 viewModel.deleteAlbum(albumId) → albumRepository.deleteAlbum() 返回 RemoteTrashItem（含 relatedPostIds）→ 清理内存缓存/磁盘缓存/pendingOverrides → 自动切到下一个大相册 → notifyRealBackendContentChanged(postIds) + SyncVersionTracker.markLocalMutation(ALBUMS)。

涉及: AlbumPageScreen.kt (删除确认弹窗), RealPhotoViewModels.kt (deleteAlbum L414-499), TrashService.java (deleteLargeAlbum L90-131)

### 流程5: 从回收站恢复大相册

用户在 TRASH tab 选择 largeAlbumDeleted 分类 → RealTrashListViewModel.refresh() 调 trashRepository.getTrashItems("largeAlbumDeleted") → 恢复操作调 trashRepository.restoreTrashItem() → 成功后 notifyRealBackendContentChanged() → AlbumPageRealViewModel 通过 mutation bus 监听并 refresh() → 大相册重新出现在目录中。

涉及: RealTrashViewModels.kt, RealRepositories.kt (RealTrashRepository L677-822), TrashService.java (restoreLargeAlbumDeleted L427-454)

## 三、数据流向

### 3.1 状态管理架构

```
AlbumPageRealViewModel (MutableStateFlow<AlbumPageRealUiState>)
  |-- isLoading, isPostsLoading, isPostsRefreshing, isAlbumMutating
  |-- isOfflineReadOnly, tokenMissing, errorMessage, postsErrorMessage
  |-- statusMessage, albums, selectedAlbumId, posts
  |
  v collectAsState()
RealAlbumPageScreen (Compose)
  |-- when 分支: tokenMissing / loading / error / empty / 正常内容
  |-- AlbumSwitchSection + AlbumPostCard 网格 + 空态/加载态卡片
```

### 3.2 缓存架构

**双层缓存**：
- L1 内存: `albumPostCardCacheByAlbumId: Map<String, List<AlbumPostCardUiModel>>`
- L2 磁盘: `AppReadCacheStore` → JSON 文件 `read-cache/album-directory__{sha1(baseUrl)}__{sha1(userId)}.json`
- 结构: `CachedAlbumDirectory { albums, postsByAlbumId, previewMediaByPostId }`

**写入路径**: ViewModel.persistAlbumDirectory() → AppReadCacheStore.writeAlbumDirectory() → Gson.toJson()
**读取路径**: ViewModel.readCachedDirectory() → AppReadCacheStore.readAlbumDirectory() → 校验 schemaVersion/baseUrl/userId

### 3.3 Mutation Bus 通知

```
RealBackendMutationBus (object singleton)
  notifyRealBackendAlbumsChanged() → scopes={ALBUMS, SYSTEM_MEDIA_DESTINATIONS}  // rename/create
  notifyRealBackendContentChanged(postIds) → scopes={PHOTO_FEED, ALBUMS, POST_DETAIL, ...}  // delete/restore
```

### 3.4 前后端 API 交互

| 功能 | Android API | Server Endpoint |
|------|------------|-----------------|
| 创建大相册 | AlbumApi.createAlbum() | POST /api/albums |
| 列出大相册 | AlbumApi.getAlbums() | GET /api/albums |
| 列出子小相册 | AlbumApi.getAlbumPosts() | GET /api/albums/{id}/small-albums |
| 重命名 | AlbumApi.updateAlbum() | PATCH /api/albums/{id} |
| 删除 | AlbumApi.deleteAlbum() | DELETE /api/albums/{id} |
