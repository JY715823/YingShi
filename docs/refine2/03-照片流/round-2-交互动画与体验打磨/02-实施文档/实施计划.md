## FR-9: 协作人筛选切换动画

**目标**: 筛选切换时协作人圆点有颜色过渡动画，照片流有淡入淡出过渡。

### 变更文件清单

| 文件路径 | 端 | 变更类型 | 变更内容 |
|---------|-----|---------|---------|
| `app/.../feature/photos/CollaboratorComponents.kt` | Android | 修改 | `CollaboratorFilterChip` 选中态颜色过渡 |
| `app/.../feature/photos/PhotoFeedScreen.kt` | Android | 修改 | `PhotoFeedCollaboratorControlsRow` 增加 `AnimatedContent` 包装照片流 |

### 组件级计划

**CollaboratorFilterChip** (L62-109):
- 将 `color = if (selected) colors.primaryContainer... else colors.raisedSurface...` 改为 `animateColorAsState`
- 将 `border` 的 `color` 也改为 `animateColorAsState`
- 将 `shadowElevation` 也改为 `animateDpAsState`
- 动画时长: 200ms，easing: `FastOutSlowInEasing`
- 遵循 `motionEnabled` 守卫: motionEnabled=false 时动画时长为 0

**照片流内容切换** (PhotoFeedScreen.kt L1432-1513):
- 在 LazyColumn 外层包裹 `AnimatedContent(targetState = selectedCollaboratorUserIds, transitionSpec = fadeIn(200ms) + fadeOut(200ms))`
- 但是注意: `AnimatedContent` 需要 `key` 来区分不同内容，`selectedCollaboratorUserIds` 变化时触发动画
- 更简单方案: 给 LazyColumn 的 `Modifier` 添加 `animateItemPlacement()` 以确保 blocks 变化时条目平滑过渡
- 同时给 LazyColumn 添加 `AnimatedVisibility` 的 fade 效果: 使用 `crossfade` 或 `graphicsLayer { alpha }` + `Animatable`

**推荐方案**: 使用 `AnimatedContent` 包裹 `LazyColumn` 所在的 `Box`，以 `selectedCollaboratorUserIds.hashCode()` 为 key，transitionSpec 为 `fadeIn(200ms) + fadeOut(200ms)`。

| `app/.../feature/photos/PhotoFeedScreen.kt` | Android | 修改 | `PhotoFeedCard` 选中态增加 scale 动画 |

### 组件级计划

**PhotoTopBar 多选模式** (L759-816):
- 将 `if (isSelectionContext)` 分支改为 `AnimatedVisibility`
- 进入动画: `slideInVertically(initialOffsetY = { -it })` + `fadeIn()`，250ms
- 退出动画: `slideOutVertically(targetOffsetY = { -it })` + `fadeOut()`，200ms
- 非多选模式也包裹 `AnimatedVisibility(visible = !isSelectionContext)`，向下滑入
- 遵循 `motionEnabled` 守卫

**底栏** (YingShiApp.kt L1206-1217):
- 在 `AppShellScaffold` 的 `bottomBarOverride` 外层包裹 `AnimatedVisibility`
- 进入动画: `slideInVertically(initialOffsetY = { it })` + `fadeIn()`，250ms
- 退出动画: `slideOutVertically(targetOffsetY = { it })` + `fadeOut()`，200ms
- 注意: 需要在 `YingShiApp.kt` 修改，`bottomBarOverride` 已经是 lambda，外层加 `AnimatedVisibility` 即可

**PhotoFeedCard 选中态** (PhotoFeedScreen.kt L3335+):
- 在 `PhotoFeedCard` 的 `Modifier` 上添加 `graphicsLayer { scaleX/scaleY }` 或 `animateFloatAsState`
- 选中时 scale = 0.97f，非选中时 scale = 1f
- 动画时长: 150ms，easing: `FastOutSlowInEasing`
- 遵循 `motionEnabled` 守卫

## FR-8: 删除媒体动画

**目标**: 删除时卡片缩小+淡出，后续卡片平滑上移填补空位。

### 变更文件清单

| 文件路径 | 端 | 变更类型 | 变更内容 |
|---------|-----|---------|---------|
| `app/.../feature/photos/RealPhotoFeedViewModel.kt` | Android | 修改 | 删除前先标记 `deletingMediaIds`，延迟从数据源移除 |
| `app/.../feature/photos/PhotoFeedScreen.kt` | Android | 修改 | LazyColumn 添加 `animateItemPlacement()`，卡片添加删除动画 |
| `app/.../feature/photos/RealPhotoFeedPage.kt` | Android | 修改 | 删除确认前先触发动画，动画完成后才调 ViewModel |

### 组件级计划

**RealPhotoFeedPage 删除流程** (L198-225):
- 确认删除后，不立即调 `viewModel.deleteSelectedMedia()`
- 先设置一个 `animatingDeleteMediaIds` 状态（Set<String>）
- 传递 `animatingDeleteMediaIds` 给 `PhotoFeedScreen`
- 延迟 200ms 后调用 `viewModel.deleteSelectedMedia()`

**PhotoFeedScreen 删除动画**:
- 新增参数: `animatingDeleteMediaIds: Set<String> = emptySet()`
- 传递到 `PhotoFeedCard` / `PhotoFeedGridRowContent`
- 卡片在 `mediaId in animatingDeleteMediaIds` 时:
  - `graphicsLayer { alpha = 0f; scaleX = 0.8f; scaleY = 0.8f }` 通过 `Animatable`
  - 动画时长: 200ms，easing: `FastOutSlowInEasing`
- LazyColumn 添加 `Modifier.animateItemPlacement()` (L1601)
  - 需要 import `androidx.compose.foundation.lazy.items` 和 `animateItemPlacement`
  - 注意: `animateItemPlacement()` 需要 `androidx.compose.animation` 依赖

**RealPhotoFeedViewModel 删除逻辑** (L328-407):
- 不需要修改核心逻辑，但需要确保删除结果返回后 `animatingDeleteMediaIds` 被清除
- 在 `RealPhotoFeedPage` 中通过 `LaunchedEffect` 监听删除完成

**架构简化方案** (推荐):
- 不修改 ViewModel，直接在 `RealPhotoFeedPage` 中处理:
  1. 确认删除 → 设置 `animatingDeleteMediaIds` → 传递到 `PhotoFeedScreen`
  2. `LaunchedEffect(animatingDeleteMediaIds)` → delay(200ms) → 调用 `viewModel.deleteSelectedMedia()`
  3. 删除完成后 `animatingDeleteMediaIds` 清空
- 在 `PhotoFeedScreen` 中: 卡片被删除时通过 `AnimatedVisibility` 做缩小+淡出
- 但这依赖 LazyColumn 的 key 稳定性，更简单的是直接在 `PhotoFeedCard` 上用 `graphicsLayer`

**最终推荐方案**: 
1. `PhotoFeedScreen` 新增 `animatingDeleteMediaIds` 参数
2. `PhotoFeedGridRowContent` 传递 `animatingDeleteMediaIds`
3. `PhotoFeedCard` 接收 `isDeleting` 参数，通过 `animateFloatAsState` 控制 alpha 和 scale
4. LazyColumn 添加 `animateItemPlacement()`
5. `RealPhotoFeedPage` 控制时序: 标记动画 → 200ms 延迟 → 调删除 → 等待完成 → 清除标记

## FR-6: 密度切换转场增强

**目标**: 密度切换时标题有缩放+淡入淡出，标尺标签有滑动过渡，协作人圆点有弹性缩放。

### 变更文件清单

| 文件路径 | 端 | 变更类型 | 变更内容 |
|---------|-----|---------|---------|
| `app/.../feature/photos/PhotoFeedScreen.kt` | Android | 修改 | 标题缩放动画、标尺标签过渡、协作人圆点弹性缩放 |

### 组件级计划

**标题缩放+淡入淡出** (L1626-1648):
- 当前 `liveHeaderScale` 始终为 1f
- 在 densityTransitionPreviewScene 中动态设置 `liveHeaderScale`:
  - PREVIEWING/REBOUNDING: `1f - 0.04f * previewProgress`（缩放至 0.96）
  - COMMITTING: `0.96f + 0.04f * morphProgress`（回弹至 1.0）
  - SETTLING/IDLE: 1f
- 同时调整 `liveHeaderAlpha` 逻辑，确保标题在缩放时 alpha 也联动

**标尺标签滑动过渡** (L2339-2636):
- 当前标尺标签直接切换文本，无动画
- 在 `PhotoFeedTimeScrubber` 中:
  - 使用 `AnimatedContent(targetState = displayedScrubberLabel, transitionSpec = slideInVertically + fadeIn / slideOutVertically + fadeOut)`
  - 或者更简单: 使用 `graphicsLayer { translationY }` + `Animatable` 做标签上下滑动
  - 动画时长: 200ms，`FastOutSlowInEasing`
- 注意: 标尺标签在密度切换时通过 `densityTransitionSourceScrubberSnapshot` / `densityTransitionTargetScrubberSnapshot` 已有快照机制，但标签的过渡动画未实现

**协作人圆点弹性缩放** (L1436-1512):
- 在 `PhotoFeedCollaboratorControlsSceneRow` 中，密度转场时给圆点增加弹性缩放
- 使用 `animateFloatAsState` 或 `spring` 动画:
  - 当 densityTransitionStage 非 IDLE 时，target scale = 0.92f
  - 当恢复到 IDLE 时，target scale = 1f
  - 使用 `spring(dampingRatio = 0.6f, stiffness = 400f)` 获得弹性效果
- 遵循 `motionEnabled` 守卫

**实施难点**: FR-6 的改动需要精确控制 `densityTransitionPreviewScene` 的 `liveHeaderScale` 值，当前该值在 `densityTransitionPreviewScene` 中定义 (L767-777)，需要修改 `PhotoFeedDensityPreviewScene` 的 `liveHeaderScale` 计算逻辑。
