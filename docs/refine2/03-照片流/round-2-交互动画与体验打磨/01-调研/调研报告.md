## 一、FR-6: 密度切换转场增强

### 1.1 密度切换基础架构

**文件**: `DiscreteZoomGesture.kt` L1-232 — 完整的密度切换手势状态机

核心组件：
- `DiscreteZoomDirection` (L20-23): TO_SPARSE（捏合放大→变稀疏）和 TO_DENSE（捏合缩小→变密集）
- `DiscreteZoomPreviewState<T>` (L25-33): 包含 sourceLevel、targetLevel、direction、rawProgress (0-1)、renderProgress (smootherstep)、accumulatedZoom、centroid
- `buildPreviewState()` (L185-226): 计算 preview 状态，方向锁定阈值 1.05/0.95，提交阈值 0.66
- `discreteZoomLevelGesture()` (L35-166): 手势入口，支持 `commitOnGestureEnd=true`、`onPreviewStateChange`、`onLevelCommitted`、`onGestureFinished`

**调用链** (PhotoFeedScreen.kt L1522-1568):
```
discreteZoomLevelGesture
  → onPreviewStateChange → syncDensityPreview(previewState)
  → onGestureFinished → reboundDensityPreview() 或 beginDensityTransition()
  → onLevelChange → updateDensity() → densityName = newLevel.name
```

### 1.2 密度转场状态机

**文件**: `PhotoFeedScreen.kt` L299-329 — 密度转场状态变量

当前已有复杂的状态机：
- `densityTransitionStage`: IDLE → PREVIEWING → REBOUNDING/COMMITTING → SETTLING → IDLE
- `densityPreviewState`: 双指捏合时的实时 preview
- `densityTransitionOverlayEntries`: 转场覆盖层条目（媒体+标题+标尺快照）
- `densityTransitionPreviewProgress` / `densityTransitionReleaseProgress`: 进度值
- `densityMorphProgress` (Animatable): 形态变换动画进度
- `densityHeaderRevealAlpha` (Animatable): 标题揭示 alpha
- `densityTransitionSourceHeaderSnapshots` / `densityTransitionTargetHeaderSnapshots`: 源/目标标题快照
- `densityTransitionSourceScrubberSnapshot` / `densityTransitionTargetScrubberSnapshot`: 源/目标标尺快照

### 1.3 现有标题渲染

**文件**: `PhotoFeedScreen.kt`

- `PhotoFeedSectionHeaderRow` (L2636-2666): 年/月标题，接收 density 参数，调用 `PhotoFeedTimeHeaderText`
- `PhotoFeedDayHeaderRow` (L2983-3008): 日标题，接收 density 参数
- `PhotoFeedTimeHeaderText` (L3048-3160): 核心标题渲染，Round 1 已添加年标题 shimmer 扫过效果

**当前标题的密度转场 alpha 处理** (L1626-1648):
- `PhotoFeedSectionHeader` 在 `densityTransitionStage` 非 IDLE 时通过 `photoFeedLiveHeaderAlpha()` 计算 alpha
- 有 `liveHeaderScale` 和 `transformOrigin` 控制，但当前 `liveHeaderScale` 始终为 1f

**问题**: 
- 标题在密度切换时只有 alpha 变化，没有缩放动画
- 标尺（`PhotoFeedTimeScrubber` L2339-2636）有滚动联动，但密度切换时无水波过渡效果
- 协作人圆点（`CollaboratorFilterChip` L62-109）在密度切换时无动画反馈

### 1.4 标尺渲染

**文件**: `PhotoFeedScreen.kt` L2339-2636 — `PhotoFeedTimeScrubber`

- 手柄尺寸: 26dp x 64dp
- 年标记概览 (yearMarkers): 180ms 扩展动画 (L2383-2393)
- 标签: 根据 `scrubberInteracting` 状态切换 label
- 密度感知: 标签格式化函数 `formatScrubberLabel` 根据密度输出不同标签

**问题**: 标尺在密度切换时没有标签过渡动画，直接切换文本。

### 1.5 协作人渲染

**文件**: `PhotoFeedScreen.kt` L1436-1512 — 协作人控制行

- 渲染在 `Column` 顶部，`LazyColumn` 上方
- 密度转场时有三层渲染（source/target/live），通过 alpha 控制切换
- `PhotoFeedCollaboratorControlsSceneRow` (L2692-2722) 封装了 alpha + scale 控制

**问题**: 协作人圆点本身没有弹性缩放，只是整体 alpha 控制。

## 三、FR-8: 删除媒体动画

### 3.1 删除逻辑

**文件**: `RealPhotoFeedViewModel.kt` L328-407 — `deleteSelectedMedia()`

删除流程：
1. 设置 `isDeleting = true`
2. 逐个调用 `mediaRepository.systemDeleteMedia(mediaId)`
3. 删除成功后通过 `filterNot` 从 `feedItems` 移除 (L384)
4. 持久化快照 + 清理本地缓存
5. 通知其他模块

**当前状态**: 删除完成后 `feedItems` 直接通过 `filterNot` 更新，LazyColumn 会立即重排。**无卡片缩小+淡出动画**，无 `animateItemPlacement`。

### 3.2 LazyColumn 配置

**文件**: `PhotoFeedScreen.kt` L1591-1622

```kotlin
LazyColumn(
    state = listState,
    modifier = Modifier
        .fillMaxSize()
        .graphicsLayer { ... },
    verticalArrangement = Arrangement.spacedBy(sectionSpacing(density)),
    contentPadding = PaddingValues(...),
) {
    items(
        items = blocks,
        key = { it.key },
        contentType = { ... },
    ) { block -> ... }
}
```

**当前状态**: LazyColumn 使用 `items()` 而非 `items(count, key)`，**没有 `animateItemPlacement()` modifier**。删除后剩余卡片会瞬间跳到新位置。

### 3.3 删除 UI 反馈

**文件**: `RealPhotoFeedPage.kt` L198-225 — 删除确认对话框

- 点击删除按钮 → 弹出 AlertDialog 确认 → 调用 `viewModel.deleteSelectedMedia()`
- 删除完成后通过 `uiState.statusMessage` 展示成功提示
- 提示 3.2 秒后自动消失

**当前状态**: 删除确认对话框是标准 Material3 AlertDialog，无特殊动画。删除过程中无进度指示器（有 `isDeleting` 状态但未在 UI 层使用）。

## 五、FR-10: 空态视觉精修

### 5.1 空态触发条件

**文件**: `PhotoFeedScreen.kt` L1807-1817 — `PhotoFeedEmptyCollaboratorState`

```kotlin
if (blocks.isEmpty()) {
    item(key = "photo-feed-empty-filter", contentType = "empty-filter") {
        PhotoFeedEmptyCollaboratorState(
            hasCollaborators = collaboratorDirectory.all.isNotEmpty(),
            selectionEmpty = selectedCollaboratorUserIds.isEmpty(),
            modifier = Modifier.fillMaxWidth().padding(top = spacing.lg),
        )
    }
}
```

`blocks.isEmpty()` 在以下情况触发：
- 没有任何照片（初始空态）
- 筛选了协作人但该协作人没有照片
- 未选中任何协作人账号

### 5.2 空态组件实现

**文件**: `PhotoFeedScreen.kt` L2953-2980 — `PhotoFeedEmptyCollaboratorState`

当前实现：
- 三种文案："未选中任何账号，当前不展示媒体" / "当前筛选下还没有媒体" / "还没有可以展示的协作账号"
- `Surface` 包裹：`sectionBackground@0.68f` 背景 + `dividerSoft@0.58f` 边框
- 纯文本居中，无图标

**问题**:
- 无图标轮廓，视觉单调
- 文案偏功能描述，缺少温度
- 无"还没有照片"的通用空态（RealPhotoFeedPage.kt L324-332 的 `BackendNoticeCard` 是另一种空态）

### 5.3 RealPhotoFeedPage 的空态

**文件**: `RealPhotoFeedPage.kt` L324-332

```
BackendNoticeCard(
    title = "还没有媒体",
    text = "当前空间的照片流为空，可以先从系统媒体导入几张。",
    actionLabel = "刷新",
    onAction = viewModel::refresh,
)
```

这是真机模式下的空态，使用 `BackendNoticeCard` 组件，有标题+描述+操作按钮。Fake 模式下的空态在 `PhotoFeedScreen` 中。
