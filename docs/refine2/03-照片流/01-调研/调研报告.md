## 二、用户流程

### 流程1: 正常浏览照片流
用户进入照片 Tab → 看到 PHOTOS variant 极光背景 + 照片流 → 按时间倒序显示照片（月+日标题分组）→ 双指捏合切换密度（2→3→4→8→16）→ 捏合过程中 source scene 持续可见逐步变淡，target scene 逐步长出来 → 松手提交目标密度 → 右侧时间标尺可拖拽快速定位。

涉及: `PhotosRootScreen.kt`, `RealPhotoFeedPage.kt`, `PhotoFeedScreen.kt`, `DiscreteZoomGesture.kt`

### 流程2: 密度切换转场
用户双指捏合 → 进入 PREVIEWING 状态 → source live 层 alpha 从 1.0 渐变到 0.40 → target overlay 逐步淡入 → 一次手势只锁相邻一档 → 松手时 rawProgress >= 0.66 则 COMMITTING → source overlay 淡出、target overlay 交棒、live target list 淡入 → SETTLING → IDLE。若 rawProgress < 0.66 则 REBOUNDING → source 恢复、target 退回。

涉及: `DiscreteZoomGesture.kt`, `PhotoFeedScreen.kt` (转场状态机)

### 流程3: 多选操作
用户长按照片 → 进入多选模式 → 顶栏切换为玻璃拟态 → 勾选多张照片 → 底栏显示分享/新建/加入/删除 → 删除时逐条调用 API + 本地即时移除 → 删除提示 3.2s 后消失。

涉及: `PhotoFeedSelectionState`, `PhotosRootScreen.kt`, `RealPhotoFeedViewModel.kt`

### 流程4: 协作筛选
用户点击"我"或"TA"圆点 → 切换照片筛选 → 低密度下可用小时桶 → 高密度（8/16列）下小时桶自动隐藏。

涉及: `HomeCollaboratorDot`（复用首页组件）, `PhotoFeedGrouping.kt`

## 三、数据流向

### 照片流数据架构

```
用户操作
  → PhotoFeedScreen (Composable, 4942行)
    → RealPhotoFeedPage (REAL模式) / 直接调用 (FAKE模式)
      → RealPhotoFeedViewModel
        → RepositoryProvider.photoFeedRepository
          → API: GET /api/photo-feed (keyset分页)
        → AppReadCacheStore (缓存读写)
    → PhotoFeedGrouping.kt (时间分组)
      → PhotoFeedModels.kt (数据模型)
        → PhotoFeedPresentation (MAIN_STREAM / EMBEDDED)
        → PhotoFeedTimeGranularity (YEAR / MONTH / DAY / HOUR)
    → DiscreteZoomGesture.kt (捏合手势)
      → 转场状态机 (IDLE/PREVIEWING/COMMITTING/SETTLING/REBOUNDING)
  → PhotosRootScreen.kt (容器)
    → YingShiAuroraBackdrop(PHOTOS)
    → PhotoFeedSelectionState (多选)
    → HorizontalPager (Tab切换)
```

### 服务端上传/去重

```
客户端上传
  → POST /api/uploads/token → 获取 uploadId
  → POST /api/uploads/{uploadId}/file → multipart 文件上传
    → UploadService: 固定 application/json 响应
    → 视频 previewUrl → cover 变体
    → MediaService: 三级去重 (checksum → fingerprint → 形态键)
  → GET /api/uploads/{uploadId} → 查询状态
  → POST /api/uploads/{uploadId}/confirm → 确认
```

## 七、视觉现状深度分析

### 7.1 时间标题颜色体系

标题**不是全石墨黑**，而是四季色相偏移：

| 季节 | 月份 | 基础色 | glint | glow | shadow | mist |
|------|------|--------|-------|------|--------|------|
| 冬 | 12/1/2 | #35546E (冷蓝) | #5B8BA8 | #2A4560 | #1E3347 | #4A7090 |
| 春 | 3/4/5 | #2F665C (柔绿) | #4A9E8E | #245248 | #1A3D35 | #3D8A7A |
| 夏 | 6/7/8 | #325B7A (冰蓝) | #5A8FB0 | #284A65 | #1D374D | #4A7FA0 |
| 秋 | 9/10/11 | #70553C (暖棕) | #A08060 | #5A4430 | #403020 | #907050 |

每个 palette 含 5 个角色色，用于标题的不同层叠效果。

### 7.2 16 列年标题增强

4 层文字叠加：
1. 阴影层（shadow 色，offset +2dp）
2. 高光层（glint 色，alpha 0.3，offset -1dp）
3. 辉光层（glow 色，blur 效果）
4. 主体文字（base 色）

外加 scale 增强（1.08x）和更厚的 glow。

### 7.3 氛围层

三层渐变：
1. 左上径向：glowWash alpha 0.28
2. 垂直渐变：raisedSurface → Transparent → titleAccent@0.06
3. 右侧径向：memoryContainer alpha 0.12

整体 alpha 由 feedAtmosphereAlpha(0.34) 控制。

### 7.4 Token 使用合规性

照片流大量使用 YingShiThemeTokens，四季色相是硬编码但在设计文档中有明确定义（属于"季节语义色"，类似 AUTH variant 的装饰色）。氛围层使用 glowWash/memoryContainer/raisedSurface/titleAccent 等 token。整体合规。
