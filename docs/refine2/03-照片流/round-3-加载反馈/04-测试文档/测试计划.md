## 二、功能测试 (FR-11)

### TC-1: 静默刷新时指示器显示 (AC-1)
- **对应**: FR-11 / AC-1
- **端**: Android
- **前置条件**: 
  - 照片流已有数据（feedItems 非空）
  - 触发下拉刷新（非首次加载）
- **步骤**:
  1. 打开 App，进入照片流首页
  2. 确认照片流已有数据
  3. 下拉触发刷新
  4. 观察协作人控制行下方
- **预期结果**: 顶部出现极轻的扫光指示条（1.5dp 高，半透明 glassStroke 色），从左到右循环扫过
- **通过标准**: 指示器可见，不阻塞内容

### TC-2: 指示器不阻断用户操作 (AC-2)
- **对应**: FR-11 / AC-2
- **端**: Android
- **前置条件**: 静默刷新进行中（指示器可见）
- **步骤**:
  1. 触发静默刷新
  2. 在指示器显示期间，尝试滚动列表
  3. 在指示器显示期间，尝试点击照片
  4. 在指示器显示期间，切换协作人筛选
- **预期结果**: 所有操作正常响应，不受指示器影响
- **通过标准**: 滚动/点击/筛选均正常工作

### TC-3: 刷新完成后指示器淡出 (AC-3)
- **对应**: FR-11 / AC-3
- **端**: Android
- **前置条件**: 静默刷新进行中
- **步骤**:
  1. 触发静默刷新
  2. 等待刷新完成
  3. 观察指示器状态
- **预期结果**: 刷新完成后指示器使用 fadeOut 动画（300ms）平滑消失
- **通过标准**: 指示器完全消失，无残留

### TC-4: 首次加载不显示指示器
- **对应**: FR-11 / 边界条件
- **端**: Android
- **前置条件**: 清空缓存，首次进入照片流
- **步骤**:
  1. 清除 App 数据
  2. 重新进入照片流
  3. 观察顶部是否出现静默刷新指示器
- **预期结果**: 首次加载显示的是全屏 Loading（isLoading=true），不显示静默刷新指示器
- **通过标准**: 只显示 Loading，不显示扫光指示器

## 三、影响范围测试

### TC-5: UiState 默认值不影响现有状态 (IA-1)
- **对应**: IA-1
- **端**: Android
- **前置条件**: 无
- **步骤**:
  1. 检查 `RealPhotoFeedUiState` 默认构造函数
  2. 确认 `isSilentlyRefreshing` 默认值为 `false`
  3. 验证现有状态收集逻辑不受影响
- **预期结果**: `isSilentlyRefreshing` 默认 `false`，不影响现有 isLoading/isLoadingMore 逻辑
- **通过标准**: 代码审查通过

### TC-6: EMBEDDED 模式不受影响 (IA-2)
- **对应**: IA-2
- **端**: Android
- **前置条件**: 无
- **步骤**:
  1. 检查 `PhotoFeedScreen` 的 `isSilentlyRefreshing` 参数默认值
  2. 确认 EMBEDDED 模式（picker/小相册详情）不传该参数
  3. 验证 EMBEDDED 模式正常显示
- **预期结果**: 默认值为 `false`，EMBEDDED 模式不显示指示器
- **通过标准**: EMBEDDED 模式无异常

### TC-7: 指示器不推动内容布局 (IA-3)
- **对应**: IA-3
- **端**: Android
- **前置条件**: 静默刷新进行中
- **步骤**:
  1. 触发静默刷新
  2. 观察指示器出现时 LazyColumn 内容是否产生位移
  3. 观察指示器消失时 LazyColumn 内容是否产生位移
- **预期结果**: 指示器作为独立元素放置在 LazyColumn 上方（Box.weight(1f) 之前），不推动内容
- **通过标准**: 内容位置不变
