## Round 1: 数据基础重构

**预估**: 大
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 存储三域隔离 | Both | P0 | Album/Post/Media 加 domain 字段，数据迁移，MinIO 前缀隔离，Android 上传适配 |
| FR-9 | 服务端时区一致性 | Server | P1 | addMedia/addBowelEvent 接受 zoneId 参数 |
| FR-10 | 大便事件改软删除 | Server | P2 | BowelEventEntity 加 deletedAt，查询过滤 |
| FR-11 | RegisterPushToken DTO 包修正 | Server | P2 | 从 dto/life/ 移到 dto/push/ |

**本轮重点**:
1. Flyway V26: albums/small_albums/media 三表加 domain 列（DEFAULT 'photo'），现有数据自动归入 photo 域
2. Flyway V27: bowel_events 加 deleted_at 列
3. LifeConsoleService 全面改写：所有查询和写入带 domain='life' 条件，ensureSystemAlbum/ensureMonthlySmallAlbum 改为 domain-aware
4. PhotoFeedService / AlbumService / ContentService 等：查询加 domain='photo' 过滤
5. UploadService: 接受 domain 参数，MinIO 路径改为 `{domain}/{libraryId}/...`
6. Android 端: LifeConsoleApi + UploadBridge 上传时传 domain='life'
7. 数据清理: pg_dump 备份 → 清除 life domain 旧数据 → MinIO 清除 life/ 前缀
8. Widget: LifeConsoleWidgetStore 清理旧缓存
9. 时区修复: Controller 参数 + Service 方法签名统一
10. 大便软删除: Entity + Repository + Service 三层改
11. DTO 包迁移: 移文件 + 改 import

**前置条件**:
- Docker Desktop 运行中（PostgreSQL + MinIO 容器可用）
- 做好 DB 备份（pg_dump）和 MinIO 备份（mc mirror）

## Round 2: UI 大改造

**预估**: 大
**依赖**: Round 1 完成（API 契约稳定）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |

## Round 3: 健壮性增强

**预估**: 中
**依赖**: Round 2 完成（UI 已稳定）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-5 | 离线读缓存 | Android | P0 | AppReadCacheStore 模式缓存快照，离线 fallback |
| FR-6 | 错误处理分级 | Android | P0 | 区分网络/超时/服务端错误，SnackBar 展示 |
| FR-7 | SyncVersionsDto 补 chatVersion | Android | P1 | 补全 chatVersion 字段 |

**本轮重点**:
1. 新建 LifeConsoleCacheStore：缓存 today 快照 JSON + 历史数据到 filesDir
2. RealLifeConsoleRepository 加缓存层：成功时写缓存，失败时读缓存
3. ViewModel 加 offlineState：offline/online/unknown 三态
4. LifeConsoleScreen 加 StaleBanner："离线数据"提示，网络恢复后自动消失
5. 错误分级：Repository 层捕获 IOException(网络)/SocketTimeoutException(超时)/HttpException(服务端) 分别封装
6. ViewModel 错误状态：networkError/timeoutError/serverError 三种
7. LifeConsoleScreen 错误展示：SnackBar + 重试按钮（非红色 actionMessage 纯文本）
8. SyncVersionsDto 加 chatVersion: Long 字段
9. SyncVersionTracker 消费 chatVersion

**前置条件**:
- Round 2 UI 已稳定
- 能测试离线场景（飞行模式 / 关闭 Docker server 容器）

## 风险与注意事项

| # | 风险 | 关联轮次 | 缓解措施 |
|---|------|---------|---------|
| 1 | domain 迁移影响照片模块现有数据 | R1 | 默认值 photo 确保现有数据不受影响；迁移前先 pg_dump 备份 |
| 2 | Widget 离线缓存在 domain 切换后失效 | R1 | 迁移后清理 Widget SharedPreferences |
| 3 | UI 大改文件过大（LifeConsoleScreen.kt ~1337行） | R2 | 可考虑拆分为 TodayView.kt + HistoryView.kt 子文件 |
| 4 | 后端测试依赖 Testcontainers 环境 | R4 | 确保 Docker Desktop 运行；CI fallback H2 |
| 5 | 数据清理操作不可逆 | R1 | 清理前完整备份 |
| 6 | 高德 API Key 需用户申请 | R6 | 提前告知用户，未获取前可先用空值测试 |
| 7 | FusedLocationProvider 依赖 Google Play Services | R6 | 无 GMS 设备需 fallback 方案 |
| 8 | 位置隐私合规 | R6 | 仅在用户授权后采集，数据仅存服务端 |
