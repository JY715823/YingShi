# 今日足迹 (LifeConsole) 需求文档

> 版本: v1.0 | 日期: 2026-07-17 | 状态: 已确认

## 一、模块目标

将今日足迹从"功能可用但架构耦合、视觉朴素"升级为"存储三域隔离、视觉达到生活手账级别、健壮性与照片模块对齐"的品质模块。核心三件事：(1) 存储域隔离——足迹数据不再与照片模块共用 Album/Post/Media 系统相册链路，改用 domain 字段做三域(photo/life/chat)隔离；(2) UI 全面重设计——今日页从四宫格改为生活手账风卡片布局，历史页从扁平列表改为时间轴卡片流；(3) 工程健壮性——离线缓存、错误分级、后端全覆盖测试。

## 二、功能需求

### FR-1: 存储三域隔离 (Data Domain Isolation)

**描述**: 给 Album、Post(Post/SmallAlbum)、Media 三层实体加 `domain` 字段（`photo` / `life` / `chat`），实现三个业务域的数据完全隔离。足迹数据不再出现在照片流中，聊天记录也不混入足迹。上传走同一套 UploadPipeline，但 domain 参数不同。MinIO 对象路径按 domain 前缀隔离（`life/`、`photo/`、`chat/`）。清理现有数据库和 MinIO 中旧的足迹数据（回到从零开始的状态）。

**端**: Both
**优先级**: P0

**验收标准**:
- AC-1: albums / small_albums / media 三张表均有 domain 列，默认值 `photo`
- AC-2: LifeConsoleService 的所有查询和写入均带 `domain = 'life'` 条件
- AC-3: 照片流(PhotoFeed)查询仅包含 `domain = 'photo'` 的数据
- AC-4: 上传 API 接受 domain 参数，MinIO 对象路径以 `{domain}/` 为前缀
- AC-5: 现有数据全部迁移到 `photo` 域，旧的 life 域系统相册记录被清除
- AC-6: 新迁移 V26 幂等可重跑

**涉及文件**:
- `AlbumEntity.java`, `PostEntity.java`, `MediaEntity.java` — 加 domain 字段
- `AlbumRepository.java`, `PostRepository.java`, `MediaRepository.java` — 查询加 domain 过滤
- `LifeConsoleService.java` — 全部查询改写为 domain=life
- `LifeConsoleController.java` — addMedia 接口传 domain
- `UploadService.java`, `UploadController.java` — 上传接受 domain 参数
- `ContentMapper.java` — DTO 含 domain
- `SyncService.java` — lifeConsoleVersion 查询加 domain 过滤
- `PhotoFeedService.java`(或同等) — 查询加 domain=photo
- Flyway 迁移: `V26__data_domain_isolation.sql`
- `application.yml` — 配置项（如有）
- Android: `LifeConsoleApi.kt`, `LifeConsoleDtos.kt`, `RealRepositories.kt` — 上传传 domain

### FR-5: 离线读缓存 (Offline Read Cache)

**描述**: 给 LifeConsole 加离线读缓存，对齐照片模块的 `AppReadCacheStore` 模式。缓存最近一次 today 快照 JSON + 历史数据到本地（SharedPreferences 或 filesDir），离线时 fallback 到缓存数据并展示"离线数据"提示 Banner。网络恢复后自动刷新。缓存按 domain 键隔离。

**端**: Android
**优先级**: P0

**验收标准**:
- AC-1: 网络可用时，成功获取的数据写入本地缓存
- AC-2: 网络不可用时，展示缓存数据 + "离线数据"Banner
- AC-3: Banner 使用 StaleBanner 组件样式，不影响现有设计
- AC-4: 网络恢复后自动触发刷新，Banner 消失
- AC-5: 缓存过期策略合理（如 7 天未刷新则不展示缓存）

**涉及文件**:
- `RealRepositories.kt` — RealLifeConsoleRepository 加缓存层
- `LifeConsoleViewModel.kt` — 离线状态管理
- `LifeConsoleScreen.kt` — 离线 Banner 展示
- 新建 `LifeConsoleCacheStore.kt` — 缓存读写逻辑

**端**: Android
**优先级**: P0

**验收标准**:

- AC-3: 服务端 5xx 时显示"服务暂时不可用"+ 稍后再试
- AC-4: 错误展示使用 SnackBar 组件（非 actionMessage 纯文本）

**涉及文件**:

### NFR-3: API 向后兼容
domain 隔离不应破坏已有的 API 路径和响应结构。Android 旧版本仍可调用（domain 字段对旧客户端透明）。

### NFR-4: 数据清理完整
清理操作需覆盖 DB 数据 + MinIO 对象 + Android 本地缓存（Widget SharedPreferences、缩略图文件缓存）。

## 四、范围边界

### 在范围内
- 存储三域隔离（Album/Post/Media domain 字段 + MinIO 前缀 + 数据清理）
- 今日页 + 历史页 UI 全面重设计
- 离线缓存、错误分级、后端测试
- 大便软删除、时区修复、DTO 包修正、SyncVersion 补全、AMOLED 适配
- Widget 适配 domain 隔离（Widget 数据获取逻辑更新）
- 推送适配 domain 隔离（推送查询加 domain 条件）

### 不在范围内
- 不加新功能（月度回顾卡、连续打卡、智能引导等均不做）
- 不改变照片模块、聊天记录模块的现有逻辑（仅加 domain 过滤条件）
- 不改变 FCM 配置（FCM_ENABLED 仍由用户手动开启）
- 不改导航路由、AppShell、底部导航栏
- 不改 UploadPipeline 核心逻辑（仅扩展 domain 参数）

## 五、跨模块依赖

| 依赖模块 | 依赖方向 | 依赖内容 | 影响说明 |
|---------|---------|---------|---------|
| 照片流 PhotoFeed | 双向 | Album/Post/Media 表共享 | domain 隔离后 PhotoFeed 查询需加 domain=photo |
| 相册 Albums | 双向 | Album/Post 表共享 | domain 隔离后相册查询需加 domain=photo |
| 上传中心 Upload | 单向依赖 | UploadPipeline | 上传需接受 domain 参数 |
| 回收站 Trash | 单向依赖 | TrashService.systemDeleteMedia | 需适配 domain 字段 |
| 推送 Push | 双向 | PushNotificationService | 推送查询可能需适配 |
| 同步 Sync | 双向 | SyncService/SyncVersionTracker | lifeConsoleVersion 查询需加 domain |
| Widget | 单向依赖 | WidgetStore/WidgetProvider | Widget 数据获取需走 domain=life |
| 账本 Ledger | 无直接依赖 | — | Ledger 有独立表，不受影响 |
| 定位服务 Location | 单向依赖 | FusedLocationProvider | Android 端 GPS 定位，无权限时静默跳过 |
| 高德地图 API | 单向依赖 | 反向地理编码 REST API | 经纬度→地址文字，需 API Key |
