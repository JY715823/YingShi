# Round 6 调研报告：位置追踪功能

> 调研时间: 2026-07-18
> 调研范围: FR-18 (位置追踪后端) + FR-19 (位置追踪 Android) + FR-20 (历史页位置标签展示)
> 调研方式: 3 个并行 Agent (Android / Server / 构建跨端) + 用户确认高德 Web Key
> 数据流方案: **方案 B（服务端集成 GeocodingService）** — Android 获取 GPS 坐标，服务端调高德 API 反向地理编码

### 1.1 数据流方案确认（方案 B）

| 业界实践 | 不推荐 | **主流做法** |

### 4.3 LifeConsoleService 关键方法

| 方法 | 当前签名 | 改造点 |
|------|---------|--------|
| `addMedia` | `(LifeConsoleMediaRequest, zoneId, user) → TodayResponse` | request 不加位置（位置在上传 token 阶段已落库），仅需在响应中通过 MediaDto 返回位置 |

| 改造点 | Android | Server |
|--------|---------|--------|
| 上传时携带位置 | UploadTokenRequestDto + UploadBridge | UploadTokenRequest + UploadService |
| MediaEntity 持久化 | — | MediaEntity + V29 |
| BowelEventEntity 持久化 | — | BowelEventEntity + V29 |

**关键澄清**: `LifeConsoleMediaRequestDto` **不需要加位置字段**（位置在上传 token 阶段已落库到 MediaEntity，addMedia 只是关联到 life_console，不再次传位置）。这与原 Android 调研 Agent 表面建议不同，以服务端 Agent 结论为准。

### 5.5 高德 API 规范

- Endpoint: `GET https://restapi.amap.com/v3/geocode/regeo`
- 必需参数: `key` + `location`（格式 `经度,纬度`，**lng 在前 lat 在后**）
- 返回: `regeocode.formatted_address`（如 "北京市朝阳区望京街道阿里中心"）
- 配额: 个人开发者 2000-5000 次/日（映世业务量 10-20 次/日，远低于配额）
- 错误码: status=0 时关注 infocode（10001 Key 不正确 / 10003 配额超限等）

## 六、用户流程

### 流程1: 上传媒体带位置

1. 用户在今日页点击上传 → PhotoPicker 选图
2. **Android**: LocationHelper 用 FusedLocationProvider 获取 (lat, lng)，无权限/无信号时返回 null（静默跳过）
3. **Android**: createUploadToken 携带 lat/lng → 后端 UploadService 落库到 UploadTaskEntity
4. **Android**: uploadLocalStream 上传文件 → 后端 buildMediaFromTask 透传位置到 MediaEntity
5. **Android**: addMedia 关联到 life_console
6. **Server**: LifeConsoleService.addMedia 不需再处理位置（已落库）
7. **Server**: 异步或同步调用 GeocodingService.reverseGeocode(lat, lng) → locationLabel
8. **Server**: 更新 MediaEntity.locationLabel
9. **Server**: 返回 TodayResponse，MediaDto 含位置字段
10. **Android**: 今日页卡片展示 locationLabel

### 流程2: 记录排便带位置

1. 用户点击 + 按钮
2. **Android**: ViewModel.addBowelEvent() → LocationHelper 获取 (lat, lng)
3. **Android**: repository.addBowelEvent(zoneId, lat?, lng?) → API 发送 AddBowelEventRequest body
4. **Server**: Controller 接收 body → Service.addBowelEvent 创建 BowelEventEntity 含位置
5. **Server**: GeocodingService.reverseGeocode → locationLabel，更新 BowelEventEntity
6. **Server**: 返回 BowelMutationResponse，BowelEventDto 含位置字段
7. **Android**: 今日页 BowelCard 展示 locationLabel

### 流程3: 历史页查看位置

1. 用户打开历史页 → getHistory API
2. **Server**: 返回 HistoryResponse，每天的 MediaDto/BowelEventDto 含位置字段
3. **Android**: 时间轴卡片展示 locationLabel（labelSmall + textSecondary，无位置时静默不显示）
