## 三、数据流图

### 3.1 媒体上传位置数据流

```
[Android 端]
1. 用户点击上传媒体
2. LifeConsoleUploadBridge.uploadMedia(context, category, uris) 调用
3. LocationHelper.getCurrentLocation(context) 异步获取 GPS
   ├─ 无定位权限 → 返回 null
   ├─ FusedLocationProvider 失败 → 返回 null
   ├─ 3s 超时 → 返回 null
   └─ 成功 → LocationSnapshot(latitude, longitude)
4. UploadMetadata 携带 location
5. toTokenPayload() → UploadTokenRequestDto(latitude, longitude)
6. POST /api/upload/tokens { ..., latitude, longitude }
            ↓
[服务端]
7. UploadController.createUploadToken → UploadService.createUploadToken
8. UploadTokenRequest 解包 latitude/longitude
9. 复制到 UploadTaskEntity (latitude, longitude, locationLabel=null)
10. 持久化 UploadTaskEntity
11. 返回 upload token 给客户端
            ↓
[Android 端]
12. 客户端用 token 分块上传文件到 MinIO
            ↓
[服务端 - 后台回调]
13. UploadService.completeUpload / buildMediaFromTask
14. 从 UploadTaskEntity 复制 lat/lng 到 MediaEntity
15. GeocodingService.reverseGeocode(lat, lng) 调高德 API
    ├─ amap.enabled=false → NoopGeocodingService 返回 null
    ├─ HTTP 调用失败 → 返回 null（不阻断）
    └─ 成功 → formatted_address 字符串
16. 若 label 非 null → media.setLocationLabel(label) → save(media)
17. 若 label 为 null → media.locationLabel 保持 null（不阻断）
18. MediaEntity 持久化完成
            ↓
[Android 端]
19. LifeConsoleViewModel 刷新今日快照
20. GET /api/life-console/today → 返回 MediaDto（含 lat/lng/locationLabel）
21. RealLifeConsoleRepository → RemoteMedia（含 lat/lng/locationLabel）
22. LifeConsoleScreen LifeMediaFrame 展示 locationLabel（如有）
```

### 3.2 排便事件位置数据流

```
[Android 端]
1. 用户点击 + 排便按钮
2. LifeConsoleViewModel.addBowelEvent() 启动
3. LocationHelper.getCurrentLocation(appContext) 异步获取 GPS（同上）
4. RealLifeConsoleRepository.addBowelEvent(zoneId, lat, lng)
5. LifeConsoleApi.addBowelEvent(zoneId, LifeConsoleBowelEventRequestDto(lat, lng))
6. POST /api/life-console/bowel-events?zoneId=... { latitude, longitude }
            ↓
[服务端]
7. LifeConsoleController.addBowelEvent(@Body request, @Query zoneId, user, httpReq)
8. LifeConsoleService.addBowelEvent(request, zoneId, currentUser)
9. 创建 BowelEventEntity（设置 lat/lng/locationLabel）
10. bowelEventRepository.save(event)
11. GeocodingService.reverseGeocode(lat, lng) 调高德 API（同上）
12. 若 label 非 null → event.setLocationLabel(label) → save(event)
13. 返回 LifeConsoleBowelMutationResponse（含 bowelEvent: BowelEventDto[lat/lng/label]）
            ↓
[Android 端]
14. 乐观本地更新已包含位置
15. 服务端返回确认 → 更新本地状态
16. LifeConsoleScreen BowelCard 展示 user.latestLocationLabel
```

### 3.3 历史页位置数据流

```
[Android 端]
1. 用户打开历史页
2. LifeConsoleViewModel.loadHistory() → RealLifeConsoleRepository.getHistory()
3. GET /api/life-console/history?days=30&zoneId=...
            ↓
[服务端]
4. LifeConsoleController.getHistory → LifeConsoleService.getHistory
5. 查询最近 30 天的 MediaEntity（domain=life）+ BowelEventEntity（deletedAt=null）
6. 按 day 聚合:
   - LifeConsoleHistoryDayDto: locationLabel = 取最新媒体的 locationLabel
   - LifeConsoleBowelHistoryDayDto: locationLabel = 取最新事件的 locationLabel
   - LifeConsoleBowelUserSummaryDto: latestLocationLabel = 该用户最新事件的 locationLabel
7. 返回聚合结果
            ↓
[Android 端]
8. RealLifeConsoleRepository → RemoteLifeConsoleHistory (含 locationLabel 字段)
9. LifeConsoleScreen 4 处 UI 展示:
   - LifeConsoleHistoryDaySection: day.locationLabel
   - LifeConsoleHistoryBowelDayCard: day.locationLabel
   - LifeMediaFrame: slot.mediaItems.maxByOrNull{displayTimeMillis}.locationLabel
   - BowelCard: user.latestLocationLabel
```

## 五、API 契约变更摘要

### 5.1 POST /api/upload/tokens（请求体加字段）

**变更前**:
```json
{
  "libraryId": "...",
  "domain": "life",
  ... 17 个字段
}
```

**变更后**:
```json
{
  "libraryId": "...",
  "domain": "life",
  ... 17 个字段,
  "latitude": 39.9075,
  "longitude": 116.39723,
  "locationLabel": null
}
```

**兼容性**: 字段全可选，旧客户端不传 → 反序列化为 null → 不影响上传流程。

### 5.2 POST /api/life-console/bowel-events（请求体新增）

**变更前**: 无请求体，仅 Query 参数 `zoneId`

**变更后**:
```json
{
  "latitude": 39.9075,
  "longitude": 116.39723,
  "locationLabel": null
}
```

**兼容性**: `@RequestBody(required=false)`，旧客户端不发 body → request 为 null → service 内 `if (request != null)` 守护 → 位置字段为 null。

### 5.3 GET /api/life-console/today（响应体加字段）

**变更前** MediaDto:
```json
{
  "mediaId": "...",
```

## 七、本轮 Flyway 迁移链

```
V25 (基线) → V26 数据域隔离 (R1) → V27 大便软删除 (R1) → V28 上传任务域 (R1)
   → V29 位置追踪 (R6, 本轮)
```

- V29 文件: `YingShi-Server/src/main/resources/db/migration/postgresql/V29__life_console_location_tracking.sql`
- 幂等保证: 所有 `ALTER TABLE` 使用 `IF NOT EXISTS`
- 字段类型: `DOUBLE PRECISION`（PostgreSQL 原生类型，对应 Java Double）
- 字符串长度: `VARCHAR(255)` 与 Entity `@Column(length=255)` 一致
- 回滚方案: 手动执行 `ALTER TABLE ... DROP COLUMN ...`（Flyway 不支持回滚）
