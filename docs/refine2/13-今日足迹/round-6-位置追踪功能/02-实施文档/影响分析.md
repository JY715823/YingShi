## 三、必须测试的影响路径清单

### IA-1: V29 迁移幂等性
- **路径**: V29 SQL → 多次执行不报错 → 三表新字段存在
- **测试方式**: `docker compose up -d --build server` 启动后查询 `\d media` / `\d bowel_events` / `\d upload_tasks` 确认字段
- **风险**: 测试环境 ddl-auto=validate 严格校验，字段类型必须为 DOUBLE PRECISION（Double 映射）

### IA-2: MediaDto 共享 DTO 向后兼容
- **路径**: 新增 3 个可选字段 → 旧客户端不传位置 → MediaDto 序列化时 NON_NULL 过滤 → 旧客户端无感
- **测试方式**: 用旧版本 DTO JSON 反序列化新版本，无字段缺失；新版本序列化空位置字段不出现 key
- **风险**: 漏掉某处构造 MediaDto 未传递新字段 → 序列化为 null → NON_NULL 自动过滤（无错但位置丢失）

### IA-3: withDisplayTime 位置同步（高风险）
- **路径**: LifeConsoleService L479-503 `withDisplayTime` 方法重建 MediaDto 时必须同步传递 lat/lng/locationLabel
- **测试方式**: 上传带位置的媒体 → 调用 getHistory → 验证响应中 locationLabel 非空
- **风险**: 漏传字段 → 历史页位置丢失（只能通过端到端测试发现）

### IA-4: addBowelEvent 破坏性变更向后兼容
- **路径**: Controller `@RequestBody(required=false)` → 旧客户端无 body → request 为 null → service 内 `if (request != null)` 守护 → 位置字段为 null
- **测试方式**: 用 curl 不发 body 调用 POST /api/life-console/bowel-events → 200 OK + 正常响应
- **测试方式**: 用 curl 发带位置 body → 200 OK + 响应包含位置字段
- **风险**: required=true → 旧客户端 400 BadRequest

### IA-5: GeocodingService 配置开关
- **路径**: AMAP_GEOCODING_ENABLED=false → NoopGeocodingService 注入 → reverseGeocode 返回 null → 不报错
- **路径**: AMAP_GEOCODING_ENABLED=true + Key 缺失 → AmapGeocodingService 注入 → HTTP 调用 401 → 返回 null → 不报错
- **测试方式**: 关闭开关启动服务 → 上传带位置的媒体 → locationLabel 为 null，无异常
- **测试方式**: 开启开关但 Key 错误 → 上传带位置 → locationLabel 为 null，日志告警
- **风险**: 配置缺失导致服务启动失败

### IA-6: 高德 API location 参数顺序
- **路径**: AmapGeocodingService URL 构造 `location=lng,lat`（不是 lat,lng）
- **测试方式**: 真实调用一次高德 API → 验证返回的 formatted_address 与实际位置匹配
- **风险**: 顺序写反 → 返回的位置文字与实际位置不符（北京坐标变成上海地址）

### IA-7: Android 静默 fallback
- **路径**: 用户未授权定位 → LocationHelper.hasLocationPermission=false → 返回 null → 上传不带位置 → API 接受 null → 正常响应
- **测试方式**: 拒绝定位权限 → 上传媒体 → 不弹错误，不阻断，locationLabel 为 null
- **风险**: 抛 SecurityException → 上传流程中断

### IA-8: 超时静默
- **路径**: GPS 信号弱 → 3s 超时 → withTimeoutOrNull 返回 null → 上传不带位置
- **测试方式**: 飞行模式下上传 → 不阻断（无 GPS 也无网络，但 LocationHelper 仍能返回最后已知位置或 null）
- **风险**: 超时抛异常 → 上传流程中断

### IA-9: 历史页代表性位置策略
- **路径**: 一天有多张媒体，位置不同 → 取 displayTimeMillis 最大的一张的 locationLabel
- **测试方式**: 同一天上传两张不同位置的媒体 → 调用 getHistory → 验证 day.locationLabel 为较新一张的位置
- **风险**: 取第一张位置 → 显示旧位置不准；或聚合错误显示空

### IA-10: Android UI 展示 4 处
- **路径**: locationLabel 为 null → UI 不显示位置标签（非"未知位置"）；非 null → 显示截断文字
- **测试方式**: 跑 Compose Preview + 真机验证 4 个 Composable
- **风险**: 显示"未知位置" / "null" 文字 / 抢视觉焦点

### IA-11: 跨模块回归 - 照片模块
- **路径**: MediaDto 新增字段 → PhotoFeed/Album/MediaFeed 序列化响应包含可选字段 → 旧客户端忽略
- **测试方式**: `mvnw.cmd test -Dtest=PhotoFeed*Test,Album*Test` 通过
- **风险**: 测试环境序列化断言严格匹配 → 新字段导致测试失败

### IA-12: 跨模块回归 - 上传模块
- **路径**: UploadTokenRequest 加可选字段 → 照片上传不传位置 → UploadService 接受 null → 不调 GeocodingService
- **测试方式**: 照片上传 → 媒体记录的 latitude/longitude/locationLabel 均为 null
- **风险**: 上传流程阻断
