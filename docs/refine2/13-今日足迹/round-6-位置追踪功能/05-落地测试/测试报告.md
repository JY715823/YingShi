## 八、发现并修复的 Bug

### BUG-1: GeocodingService bean 注册失败 (P0，已修复)

**问题**: 30 个 JUnit 测试全部失败 (15 Service + 15 Controller)，错误:
```
NoSuchBeanDefinitionException: No qualifying bean of type 'com.yingshi.server.service.geocoding.GeocodingService'
```

**根因**: `NoopGeocodingService` 使用 `@ConditionalOnMissingBean(GeocodingService.class)` 注解。根据 Spring Boot 官方文档:
> The condition can only match the bean definitions that have been processed by the application context so far and, as such, it is strongly recommended to use this condition on auto-configuration classes only.

`@ConditionalOnMissingBean` 在 component-scanned 的 `@Service` 类上不可靠 (评估顺序问题)。当 `AmapGeocodingService` 因 `@ConditionalOnProperty` 不满足而被跳过时，`NoopGeocodingService` 的 `@ConditionalOnMissingBean` 条件未能正确检测到"没有 GeocodingService bean"，导致两个实现都未注册。

**修复**: 将 `NoopGeocodingService` 的条件改为 `@ConditionalOnProperty` 反向匹配:
```java
// 修复前 (不可靠):
@Service
@ConditionalOnMissingBean(GeocodingService.class)
public class NoopGeocodingService implements GeocodingService {

// 修复后 (标准 fallback 模式):
@Service
@ConditionalOnProperty(prefix = "app.geocoding.amap", name = "enabled", havingValue = "false", matchIfMissing = true)
public class NoopGeocodingService implements GeocodingService {
```

与 `AmapGeocodingService` 的 `@ConditionalOnProperty(... havingValue="true")` 形成互斥，是 Spring Boot 官方推荐的 fallback bean 模式，无评估顺序依赖。

**验证**: 修复后重跑 `mvnw.cmd test "-Dtest=LifeConsoleServiceTest,LifeConsoleControllerTest"` → 30/30 全部通过，退出码 0。

### BUG-2: docker-compose.yml 变量插值语法错误 (P1，已修复)

**问题**: `docker compose up -d --build server` 失败:


**根因**: docker-compose.yml L108 使用 `${FCM_DRY_RUN:false}` (单冒号)，Docker Compose 变量插值要求 `${VAR:-default}` (冒号+短横)。这是预存 bug，非 Round 6 引入。

### BUG-3: JPA `updatable=false` 导致测试无法更新 `createdAt` (P2，Stage 6 已修复)

**问题**: Stage 6 新增测试 `LifeConsoleServiceTest.mediaHistoryPreservesLocationThroughWithDisplayTime` 失败:
```
java.lang.AssertionError: [personDays should contain at least one day with our media] Expecting actual not to be empty
```

**根因**: `BaseEntity.createdAt` 字段标注 `@Column(nullable = false, updatable = false)`，JPA 规范在 `updatable=false` 时会忽略实体对象对该字段的修改，`postMediaRepository.save(rel)` + `flush()` 不会将 `setCreatedAt(yesterday)` 写入数据库。因此 `getHistory()` 读到的 `createdAt` 仍是今天，被 `!mediaDate.isBefore(today)` 过滤掉，`personDays` 为空。

**修复**: 在测试中改用 `JdbcTemplate.update()` 原生 SQL 直接更新 `small_album_media.created_at` 列，绕过 JPA 的 `updatable=false` 限制；并调用 `entityManager.clear()` 清空持久化上下文缓存，确保后续 `getHistory()` 重新从 DB 读取最新状态。

```java
int updatedRows = jdbcTemplate.update(
        "UPDATE small_album_media SET created_at = ? WHERE media_id = ?",
        java.sql.Timestamp.from(yesterday),
        media.getId()
);
assertThat(updatedRows).as("PostMediaEntity should exist for media %s", media.getId()).isGreaterThan(0);
entityManager.clear();
```

**验证**: 修复后单测 PASS，13 个新测试 100% 通过 (43/43 JUnit 全绿)。

> **注**: 此为测试代码问题，不影响生产逻辑。生产代码 `addMedia` 通过 `@PrePersist` 在 INSERT 时设置 `createdAt`，`updatable=false` 是合理的不可变字段保护。
