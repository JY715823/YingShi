#### 测试关键点

- `getToday` 和 `getHistory` 是 `@Transactional(readOnly=true)`，不会产生脏数据
- `addMedia` 内部调用 `ensureSystemAlbum` + `ensureMonthlySmallAlbum`（幂等创建），然后 `getToday` 返回最新快照
- `deleteMedia` 依赖 `trashService.systemDeleteMedia` 做软删除，需要回收站逻辑完整
- `deleteLatestBowelEvent` 设置 `deletedAt` 时间戳而非物理删除
- `notifyLifeConsoleChanged` 使用 `PushDispatchSupport.afterCommitAsync`，测试中 `CapturingPushMessageSender` 会捕获推送
- `resolveLifeUsers` 依赖种子数据（user_demo_a + user_demo_b + library_shared）
- `buildMediaSlot` 和 `buildHistoryDays` 中查询带 `domain='life'` 过滤，确保隔离

## 五、技术约束

| 约束 | 说明 |
|------|------|
| Flyway 迁移 | V1~V27 全部自动执行，包括 domain 列和 deleted_at 列 |
| Testcontainers | 需要 Docker Desktop 运行 |
| 测试隔离 | 每个 `@Test` 方法默认 `@Transactional` 回滚，但 MockMvc 请求在独立线程，需要手动清理 |
| 异步通知 | `notifyLifeConsoleChanged` 使用 `afterCommitAsync`，CapturingPushMessageSender 在主线程捕获 |
| MockMvc | 不经过 Servlet Filter 链（需手动验证 `@AuthRequired` 效应） |
| 上传链路 | addMedia 需要 mediaId 已存在于 DB，需要先走上传流程 |

## 六、测试设计策略

### 6.1 LifeConsoleServiceTest（Service 层单元测试）

**方式**: 继承 `AbstractPostgresIntegrationTest`，不通过 MockMvc，直接注入 `LifeConsoleService` 和 Repository 调用。

**覆盖方法**:
1. `getToday` — 空数据快照 / 有数据正确分组

4. `deleteMedia` — 软删除 / 权限校验（只能删自己的）
5. `addBowelEvent` — 事件创建 / 当天摘要

**测试数据准备策略**:
- 通过 Repository 直接插入媒体数据，避免走上传链路
- 通过 `addMedia` 自动创建系统相册（幂等）
- 通过 `addBowelEvent` 创建排便事件

### 6.2 LifeConsoleControllerTest（Controller 层集成测试）

**方式**: 继承 `AbstractPostgresIntegrationTest`，使用 `MockMvc` 发送 HTTP 请求。

**覆盖**:

## 七、风险评估

| # | 风险 | 严重度 | 缓解措施 |
|---|------|--------|---------|
| 1 | 测试数据准备需要走上传链路 | 中 | 通过 Repository 直接插入 MediaEntity，绕过上传 |
| 2 | MockMvc 请求不在 @Transactional 事务中 | 中 | 每个测试独立准备数据，或使用 `@Sql` 初始化 |
| 3 | `afterCommitAsync` 异步通知在测试中不可控 | 低 | CapturingPushMessageSender 在主线程即可捕获 |
| 4 | Testcontainers 首次启动慢 | 低 | 单例容器模式已实现，多测试类共享 |
| 5 | 测试间数据污染 | 中 | 每个测试方法用 `@AfterEach` 清理，或依赖 `@Transactional` 回滚 |
