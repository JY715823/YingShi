# Round 1 数据基础重构 — 影响分析

> 基于实施计划 | 日期: 2026-07-17

---

## 变更文件 → 影响链

### 1. AlbumEntity.java — 新增 domain 字段

**直接影响**:
- 所有创建 AlbumEntity 的代码必须设 domain 值
- 所有查询 AlbumEntity 的 Repository 方法可能需要加 domain 过滤

**影响链**:
- `AlbumEntity` → `LifeConsoleService.ensureSystemAlbum()` → 创建时设 domain='life'
- `AlbumEntity` → `AlbumService` (创建大相册) → 创建时设 domain='photo'（默认值）
- `AlbumEntity` → `AlbumRepository` 查询方法 → 系统相册查询加 domain 过滤

**间接影响**:
- `ContentMapper` — 如果 DTO 映射包含 domain，需更新
- `SyncService.getVersions()` — album 版本查询

**影响路径清单**:
- IA-1: LifeConsoleService 通过 albumRepository 查系统相册 — 必须带 domain='life'
- IA-2: AlbumService 创建/列出大相册 — 必须带 domain='photo' 或默认值
- IA-3: SyncService albumsVersion 计算 — 可能受影响

---

### 2. PostEntity.java — 新增 domain 字段

**直接影响**:
- 所有创建 PostEntity 的代码必须设 domain 值
- 所有查询 PostEntity 的 Repository 方法可能需要加 domain 过滤

**影响链**:
- `PostEntity` → `LifeConsoleService.ensureMonthlySmallAlbum()` → 创建时设 domain='life'
- `PostEntity` → `LifeConsoleService.buildMediaSlot()` → 查询加 domain='life'
- `PostEntity` → `LifeConsoleService.buildHistoryDays()` → 查询加 domain='life'
- `PostEntity` → `PostService` (创建/列出小相册) → 创建时设 domain='photo'
- `PostEntity` → `SyncService.lifeConsoleVersion` → 查询加 domain 过滤

**间接影响**:
- `PostMediaRepository` — 关联表查询不直接依赖 Post domain，但调用方查询 post 时已过滤
- `ContentMapper` — 同 AlbumEntity

**影响路径清单**:
- IA-4: LifeConsoleService 所有 post 查询 → 必须带 domain='life'
- IA-5: PostService 创建/列出小相册 → 必须带 domain='photo'
- IA-6: SyncService lifeConsoleVersion → post 查询加 domain='life'

---

### 3. MediaEntity.java — 新增 domain 字段

**直接影响**:
- 所有创建 MediaEntity 的代码必须设 domain 值
- 所有查询 MediaEntity 的 Repository 方法可能需要加 domain 过滤

**影响链**:
- `MediaEntity` → `UploadService.createUploadToken()` / `uploadFile()` → 创建时设 domain
- `MediaEntity` → `LifeConsoleService.addMedia()` → 关联 media 时设 domain='life'
- `MediaEntity` → `MediaService` (照片流) → 查询加 domain='photo'
- `MediaEntity` → `MediaRepository.findFeedPage()` → 加 domain='photo'

**间接影响**:
- `TrashService` — 软删除 media 不影响 domain
- `ContentMapper` — 同 AlbumEntity

**影响路径清单**:
- IA-7: UploadService 创建 media → 必须设 domain（默认 'photo'）
- IA-8: MediaService 照片流 → 查询加 domain='photo'
- IA-9: LifeConsoleService.addMedia → 关联 media 时设 domain='life'

---

### 4. LifeConsoleService.java — 核心变更

**直接影响**:
- 所有查询/创建 Album/Post/Media 的地方加 domain 过滤
- addMedia/addBowelEvent/deleteLatestBowelEvent 方法签名变更

**影响链**:
- `LifeConsoleService` → `LifeConsoleController` → 调用方需传 zoneId 参数
- `LifeConsoleService` → `PushNotificationService` → 推送通知逻辑不变
- `LifeConsoleService` → `TrashService` → 删除逻辑不变

**影响路径清单**:
- IA-10: LifeConsoleController 所有调用 LifeConsoleService 的端点 → 签名变更需同步
- IA-11: addMedia 返回的 today 快照 → 数据一致性验证

---

### 5. UploadService.java + LocalMediaStorageService.java — 上传链路

**直接影响**:
- 对象存储路径从 `originals/{month}/{mediaId}.ext` 变为 `{domain}/originals/{month}/{mediaId}.ext`
- MinIO 中现有文件路径不变（旧文件仍在旧路径下）

**影响链**:
- `UploadService` → `UploadController` → API 请求体新增 domain 字段
- `UploadService` → `LocalMediaStorageService` → 方法签名变更
- `UploadService` → `MediaEntity` → 创建时设 domain
- `UploadService` → `UploadTaskEntity` → 不存储 domain（仅和 media 关联）

**间接影响**:
- 已有 media 的 storagePath 不变（V26 迁移不改 storagePath）
- 预览图路径不变（基于 storagePath 计算）
- 视频封面路径不变

**影响路径清单**:
- IA-12: 新上传的 media → storagePath 以 `{domain}/` 开头
- IA-13: 旧 media 的 storagePath → 不变，仍以 `originals/` 开头
- IA-14: 预览/封面生成 → 基于 storagePath 自动适配新路径

---

### 6. MediaRepository.findFeedPage() — 加 domain='photo'

**直接影响**:
- 照片流只返回 domain='photo' 的 media

**影响链**:
- `MediaRepository` → `MediaService` → 照片流 API
- `MediaRepository` → 其他使用 findFeedPage 的调用方

**影响路径清单**:
- IA-15: 照片流 API → 只返回 domain='photo' 的 media
- IA-16: Widget 照片流（如有） → 同样只返回 photo 域

---

### 7. SyncService.getVersions() — 版本计算

**直接影响**:
- lifeConsoleVersion 的 post 查询加 domain='life'

**影响链**:
- `SyncService` → `SyncController` → Android SyncVersionTracker
- `SyncService` → albumsVersion 计算（album 查询可能受影响）

**影响路径清单**:
- IA-17: lifeConsoleVersion 变更 → Android 端 SyncVersionTracker 收到更新
- IA-18: albumsVersion 不受影响 → album 查询默认不区分 domain

---

### 8. BowelEventEntity + Repository + Service — 软删除

**直接影响**:
- 所有 bowelEvent 查询加 deletedAt IS NULL
- deleteLatestBowelEvent 行为从物理删除变为软删除

**影响链**:
- `BowelEventRepository` → `LifeConsoleService` 所有查询 → 自动过滤软删除
- `BowelEventRepository` → `SyncService.lifeConsoleVersion` → 版本计算
- `BowelEventEntity` → 数据库 → V27 迁移

**影响路径清单**:
- IA-19: getToday 中 bowel summary → 不包含软删除事件
- IA-20: getHistory 中 bowel history → 不包含软删除事件
- IA-21: 重复删除 → 查询返回空 → 抛 NOT_FOUND
- IA-22: SyncService bowel 版本 → 软删除事件 updatedAt 会触发版本更新

---

### 9. RegisterPushToken DTO 包迁移

**直接影响**:
- PushDeviceController 的 import 路径变更

**影响链**:
- `PushDeviceController` → 引用 `dto.push.*` 包
- 其他引用 `dto.life.RegisterPushToken*` 的代码 → 无（仅 PushDeviceController 使用）

**影响路径清单**:
- IA-23: PushDeviceController 编译通过 → import 更新后编译
- IA-24: PushNotificationService 内部引用 → 无影响（Service 不直接引用 DTO 包）

---

### 10. Android 端变更

**直接影响**:
- CreateUploadTokenPayload 新增 domain 字段
- LifeConsoleUploadBridge 上传时传 domain='life'

**影响链**:
- `CreateUploadTokenPayload` → `LifeConsoleUploadBridge.toTokenPayload()` → 上传流程
- `CreateUploadTokenPayload` → `UploadRepository.createUploadToken()` → API 调用
- `LifeConsoleUploadBridge` → `LifeConsoleUploadRuntime` → Widget 后台上传

**影响路径清单**:
- IA-25: 主 App 上传 → 传 domain='life' → 后端存储路径正确
- IA-26: Widget 后台上传 → 同样传 domain='life'
- IA-27: 照片流上传 → 不传 domain（默认 photo）→ 路径不变
