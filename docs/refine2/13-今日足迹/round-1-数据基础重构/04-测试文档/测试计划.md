## 二、功能测试

### FR-1: 存储三域隔离

#### TC-1.1: 创建 LifeConsole 系统相册时 domain='life'
- 对应: FR-1 / AC-1
- 端: Server
- 前置条件: 用户已登录，life_console 系统相册不存在
- 步骤: 调用 `POST /api/life-console/media` 添加一条媒体
- 预期结果: 系统自动创建 album 和 small_album，domain='life'
- 验证命令: `docker exec yingshi-postgres psql -U yingshi -d yingshi -c "SELECT id, title, system_key, domain FROM albums WHERE system_key='life_console';"`
- 通过标准: 查询结果中 domain='life'

#### TC-1.2: 现有照片流数据 domain='photo'（默认值）
- 对应: FR-1 / AC-2
- 端: Server
- 前置条件: 数据库中有旧数据（无 domain 列）
- 步骤: 运行 V26 迁移后查询任意 album
- 预期结果: 所有旧数据的 domain 默认值为 'photo'
- 验证命令: `docker exec yingshi-postgres psql -U yingshi -d yingshi -c "SELECT id, domain FROM albums WHERE system_key IS NULL LIMIT 3;"`
- 通过标准: 所有旧数据 domain='photo'

#### TC-1.3: 照片流不返回 LifeConsole 的 media
- 对应: FR-1 / AC-3
- 端: Server

- 预期结果: 只返回 domain='photo' 的 media
- 验证: 返回的 media 列表中不含 domain='life' 的条目
- 通过标准: 照片流不包含 LifeConsole 的 media

#### TC-1.4: Upload API 接受 domain 参数
- 对应: FR-1 / AC-4

- 前置条件: 用户已登录

- 验证: 检查响应中的 objectKey 以 `life/` 开头

#### TC-1.6: addMedia 后 media 的 domain 变为 'life'

- 验证命令: `docker exec yingshi-postgres psql -U yingshi -d yingshi -c "SELECT id, domain FROM media WHERE id='{mediaId}';"`

#### TC-1.7: getToday 返回数据包含 domain='life' 的 media

- 对应: FR-10 / AC-2

- 通过标准: 软删除数据保留

#### TC-10.3: 重复删除已软删除的事件返回错误
- 对应: FR-10 / AC-3
- 端: Server
- 前置条件: 已软删除当天所有 bowel 事件
