## 二、改动盘点

### 2.1 阶段 5 — 上传后滚动定位 Bug

**问题**: 上传照片后页面没有自动跳转到新上传的那条。

**根因**: `LifeConsoleViewModel.lastUploadedMediaId` 未在滚动完成后清空，导致 LaunchedEffect 反复触发但目标 page 已经是当前 page。

**修复**:
- `LifeConsoleScreen.LifeMediaFrame` 新增 `onUploadConsumed` 回调
- `LaunchedEffect(slotKey, initialMediaId, slot.mediaItems, pagerState.currentPage)` 在 `current?.mediaId == initialMediaId` 时调用 `onUploadConsumed()`
- ViewModel 的 `consumeLastUploadedMediaId()` 清空 UiState.lastUploadedMediaId

**验证**: 编译通过；运行时行为：上传 → Bridge 返回 mediaId → ViewModel 设置 lastUploadedMediaId → Screen 传入 LifeMediaFrame → HorizontalPager scrollToPage(targetIndex) → 命中后 consume → 后续重组不再触发。

## 八、复检后修复 — 闪退 BUG-7A (2026-07-19)

**用户反馈**: 一进今日痕迹页就闪退。

**根因分析**:

通过 `adb logcat` 抓到崩溃栈：

```
java.lang.IllegalStateException: Vertically scrollable component was measured with an infinity 
maximum height constraints, which is disallowed. One of the common reasons is nesting layouts 
like LazyColumn and Column(Modifier.verticalScroll()).
```

**崩溃链**:
```
ShellPage 的 content = Column(weight(1f).verticalScroll())   ← 外层可滚动，子级拿到无限高度
  → LifeConsoleTodayPager.Column(fillMaxWidth())
    → HorizontalPager(fillMaxWidth())                        ← 不限制子级高度
      → LifeConsoleTodayMediaPage.LazyColumn(fillMaxSize())  ← 拿到无限高度 → 崩溃
      → LifeConsoleTodayBowelPage.LazyColumn(fillMaxSize())  ← 同上
```

`ShellPage` 的 content lambda 包在 `Column(weight(1f).verticalScroll())` 内，verticalScroll 使子级在垂直方向拿到 `maxHeight = Infinity` 约束。Round 7 阶段 4 改造时把 `LifeConsoleTodayMediaPage` / `LifeConsoleTodayBowelPage` 内部改成了 `LazyColumn(Modifier.fillMaxSize())`，但 LazyColumn 不接受无限高度约束，启动即崩溃。

**修复**:

把两个 page 内部的 `LazyColumn(Modifier.fillMaxSize())` 改成普通 `Column(Modifier.fillMaxWidth())`，让内容融入 ShellPage 的外层 verticalScroll。`itemsIndexed { ... }` 改为 `forEach { ... }`。

| 文件 | 改动 |
|------|------|
| `LifeConsoleScreen.kt` `LifeConsoleTodayMediaPage` | `LazyColumn(fillMaxSize)` + 2 个 `item {}` → `Column(fillMaxWidth)` + 2 个直接子项 |
| `LifeConsoleScreen.kt` `LifeConsoleTodayBowelPage` | `LazyColumn(fillMaxSize)` + `itemsIndexed` + `item {}` → `Column(fillMaxWidth)` + `forEach` + 直接子项 |

**为何此方案可行**:
- page 内容很少 (媒体页固定 2 个 LifeMediaFrame；大便页通常 < 10 个 event)，不需要懒加载
- 不再有嵌套垂直滚动，避免双滚动冲突
- 所有 page 内容自然成为 ShellPage 滚动列表的一部分，体验更连贯

**为何历史页 `LifeConsoleHistoryPanel` 不受影响**: 历史页的 `HorizontalPager` 用了 `Modifier.fillMaxWidth().weight(1f)`，有有限高度约束，内部 `LazyColumn` 不会拿到无限高度。

**验证**:
- 编译: `.\gradlew.bat :app:assembleDebug` → BUILD SUCCESSFUL in 2m 16s
- 真机: `adb install -r` + `adb shell am start -a OPEN_LIFE_CONSOLE` → 进程正常运行 (PID 19734)，无 FATAL/AndroidRuntime 异常，Widget 正常更新
