## 二、FR-5: 离线读缓存

### 2.1 现有基础设施

**AppReadCacheStore** (`data/cache/AppReadCacheStore.kt`):
- 单例 object，使用 `filesDir/read-cache/` 目录
- `read<T>(scope, userId, payloadType)` → `CachedPayload<T>?`（含 `cachedAtMillis` + `payload`）
- `write<T>(scope, userId, payload, payloadType)` → 写 JSON 文件
- 已有 scope: current-user, photo-feed, album-directory, post-detail, notification-list, trash-list, trash-detail
- Schema version 1，baseUrl 匹配校验，userId 匹配校验
- 线程安全（synchronized lock）

**RealLifeConsoleRepository** (`RealRepositories.kt:1345-1482`):
- `getToday(date, zoneId)` → `ApiResult<RemoteLifeConsoleToday>`
- `getHistory(zoneId, limitDays)` → `ApiResult<RemoteLifeConsoleHistory>`
- 当前无缓存层，直接调 API

### 2.2 改造方案

**新建 `LifeConsoleCacheStore`**:
- 在 `AppReadCacheStore` 中新增两个 scope: `life-console-today`, `life-console-history`
- 或新建独立文件 `LifeConsoleCacheStore.kt` 封装对 AppReadCacheStore 的 today/history 读写
- 缓存策略: 成功时写入，失败时读取；过期 7 天不展示

**RealLifeConsoleRepository 加缓存层**:
- `getToday()`: 成功后 `AppReadCacheStore.write(LIFE_CONSOLE_TODAY, null, today, ...)`，失败后 `AppReadCacheStore.read(...)` fallback
- `getHistory()`: 同上

**LifeConsoleViewModel 加离线状态**:
- `UiState` 新增 `offlineMode: Boolean` 和 `isCacheData: Boolean`
- 判断 `currentTimeMillis - cachedAtMillis > 7 * 24 * 60 * 60 * 1000` 为过期

**LifeConsoleScreen 加 StaleBanner**:
- 复用 `StaleBanner` 组件（`feature/sync/StaleBanner.kt`）
- 或自定义一个离线 Banner（"离线数据" + 刷新按钮）

## 三、FR-6: 错误处理分级

### 3.1 现有状态

**当前错误处理**:
- Repository 层: `runCatching` → `ApiResult.Error(code, message, throwable)` — 不区分异常类型
- ViewModel 层: `ApiResult.Error` → `it.copy(actionMessage = result.message)` — 统一红色文字
- UI 层: `actionMessage` 显示在 `Text` 中（红色 error 色）

**当前 SnackBar 模式**:
- ViewModel 有 `YingShiNotice` 通知系统（`showNotice(message, tone)` → `_uiState.notice`）
- LifeConsoleScreen 有 `YingShiNoticeHost` 组件接收 notice
- 但错误消息走 `actionMessage` 而非 `notice`

### 3.2 改造方案

**错误分类**（Repository 层封装）:
```kotlin
sealed class LifeConsoleError {
    data class Network(val message: String) : LifeConsoleError()
    data class Timeout(val message: String) : LifeConsoleError()
    data class Server(val message: String) : LifeConsoleError()
    data class Unknown(val message: String) : LifeConsoleError()
}
```

或在 `ApiResult` 中新增 `errorType` 字段：
```kotlin
enum class ApiErrorType { NETWORK, TIMEOUT, SERVER, UNKNOWN }
```

**Repository 层异常捕获**:
- `java.net.UnknownHostException` / `java.net.ConnectException` → Network
- `java.net.SocketTimeoutException` → Timeout
- `retrofit2.HttpException` (5xx) → Server
- 其他 → Unknown

**ViewModel 层**:
- `actionMessage` 改为 `errorState: LifeConsoleError?`
- 根据 error 类型设置不同 notice tone

**UI 层**:
- 使用 `YingShiNoticeHost` 展示错误（SnackBar 样式）
- Network: "网络已断开，请检查网络连接" + 引导按钮
- Timeout: "请求超时，请重试" + 重试按钮
- Server: "服务暂时不可用，请稍后重试"

## 四、FR-7: SyncVersionsDto 补 chatVersion

### 4.1 现状

**SyncVersionsDto** (`SyncApi.kt:6-13`):
```kotlin
data class SyncVersionsDto(
    val photoFeedVersion: Long,
    val albumsVersion: Long,
    val trashVersion: Long,
    val notificationVersion: Long = 0L,
    val lifeConsoleVersion: Long,
    val serverTimeMillis: Long,
)
```
缺少 `chatVersion` 字段。

**SyncVersionTracker** 消费:
- `fetchRemoteVersions()` 解析 remote versions
- `updateLocalVersionFor()` 更新 local versions
- 聊天模块目前无版本追踪

### 4.2 改造方案

**SyncVersionsDto** 加字段:
```kotlin
val chatVersion: Long = 0L,
```

**SyncVersionTracker** 消费:
- `SyncStaleState` 暂不加 chat stale（聊天模块未接入 SyncVersionTracker）
- `updateLocalVersionFor()` 如需要则加 chatVersion 映射
- 当前仅补字段，不影响现有逻辑
