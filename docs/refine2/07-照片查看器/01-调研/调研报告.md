## 二、用户流程

### 流程1: 从照片流进入查看图片
用户点击照片流网格中的缩略图 → PhotoFeedScreen 构建 PhotoViewerRoute(mediaItems列表 + initialIndex) → YingShiApp.kt 路由到 PhotoViewerScreen → 进入全屏沉浸模式 → HorizontalPager 定位到初始页 → PrefetchViewerMediaAssets 预取 currentIndex±1 预览图 → Coil 加载预览图（优先access["preview"].signedUrl） → 用户可双指缩放/双击放大/单击切换overlay/左右滑动翻页。

涉及: `PhotoViewerScreen.kt`, `YingShiApp.kt`, `PhotoFeedScreen`, `AppContentMediaSource`, `RealOriginalLoadRepository`

### 流程2: 查看视频
进入视频类型媒体 → PhotoViewerCanvas 渲染 AndroidView(PlayerView) → ExoPlayer.Builder 构建播放器 → MediaItem.fromUri(videoUrl) → ProgressiveMediaSource → player.prepare()+play() → 后端支持HTTP Range 206 → 用户拖动seek → ViewerVideoPlaybackState.seekRequestMillis+nonce去抖 → 松手后seekTo目标时间 → 2.8秒无操作自动隐藏控件。

涉及: `PhotoViewerScreen.kt`(视频分支), `ViewerVideoPlaybackState`, `MediaController.getMediaFile()`

### 流程3: 查看所属小相册
三横线菜单 → "所属小相册" → showRelatedPostsSheet=true → LaunchedEffect 查询 albums+posts → 标题解析(route→远端summary→缓存→兜底) → ViewerRelatedPostsSheet展示列表(含大相册chip) → 点击某行 → onOpenPostDetail(route) → 退出Viewer → 进入小相册详情。

涉及: `PhotoViewerScreen.kt`, `RepositoryProvider.albumRepository`, `RepositoryProvider.postRepository`

### 流程4: 关闭Viewer回照片流
Back键 → 如果放大状态: 复位缩放 → 如果沉浸状态: 唤出overlay → 再按Back: 写入 pendingScrollTargetMediaId → 关闭Viewer → 照片流滚动到对应媒体位置。

涉及: `PhotoViewerScreen.kt`(BackHandler), `GlobalPhotoFeedPageStateStore`

### 流程5: 离线查看小相册详情
在线时打开过小相册详情 → AppReadCacheStore 缓存 RemotePostDetail → 离线时 PostDetailRealViewModel 先读缓存渲染 → 尝试网络刷新失败不清空缓存 → 只读展示。

涉及: `AppReadCacheStore`, `PostDetailRealViewModel`, `PostDetailScreen.kt`

## 三、数据流向

### 前后端数据流
```
[照片流/相册] → PhotoViewerRoute(mediaItems) → [PhotoViewerScreen]
                                                       ↓
                                              Coil ImageRequest (JWT header)
                                                       ↓
                                              [Server MediaController]
                                                       ↓
                                              [MediaService → MinIO S3]
                                                       ↓
                                              预签名URL / 文件流 → [Coil缓存 → 渲染]
```

### 媒体URL三层策略
1. **预签名URL**（优先）: access[variant].signedUrl，S3Presigner 15分钟有效
2. **Fallback URL**: access[variant].url → /api/media/files/{id}?variant=xxx，需JWT
3. **顶层字段兜底**: url/previewUrl/originalUrl/videoUrl/coverUrl

### 跨模块数据交互
- Viewer ← 照片流: 媒体列表数据（PhotoFeedItem）
- Viewer ← 相册: 小相册/大相册标题（AlbumRepository + PostRepository 只读查询）
- Viewer ← 评论: 媒体评论（CommentRepository）
- Viewer ← 设置: hideOverlaysWhenZoomed/autoPauseVideoOnMediaSwitch/autoLongImageReading
- Viewer → 照片流: 关闭时回传滚动锚点（GlobalPhotoFeedPageStateStore）
- Viewer → 认证: 取JWT token（AuthSessionManager.peekAccessToken）
- Viewer ← 网络: 离线状态感知（NetworkConnectivityMonitor）

## 七、UI/视觉现状评估

### Theme Token使用
- Viewer使用**独立深色token系统**（viewerBackground #101F26, viewerSurface #1D333C, viewerAccent #BDEFFF等）
- 5处使用了 deprecated Window API（FLAG_FULLSCREEN/systemUiVisibility/statusBarColor），通过 @Suppress 压制
- statusBarColor 硬编码为 `Color.rgb(0x18, 0x2A, 0x35)` 和 `Color.rgb(0x10, 0x1F, 0x26)`，后者恰好等于 viewerBackground

### 视觉层
- overlay控制栏使用 AnimatedVisibility + fadeIn/fadeOut + slideInVertically/slideOutVertically
- 时间胶囊为圆角胶囊样式，底部居中偏左
- 所属小相册使用 ModalBottomSheet
- 三横线菜单使用 DropdownMenu

### 与设计计划的差距
- 设计计划要求"材质光影（磨砂玻璃、金属边线、丝绸渐变光泽）"——当前Viewer overlay为纯色+简单alpha，缺少质感层次
- 设计计划要求"更精致的装饰元素"——当前overlay控件较朴素
- Viewer独立深色系统已建立，但浮层设计较简陋

## 八、总结

照片查看器是映世App中**功能最密集、代码最复杂**的模块之一。上轮精修(2026-06-18 closed)已完成了核心功能闭环：缩放手势体系（稳定6x/弹性9x/双击/焦点锚定）、沉浸模式、视频播放控件、所属小相册、离线缓存等。

**当前主要问题集中在三方面**：

1. **代码架构**：PhotoViewerScreen.kt 3816行巨型单文件，可维护性和可测试性差。手势代码、overlay UI、视频播放、sheet、时间编辑等混在一起。
2. **技术债**：5处 deprecated Window API（AGP升级风险），硬编码状态栏颜色，5+全局object单例。
3. **视觉品质**：overlay设计较朴素，与design-plan的"材质光影"方向有差距。

**服务端完全就绪**，所有Viewer需要的API已完整实现，无需新增端点。可能的增强方向是完整EXIF元数据和自适应视频流，但优先级低。
