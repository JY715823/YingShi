## 一、变更文件影响链

### 文件1: PhotoFeedInteractionModels.kt

**变更**: 新增 HeroOrigin 数据类；PhotoViewerRoute 新增 `heroOrigin: HeroOrigin? = null` 字段

**影响链**:
```
PhotoFeedInteractionModels.kt (PhotoViewerRoute 新增字段)
├── PhotoFeedScreen.kt (构造 PhotoViewerRoute 时传入 heroOrigin)
│   ├── onMediaClick (1852-1858) → 新增 heroOrigin
│   └── onOpenMedia (1865-1871) → 新增 heroOrigin
├── PhotoViewerScreen.kt (读取 route.heroOrigin)
│   ├── 初始页 PhotoViewerCanvas → 应用 heroGraphicsLayer
│   ├── 背景层 → alpha 跟随 heroProgress
│   └── onBack → 包装为 handleBack 带退出动画
├── PostDetailScreen.kt (toInPostViewerRoute 构造)
│   └── 行 711-724 → 不传 heroOrigin（默认 null，无 Hero）
├── AppPhotoFeedPickerScreen.kt (viewerRoute 构造)
│   └── 行 182-188, 254-260 → 不传 heroOrigin（默认 null）
├── YingShiApp.kt (PhotoViewerScreen 渲染)
│   └── 行 1828-1864 → 透传 route（含 heroOrigin），无需改动
└── ViewerSupportFiles.kt (Preview)
    └── 行 385-393 → Preview 不传 heroOrigin（默认 null）
```

**影响说明**: PhotoViewerRoute 新增字段为可选（默认 null），所有现有构造点**无需强制改动**即可编译。只有 PhotoFeedScreen 的两处需主动传入 heroOrigin 以启用 Hero 动画。

### 文件2: ViewerHeroTransition.kt（新建）

**影响链**:
```
ViewerHeroTransition.kt (新建)
├── HeroOrigin 数据类 → 被 PhotoFeedInteractionModels.kt 引用（同 package，无需 import）
├── HeroGraphicsParams → 内部使用
├── computeHeroGraphicsParams() → 内部使用
├── heroGraphicsLayer Modifier 扩展 → 被 PhotoViewerScreen.kt 调用
└── HeroTransitionMillis 常量 → 被 PhotoViewerScreen.kt 引用
```

**影响说明**: 纯新增文件，不影响现有代码。所有符号为 `internal`，仅限 feature/photos 模块内可见。

### 文件3: PhotoFeedScreen.kt

**变更**: onMediaClick（1852-1858）和 onOpenMedia（1865-1871）新增 heroOrigin 构造

**影响链**:
```
PhotoFeedScreen.kt (onMediaClick/onOpenMedia 修改)
├── itemBoundsByMediaId[item.mediaId] → 取 bounds（已有机制，行 311 声明）
│   └── PhotoFeedCard 的 onGloballyPositioned → coordinates.boundsInRoot()（行 3629-3631，已有）
├── HeroOrigin(mediaId, boundsInRoot) → 构造
└── PhotoViewerRoute(heroOrigin = ...) → 传入
    └── onOpenViewer 回调 → YingShiApp.kt:1578 设置 photoViewerRoute
        └── YingShiApp.kt:1828 渲染 PhotoViewerScreen(route)
```

**影响说明**:
- 利用现成的 `itemBoundsByMediaId` 机制，无需新增 bounds 记录逻辑
- 仅修改两处 PhotoViewerRoute 构造，每处 +3 行
- 不影响 PhotoFeedScreen 的其他功能（滚动/选择/内联视频/动画）

### 文件4: PhotoViewerScreen.kt

**变更**: 接收 heroOrigin，应用进入/退出动画

**影响链**:
```
PhotoViewerScreen.kt (修改)
├── 新增状态: heroOrigin, heroProgress, heroExiting, heroContainerSize
├── LaunchedEffect → 进入动画 animateTo(1f)
├── handleBack → 替换 onBack，带退出动画
│   ├── ViewerBackHandler → 使用 handleBack
│   ├── PhotoViewerTopBar onBack → 使用 handleBack
│   └── 其他 onBack 调用点 → 使用 handleBack
├── 背景层 → alpha = heroProgress.value（仅 heroOrigin != null 时）
├── HorizontalPager userScrollEnabled → 动画期间禁用
├── 初始页 PhotoViewerCanvas modifier → heroGraphicsLayer
│   └── 仅当 page == initialPage && heroOrigin.mediaId 匹配 && progress < 1f
└── overlay alpha → 跟随 heroProgress（仅 heroOrigin != null 时）
```

**影响说明**:
- 所有改动都在 `heroOrigin != null` 条件下生效，null 时行为完全不变
- handleBack 替换所有 onBack 调用点，确保退出时播放动画
- HorizontalPager 的 userScrollEnabled 在动画期间禁用，progress>=1f 后恢复

## 五、风险与缓解

| # | 风险 | 严重度 | 影响路径 | 缓解措施 |
|---|------|--------|---------|---------|
| 1 | heroContainerSize 首帧为 Zero 导致缩放计算异常 | 中 | IA-16 | computeHeroGraphicsParams 对 size<=0 降级返回 alpha=progress |
| 2 | 退出动画期间用户快速操作（滑动/返回） | 中 | IA-17 | heroExiting 防重入 + userScrollEnabled 动画期间禁用 |
| 3 | itemBoundsByMediaId 为 null（项被回收） | 低 | IA-18 | 取不到 bounds 时 heroOrigin=null，降级为无动画 |
| 4 | HorizontalPager 初始页与 heroOrigin.mediaId 不匹配 | 低 | IA-1 | heroGraphicsLayer 仅在 mediaId 匹配时应用 |
| 5 | PhotoViewerScreen.kt 行数接近 800 上限 | 低 | - | 控制新增代码 < 60 行；如超 850 抽离到 ViewerHeroTransition.kt |
| 6 | B 类 Viewer 误传 heroOrigin | 低 | IA-19~23 | B 类不走 PhotoViewerScreen，无法传入 heroOrigin |
