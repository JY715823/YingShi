## 总体策略

**技术方案**: 记录缩略图 bounds + 自定义 graphicsLayer 缩放/位移动画（不使用 Compose sharedElement API）

**理由**:
1. `motion-plugin-tooling-guide-v1.md:385` 明确禁止 SharedTransitionLayout/sharedElement/sharedBounds
2. 需求风险 #4 警告与 HorizontalPager 冲突（高风险）
3. 实验性 API 不稳定
4. 分轮次规划明确提供此降级方案

**实施顺序**（每步编译验证）:
1. 新增 HeroOrigin 数据类 + PhotoViewerRoute 字段
2. 新建 ViewerHeroTransition.kt — Hero 过渡辅助
3. 修改 PhotoFeedScreen.kt — onMediaClick/onOpenMedia 传入 heroOrigin
4. 修改 PhotoViewerScreen.kt — 应用进入/退出动画
5. 全量编译验证

**设计约束**:
- 新增 Composable 必须使用 `YingShiThemeTokens.colors.*`
- 动画时长 300ms，FastOutSlowInEasing（AC-4: 250-350ms）
- heroOrigin 默认 null，null 时降级为无动画（AC-6 多入口兼容）
- 不影响 HorizontalPager 滑动（AC-5）
- 不引入实验性 API

**行数控制**:
- PhotoViewerScreen.kt 当前 759 行，预估 +60 行 = ~820 行（需控制 < 850）
- PhotoFeedScreen.kt 当前 5169 行，预估 +15 行
- 新建 ViewerHeroTransition.kt 预估 ~120 行

#### 文件2: ViewerHeroTransition.kt（新建，~120 行）

**目标**: 封装 Hero 过渡的进度管理和 graphicsLayer 变换计算。

**内容设计**:

```kotlin
package com.example.yingshi.feature.photos

import androidx.compose.animation.core.Animatable
import androidx.compose.animation.core.FastOutSlowInEasing
import androidx.compose.animation.core.tween
import androidx.compose.runtime.Composable
import androidx.compose.runtime.LaunchedEffect
import androidx.compose.runtime.Stable
import androidx.compose.runtime.getValue
import androidx.compose.runtime.remember
import androidx.compose.runtime.rememberCoroutineScope
import androidx.compose.ui.Modifier
import androidx.compose.ui.composed
import androidx.compose.ui.geometry.Rect
import androidx.compose.ui.graphics.TransformOrigin
import androidx.compose.ui.graphics.graphicsLayer
import androidx.compose.ui.layout.layout
import androidx.compose.ui.unit.IntSize
import kotlin.math.max

internal const val HeroTransitionMillis = 300
internal const val HeroExitDelayMillis = 0L

/**
 * Hero 起源信息（缩略图位置+尺寸）。
 * boundsInRoot 来自 PhotoFeedCard 的 onGloballyPositioned → coordinates.boundsInRoot()。
 */
@Immutable
internal data class HeroOrigin(
    val mediaId: String,
    val boundsInRoot: Rect,
)

/**
 * 计算 Hero 过渡的 graphicsLayer 参数。
 * progress=0f: 完全在起源位置（缩略图位置+尺寸）
 * progress=1f: 完全在目标位置（全屏）
 *
 * @param origin 起源 bounds（在 root 坐标系）
 * @param containerSize Viewer 容器尺寸（全屏）
 * @param progress 过渡进度 [0f, 1f]
 */
@Stable
internal data class HeroGraphicsParams(
    val scaleX: Float,
    val scaleY: Float,
    val translationX: Float,
    val translationY: Float,
    val alpha: Float,
)

internal fun computeHeroGraphicsParams(
    origin: Rect,
    containerSize: IntSize,
    progress: Float,
): HeroGraphicsParams {
    if (progress >= 1f) {
        return HeroGraphicsParams(1f, 1f, 0f, 0f, 1f)
    }
    if (progress <= 0f) {
        return HeroGraphicsParams(0f, 0f, 0f, 0f, 0f)
    }
    val containerWidth = containerSize.width.toFloat()
    val containerHeight = containerSize.height.toFloat()
    if (containerWidth <= 0f || containerHeight <= 0f) {
        return HeroGraphicsParams(1f, 1f, 0f, 0f, progress)
    }
    // 起源尺寸
    val originWidth = origin.width.takeIf { it > 0f } ?: return HeroGraphicsParams(1f, 1f, 0f, 0f, progress)
    val originHeight = origin.height.takeIf { it > 0f } ?: return HeroGraphicsParams(1f, 1f, 0f, 0f, progress)
    // 缩放：从 originWidth/containerWidth 到 1f
    val targetScaleX = originWidth / containerWidth
    val targetScaleY = originHeight / containerHeight
    val scaleX = lerp(targetScaleX, 1f, progress)
    val scaleY = lerp(targetScaleY, 1f, progress)
    // 位移：起源中心 → 容器中心
    val originCenterX = origin.left + originWidth / 2f
    val originCenterY = origin.top + originHeight / 2f
    val containerCenterX = containerWidth / 2f
    val containerCenterY = containerHeight / 2f
    // graphicsLayer 的 translation 是在缩放后的坐标系中
    // 要让"缩放后的图片中心"对齐到目标位置，translation = originCenter - containerCenter * scale
    val translationX = originCenterX - containerCenterX * scaleX
    val translationY = originCenterY - containerCenterY * scaleY
    val alpha = progress  // 图片淡入
    return HeroGraphicsParams(scaleX, scaleY, translationX, translationY, alpha)
}

private fun lerp(start: Float, stop: Float, fraction: Float): Float =
    start + (stop - start) * fraction

/**
 * 应用 Hero 过渡的 graphicsLayer。
 */
internal fun Modifier.heroGraphicsLayer(
    origin: Rect,
    containerSize: IntSize,
    progress: Float,
): Modifier = this.graphicsLayer {
    val params = computeHeroGraphicsParams(origin, containerSize, progress)
    this.scaleX = params.scaleX
    this.scaleY = params.scaleY
    this.translationX = params.translationX
    this.translationY = params.translationY
    this.alpha = params.alpha
    this.transformOrigin = TransformOrigin.TopLeft
}
```

            heroProgress.animateTo(
                targetValue = 0f,
                animationSpec = tween(HeroTransitionMillis, easing = FastOutSlowInEasing),

## 风险与缓解

| # | 风险 | 严重度 | 缓解措施 |
|---|------|--------|---------|
| 1 | heroContainerSize 获取时机：首帧可能为 Zero | 中 | heroGraphicsLayer 内部对 size<=0 做降级（返回 alpha=progress） |
| 2 | 用户在 300ms 动画期间快速滑动 Pager | 低 | 动画期间 userScrollEnabled=false；且 hero 只作用于 initialPage，滑动后 initialPage 不变 |
| 3 | onBack 退出动画期间用户再次点击返回 | 低 | heroExiting 标志位防重入 |
| 4 | itemBoundsByMediaId 可能为 null（滚动后项被回收） | 低 | 取不到 bounds 时不传 heroOrigin（降级为无动画） |
| 5 | PhotoViewerScreen.kt 行数增长（+60 行 → ~820 行） | 低 | 接近 800 上限但仍在容忍范围；如超 850 需抽离到 ViewerHeroTransition.kt |
