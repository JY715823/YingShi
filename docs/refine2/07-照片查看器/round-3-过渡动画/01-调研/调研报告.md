### 1.2 sharedElement API 支持情况

**技术上支持**。`SharedTransitionLayout` / `SharedTransitionScope` / `sharedElement` / `sharedBounds` / `rememberSharedContentState` 自 Compose 1.7.0 起加入 `androidx.compose.animation` artifact（标记 `@ExperimentalSharedTransitionApi`）。当前 BOM 2024.09.00 对应 1.7.x，已包含该 API，且 `androidx.compose.animation` 依赖已在 `app/build.gradle.kts:171` 声明，无需新增 artifact。

### 1.3 项目现状

- **源代码中未使用**：在 `app/src` 下 Grep `sharedElement|sharedBounds|SharedTransitionLayout|SharedTransitionScope|rememberSharedContentState`，零匹配。
- **文档中 3 处提及**：
  - `docs/refinement/chatShower.md:329` — 未来愿景（未实现）
  - `docs/design/motion-plugin-tooling-guide-v1.md:385` — **明确声明"不恢复本轮已放弃的 SharedTransitionLayout/sharedElement/sharedBounds"** ⚠️
  - `docs/refine2/07-照片查看器/02-需求文档/分轮次规划.md:86` — 规划备注（待确认）

### 1.4 技术决策：不使用 Compose sharedElement API

**理由**:
1. `motion-plugin-tooling-guide-v1.md:385` 明确禁止恢复该 API（motion skill 工具指南约束）
2. 需求风险 #4 警告"Shared Element Transition 与 HorizontalPager 冲突"（高风险）
3. API 为实验性（`@ExperimentalSharedTransitionApi`），未来可能变化
4. 分轮次规划 Round 3 明确提供降级方案："自定义 AnimatedVisibility + 缩放/位移动画模拟 Hero 效果"

**采用方案**: 记录缩略图 bounds + 自定义缩放/位移动画（满足全部 7 个 AC，不依赖实验性 API）

## 八、技术方案设计

### 8.1 方案选择

| 方案 | 是否采用 | 理由 |
|------|---------|------|
| A. Compose sharedElement API | ❌ | motion-plugin-tooling-guide 禁止 + 实验性 API + 与 Pager 冲突风险 |
| B. 记录 bounds + 自定义缩放/位移动画 | ✅ | 满足全部 AC，不依赖实验性 API，与 motion 指南不冲突 |

### 8.2 方案 B 详细设计

**核心思路**:
1. PhotoFeedCard 点击时，记录缩略图在 window 中的 bounds（位置+尺寸）
2. 通过 `PhotoViewerRoute.heroOrigin` 传入 PhotoViewerScreen
3. PhotoViewerScreen 初始页图片应用 `graphicsLayer` 动画：从 originBounds 位置/尺寸 → 全屏位置/尺寸
4. 背景用 `AnimatedVisibility` 的 fadeIn（AC-3 背景渐暗）
5. 关闭时反向动画（AC-2）
6. 动画时长 300ms，FastOutSlowInEasing（AC-4）

**新增文件**: `feature/photos/ViewerHeroTransition.kt`
- `data class HeroOrigin(val mediaId: String, val boundsInWindow: Rect)`
- `rememberHeroTransitionState()` — 管理过渡进度
- `Modifier.heroSource(...)` — 标记缩略图位置
- `Modifier.heroTarget(...)` — Viewer 图片应用过渡

**修改文件**:
1. `PhotoFeedInteractionModels.kt` — PhotoViewerRoute 新增 `heroOrigin: HeroOrigin? = null`
2. `PhotoFeedScreen.kt` — PhotoFeedCard 的 Box 加 onGloballyPositioned 记录 bounds；onMediaClick 传入 heroOrigin
3. `PhotoViewerScreen.kt` — 接收 heroOrigin，对初始页 PhotoViewerCanvas 应用过渡 modifier
4. `YingShiApp.kt` — PhotoViewerScreen 渲染处加 AnimatedVisibility 包裹（背景渐暗）

### 8.3 多入口兼容策略

| 入口 | 是否传 heroOrigin | 行为 |
|------|-----------------|------|
| 照片流 onMediaClick / onOpenMedia | ✅ 传 | Hero 动画 |
| 通知自动打开 | ❌ 不传 | 直接显示（无 Hero） |
| 小相册详情 | ❌ 不传 | 直接显示（无 Hero，AC-6 允许） |
| 照片选择器 | ❌ 不传 | 直接显示（无 Hero） |
| B 类独立 Viewer | 不走 PhotoViewerScreen | 完全不受影响 |

`heroOrigin` 默认 null，null 时自然降级为无动画，满足 AC-6。
