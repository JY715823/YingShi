# 07-照片查看器 需求文档

> 版本: v1.0 | 日期: 2026-07-12 | 状态: 已确认
> 基于: 调研报告 2026-07-12

## 一、模块目标

将照片查看器从"功能齐全但代码臃肿、视觉朴素"的状态，提升为"架构清晰、视觉精致、过渡流畅"的沉浸式媒体查看体验。核心改进：拆分 3816 行巨型单文件为职责清晰的模块体系，消除 deprecated API 技术债，overlay 升级至 design-plan 的材质光影标准，新增照片流→Viewer 的 Hero 过渡动画。服务端本轮无变更。

## 二、功能需求

### FR-1: PhotoViewerScreen.kt 全面拆分重构

**描述**: 将 3816 行的 PhotoViewerScreen.kt 拆分为 6-7 个职责清晰的文件，每个文件 300-600 行。拆分后保持全部现有功能不变，手势行为不变，视觉效果不变。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: 拆分后无单一文件超过 800 行
- AC-2: 所有现有功能回归通过（缩放/双击/沉浸/Back/视频/sheet/评论/时间胶囊/原图加载/离线缓存）
- AC-3: `gradlew.bat assembleDebug` 编译通过，无新增 warning
- AC-4: 拆分后的文件间通过明确的参数/回调接口通信，不引入新的全局单例
- AC-5: 共享组件（ViewerZoomState、手势函数）被 SystemMediaViewerScreen、ChatMediaViewer 等复用方正常引用，不破坏外部调用

**涉及文件**:
- `feature/photos/PhotoViewerScreen.kt` — 拆出以下内容，自身保留主容器编排
- `feature/photos/ViewerImageCanvas.kt` — 新建，图片渲染+缩放手势（从 PhotoViewerCanvas 抽取）
- `feature/photos/ViewerOverlayChrome.kt` — 新建，顶部/底部 overlay 控制栏
- `feature/photos/ViewerRelatedAlbumsSheet.kt` — 新建，所属小相册 ModalBottomSheet
- `feature/photos/ViewerVideoPlayer.kt` — 新建，ExoPlayer 视频播放封装
- `feature/photos/ViewerZoomState.kt` — 新建，缩放状态管理（从现有散落代码抽取）
- `feature/photos/ViewerBackHandler.kt` — 新建，Back 键三级逻辑

---

### FR-2: Deprecated Window API 迁移

**描述**: 将 5 处 `@Suppress("DEPRECATION")` 的旧 Window API 迁移到现代 `WindowInsetsController` + `enableEdgeToEdge` API。消除 AGP 升级时的编译风险。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: PhotoViewerScreen.kt 及 Viewer 相关文件中无 `@Suppress("DEPRECATION")` 与 Window API 相关
- AC-2: 不再使用 `FLAG_FULLSCREEN`、`systemUiVisibility`、`statusBarColor`
- AC-3: 使用 `WindowCompat.setDecorFitsSystemWindows()` + `WindowInsetsControllerCompat.hide/show()` 实现沉浸
- AC-4: 沉浸模式行为与当前一致（隐藏状态栏，overlay 切换时状态栏跟随显隐）
- AC-5: 真机验证：Android 12+ 和 Android 11 设备上沉浸/唤出行为正常

**涉及文件**:
- `feature/photos/PhotoViewerScreen.kt`（或拆分后的 `ViewerOverlayChrome.kt`）— 修改 `setViewerImmersiveMode()` 函数
- `feature/photos/PhotoViewerScreen.kt`（或拆分后对应文件）— 修改 `ViewerStatusBarEffect` Composable

---

### FR-3: 硬编码颜色统一到 Viewer 深色 token

**描述**: 清理 Viewer 中所有硬编码的 `Color.rgb()` 调用，统一使用 Viewer 深色 token（viewerBackground、viewerSurface、viewerAccent、viewerText、viewerTextSecondary）。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: Viewer 相关文件中无 `Color.rgb()`、`Color(` 等硬编码颜色值（除极少数确实需要动态计算的场景）
- AC-2: 所有颜色引用通过 `YingShiThemeTokens.colors.viewerBackground` 等 token
- AC-3: 视觉效果与当前一致（深色沉浸），仅颜色来源变更
- AC-4: 编译通过，无新增 warning

**涉及文件**:
- `feature/photos/PhotoViewerScreen.kt` 及拆分后的所有 Viewer 文件
- 可能涉及 `ui/theme/` 中的 token 定义（如有缺失 token 需补充）

---

### FR-4: Overlay 材质光影升级

**描述**: 将 Viewer 的 overlay 控制栏从"纯色+简单 alpha"升级为符合 design-plan 的材质光影风格。具体：顶部/底部控制栏加毛玻璃效果，边缘加微光线，时间胶囊增加渐变质感，三横线菜单升级为带阴影浮层。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: 顶部/底部 overlay 有 `drawBehind` 毛玻璃效果（模拟 backdrop-filter blur）
- AC-2: overlay 边缘有 1px 微光线（使用 glassStroke token 或 viewerAccent alpha）
- AC-3: 时间胶囊有微妙渐变背景（非纯色），提升质感
- AC-4: 三横线 DropdownMenu 有阴影层次（多层 shadow）
- AC-5: 所有新增视觉效果使用 Viewer 深色 token，不使用浅色壳层 token
- AC-6: 沉浸模式下 overlay 显隐动画流畅（fadeIn/fadeOut + slide）
- AC-7: 不影响照片本身的显示质量和色彩还原

**涉及文件**:
- `feature/photos/ViewerOverlayChrome.kt`（FR-1 拆分后的文件）— 主要修改
- `ui/theme/` — 可能补充 overlay 专用 token（如 viewerOverlayBlur、viewerOverlayBorder）

---

### FR-5: 视频播放器错误状态 UI 优化

**描述**: 优化视频播放失败/加载超时时的 UI 展示。当前是简单的重试按钮，升级为更优雅的视觉呈现：错误图标+提示文字+重试按钮，使用 Viewer 深色 token，带过渡动画。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: 视频加载失败时显示居中的错误状态 UI（图标+文字+重试按钮）
- AC-2: 错误状态 UI 使用 Viewer 深色 token（viewerSurface 背景、viewerAccent 图标、viewerText 文字）
- AC-3: 重试按钮使用 viewerAccent 色调，有按压态反馈
- AC-4: 从正常播放态→错误态有淡入过渡动画
- AC-5: 重试后从错误态→加载态有过渡动画
- AC-6: 网络恢复后自动重试逻辑不变

**涉及文件**:
- `feature/photos/ViewerVideoPlayer.kt`（FR-1 拆分后的文件）— 修改视频错误状态 Composable

---

### FR-6: 照片流→Viewer Shared Element Transition

**描述**: 从照片流网格点击缩略图进入 Viewer 时，实现 Hero 过渡动画：缩略图平滑放大/移动到全屏位置。关闭 Viewer 时反向动画。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: 从照片流点击进入 Viewer 时，图片有从缩略图位置到全屏位置的过渡动画
- AC-2: 关闭 Viewer 时，图片有从全屏位置回到缩略图位置的反向动画
- AC-3: 过渡期间背景渐暗（overlay fade）
- AC-4: 动画时长 250-350ms，easing 使用 FastOutSlowIn 或类似
- AC-5: 不影响 HorizontalPager 的左右滑动翻页功能
- AC-6: 从其他入口进入 Viewer（小相册详情、回收站等）不强制要求 Hero 动画，但不得崩溃
- AC-7: 编译通过，无新增 crash

**涉及文件**:
- `feature/photos/PhotoViewerScreen.kt` — 入口路由增加 transition 参数
- `feature/photos/PhotoFeedScreen.kt` — 缩略图添加 shared element 标记
- `app/YingShiApp.kt` — 路由层传递 transition 信息
- 可能新增 `feature/photos/ViewerTransition.kt` — 过渡动画辅助

## 三、非功能需求

### NFR-1: 编译性能

拆分后 Android 增量编译时间不应显著增加（目标：增量编译 < 90 秒）。

### NFR-2: 运行时性能

Overlay 毛玻璃效果不得导致帧率下降。目标：overlay 显隐时保持 60fps（或设备原生刷新率）。如在低端设备性能不达标，提供 fallback 方案（降级为半透明纯色）。

### NFR-3: 向后兼容

所有变更不得破坏现有入口（小相册详情→Viewer、回收站→Viewer、聊天→Viewer、生活→Viewer）。这些入口即使不实现 Hero 动画，也必须功能正常。

## 四、范围边界

### 在范围内
- PhotoViewerScreen.kt 拆分重构
- Deprecated Window API 迁移
- 硬编码颜色清理
- Overlay 材质光影升级
- 视频错误状态 UI 优化
- 照片流→Viewer Hero 过渡动画
- 手势/视频/离线缓存等全部现有功能的回归验证

### 不在范围内
- 服务端任何变更（API/DTO/数据库）
- 新增 Viewer 设置项
- 重做上传/评论/回收站协议
- EXIF 元数据扩展（GPS/相机型号等）
- HLS/DASH 自适应视频流
- 视频 seek 缩略图预览
- SystemMediaViewerScreen / ChatMediaViewer / LifeMediaQuickViewer 的拆分重构（仅保证不破坏）

## 五、跨模块依赖

| 依赖模块 | 依赖方向 | 依赖内容 | 影响说明 |
|---------|---------|---------|---------|
| 照片流 | Viewer ← 照片流 | 媒体列表数据(PhotoFeedItem) | FR-1 拆分不改变数据模型，FR-6 需在照片流添加 shared element 标记 |
| 相册/小相册 | Viewer ← 相册 | 小相册/大相册标题查询 | FR-1 拆分后查询逻辑移到 ViewerRelatedAlbumsSheet，接口不变 |
| 评论 | Viewer ← 评论 | 媒体评论 CRUD | FR-1 拆分后评论逻辑保持通过 RealViewerCommentViewModel，接口不变 |
| 设置 | Viewer ← 设置 | hideOverlaysWhenZoomed 等偏好 | FR-1 拆分后设置读取位置变更，功能不变 |
| 回收站 | 回收站 → Viewer | 只读 Viewer 共享手势 | FR-1 拆分后 ViewerZoomState 需保持可被 RealTrashScreens 引用 |
| 聊天 | 聊天 → Viewer | ChatMediaViewer 共享部分组件 | FR-1 拆分不破坏 ChatMediaViewer 的引用 |
| 生活 | 生活 → Viewer | LifeMediaQuickViewerActivity 独立 | FR-1 不影响 Activity 形态的 Viewer |
| YingShiApp.kt | 路由 | PhotoViewerRoute + 状态快照 | FR-1/FR-6 需修改路由层传递 transition 参数 |

## 六、数据模型变更

无。本轮不涉及任何数据库表或 DTO 结构变更。
