## Round 1: 架构基础 — 拆分重构 + API迁移 + 颜色清理

**预估**: 大
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 全面拆分重构 | Android | P0 | 3816行→6-7个文件，每个<800行 |
| FR-2 | Deprecated Window API 迁移 | Android | P0 | 5处@Suppress消除，迁移到现代API |
| FR-3 | 硬编码颜色清理 | Android | P0 | Color.rgb()统一到Viewer token |

**本轮重点**:
- FR-2 和 FR-3 在拆分过程中同步完成（拆分时顺便清理，不需要单独一轮）
- 拆分策略：先通读 PhotoViewerScreen.kt 全文，识别清晰的边界（手势区/overlay区/视频区/sheet区/Back区），按边界切割
- ViewerZoomState 抽取后必须保持公共 API 签名不变，确保 RealTrashScreens.kt 和 PostMediaListScreen.kt 的引用不中断
- 拆分顺序：先抽最独立的（ViewerBackHandler → ViewerRelatedAlbumsSheet → ViewerVideoPlayer → ViewerOverlayChrome → ViewerImageCanvas → ViewerZoomState），最后整理 PhotoViewerScreen.kt 主容器
- 每抽出一个文件立即编译验证，不要等全部抽完再编译

**前置条件**:
- `gradlew.bat assembleDebug` 当前编译通过
- 确认 ViewerZoomState 在 RealTrashScreens.kt 和 PostMediaListScreen.kt 中的引用方式（函数签名/参数类型）

## Round 2: 视觉提升 — Overlay材质 + 视频错误态

**预估**: 中
**依赖**: Round 1（依赖拆分后的文件结构）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-4 | Overlay 材质光影升级 | Android | P1 | 毛玻璃+金属边线+渐变时间胶囊 |
| FR-5 | 视频错误状态 UI 优化 | Android | P1 | 错误图标+提示+重试+过渡动画 |

**本轮重点**:
- FR-4 主要修改 ViewerOverlayChrome.kt（Round 1 拆分产物），在 overlay 的 `drawBehind` 层加入毛玻璃模拟效果
- 毛玻璃实现方案：Compose `GraphicsLayer` + `RenderEffect.createBlurEffect()`（Android 12+），低版本 fallback 为半透明深色+noise纹理
- 时间胶囊渐变：使用 `Brush.linearGradient` 从 viewerSurface 到 viewerSurface+alpha 过渡
- 边缘微光线：overlay 顶部/底部边缘 1px `drawLine`，颜色 viewerAccent.copy(alpha=0.15f)
- FR-5 在 ViewerVideoPlayer.kt 中新增 `ViewerVideoErrorState` Composable
- NFR-2（性能）在本轮验证：低端设备 fallback 方案

**前置条件**:
- Round 1 完成，ViewerOverlayChrome.kt 和 ViewerVideoPlayer.kt 已存在且功能正常
- 确认 Compose `RenderEffect` 在目标 minSdk 上的可用性

## Round 3: 过渡动画 — Hero Transition

**预估**: 中
**依赖**: Round 1（依赖拆分后的文件结构），Round 2（确保视觉层已稳定）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-6 | 照片流→Viewer Hero动画 | Android | P1 | Shared Element Transition |

**本轮重点**:
- 技术方案评估：优先使用 Compose 1.7+ 的 `sharedElement` / `sharedBounds` Modifier（需确认当前 BOM 版本是否支持）
- 如果 Compose shared element API 不可用或与 HorizontalPager 冲突，降级方案：自定义 `AnimatedVisibility` + 缩放/位移动画模拟 Hero 效果
- 需要在 PhotoFeedScreen.kt 的缩略图 Composable 上添加 shared element key
- YingShiApp.kt 路由层需传递 transition 源信息（起始位置/尺寸）
- 仅照片流入口实现 Hero 动画，其他入口（小相册详情/回收站/聊天/生活）保持当前行为
- NFR-3（向后兼容）在本轮重点验证：所有入口的 Viewer 功能不受影响

**前置条件**:
- Round 1 + Round 2 完成
- 确认 Compose BOM 2024.09.00 中 shared element API 的可用性
- 确认 PhotoFeedScreen 缩略图 Composable 的结构（需要知道在哪里添加 shared element key）
