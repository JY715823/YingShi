## 三、发现并修复的 Bug

### BUG-1（复检前已修复）: LongImageHeightWidthRatioThreshold 阈值错误
**问题**: 拆分时 `LongImageHeightWidthRatioThreshold` 从原始 `2.2f` 被错误改为 `3.8f`，导致 2 个单元测试 FAIL
**根因**: 通过 `git log -p -S` 检索历史值，确认原始值为 `2.2f`
**修复**: ViewerImageCanvas.kt 第 60 行改回 `2.2f`
**验证**: 重测 `PhotoViewerBehaviorTest` BUILD SUCCESSFUL

### BUG-2: ViewerOverlayChrome.kt 第 362 行违反 FR-3
**问题**: `text = { Text(text = "删除媒体", color = MaterialTheme.colorScheme.error) }` 使用了 MaterialTheme.colorScheme.error 而非 YingShiThemeTokens
**根因**: 拆分时遗漏的颜色硬编码
**修复**: 改为 `color = YingShiThemeTokens.colors.destructive`
**验证**: grep `MaterialTheme.colorScheme.error` 在 Viewer 文件中 = 0 匹配

### BUG-3: ViewerBackHandlerChain 是死代码
**问题**: 实施计划要求用 ViewerBackHandlerChain 替换 PhotoViewerScreen 中的内联 BackHandler，但实际未执行替换，ViewerBackHandlerChain 从未被调用
**根因**: 现有 7 个内联 BackHandler 比 3 级链更细粒度（覆盖 comment/sheet/timeEditor 子状态），直接替换会丢失语义
**修复**: 采用方案 A — 删除 ViewerBackHandlerChain 死代码（ViewerBackHandler.kt），保留现有 7 个 BackHandler
**偏差说明**: 实施计划此项未执行，但保留现有更细粒度的 BackHandler 实际是更优方案
**验证**: grep `ViewerBackHandlerChain` = 0 匹配

### BUG-4: isViewerVideoImmersiveToggleTap 死代码
**问题**: ViewerBackHandler.kt 中的 isViewerVideoImmersiveToggleTap 函数从未被调用
**修复**: 删除该函数（连同其依赖的 Offset/IntSize import）
**验证**: grep `isViewerVideoImmersiveToggleTap` = 0 匹配

### BUG-5: PhotoViewerScreen.kt 77 个冗余 import
