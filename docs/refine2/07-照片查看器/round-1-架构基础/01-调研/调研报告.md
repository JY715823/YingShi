**ViewerZoomState 公共 API**（即使 private，主容器调用需保持签名）：
- 构造: `ViewerZoomState()` 无参

## 九、技术约束与风险

### 9.1 拆分技术约束

1. **ViewerZoomState 虽 private 但主容器依赖**: 拆分到 ViewerZoomState.kt 后，PhotoViewerScreen.kt 主容器需 import。建议升级为 `internal class`（模块内可见），保持文件级封装。
2. **viewerSingleTapGesture 被主容器调用**（第 997 行）: 拆分到 ViewerImageCanvas.kt 后需保持 `internal`。
3. **applyViewerStatusBarVisibility 被 PhotoViewerScreen 调用**（第 893 行附近）: 拆分到 ViewerBackHandler.kt 后需保持 `internal`。
4. **BackHandler 三级逻辑内联在主容器**（行 903-923）: 需封装为独立 Composable `ViewerBackHandlerChain`。
5. **PhotoViewerCommentSheet（269行）+ ViewerCacheActionSheet（70行）**: 并入 ViewerOverlayChrome.kt 后，该文件预估行数需核算（见下）。

### 9.2 拆分后行数预估

| 目标文件 | 预估行数 | 含 import + 常量 |
|---------|---------|----------------|
| ViewerZoomState.kt | ~200 | 6 常量 + 类 |
| ViewerImageCanvas.kt | ~550 | 手势 + Canvas + 扩展 |
| ViewerOverlayChrome.kt | ~900 | overlay + sheet + comment（**可能超 800**） |
| ViewerRelatedAlbumsSheet.kt | ~350 | sheet + 标题解析 |
| ViewerVideoPlayer.kt | ~600 | 视频 Canvas + 控件 |
| ViewerBackHandler.kt | ~250 | back + immersive |
| PhotoViewerScreen.kt（主） | ~700 | 主容器 + prefetch + 辅助 |

**风险**: ViewerOverlayChrome.kt 可能超 800 行（AC-1 要求 <800）。**决策**: 若 CommentSheet 导致超限，将 PhotoViewerCommentSheet 独立为第 7 个文件 `ViewerCommentSheet.kt`。

### 9.3 FR-2 迁移方案

**统一用**:
- `WindowCompat.setDecorFitsSystemWindows(window, false)` — 已在 MainActivity 全局启用，Viewer 无需重复
- `WindowInsetsControllerCompat.hide(WindowInsetsCompat.Type.statusBars())` — 隐藏状态栏
- `WindowInsetsControllerCompat.show(WindowInsetsCompat.Type.statusBars())` — 显示状态栏
- `systemBarsBehavior = WindowInsetsControllerCompat.BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` — 滑动恢复

**消除**:
- 所有 `FLAG_FULLSCREEN` 调用
- 所有 `systemUiVisibility` 赋值
- 所有 `statusBarColor` 赋值（含 2 处 Color.rgb）
- 5 处 `@Suppress("DEPRECATION")`

### 9.4 FR-3 颜色迁移方案

- 行 552 `Color.rgb(0x18, 0x2A, 0x35)` → 迁移到 `YingShiViewerSurface`（#1D333C，视觉接近）或新增 `viewerStatusBarTint` token

## 十二、调研结论

1. **拆分边界清晰**: 59 个顶级声明可明确归入 7 个目标文件，行号映射已精确到每个声明。
2. **外部契约安全**: PhotoViewerScreen 6 参数签名 + PhotoViewerRoute 字段必须保持；ViewerZoomState 无外部引用（private），拆分自由度高。
3. **FR-2 迁移方案明确**: 统一到 WindowInsetsControllerCompat，消除 5 处 @Suppress + 7 处 FLAG_FULLSCREEN + 8 处 systemUiVisibility + 4 处 statusBarColor。
4. **FR-3 颜色清理点少**: 仅 2 处 Color.rgb + 可能的 3 个 Night* 别名，清理量小。
5. **测试覆盖低**: 仅 shouldUseLongImageReading 有测试，拆分需依赖编译+功能回归验证。
6. **行数风险**: ViewerOverlayChrome.kt 可能超 800 行，需备好 ViewerCommentSheet.kt 独立方案。
7. **复用方零影响**: 5 个复用 Viewer 完全解耦。
