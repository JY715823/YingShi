## 二、用户流程

### 流程1: 照片模块进入与分页切换

用户从底部导航进入照片模块 → 壳层 selectedDestination=PHOTOS → 渲染 PhotosRootScreen → 内部 HorizontalPager 根据 photosTopDestinationName 恢复上次页签 → 用户点击顶栏 tab 或左右滑动 → pagerState.currentPage 变化 → LaunchedEffect 回调壳层同步 selectedTopDestinationName → HorizontalPager 渲染对应子页（RealPhotoFeedPage / AlbumPageScreen / TrashPageScreen）。

涉及: PhotosRootScreen.kt (L109, L615-L702, L286-L291), YingShiApp.kt (L1553), AppNavigation.kt (RootDestination, PhotosTopDestination)

### 流程2: 照片多选操作

用户在照片分页长按照片进入选择模式 → photoSelectionState 更新 → 顶栏切换为选择态 UI（"取消"+"已选 N 项"）→ photoSelectionShellState 通过 onPhotoSelectionShellStateChange 上抛到壳层 → 壳层检测 showPhotoSelectionBottomBar=true → bottomBarOverride 注入 PhotoSelectionBottomBar 替换默认底栏 → 用户点击底栏按钮 → dispatchPhotoSelectionAction → PhotosRootScreen 内 LaunchedEffect 监听并分发到对应操作（分享/新建/加入/删除）→ 操作完成后清除选择状态。

涉及: PhotosRootScreen.kt (L315-L333, L447-L451), YingShiApp.kt (L1181-L1235), RealPhotoFeedPage.kt (L78-L87), PhotoFeedInteractionModels.kt (PhotoFeedSelectionState)

### 流程3: 回收站多选操作

用户在回收站进入多选 → 状态由壳层管理（trashSelectionModeState, trashSelectedEntryIdsState）→ 通过参数传入 TrashPageScreen → 返回键 BackHandler 退出选择 → 回收站的选择态**不触发**底栏接管（条件限定 photosTopDestinationName==PHOTOS.name）。

涉及: YingShiApp.kt (L158-L163), PhotosRootScreen.kt (L452-L458, L682-L698)

### 流程4: 新建大相册

用户在相册页点击"新建大相册" → 回调 onCreateLargeAlbum → PhotosRootScreen 中 showCreateAlbumDialog=true → AlertDialog 输入标题/说明 → 调用 RepositoryProvider.albumRepository.createAlbum → 成功: 设置 AlbumPageStateStore.pendingSelectedAlbumId + REAL 模式触发 notifyRealBackendAlbumsChanged → 失败: 显示错误信息。

涉及: PhotosRootScreen.kt (L340-L445), AlbumPageScreen.kt (L663-L666), AlbumPageStateStore.kt

### 流程5: 传输状态查看

PhotosRootScreen 读取 LocalSystemMediaBridgeRepository.uploadTasks → 计算 hasTransferFailure 和 runningTransferCount → 传输中心按钮显示 badge（失败"!"红色，进行中数量，>99 "99+"）→ 点击进入传输中心 → 壳层设置 transferCenterRoute。

涉及: PhotosRootScreen.kt (L139-L143, L1326-L1440), TransferCenterScreen.kt (L624)

## 三、数据流向

### 3.1 状态管理架构

PhotosRootScreen 本身**不持有 ViewModel**，是纯状态协调壳层。REAL 模式下子页各自持有 ViewModel：

- RealPhotoFeedPage → RealPhotoFeedViewModel → RealPhotoFeedUiState
- AlbumPageScreen → AlbumPageRealViewModel → AlbumPageRealUiState
- TrashPageScreen → RealTrashViewModel

选择状态通过 onSelectionShellStateChange 回调从子页 ViewModel 层上抛到 PhotosRootScreen，再上抛到壳层 YingShiApp。

### 3.2 壳层协议

**下行参数（YingShiApp → PhotosRootScreen）：** selectedTopDestinationName、trashSelectedTypeName、trashSelectionMode、photoFeedScrollTrigger、photoSelectionClearTrigger、photoSelectionAction + photoSelectionActionNonce、inlineVideoAutoPlayEnabled 等。

**上行回调（PhotosRootScreen → YingingShiApp）：** onPhotoSelectionShellStateChange、onOpenViewer、onOpenPostDetail、onOpenSystemMedia、onOpenTransferCenter 等。

**关键协议类型：** PhotosRootSelectionUiState（选择态上行）、PhotoSelectionShellAction（壳层下行操作指令）。

### 3.3 与传输中心交互

LocalSystemMediaBridgeRepository.uploadTasks（object 单例）提供上传任务列表 → PhotosRootScreen 和 TransferCenterScreen 都读取同一数据源。

### 3.4 前后端 API 交互

照片根目录依赖的后端 API 全部来自已有接口：MediaController（照片流）、AlbumController（相册 CRUD）、PostController（小相册）、TrashController（回收站）、UploadController（传输）、SyncController（同步版本号）。前端 13 个 Retrofit API 接口与服务端 15 个 Controller 一一对应，无漂移。

### 3.5 与其他模块的数据交互

- **AppShell（壳层）**：16+ 个参数传递，双向耦合
- **photo_feed（照片流）**：选择态、分页、底栏接管
- **albums（相册）**：新建大相册入口、相册分页切换
- **trash（回收站）**：回收站多选状态穿透
- **transfer_center（传输中心）**：uploadTasks 单例共享
- **RealBackendMutationBus**：全局 object 单例，跨模块变更通知
