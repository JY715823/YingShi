## 二、发现并修复的 Bug

### BUG-1: 未使用的 import（P1）

**问题**: PhotosRootScreen.kt 中有 4 个未使用的 import：
- `androidx.compose.animation.ExperimentalAnimationApi`
- `androidx.compose.ui.graphics.StrokeCap`
- `androidx.compose.ui.graphics.drawscope.Stroke`
- `com.example.yingshi.data.model.UploadState`

**根因**: Round 1 删除了一些使用这些 import 的代码后，import 未同步清理。

**修复**: 删除 4 个未使用的 import。

**验证**: `gradlew.bat assembleDebug` → BUILD SUCCESSFUL。

---

### BUG-2: Data class 死字段（P1）

**问题**: PhotoFeedInteractionModels.kt 中 3 个 data class 包含从未被引用的字段：
- `PhotosRootDialogState`: `showConfirmation`, `showDestroyConfirm`, `bulkDialogMessage`（3 个）
- `PhotosRootTrashParams`: 16 个字段（除 `selectedTypeName` 外全部未使用）
- `PhotosRootSelectionParams`: 5 个字段（`onOpenViewer`, `onOpenPostDetail`, `onShareSelection`, `onDownloadSelection`, `addToPostTrigger`）

**根因**: FR-7 实施时参照原始函数签名复制了所有参数，但实际函数体内仅使用部分字段（其余通过局部状态或未实现）。

**修复**: 删除所有未使用的字段：
- `PhotosRootDialogState`: 保留 4 个字段（showDeleteConfirm, showAddToPostDialog, showCreateAlbumDialog, addToPostDialogMessage）
- `PhotosRootTrashParams`: 保留 1 个字段（selectedTypeName）
- `PhotosRootSelectionParams`: 保留 3 个字段（onAddedMediaToPost, photoFeedScrollTrigger, photoSelectionClearTrigger）

**验证**: `gradlew.bat assembleDebug` → BUILD SUCCESSFUL。
