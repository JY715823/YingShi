## FR-4: FAKE/REAL 双路径清理

**描述**: 当前 PhotosRootScreen 无条件调用 `FakeAlbumRepository.getAlbums()/getPosts()/getPhotoFeed()`，REAL 模式下这些 FAKE 数据仍被加载并传给子组件。需要改为条件化加载。

**涉及文件**: `app/src/main/java/com/example/yingshi/feature/photos/PhotosRootScreen.kt`

**具体改动**:

1. 在函数体开头（`val context = LocalContext.current` 之后）添加：
   ```kotlin
   val isFakeMode = RepositoryProvider.currentMode == RepositoryMode.FAKE
   ```

2. 将三处 FAKE 数据加载改为条件化：
   ```kotlin
   // 改前
   val albumSummaries = FakeAlbumRepository.getAlbums()
   val albumPosts = FakeAlbumRepository.getPosts()
   val feedItems = FakePhotoFeedRepository.getPhotoFeed()
   
   // 改后
   val albumSummaries = remember(isFakeMode) {
       if (isFakeMode) FakeAlbumRepository.getAlbums() else emptyList()
   }
   val albumPosts = remember(isFakeMode) {
       if (isFakeMode) FakeAlbumRepository.getPosts() else emptyList()
   }
   val feedItems = remember(isFakeMode) {
       if (isFakeMode) FakePhotoFeedRepository.getPhotoFeed() else emptyList()
   }
   ```

3. 删除确认弹窗中的删除逻辑（搜索 `FakeAlbumRepository.previewGlobalMediaDelete` 所在位置），用 `if (isFakeMode) { ... }` 包裹整个 FAKE 删除代码块。REAL 模式下跳过（REAL 模式由 RealPhotoFeedPage 内部处理删除）。

4. 加帖对话框中的 FAKE 加帖逻辑（搜索 `FakeAlbumRepository.appendPhotoFeedItemsToPost`），同样用 `if (isFakeMode) { ... }` 包裹。

**验收标准**:
- AC-1: REAL 模式下不调用 FakeAlbumRepository/FakePhotoFeedRepository 的数据加载方法
- AC-2: REAL 模式下删除确认弹窗不执行 FAKE 删除逻辑
- AC-3: FAKE 模式下所有行为不变
- AC-4: `gradlew.bat assembleDebug` 编译通过
