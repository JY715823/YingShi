## FR-13: 上传历史列表真分页

### 变更 1: UploadTaskRepository.java — 新增 findVisibleHistoryPage

| 维度 | 内容 |
|------|------|
| 变更类型 | 新增方法 |
| 直接影响 | 无（新增方法，不修改现有 `findVisibleHistory` 方法） |
| 间接影响 | `UploadService.listUploadHistory` 将调用此新方法 |
| 影响说明 | 纯新增。现有 `findVisibleHistory` 方法保持不变，`dismissUploadBatch` 等其他调用方不受影响 |

### 变更 2: UploadService.java — 重构 listUploadHistory

| 维度 | 内容 |
|------|------|
| 变更类型 | 方法签名变更 + 内部逻辑重构 |
| 直接影响 | `listUploadHistory(AuthenticatedUser, String, String, Integer)` → `listUploadHistory(AuthenticatedUser, String, String, Integer, String)` |
| 间接影响 | 调用方：`UploadController.listUploads` — 需同步更新 |
| 影响说明 | 返回类型从 `List<UploadTaskResponse>` 改为 `UploadHistoryResult`（含 items + nextCursor + hasMore） |
| 风险 | 返回类型变更意味着 Controller 调用方必须同步修改 |

**影响路径清单**:
- IA-4: `listUploadHistory` 分页正确性 — 验证 pageSize 控制返回条数，hasMore 判断正确
- IA-5: `nextCursor` 生成正确性 — 验证生成的 cursor 可被后续请求正确使用
- IA-6: 不传 cursor 时的向后兼容 — 验证默认行为与之前一致（返回最新 pageSize 条）

### 变更 3: UploadController.java — 更新 listUploads 端点

| 维度 | 内容 |
|------|------|
| 变更类型 | 方法签名变更（新增参数）+ 内部逻辑变更 |
| 直接影响 | `listUploads` 方法 |
| 间接影响 | Android 端 `UploadApi.getUploadHistory` — 需确认兼容性 |
| 影响说明 | API 端点新增可选 cursor 参数，不传时行为与之前完全一致。API 响应格式不变（`ApiResponse` 的 `data` 仍是 `List`，`pageInfo` 字段新增真实值） |
| Android 兼容性 | Android `UploadApi.getUploadHistory` 返回 `ApiEnvelopeDto<List<UploadTaskDto>>`，不解析 `pageInfo` 字段，完全兼容 |

**影响路径清单**:
- IA-7: API 端点向后兼容 — 不传 cursor 时返回与之前相同格式的响应
- IA-8: API 端点新增 cursor 参数 — 传入 cursor 时返回正确的下一页数据
- IA-9: Android 端调用兼容 — 不传 cursor 参数，行为不变

### 变更 4: Android UploadApi.kt — 无需修改

| 维度 | 内容 |
|------|------|
| 变更类型 | 无变更 |
| 影响说明 | 后端新增的 cursor 参数为可选，Android 端不传 cursor 时行为与之前完全一致 |
| 验证 | `gradlew.bat assembleDebug` 编译通过即可确认无破坏性影响 |
