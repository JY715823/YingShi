## 关键改动说明

### FR-12: resolveFirstVisibleMediaId
- **改动前**: N+1 次 SQL（1 次 relations + N 次逐条 media 查询）
- **改动后**: 2 次 SQL（1 次 relations + 1 次批量 media 查询 `findByLibraryIdAndIdInAndDeletedAtIsNull`）
- **边界处理**: `excludedMediaId` 过滤逻辑保持不变；空列表时直接返回 `Optional.empty()`

### FR-12: purgeMediaRemovedItemsForSmallAlbum
- **改动前**: 全量加载所有 MEDIA_REMOVED 项后在 Java 层 `stream().filter()` 按 sourcePostId 过滤
- **改动后**: 1 次精确 SQL 查询 `findByLibraryIdAndStateAndItemTypeAndSourcePostId`，将过滤下推到数据库层
- **边界处理**: 查询结果为空时跳过 `deleteAll`

### FR-13: listUploadHistory
- **改动前**: `findVisibleHistory` 全量查询后 `.limit(pageSize)` Java 层截断，返回 `List<UploadTaskResponse>`
- **改动后**: `findVisibleHistoryPage` 使用 `PageRequest.of(0, pageSize+1)` 分页，返回 `UploadHistoryResult(items, nextCursor, hasMore)`
- **hasMore 判断**: 查询 `pageSize+1` 条，若返回 > pageSize 条则 hasMore=true
- **nextCursor 格式**: `updatedAt_epochMillis:id`

### FR-13: UploadController
- **改动前**: `new PageInfo(1, items.size(), null, false)` 硬编码伪分页
- **改动后**: `new PageInfo(1, result.items().size(), result.nextCursor(), result.hasMore())` 真实分页
- **向后兼容**: 新增 cursor 参数为可选，不传时行为与之前一致
