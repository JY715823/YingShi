## 四、模块精修总结

### 整体成果

**前端（Android）**：
- 标题光晕从 slot 几何中心修正到文字实际位置（centerY 0.42→0.78），解决了"文字不在颜色中间"的核心问题
- 12 处光晕硬编码颜色 + 13 处 error 色全部提取为 YingShiColors token
- 标题切换新增 4s 呼吸动画 + fade-in/out 过渡 + motionEnabled 降级
- FAKE/REAL 数据源混杂问题彻底清理，REAL 模式不再加载 FAKE 数据
- 11 个散落状态变量通过 ViewModel 整合为 8 个 StateFlow + 2 个本地状态
- 函数签名简化为 9 个参数（trashParams + selectionParams 分组）
- 工具按钮统一为 scale+alpha 组合按压反馈 + motionEnabled 降级
- 多选态顶栏改为 ghost 取消按钮 + 玻璃胶囊 badge
- 底栏按钮加入图标（Upload/Add/Folder/Delete）+ Column 布局
- 玻璃容器支持 variant 参数动态适配 Aurora 背景
- 对话框统一为 24dp 圆角 + raisedSurface 玻璃感表面
- PhotoBellButton 死代码（~70行）清理

**后端（Server）**：
- TrashService.resolveFirstVisibleMediaId() N+1 查询改为批量查询（2 次 SQL 替代 N+1 次）
- TrashService.purgeMediaRemovedItemsForSmallAlbum() 全量扫描改为 Repository 层 sourcePostId 过滤
- UploadController.listUploads() 伪分页改为 cursor 真分页

### 关键改进
1. **视觉精准度**：光晕跟随文字而非 slot 几何中心，这是最核心的视觉修复
2. **架构整洁度**：ViewModel 引入将状态管理从 Composable 函数体迁移到独立类
3. **数据源正确性**：FAKE/REAL 双路径清理消除了 REAL 模式下误用 FAKE 数据的隐患
4. **性能**：服务端 N+1 查询和全量扫描修复，数据量增长后不会成为瓶颈

### 关键教训
- **大文件操作前必须 git commit**：Trae 轮次改动未 commit 导致永久丢失，恢复成本极高
- **文件拆分需用正则匹配 `@Composable` 注解**：行号截取会遗漏注解行
- **brace-depth 追踪会被默认参数 `{}` 干扰**：应从函数体首 `{` 开始计数
