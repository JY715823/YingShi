## Round 1: 标题视觉精准化

**预估**: 中
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 标题光晕居中对齐修复 | Android | P0 | Canvas 与文字统一坐标参考系，光晕居中，offset 对称化 |
| FR-2 | 硬编码颜色 token 化 | Android | P0 | 12 处光晕颜色 + 13 处 error 色 + 玻璃容器色提取为 token |
| FR-3 | 标题切换动效增强 | Android | P1 | 光晕呼吸动画 + fade-in/out 过渡 |

**本轮重点**:
- FR-1 和 FR-2 高度耦合（都在 PhotoBrandTabs 和 PhotoSelectedTitleAura 中改动），必须同文件同轮完成
- FR-2 需要先在 Tokens.kt 中新增 token 定义，再替换 PhotosRootScreen.kt 中的引用
- FR-3 依赖 FR-1 的居中修复完成后再加动画，否则动画的基准位置不对
- 实施顺序：FR-2（先定义 token）→ FR-1（修复居中，使用新 token）→ FR-3（加动画）

**前置条件**:
- 确认 YingShiColors 中新增 token 的命名和色值
- 确认 AuroraBackdrop 的 sparkleBreath 动画周期参数（用于同步呼吸节奏）

**实施顺序**:
1. Tokens.kt — 新增 titleAuraWarmGlow / titleAuraCoolGlow / titleAuraBottomTrail / titleAuraMainHighlight / destructiveContainer / destructive / onDestructiveContainer / glassSurfaceBase 等 token
2. PhotosRootScreen.kt — PhotoSelectedTitleAura：光晕坐标居中修复 + 使用新 token
3. PhotosRootScreen.kt — PhotoBrandTabs：文字 offset 对称化 + 使用新 token + 替换 MaterialTheme.colorScheme.error*
4. PhotosRootScreen.kt — PhotoTopGlassSurface：使用新 glassSurfaceBase token
5. PhotosRootScreen.kt — PhotoSelectionBottomBarAction / PhotoCircleToolButton / SelectionActionChip：替换 error 色为 destructive token
6. PhotosRootScreen.kt — PhotoBrandTabs / PhotoSelectedTitleAura：新增呼吸动画和 fade-in/out 过渡

## Round 2: 架构清理与数据源修正

**预估**: 大
**依赖**: Round 1（token 定义已就位，Round 2 的视觉改动可复用）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-4 | FAKE/REAL 双路径清理 | Android | P0 | REAL 模式下不加载 FAKE 数据，删除/加帖走 REAL 路径 |
| FR-5 | 死代码清理 | Both | P1 | 删除 PhotoBellButton + TrashService 冗余方法 |
| FR-6 | 状态管理重构 | Android | P1 | 提取 PhotosRootDialogState，减少本地状态变量 |
| FR-7 | 壳层参数简化 | Android | P1 | 打包 trash/selection 参数为 data class |

**本轮重点**:
- FR-6 和 FR-7 都是重构，应在同一轮完成以避免两次改动 PhotosRootScreen 函数签名
- 实施顺序：先 FR-5（最简单，纯删除）→ FR-6（状态提取）→ FR-7（参数打包）→ FR-4（最复杂，需确认 REAL 路径）
- FR-4 需要先深入确认 RealPhotoFeedPage 的删除回调接口和 REAL 相册数据来源，避免改错
- FR-5 服务端改动需搜索所有 `systemDeleteMediaAllowingEmptySmallAlbums` 调用方

**前置条件**:
- 确认 RealPhotoFeedPage 中删除操作的回调接口（是否已有 onRealDelete 回调或需要通过 ViewModel 触发）
- 确认 REAL 模式下 AlbumPageScreen 内部是否独立从 API 取 albums/posts 数据
- 搜索服务端 `systemDeleteMediaAllowingEmptySmallAlbums` 的所有调用方

**实施顺序**:
1. 服务端：搜索并替换 systemDeleteMediaAllowingEmptySmallAlbums 调用方 → 删除冗余方法 → mvnw.cmd compile
2. Android：删除 PhotoBellButton → gradlew.bat assembleDebug
3. PhotoFeedInteractionModels.kt — 新增 PhotosRootDialogState data class
4. PhotosRootScreen.kt — 状态管理重构（FR-6）：将对话框状态迁移到 DialogState
5. PhotoFeedInteractionModels.kt — 新增 PhotosRootTrashParams / PhotosRootSelectionParams data class
6. PhotosRootScreen.kt — 参数列表重构（FR-7）
7. YingShiApp.kt — 同步更新 PhotosRootScreen 调用方
8. PhotosRootScreen.kt — FAKE/REAL 条件化数据加载（FR-4）
9. gradlew.bat assembleDebug 验证

## Round 4: 服务端性能修复

**预估**: 小
**依赖**: 无前端依赖，可独立实施
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |

| FR-12 | 服务端 N+1 查询修复 | Server | P1 | resolveFirstVisibleMediaId 批量查询 + purgeMediaRemoved 下推过滤 |
| FR-13 | 上传历史列表真分页 | Server | P2 | UploadController cursor 分页 + Android 端同步 |

**本轮重点**:
- FR-12 是纯后端优化，不改变 API 契约，风险低

- FR-12 不需要 Flyway 迁移（只改查询方式）
- FR-13 不需要 Flyway 迁移（只改查询方式）
- 本轮完成后运行 Testcontainers 测试验证

**前置条件**:
- 确认 MediaRepository 是否已有批量查询方法（如 findAllByIdIn）
- 确认 Android 端 UploadApi 对 PageInfo 的使用方式

**实施顺序**:
1. TrashItemRepository.java — 新增 findByLibraryIdAndStateAndItemTypeAndSourcePostId 方法
2. MediaRepository.java — 新增批量查询方法（如不存在）
3. TrashService.java — 重构 resolveFirstVisibleMediaId（批量查询）
4. TrashService.java — 重构 purgeMediaRemovedItemsForSmallAlbum（Repository 层过滤）
5. mvnw.cmd compile + 测试验证
6. UploadTaskRepository.java — 新增 cursor 分页查询方法
7. UploadService.java — 重构 listUploadHistory 支持 cursor 分页
8. UploadController.java — 更新 listUploads 端点
9. Android UploadApi.kt — 同步更新（如需要）
10. mvnw.cmd compile + gradlew.bat assembleDebug 验证
