# Round 1 依赖映射

> 基于实施计划: Round 1 — P0 稳定性修复

---

## 本模块依赖的外部模块/服务

| 依赖模块 | 本轮是否改动接口 | 说明 |
|---------|----------------|------|
| 推送偏好端点 | 否（仅扩展默认值） | GET/POST /api/push/preferences 接口不变，返回项从 6 到 8 |
| 设置模块 | 否 | 已有 8 个开关，仅修复 Server 端识别 |
| 首页模块 | 否 | 铃铛读取 NotificationCenterMemoryCache |
| AppReadCacheStore | 否 | 仅增加调用频率（已有 API） |
| NotificationCenterLocalStore | 否 | 仅增加调用方持久化，Store 自身不变 |
| FCM / 推送系统 | 否 | 不涉及推送发送逻辑 |

## 依赖本模块的外部调用方

| 调用方 | 本轮是否影响该接口 | 说明 |
|--------|------------------|------|
| SettingsScreen → push_preferences | 正向影响 | 8 个开关全部可用 |
| HomeScreen → 铃铛未读计数 | 正向影响 | 持久化后计数一致 |
| YingShiApp → 通知中心路由 | 无影响 | 路由不变 |
| SyncVersionTracker → stale 标记 | 无影响 | 不涉及 version 逻辑 |

## 前后端共享组件依赖

| 组件 | 是否受影响 | 说明 |

## 数据流图

### FR-1 数据流
```
Android SettingsScreen
  → POST /api/push/preferences { module: "photos", category: "system", enabled: true }
  → PushPreferenceController.updatePreference()
  → PushNotificationService.updatePreference()
  → defaultPreferences() 查找 [新增 photos:system]
  → 找到 → 更新 PushPreferenceEntity → 200 OK
  → Android 乐观更新成功
```

### FR-8 数据流
```
用户点击通知文案（未读）
  → onClick
  → 本地路径: NotificationCenterLocalStore.markRead() + persistNotificationUiState()
  → AppReadCacheStore.writeNotifications()
  → 离线缓存持久化

用户点击通知文案（未读，非本地）
  → onClick
  → API 路径: RepositoryProvider.notificationRepository.markRead()
  → 成功: persistNotificationUiState() + writeNotification()
  → 失败: 不改变 isRead + 显示错误

用户点击媒体缩略图
  → onMediaClick
  → markRead + persist + navigate（保持现有行为）

用户点击全部已读
  → onMarkAllRead
  → API 路径: markAllRead()
  → 成功: NotificationCenterLocalStore.markAllRead() + persistNotificationUiState()
  → 失败: 显示错误，不改变状态
```
