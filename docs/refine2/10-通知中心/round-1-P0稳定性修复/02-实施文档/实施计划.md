## FR-8: 已读/未读状态稳定性修复 + 点击行为改进

**目标**: 
1. 点击文案区域仅标记已读不跳转
2. 所有标记已读路径持久化到 AppReadCacheStore
3. API 失败时回滚 isRead 为 false
4. markAllRead 后持久化到 AppReadCacheStore

### 变更文件清单

| # | 文件路径 | 端 | 变更类型 | 变更内容 |
|---|---------|-----|---------|---------|
| 1 | `app/src/main/java/com/example/yingshi/feature/photos/NotificationCenterScreen.kt` | Android | 修改 | onClick 不跳转、本地路径持久化、API 错误回滚、markAllRead 持久化 |
| 2 | `app/src/main/java/com/example/yingshi/feature/photos/FakeNotificationRepository.kt` | Android | 修改 | NotificationCenterLocalStore.markRead/markAllRead 增加持久化 |

### FR-8 变更1: onClick 不跳转 + 本地路径持久化 + API 错误回滚

**位置**: `NotificationCenterScreen.kt` L593-L636

**修改方案**:

**onClick 回调** (L593-L636) 重构为：

```kotlin
onClick = {
    coroutineScope.launch {
        if (uiState.isOfflineReadOnly) {
            onOpenNotificationTarget(item)
            return@launch
        }
        if (item.isRead) {
            // 已读通知点击 → 跳转（保持现有一致性，已读不改变状态）
            onOpenNotificationTarget(item)
            return@launch
        }
        // 未读通知 → 仅标记已读，不跳转
        if (NotificationCenterLocalStore.contains(item.id)) {
            // 本地路径：标记已读 + 持久化
            NotificationCenterLocalStore.markRead(item.id)
            val updatedItem = item.copy(isRead = true)
            val updatedState = uiState.replaceNotification(updatedItem)
            updateUiState(updatedState)
            persistNotificationUiState(currentUserId, updatedState.notifications)
            return@launch
        }
        // API 路径
        when (val result = RepositoryProvider.notificationRepository.markRead(item.id)) {
            is ApiResult.Success -> {
                val updatedItem = result.data.toNotificationCenterItemUiModel()
                val updatedState = uiState.replaceNotification(updatedItem)
                updateUiState(updatedState)
                if (currentUserId != null) {
                    withContext(Dispatchers.IO) {
                        AppReadCacheStore.writeNotification(
                            userId = currentUserId,
                            notification = result.data,
                        )
                    }
                }
                persistNotificationUiState(currentUserId, updatedState.notifications)
            }
            is ApiResult.Error -> {
                // 失败：回滚 isRead 为 false，显示错误
                updateUiState(
                    uiState.copy(
                        errorMessage = result.toBackendUiMessage("标记通知已读失败。"),
                    ),
                )
                // 不改变 isRead 状态
            }
            ApiResult.Loading -> {
                // Loading 状态：不改变 isRead，保持原状态
            }
        }
    }
},
```

**关键变更**:
1. 已读通知点击 → 跳转（保持现有行为，已读不改变状态）
2. 未读通知点击 → 仅标记已读，不移除 `onOpenNotificationTarget` 调用
3. 本地路径（L601-604）增加 `persistNotificationUiState()` 调用
4. API 错误分支（L623-631）不再设置 `isRead = true`，改为不回滚
5. API Loading 分支（L632）不再设置 `isRead = true`

### FR-8 变更2: markAllRead 持久化增强

**位置**: `NotificationCenterScreen.kt` L468-L504

**修改方案**: 在 `markAllRead` 成功分支中，增加 `AppReadCacheStore.writeNotifications()` 调用（当前已有 `persistNotificationUiState` 调用，但需要确认它覆盖了所有通知的 isRead 状态）。

当前代码 L472-L480：
```kotlin
is ApiResult.Success -> {
    NotificationCenterLocalStore.markAllRead()
    val updatedState = uiState.copy(
        isMutating = false,
        notifications = uiState.notifications.map { item ->
            if (item.isRead) item else item.copy(isRead = true)
        },
    )
    updateUiState(updatedState)
    persistNotificationUiState(currentUserId, updatedState.notifications)
    // ...
}
```

`persistNotificationUiState` 已存在（L480），会写入完整的通知列表（含更新后的 isRead 状态）。此路径已有持久化，但需确认 `persistNotificationUiState` 被正确调用。

**实际检查**: L480 已有 `persistNotificationUiState(currentUserId, updatedState.notifications)` 调用，无需额外修改。

### FR-8 变更3: NotificationCenterLocalStore 持久化

**位置**: `FakeNotificationRepository.kt` L117-L131

**修改方案**: `markRead` 和 `markAllRead` 方法增加写 AppReadCacheStore 的调用。但由于 `NotificationCenterLocalStore` 是 object 且不持有 userId 上下文，持久化逻辑放在调用方（NotificationCenterScreen.kt）中已足够。

当前 `markRead` 和 `markAllRead` 只操作内存 `mutableStateListOf`。因为在 FR-8 变更1 中已在调用方（onClick 和 markAllRead）增加了 `persistNotificationUiState()` 调用，所以 `NotificationCenterLocalStore` 本身不需要修改。

**结论**: `NotificationCenterLocalStore` 无需修改。持久化已在调用方完成。
