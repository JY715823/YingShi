## 三、功能测试 — FR-8: 已读/未读状态稳定性修复 + 点击行为改进

### TC-201: 点击未读通知文案 → 标记已读不跳转
- 对应: FR-8/AC-1
- 端: Android
- 前置条件: 通知列表有未读通知
- 步骤: 点击通知卡片文案区域（非缩略图）
- 预期结果: 通知标记为已读（灰色/已读样式），不跳转到目标页
- 通过标准: isRead 变为 true，不触发 onOpenNotificationTarget

### TC-202: 点击已读通知文案 → 跳转
- 对应: FR-8/AC-1（边界）
- 端: Android
- 前置条件: 通知列表有已读通知
- 步骤: 点击已读通知卡片文案区域
- 预期结果: 跳转到目标页
- 通过标准: 触发 onOpenNotificationTarget

### TC-203: 点击媒体缩略图 → 标记已读 + 跳转
- 对应: FR-8/AC-2
- 端: Android
- 前置条件: 通知列表有含媒体缩略图的未读通知
- 步骤: 点击通知卡片上的媒体缩略图
- 预期结果: 通知标记为已读 + 跳转到目标页（保持现有行为）
- 通过标准: isRead 变为 true，触发 onOpenNotificationTarget

### TC-204: 本地路径持久化到 AppReadCacheStore
- 对应: FR-8/AC-3
- 端: Android
- 前置条件: 通知已在 NotificationCenterLocalStore 中
- 步骤: 点击未读通知文案 → 检查代码调用链
- 预期结果: onClick 中 `persistNotificationUiState()` 被调用
- 通过标准: 代码审查确认 L609 有 `persistNotificationUiState` 调用

### TC-205: API 失败时 isRead 回滚为 false
- 对应: FR-8/AC-4
- 端: Android
- 前置条件: Server 不可达或返回错误
- 步骤: 模拟 API 失败 → 点击未读通知文案
- 预期结果: isRead 保持 false，显示错误提示
- 通过标准: 代码审查确认 L627-L633 不设置 `item.copy(isRead = true)`

### TC-206: 进程重启后已读状态保持
- 对应: FR-8/AC-5
- 端: Android
- 前置条件: 通过 API 标记某条通知已读
- 步骤: 杀死进程 → 重启 App → 进入通知中心
- 预期结果: 已标记已读的通知仍显示为已读
- 通过标准: 从 AppReadCacheStore 恢复的 isRead 为 true

### TC-207: 首页铃铛未读计数一致
- 对应: FR-8/AC-6
- 端: Android
- 前置条件: 通知中心有未读通知
- 步骤: 1) 查看首页铃铛未读计数 2) 进入通知中心查看未读计数
- 预期结果: 两者一致
- 通过标准: 铃铛计数 = 通知中心 filteredNotifications 中未读数
