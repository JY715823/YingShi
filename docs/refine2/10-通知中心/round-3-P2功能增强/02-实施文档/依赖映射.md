## 一、本模块依赖的外部模块/服务

| 依赖 | 类型 | 本轮是否改动接口 | 说明 |
|------|------|----------------|------|
| `AppReadCacheStore` | Android 缓存 | 否 | 仅调用 `writeNotifications()` / `readNotifications()`，接口不变 |
| `NotificationCenterLocalStore` | Android 本地存储 | 否 | 仅调用 `getNotifications()`，接口不变 |
| `RepositoryProvider` | Android DI | 否 | 通过 `RepositoryProvider.notificationRepository` 获取实例 |
| `OfflineAccessManager` | Android 离线管理 | 否 | 仅读取 `state.isReadOnly`，接口不变 |
| `AuthSessionManager` | Android 认证 | 否 | 仅读取 `getCurrentUserSnapshot()`，接口不变 |
| `SyncVersionTracker` / `SyncModule` | Android 同步 | 否 | 仅读取 `staleState`，接口不变 |
| `commentRepository` | Server JPA | 否 | `collectNotificationEvents()` 内部调用，不修改 |
| `postRepository` | Server JPA | 否 | 同上 |
| `trashItemRepository` | Server JPA | 否 | 同上 |
| `uploadTaskRepository` | Server JPA | 否 | 同上 |
| `bowelEventRepository` | Server JPA | 否 | 同上 |
| `ledgerSnapshotRepository` | Server JPA | 否 | 同上 |
| `notificationReadRepository` | Server JPA | 否 | 同上 |
| `albumRepository` | Server JPA | 否 | 同上 |

## 二、依赖本模块的外部调用方

| 调用方 | 调用方式 | 本轮是否影响接口 | 说明 |
|--------|---------|----------------|------|
| `NotificationCenterScreen` | 直接使用 ViewModel | 是 | ViewModel 新增 `loadMore()` 方法，`uiState` 新增 `isLoadingMore`/`hasMore` 字段 |
| `FakeNotificationRepository` | 实现 `NotificationRepository` 接口 | 是 | 接口签名新增 `cursor` 参数，需更新实现类 |
| Server API 消费者（旧版 Android） | HTTP GET `/api/notifications` | 否（向后兼容） | cursor 为可选参数，不传时行为不变 |

## 三、前后端共享组件依赖

| 组件 | 受影响 | 说明 |
|------|--------|------|
| `NotificationDto` (Server DTO) | 否 | 不改动 DTO 结构 |
| `RemoteNotification` (Android Model) | 否 | 不改动数据模型 |
| `NotificationCenterItemUiModel` (Android Model) | 否 | 不改动数据模型 |
| `NotificationCenterComponents` | 否 | 复用 `NotificationCenterLoadingState` 于底部 loading |
| `YingShiThemeTokens` | 否 | 新增 "没有更多通知" 文案使用 `colors.textSecondary`，符合 token 规范 |
| `YingShiNoticeHost` / `YingShiNotice` | 否 | 不受影响 |

## 五、回归测试范围

### Server 端回归

| # | 测试范围 | 说明 |
|---|---------|------|
| S-1 | `GET /api/notifications?limit=30` | 不传 cursor，向后兼容 |
| S-2 | `GET /api/notifications?limit=30&cursor=1700000000000` | 传 cursor，分页查询 |
| S-3 | `GET /api/notifications/{id}` | 单个通知查询不受影响 |
| S-4 | `POST /api/notifications/{id}/read` | 标记已读不受影响 |
| S-5 | `POST /api/notifications/read-all` | 全部标记已读不受影响 |

### Android 端回归

| # | 测试范围 | 说明 |
|---|---------|------|
| A-1 | 通知列表初始加载 | 加载 30 条，显示正常 |
| A-2 | 滚动到底加载更多 | 触发 loadMore，追加 30 条 |
| A-3 | 全部加载完毕 | 显示"没有更多通知" |
| A-4 | 下拉刷新 | PullRefresh 指示器显示，刷新后消失 |
| A-5 | 离线只读时下拉禁用 | 下拉不触发 refresh |
| A-6 | stale 提示条刷新 | 点击后仍可正常刷新 |
| A-7 | 标记已读 | 不受分页影响 |
| A-8 | 全部标记已读 | 不受分页影响 |
| A-9 | 清空列表 | 不受分页影响 |
| A-10 | 筛选切换 | 不受分页影响 |
| A-11 | 离线缓存恢复 | 从缓存恢复后仍可触发 loadMore |
| A-12 | 错误重试 | error 消息"重试"仍可触发 refresh |
