## 变更影响链

### 变更1: NotificationController.java — listNotifications() 新增 cursor 参数

| 影响层级 | 影响对象 | 影响说明 |
|---------|---------|---------|
| 直接 | `NotificationService.listNotifications()` | 调用方需传 cursor 参数 |
| 间接 | API 调用方（Android `NotificationApi`） | 新增可选 query 参数 cursor，不传时向后兼容 |
| 间接 | API 文档（Swagger/OpenAPI） | 自动反映新参数，无需手动变更 |

**影响路径**: IA-1: 旧版 Android 客户端不传 cursor → 行为与旧版一致（向后兼容）

---

### 变更2: NotificationService.java — listNotifications() + materializeNotifications() 新增 cursor

| 影响层级 | 影响对象 | 影响说明 |
|---------|---------|---------|
| 直接 | `materializeNotifications()` | 新增 cursor 过滤逻辑，在 limit 截断前执行 |
| 直接 | `collectNotificationEvents()` | 不受影响（仍全量收集，过滤在 materialize 层） |
| 间接 | `getNotification()` | 不受影响（调用 `materializeNotifications(events, userId, null)`，cursor 为 null 不过滤） |
| 间接 | `markAllRead()` | 不受影响（调用 `collectNotificationEvents()` 而非 `materializeNotifications()`） |

**影响路径**: IA-2: `getNotification()` 仍能查到任意通知（cursor 为 null 时不过滤）

### 变更4: Contracts.kt — NotificationRepository 接口新增 cursor

**影响路径**: IA-4: 所有实现 `NotificationRepository` 的类必须更新

### 变更6: NotificationCenterViewModel.kt — 分页状态 + loadMore + isRefreshing

| 影响层级 | 影响对象 | 影响说明 |
|---------|---------|---------|
| 直接 | `NotificationCenterUiState` | 新增 `isLoadingMore`、`hasMore` 字段 |
| 直接 | `refresh()` | limit 从 100 改为 30，新增 cursor 状态管理，区分 isLoading/isRefreshing |
| 直接 | `init()` | 从 disk cache 恢复时需设置 `hasMore = true`（默认值） |
| 间接 | `NotificationCenterScreen` | `isLoadingMore` 控制底部 loading；`hasMore` 控制"没有更多"文案；`isRefreshing` 控制 PullRefresh |
| 间接 | `handleConnectivityLost()` | 不受影响（不调用 refresh，不变更 cursor 状态） |
| 间接 | `markRead()` / `markAllRead()` | 不受影响（不涉及分页） |
| 间接 | `clearList()` | 不受影响（不涉及分页） |

**影响路径**: IA-5: `refresh()` 的 loading 状态从单一 `isLoading` 升级为 `isLoading` + `isRefreshing` 双态，确保 Screen 中 `isLoading` 用于全屏 loading，`isRefreshing` 用于 PullRefresh 指示器
**影响路径**: IA-6: disk cache 恢复后仍可触发 loadMore（`hasMore` 默认 true）

---

### 变更7: NotificationCenterScreen.kt — PullRefresh + 滚动检测 + 底部 loading

| 影响层级 | 影响对象 | 影响说明 |
|---------|---------|---------|
| 直接 | LazyColumn | 外层包裹 PullToRefreshBox |
| 直接 | 底部 items | 新增 loading-more 和 no-more 两个 item |
| 直接 | LaunchedEffect | 新增滚动检测 LaunchedEffect |
| 间接 | `NotificationCenterComponents` | 不受影响（复用 `NotificationCenterLoadingState`） |
| 间接 | `NotificationCenterEmptyState` | 不受影响（空列表走不同分支） |
| 间接 | stale 提示条 | 不受影响（仍通过 `notificationStale` 触发 refresh） |

**影响路径**: IA-7: PullRefresh 和 stale 提示条共用 `viewModel.refresh()`，两种刷新方式行为一致
**影响路径**: IA-8: 离线只读时 PullRefresh 被禁用（`onRefresh` 检查 `!uiState.isOfflineReadOnly`），但 stale 提示条仍可触发（不检查离线状态）

## 必须测试的影响路径

| # | 路径 | 说明 |
|---|------|------|
| IA-1 | 不传 cursor 的旧 API 兼容性 | Server 端不传 cursor 时返回最新 N 条 |
| IA-2 | getNotification 不受 cursor 影响 | 单个通知查询仍能正常工作 |
| IA-3 | NotificationRepository 接口一致性 | 所有实现类编译通过 |
| IA-4 | FakeNotificationRepository 签名更新 | 如有 Fake 实现，也需更新签名 |
| IA-5 | refresh 双态切换 | isLoading vs isRefreshing 在不同场景下正确 |
| IA-6 | disk cache 恢复后 loadMore | 从缓存恢复的列表仍可触发 loadMore |
| IA-7 | PullRefresh 与 stale 刷新共用 | 两种触发方式调用同一 refresh() |
| IA-8 | 离线只读时 PullRefresh 禁用 | 离线时下拉不触发刷新 |
