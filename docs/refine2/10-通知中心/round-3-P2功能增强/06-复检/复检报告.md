## 发现的 Bug

### BUG-1: Server cursor 只用时间戳比较导致同毫秒通知丢失 (P1)
- **问题**: cursor 为纯 Long 时间戳，`filter(e -> e.createdAtMillis() < cursor)` 会跳过所有同时间戳的剩余条目
- **根因**: cursor 缺少 notificationId 作为二级键，排序是 `createdAtMillis DESC, notificationId ASC`，但过滤只用 `<` 比较
- **修复**: cursor 改为复合键格式 `"createdAtMillis:notificationId"`（String 类型），Server 端解析后使用 `(createdAtMillis < cursorTimestamp) || (createdAtMillis == cursorTimestamp && notificationId > cursorId)` 过滤
- **验证**: Server 编译通过，Android 编译通过

### BUG-2: refresh() 与 loadMore() 并发竞态 (P2)
- **问题**: `refresh()` 不取消 `loadMoreJob`，并发时 `currentCursor` 可能被覆盖为错误值
- **根因**: 缺少互斥保护
- **修复**: `refresh()` 开头增加 `loadMoreJob?.cancel()`
- **验证**: 编译通过，代码审查确认

### BUG-3: BUG-3 误报 — Refresh import 实际被使用 (P3)
- **问题**: 审查 Agent 误报 `import androidx.compose.material.icons.rounded.Refresh` 为 unused
- **根因**: `MaterialIcons.Rounded.Refresh` 是扩展属性，需要 `Refresh` 导入才能访问
- **修复**: 撤销删除，保留 import
- **验证**: 编译通过
