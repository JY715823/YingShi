## Round 1: P0 稳定性修复

**预估**: 中
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 推送偏好 system 类别契约修复 | Server | P0 | PushPreferenceDefaults 新增 photos:system + life:system |
| FR-8 | 已读/未读状态稳定性修复 + 点击行为改进 | Android | P0 | 点击文案仅标记已读不跳转；所有路径持久化到 AppReadCacheStore；API 失败回滚 |

**本轮重点**:
- FR-1 是纯 Server 改动，在 `PushNotificationService.java` 的默认列表中新增2行 + 确认默认值
- FR-8 涉及 NotificationCenterScreen.kt 中 `onClick` 和 `onMediaClick` 两个回调的重构：
  - `onClick`: 移除末尾 `onOpenNotificationTarget` 调用，仅执行 markRead 逻辑
  - `onMediaClick`: 保持 markRead + navigate 行为
  - 所有 markRead 路径统一：乐观更新 → API 调用 → 成功写 AppReadCacheStore / 失败回滚 isRead
  - `NotificationCenterLocalStore` 的 `markRead` 同步写 AppReadCacheStore
  - `markAllRead` 路径同步写 AppReadCacheStore
- 两个 FR 互相独立，可并行实施

**前置条件**: 无

## Round 2: P1 架构重构

**预估**: 大
**依赖**: Round 1（FR-8 修改了 NotificationCenterScreen.kt，FR-2/3/4 在此基础上拆分）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-4 | 通知模型文件重构 | Android | P1 | FakeNotificationRepository.kt 中的公共模型提取到 NotificationModels.kt |
| FR-2 | 提取 NotificationCenterViewModel | Android | P1 | 状态管理和业务逻辑移入 ViewModel |
| FR-3 | NotificationCenterScreen.kt 文件拆分 | Android | P1 | 拆为 Screen + Components + Presentation 三个文件 |
| FR-7 | 附带清理 | Android | P1 | 消除硬编码 ID + FakeAlbumRepository 耦合 |

**本轮重点**:
- **实施顺序**: FR-4 → FR-2 → FR-3 → FR-7
  1. FR-4 先做：提取模型到 NotificationModels.kt，更新所有 import。这一步不影响逻辑，只是文件移动
  2. FR-2 接着做：从 NotificationCenterScreen.kt 提取 ViewModel。此时文件还是 2081 行（加上 FR-8 的改动），提取后 Composable 大幅瘦身
  3. FR-3 然后做：将剩余的 NotificationCenterScreen.kt 拆为 Screen + Components + Presentation
  4. FR-7 最后做：在拆分后的文件中修复硬编码 ID 和 FakeAlbumRepository 耦合
- FR-2 和 FR-3 紧密耦合（ViewModel 提取后才能合理拆分文件），放同一轮
- 每步完成后编译验证

**前置条件**: Round 1 完成

## Round 3: P2 功能增强

**预估**: 中
**依赖**: Round 2（FR-5/FR-6 依赖 FR-2 产出的 NotificationCenterViewModel）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-5 | 通知列表分页加载 | Both | P2 | Server 支持 cursor 分页；Android 滚动到底自动加载 |
| FR-6 | 通知列表下拉刷新 | Android | P2 | Material3 PullRefresh 手势刷新 |

**本轮重点**:
- FR-5 前后端同步：
  - Server: NotificationController 新增 `cursor`（Long?，createdAt 毫秒时间戳）参数，NotificationService 查询增加 `WHERE created_at < cursor` 条件
  - Android: NotificationApi 新增 cursor 参数；ViewModel 管理分页状态（hasMore、isLoadingMore）；LazyColumn 检测滚动到底触发 loadMore
  - 不传 cursor 时返回最新 N 条（向后兼容）
- FR-6 纯 Android：
  - 在 NotificationCenterScreen 的 LazyColumn 外层包裹 PullRefresh
  - 下拉触发 ViewModel.refresh()，与 stale 提示条共用逻辑
  - 离线只读时禁用
- 两个 FR 可并行（不同文件区域），但建议顺序实施避免冲突

**前置条件**: Round 2 完成
