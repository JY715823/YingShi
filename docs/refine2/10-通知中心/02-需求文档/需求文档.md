# 通知中心 需求文档

> 版本: v1.0 | 日期: 2026-07-16 | 状态: 已确认

## 一、模块目标

通知中心精修后达到：推送偏好全类别可用（含 system）、已读状态稳定可靠（持久化一致、点击行为符合直觉）、代码架构与项目其他模块对齐（ViewModel + 文件拆分）、通知列表支持分页加载和下拉刷新。

## 二、功能需求

### FR-1: 推送偏好 system 类别契约修复

**描述**: Server 端 `PushNotificationService` 的 `PushPreferenceDefaults` 列表缺少 `photos:system` 和 `life:system` 两个类别。Android 设置页有这两个开关，但切换时 Server 返回 400 `"Unknown push preference category."`。需将 system 类别加入默认列表，使8个推送偏好全部可读写。

**端**: Server

**优先级**: P0

**验收标准**:
- AC-1: GET /api/push/preferences 返回的列表包含8项（photos:content_update/comment/delete/system + life:trace/ledger/chat/system）
- AC-2: POST /api/push/preferences 更新 photos:system 或 life:system 返回 200，不返回 VALIDATION_ERROR
- AC-3: photos:system 默认值为 false（关闭），life:system 默认值为 false（关闭）
- AC-4: isPushEnabled() 对 system 类别正确返回默认值 false

**涉及文件**:
- `YingShi-Server/src/main/java/com/yingshi/server/service/push/PushNotificationService.java`

---

### FR-8: 已读/未读状态稳定性修复 + 点击行为改进

**描述**: 当前已读状态存在不稳定问题：(1) `NotificationCenterLocalStore` 纯内存 `mutableStateListOf` 进程被杀后丢失；(2) 本地路径（L601-605）只改内存不写 `AppReadCacheStore`；(3) API 失败时强制设 `isRead=true` 但未持久化，下次刷新变回未读。同时改进点击行为：点击通知卡片文案区域仅标记已读不跳转，点击媒体缩略图标记已读+跳转。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: 点击通知卡片文案区域 → 标记已读（乐观更新+API调用+持久化到AppReadCacheStore），不跳转到详情/目标页
- AC-2: 点击媒体缩略图 → 标记已读 + 跳转到目标页（保持现有行为）
- AC-3: 所有标记已读路径（单条本地路径/API路径/全部已读路径）都同步写入 AppReadCacheStore 持久化
- AC-4: API 调用失败时回滚 isRead 为 false（而非强制设为 true），下次刷新保持未读状态
- AC-5: 进程被杀重启后，已标记已读的通知仍显示为已读（从 AppReadCacheStore 恢复）
- AC-6: 首页铃铛未读计数与通知中心未读计数一致

**涉及文件**:
- `app/src/main/java/com/example/yingshi/feature/photos/NotificationCenterScreen.kt`
- `app/src/main/java/com/example/yingshi/feature/photos/FakeNotificationRepository.kt`（NotificationCenterLocalStore 部分）

### FR-5: 通知列表分页加载

**描述**: 当前 `/api/notifications` 固定 `limit=100` 一次性拉取全部通知。改为 cursor 分页（基于 createdAt），Android 端滚动到底部自动加载下一批。

**端**: Both

**优先级**: P2

**验收标准**:
- AC-1: Server 端 `/api/notifications` 支持 `cursor`（createdAt 毫秒时间戳）和 `limit` 参数，返回按 createdAt 降序的指定数量通知
- AC-2: Android 端初始加载 30 条，滚动到底部自动加载下一批 30 条
- AC-3: 分页加载时有底部 loading 指示器
- AC-4: 全部加载完毕时显示 "没有更多通知" 或不再触发加载
- AC-5: 分页加载的通知正确合并到现有列表，不重复不遗漏
- AC-6: 离线缓存包含已加载的所有分页数据

**涉及文件**:
- `YingShi-Server/src/main/java/com/yingshi/server/controller/NotificationController.java`
- `YingShi-Server/src/main/java/com/yingshi/server/service/NotificationService.java`
- `app/src/main/java/com/example/yingshi/data/remote/api/NotificationApi.kt`
- `app/src/main/java/com/example/yingshi/data/repository/RealRepositories.kt`
- `app/src/main/java/com/example/yingshi/feature/photos/NotificationCenterViewModel.kt`（FR-2 产出）
- `app/src/main/java/com/example/yingshi/feature/photos/NotificationCenterScreen.kt`
