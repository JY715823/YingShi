## 二、用户流程

### 流程1: 查看通知列表
用户在首页点击铃铛按钮进入通知中心。系统先从 AppReadCacheStore 读取缓存渲染首屏，同时请求 GET /api/notifications?limit=100 刷新。Server 端 NotificationService 从 comment_posts、small_albums、trash_items、upload_tasks、life_console 等源实时物化通知事件，组装含 module/category/actor/mediaItems/targetRoute 等22个字段的 DTO 返回。Android 端按日期分组、按 Module/Category/Actor 过滤后渲染任务卡片列表。
涉及: `NotificationCenterScreen.kt`, `RealNotificationRepository.kt`, `NotificationApi.kt`, `NotificationService.java`, `NotificationController.java`

### 流程2: 推送通知接收与深链接
A 设备执行操作（评论/上传/删除等）→ Server 在事务提交后异步调用 PushNotificationService.notifyPhotoChanged → 查询 recipient 的 push_device_tokens → 按偏好过滤 → FCM 发送 hybrid notification+data → B 设备系统通知栏展示 → 用户点击 → PendingIntent 携带深链接 → MainActivity 解析路由 → 跳转到照片流定位/小相册详情/Viewer+评论面板/生活控制台。
涉及: `PushNotificationService.java`, `FcmSender.java`, `YingShiFirebaseMessagingService.kt`, `PushNotificationPresenter.kt`, `MainActivity.kt`, `YingShiApp.kt`

### 流程3: 推送偏好设置
用户进入设置页 → 读取 SharedPreferences 缓存 + GET /api/push/preferences 远端同步 → 展示8个开关 → 用户切换 → 乐观更新本地 + POST /api/push/preferences 远端 → 成功则 applyRemote / 失败则回滚。
涉及: `SettingsScreen.kt`, `SettingsRepository.kt`, `PushPreferenceController.java`, `PushPreferenceService.java`

### 流程4: Sync 版本驱动刷新
SyncVersionTracker 定时轮询 GET /api/sync/versions → 比较 effectiveNotificationVersion → 若版本推进则标记 notificationsStale → 通知中心监听 stale 状态自动 refresh(showLoading=false) → NotificationFallbackNotifier 在 FCM 未到达时补发本地系统通知。
涉及: `SyncVersionTracker.kt`, `NotificationCenterScreen.kt`, `NotificationFallbackNotifier.kt`, `SyncService.java`

## 三、数据流向

### 通知列表数据流
```
Server 6+源(评论/小相册/回收站/上传/生活/记账)
  → NotificationService.collectNotificationEvents() 实时物化
  → NotificationController GET /api/notifications
  → Android NotificationApi (Retrofit)
  → RealNotificationRepository
  → NotificationCenterScreen (缓存优先+网络刷新)
  → AppReadCacheStore (离线持久化)
```

### 推送数据流
```
Server 业务操作(Comment/Post/Trash/LifeConsole)
  → afterCommit 异步回调
  → PushNotificationService.notifyPhotoChanged()
  → 偏好过滤 + 设备token查询 + 审计记录
  → FcmSender → Firebase Cloud Messaging
  → Android YingShiFirebaseMessagingService
  → PushNotificationPresenter (权限/偏好/去重)
  → 系统通知栏 + PendingIntent深链接
```

### 跨模块数据交互
- **评论系统**: 评论创建触发通知物化 + 推送；notificationVersion 受评论更新影响
- **小相册**: 创建/编辑/评论触发通知+推送；deep link 到小相册详情
- **回收站**: 删除/恢复触发通知+推送；photoFeedVersion 和 trashVersion 同步推进
- **上传/传输中心**: 上传完成按 operationId 分组通知+推送
- **生活控制台**: 痕迹/记账/聊天触发通知+推送；life_console.changed 事件
- **同步系统**: notificationVersion 驱动通知中心刷新；NOTIFICATIONS 模块独立 stale 标记
- **设置**: 推送偏好读写；推送诊断查询
- **首页**: 铃铛未读计数从通知缓存统计

### 已读/未读状态稳定性问题（用户反馈）

| # | 问题 | 严重度 | 位置 | 说明 |
|---|------|--------|------|------|
