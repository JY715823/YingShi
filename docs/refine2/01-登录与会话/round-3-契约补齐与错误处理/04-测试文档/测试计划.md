## 二、功能测试（对应 FR-5 的 AC-1~AC-4）

### TC-4: AUTH_ACCOUNT_LOCKED 中文提示显示（AC-1）
- 对应: FR-5/AC-1, IA-1
- 端: Both
- 前置条件: 
  - 服务端运行中，账号锁定配置默认（5 次/15 分钟）
  - 测试账号: `1085060329@qq.com`
  - 故意将密码改为错误值（如 `wrongpassword`）
- 步骤:
  1. 在登录页输入正确账号 + 错误密码，点击登录，连续 5 次（触发锁定）
  2. 第 6 次点击登录（仍用错误密码）
  3. 观察错误提示文案
- 预期结果: 第 6 次请求后，显示"账号已临时锁定，请 15 分钟后再试"（中文），不显示英文 "Account is temporarily locked due to too many failed login attempts."
- 通过标准: 错误提示为中文锁定文案

### TC-5: 锁定状态下登录按钮禁用（AC-2）
- 对应: FR-5/AC-2, IA-6, IA-7
- 端: Android
- 前置条件: 已触发账号锁定（TC-4 完成后）
- 步骤:
  1. 观察登录按钮视觉状态
  2. 尝试点击登录按钮
  3. 修改密码输入框内容
  4. 再次观察按钮状态
- 预期结果: 
  - 按钮呈 disabled 视觉态（颜色变灰/透明度降低）
  - 点击按钮无响应（不触发 queueAction）
  - 修改密码不解除禁用
- 通过标准: 按钮持续 disabled，点击无效

### TC-6: 两端契约文档补充 AUTH_ACCOUNT_LOCKED（AC-3）
- 对应: FR-5/AC-3
- 端: Both
- 前置条件: 文档已修改
- 步骤:
  1. 读取 `YingShi/docs/contracts/auth-api.md`，检查 Error Codes 章节
  2. 读取 `YingShi-Server/docs/contracts/auth-api.md`，检查 Error Codes 章节 + Account Lockout 段
- 预期结果: 
  - Android 端文档 Error Codes 列表包含 `AUTH_ACCOUNT_LOCKED`
  - Server 端文档 Error Codes 列表包含 `AUTH_ACCOUNT_LOCKED`
  - Server 端文档新增 "Account Lockout" 章节说明触发条件/HTTP 状态/锁定时长/无剩余时间字段
- 通过标准: 两端文档均包含 AUTH_ACCOUNT_LOCKED 说明

### TC-7: 锁定解除后可正常重试（AC-4）
- 对应: FR-5/AC-4, IA-5
- 端: Both
- 前置条件: 已触发账号锁定（TC-4 完成后）
- 步骤:
  1. 等待 15 分钟（或手动在数据库清空 `locked_until` 字段模拟解锁）
  2. 输入正确账号 + 正确密码，点击登录
  3. 观察是否进入验证码阶段
- 预期结果: 
  - queueAction 重置 isAccountLocked=false，按钮恢复 enabled
  - 服务端 requireAccountNotLocked 放行（锁定已解除）
  - 密码校验通过，发送验证码，进入验证码阶段
- 通过标准: 登录流程恢复正常，能进入验证码阶段

## 三、影响范围测试（对应影响分析 IA-N）

### TC-8: remembered login 路径触发锁定（IA-2）
- 对应: IA-2
- 端: Both
- 前置条件: 账号已锁定
- 步骤:
  1. 确保账号有 remembered login token（之前成功登录过）
  2. 杀掉 App 重开，让 BackendAutoLoginManager 尝试 remembered login
  3. 观察错误提示
- 预期结果: 显示中文锁定提示（remembered login 走 handleActionError 同一错误处理路径）
- 通过标准: remembered login 路径也显示中文锁定文案

### TC-9: 验证码错误不触发账号锁定（IA-3）
- 对应: IA-3
- 端: Server
- 前置条件: 账号未锁定，已进入验证码阶段
- 步骤:
  1. 请求 challenge 成功，进入验证码阶段
  2. 连续输入错误验证码 5 次以上
  3. 观察是否触发 AUTH_ACCOUNT_LOCKED
- 预期结果: 验证码错误返回 AUTH_LOGIN_CODE_INVALID 或 challenge 失效，**不返回** AUTH_ACCOUNT_LOCKED
- 通过标准: 验证码错误不触发账号锁定

### TC-10: 锁定期间切换账号可登录（IA-4）
- 对应: IA-4
- 端: Android
- 前置条件: 账号 A 已锁定
- 步骤:
  1. 账号 A 锁定后，将账号输入框改为账号 B（未锁定）
  2. 输入账号 B 的正确密码，点击登录
- 预期结果: 
  - queueAction 重置 isAccountLocked=false
  - 按钮恢复 enabled
  - 账号 B 正常进入验证码阶段
- 通过标准: 切换账号后按钮恢复，新账号可登录

### TC-11: 密码错误不误触锁定分支（回归）
- 对应: 影响分析 - 回归
- 端: Both
- 前置条件: 账号未锁定
- 步骤:
  1. 输入正确账号 + 错误密码，点击登录
  2. 观察错误提示（次数 < 5，未触发锁定）
- 预期结果: 
  - 显示 AUTH_INVALID_CREDENTIALS 的原始 message（英文 "Invalid account or password."）
  - **不显示**中文锁定文案
  - 按钮仍可点击（isAccountLocked 未被设置）
- 通过标准: 密码错误走原逻辑，不误触锁定分支

### TC-12: 验证码错误流程回归（回归）
- 对应: 影响分析 - 回归
- 端: Both
- 前置条件: 已进入验证码阶段
- 步骤:
  1. 输入错误验证码，点击登录
  2. 观察错误提示
- 预期结果: 
  - 显示 AUTH_LOGIN_CODE_INVALID 的原始 message
  - **不显示**中文锁定文案
  - 按钮仍可点击
- 通过标准: 验证码错误走原逻辑，不误触锁定分支

### TC-13: 网络断开/恢复流程回归（回归）
- 对应: 影响分析 - 回归
- 端: Android
- 前置条件: 账号未锁定
- 步骤:
  1. 点击登录后立即断开网络
  2. 观察状态提示
  3. 恢复网络
  4. 观察是否自动继续
- 预期结果: 
  - 断网时显示"网络已断开，恢复后会自动继续当前登录动作"
  - 恢复后自动继续登录流程
  - isAccountLocked 不干扰 waitingForNetwork 逻辑
- 通过标准: 网络断开/恢复正常工作，锁定状态不干扰
