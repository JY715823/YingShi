## 一、本轮范围回顾

本轮仅处理 **FR-5: AUTH_ACCOUNT_LOCKED 错误码前端处理**（P1，Both 端）。
验收标准：
- AC-1: 触发账号锁定时，Android 端显示中文提示（非英文原始消息）
- AC-2: 锁定状态下登录按钮保持禁用
- AC-3: 契约文档（两端 auth-api.md）补充 AUTH_ACCOUNT_LOCKED 错误码说明
- AC-4: 锁定解除后（15 分钟），用户可正常重试

前置条件：确认 AuthService 中 AUTH_ACCOUNT_LOCKED 的响应格式（HTTP 429 + 错误码 + 消息）—— **已确认**。

## 三、用户流程

### 流程1: 账号锁定触发（现状）
1. 用户在登录页输入账号密码，点击登录 → `POST /api/auth/login/challenge`
2. 服务端 `AuthService.requireAccountNotLocked()` 校验当前是否已锁定（未锁定则继续）
3. 服务端 `AuthService` 校验账号密码，密码错误 → `recordFailedLogin()` 累计失败次数
4. 当 `failedLoginAttempts >= 5`，`recordFailedLogin()` 设置 `lockedUntil = now + 15min`
5. 第 5 次错误后，后续登录请求在步骤 2 即被拦截，抛 `ApiException(HTTP 429, AUTH_ACCOUNT_LOCKED, "Account is temporarily locked...")`
6. 服务端 `GlobalExceptionHandler` 转换为 JSON 响应：`{requestId, error:{code, message}, timestamp}`
7. Android `AuthRepository` 收到 HTTP 429 → 解析 error.code = "AUTH_ACCOUNT_LOCKED" → 返回 `ApiResult.Error`
8. Android `LoginScreen.handleActionError()` 检查 effectiveCode，**未匹配任何分支** → `errorMessage = result.message`（英文原始消息透传给用户）

**问题点**：步骤 8 显示英文 "Account is temporarily locked due to too many failed login attempts." 给用户，违反 NFR-3（文案中文化）。

### 流程2: 账号锁定解除（现状）
1. 用户等待 15 分钟
2. 用户再次输入账号密码点击登录
3. 服务端 `requireAccountNotLocked()` 检查 `lockedUntil.isAfter(Instant.now())`，时间已过 → 不拦截
4. 密码校验通过 → `resetFailedLoginAttempts()` 清零 → 正常登录
5. 密码校验失败 → `recordFailedLogin()` 重新累计（从 0 开始）

**注意**：锁定解除后失败次数从 0 重新计数，不是从 5 继续。

### 流程3: 验证码错误与账号锁定关系
- 验证码错误（`/login/verify` 返回 AUTH_LOGIN_CODE_INVALID）**不触发**账号锁定
- 账号锁定仅针对密码错误（`/login/challenge` 阶段）
- 验证码错误仅作废当前 challenge（达到 5 次错误后 challenge 失效，需重新请求）

## 四、数据流向

### 锁定状态数据流
```
[用户输入密码] 
    → Android LoginScreen.queueAction(RequestChallenge)
    → AuthRepository.loginChallenge(LoginRequestDto)
    → HTTP POST /api/auth/login/challenge
    → Server AuthController.loginChallenge()
    → Server AuthService.requestLoginChallenge()
        → requireAccountNotLocked(user)  // 锁定检查（前置）
        → validatePassword(user, password)  // 密码校验
            → 失败: recordFailedLogin(user)  // 累计+可能锁定
            → 成功: (继续发送验证码)
    → HTTP 429 + {error:{code:"AUTH_ACCOUNT_LOCKED", message:"..."}}
    → Android ApiResult.Error(code="AUTH_ACCOUNT_LOCKED", message="...")
    → LoginScreen.handleActionError(result)
    → errorMessage = result.message  // 英文透传（问题点）
```

### 关键响应字段缺失
服务端 `ApiException(HTTP 429, ErrorCode.AUTH_ACCOUNT_LOCKED, message)` 仅传 message，未传 details。
`ApiError` record 的 `details` 字段为 null，因 `@JsonInclude(NON_NULL)` 不序列化。
**结论**：响应 JSON **不包含** `lockedUntil` / `remainingMinutes` / `retryAfter` 等锁定剩余时间字段。

完整锁定响应 JSON：
```json
{
  "requestId": "<请求ID>",
  "error": {
    "code": "AUTH_ACCOUNT_LOCKED",
    "message": "Account is temporarily locked due to too many failed login attempts."
  },
  "timestamp": "2026-07-08T10:30:00Z"
}
```

## 八、技术约束与设计决策

### 约束1: 服务端响应不含锁定剩余时间
- `ApiException` 构造时只传 message，未传 details
- `ApiError.details = null`，因 `@JsonInclude(NON_NULL)` 不序列化
- **决策**：Android 端使用通用文案"账号已临时锁定，请 15 分钟后再试"，不显示精确剩余时间

### 约束2: errorMessage 状态有 16 处清除点
- `LoginScreen.kt` 中 `errorMessage = null` 出现在多处（finishLogin/launchPendingAction/网络恢复等）
- 若直接复用 errorMessage 承载锁定提示，可能在其他流程中被意外清除
- **决策**：新增独立的 `isAccountLocked` 状态（Boolean），避开 errorMessage 的清除点；锁定提示文案放入 errorMessage 但通过 isAccountLocked 标志位控制按钮禁用

### 约束3: 错误码为硬编码字符串
- 现有 `handleActionError()` 中错误码比较使用硬编码字符串（如 `"AUTH_LOGIN_CODE_EXPIRED"`）
- `ApiResult.kt` 中 `isUnauthorized()` 同样使用硬编码字符串
- **决策**：本轮保持硬编码字符串风格一致性，不引入错误码常量类（避免范围蔓延）

### 约束4: 锁定状态持久化
- 服务端 `lockedUntil` 存储在 `UserEntity`，跨请求持久化
- Android 端若仅用 `remember { mutableStateOf(false) }`，配置变更（如旋转屏幕）会丢失锁定状态
- **决策**：使用 `rememberSaveable` 持久化 `isAccountLocked` 状态，确保配置变更后按钮仍禁用

### 约束5: 锁定状态恢复
- 用户在锁定期间可能杀掉 App 重新打开
- 重新打开后 `isAccountLocked` 重置为 false，按钮可点击
- 用户再次尝试登录会再次收到 AUTH_ACCOUNT_LOCKED → 重新设置 isAccountLocked = true
- **决策**：可接受此行为（每次重新触发锁定都会重新设置状态），不引入本地持久化存储锁定状态

## 十一、调研结论

1. **服务端无需改动**：锁定机制完整，响应格式清晰（HTTP 429 + code + message，无 lockedUntil）
2. **Android 端需修改 LoginScreen.kt**：
   - 新增 `isAccountLocked` 状态（rememberSaveable）
   - `handleActionError()` 增加 AUTH_ACCOUNT_LOCKED 分支：设置 isAccountLocked=true + 中文 errorMessage
   - 按钮禁用逻辑增加 `&& !isAccountLocked`
   - 新登录尝试时重置 isAccountLocked（允许重试）
3. **两端契约文档需补充**：在 Error Codes 章节增加 AUTH_ACCOUNT_LOCKED 条目，注明 HTTP 429 + 触发条件 + 提示文案
4. **文案决策**：使用"账号已临时锁定，请 15 分钟后再试"（符合 NFR-3 中文化）
5. **无服务端测试补齐**：FR-5 范围仅含前端处理 + 契约文档，服务端测试补齐不在本轮范围
