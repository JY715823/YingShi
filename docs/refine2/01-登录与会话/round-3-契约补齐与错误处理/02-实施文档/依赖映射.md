## 一、本模块依赖的外部模块/服务

| 依赖 | 类型 | 本轮是否改动接口 | 影响说明 |
|------|------|----------------|---------|
| `ErrorCode` 枚举 (Server) | 服务端错误码定义 | 否（仅读取 AUTH_ACCOUNT_LOCKED） | 服务端已定义，Android 端通过字符串匹配识别 |
| `AuthService.requireAccountNotLocked` (Server) | 服务端锁定校验 | 否 | 服务端行为不变，Android 端仅处理响应 |
| `AuthAccountLockoutProperties` (Server) | 服务端锁定配置 | 否 | 默认 5 次/15 分钟，Android 端文案硬编码 15 分钟 |
| `ApiResult.Error` (Android) | 错误结果封装 | 否 | 复用现有 code/message 计算属性 |
| `throwable.backendErrorCode()` (Android) | 错误码解析 | 否 | 复用现有解析逻辑，从 HttpException errorBody 提取 code |
| `YingShiThemeTokens` (Android) | 颜色 token | 否 | 本轮无新增 UI 组件，无颜色引用 |
| `rememberSaveable` (Compose) | 状态持久化 | 否 | 框架 API，无改动 |

**结论**: 本轮不改动任何外部模块接口，仅消费现有服务端响应和 Android 端解析能力。

## 四、数据流图

### 锁定触发数据流（改动后）

```
[用户点击登录]
    ↓
LoginScreen.queueAction(RequestChallenge)  ★新增: isAccountLocked = false
    ↓
AuthRepository.loginChallenge(LoginRequestDto)
    ↓
HTTP POST /api/auth/login/challenge
    ↓
[Server] AuthService.requireAccountNotLocked()
    ↓ (已锁定)
HTTP 429 + {error:{code:"AUTH_ACCOUNT_LOCKED", message:"Account is temporarily locked..."}}
    ↓
[Android] ApiResult.Error(code="AUTH_ACCOUNT_LOCKED", message="Account is temporarily locked...")
    ↓
LoginScreen.handleActionError(result)  ★修改: 识别 AUTH_ACCOUNT_LOCKED
    ↓
    ├─ isAccountLocked = true  ★新增
    ├─ errorMessage = "账号已临时锁定，请 15 分钟后再试"  ★中文化
    └─ isLoading = false, pendingAction = null
    ↓
UI 更新:
    ├─ currentMessage (L165) = errorMessage → 显示中文锁定提示
    └─ YingShiPrimaryMistButton.enabled (L659-663) = ... && !isAccountLocked → false (按钮禁用)  ★修改
```

### 锁定解除数据流（改动后）

```
[用户等待 15 分钟后再次点击登录]
    ↓
LoginScreen.queueAction(RequestChallenge)  ★新增: isAccountLocked = false (重置)
    ↓
AuthRepository.loginChallenge(LoginRequestDto)
    ↓
HTTP POST /api/auth/login/challenge
    ↓
[Server] AuthService.requireAccountNotLocked()
    ↓ (锁定已解除，不拦截)
AuthService.validatePassword()
    ↓ (密码正确)
sendLoginCode() → 返回 challenge
    ↓
[Android] ApiResult.Success(challenge)
    ↓
applyChallenge(challenge) → 进入验证码阶段
    ↓
[用户输入验证码点击登录]
    ↓
LoginScreen.queueAction(VerifyChallenge)
    ↓
... → 登录成功 → finishLogin()
```

## 五、回归测试范围

| 范围 | 端 | 测试内容 |
|------|-----|---------|
| 登录正常流程 | Android | 密码 → 验证码 → 登录成功（确认 queueAction 重置不影响正常流程） |
| 密码错误流程 | Both | 密码错误 → AUTH_INVALID_CREDENTIALS → 英文/原 message 透传（确认不误触锁定分支） |
| 验证码错误流程 | Both | 验证码错误 → AUTH_LOGIN_CODE_INVALID → 原逻辑（确认不误触锁定分支） |
| remembered login 失效流程 | Both | AUTH_REMEMBERED_LOGIN_INVALID → 回退到 RequestChallenge（确认不误触锁定分支） |
| 网络断开/恢复流程 | Android | 网络断开 → waitingForNetwork → 恢复后继续（确认 isAccountLocked 不干扰） |
| 按钮禁用状态 | Android | 锁定状态下按钮 disabled 视觉态 + 点击无响应 |
| 跨模块回归 | Android | 登录成功后进入首页/照片流/设置等页面正常（确认登录流程不破坏后续路由） |
