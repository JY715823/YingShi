### TC-4 详情: AUTH_ACCOUNT_LOCKED 中文提示显示（AC-1）
**结果**: ✅ PASS
**验证方式**: 代码审查
**证据**:
- `LoginScreen.kt` L217-219:
  ```kotlin
  if (effectiveCode == "AUTH_ACCOUNT_LOCKED") {
      isAccountLocked = true
      errorMessage = "账号已临时锁定，请 15 分钟后再试"
  }
  ```
- 服务端 `AuthService.requireAccountNotLocked` (L398-410) 在账号锁定时抛 `ApiException(HTTP 429, AUTH_ACCOUNT_LOCKED, "Account is temporarily locked...")`
- `GlobalExceptionHandler` (L142) 通过 `errorCode.name()` 转换为字符串 `"AUTH_ACCOUNT_LOCKED"` 下发
- Android `ApiResult.Error.code` 通过 `throwable.backendErrorCode()` 解析得到 `"AUTH_ACCOUNT_LOCKED"`
- `handleActionError` 匹配该 code，设置中文 errorMessage
- `currentMessage` (L165) 优先取 errorMessage → UI 显示中文锁定文案
**结论**: AC-1 满足，英文原始消息不再透传给用户。

### TC-5 详情: 锁定状态下登录按钮禁用（AC-2）
**结果**: ✅ PASS
**验证方式**: 代码审查
**证据**:
- `LoginScreen.kt` L666-670:
  ```kotlin
  enabled = if (challengeState == null) {
      account.isNotBlank() && password.isNotBlank() && !isLoading && !isAccountLocked
  } else {
      verificationCode.length >= 6 && !isLoading && !isAccountLocked
  },
  ```
- `isAccountLocked` 在 `handleActionError` (L218) 收到 AUTH_ACCOUNT_LOCKED 时置为 true
- 两阶段（密码 + 验证码）均追加 `&& !isAccountLocked`，锁定期间按钮持续 disabled
**结论**: AC-2 满足，锁定状态下登录按钮保持禁用。

### TC-7 详情: 锁定解除后可正常重试（AC-4）
**结果**: ✅ PASS
**验证方式**: 代码审查 + 逻辑推导
**证据**:
- `LoginScreen.kt` L447-455 `queueAction`:
  ```kotlin
  fun queueAction(action: PendingLoginAction) {
      actionNonce += 1
      pendingAction = action
      waitingForNetwork = false
      errorMessage = null
      statusMessage = null
      isAccountLocked = false  // 重置锁定状态
      launchPendingAction(actionNonce, action)
  }
  ```
- 用户在锁定解除后点击登录 → queueAction 重置 isAccountLocked=false → 按钮恢复 enabled
- 服务端 `requireAccountNotLocked` (L402-403) 检查 `lockedUntil.isAfter(Instant.now())`，时间已过则不拦截
- 密码校验通过 → `resetFailedLoginAttempts` (L424-430) 清零 → 正常登录
**结论**: AC-4 满足，锁定解除后用户可正常重试。

### TC-8 详情: remembered login 路径触发锁定（IA-2）
**结果**: ✅ PASS
**验证方式**: 代码审查
**证据**:
- 服务端 `AuthService.loginWithRememberedDevice` (L134-145) 调用 `requireAccountNotLocked` (L138)
- 账号锁定时，remembered login 也会返回 AUTH_ACCOUNT_LOCKED
- Android 端 remembered login 错误走 `handleActionError` 同一入口（L209）
- 匹配 AUTH_ACCOUNT_LOCKED → 设置中文文案 + isAccountLocked=true
**结论**: remembered login 路径同样显示中文锁定文案。

### TC-9 详情: 验证码错误不触发账号锁定（IA-3）
**结果**: ✅ PASS
**验证方式**: 代码审查
**证据**:
- `AuthService.verifyLoginChallenge` (L102-131) **未调用** `requireAccountNotLocked`
- `requireAccountNotLocked` 仅在两处调用:
  - L85: `requestLoginChallenge`（密码阶段）
  - L138: `loginWithRememberedDevice`（remembered login 阶段）
- 验证码错误返回 AUTH_LOGIN_CODE_INVALID 或 challenge 失效，**不返回** AUTH_ACCOUNT_LOCKED
**结论**: 验证码错误不触发账号锁定，符合设计。

### TC-10 详情: 锁定期间切换账号可登录（IA-4）
**结果**: ✅ PASS
**验证方式**: 代码审查
**证据**:
- 用户修改账号后点击登录 → `queueAction` (L447) 被调用
- L453 `isAccountLocked = false` 重置锁定状态
- L666 按钮恢复 enabled（`!isAccountLocked` 为 true）
- 新账号（未锁定）在服务端 `requireAccountNotLocked` 放行 → 正常登录
**结论**: 锁定期间切换账号后按钮恢复，新账号可登录。

**证据**:
- 密码错误（次数 < 5）返回 `AUTH_INVALID_CREDENTIALS`

- 走 else 分支 L220-222: `errorMessage = result.message`（透传原 message）
- `isAccountLocked` 保持 false，按钮仍可点击
**结论**: 密码错误走原逻辑，不误触锁定分支。

### TC-13 详情: 网络断开/恢复流程回归

**结论**: 网络断开/恢复逻辑不受 isAccountLocked 影响。
