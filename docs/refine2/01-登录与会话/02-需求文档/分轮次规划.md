## Round 1: 登录页视觉重构

**预估**: 中
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | 表单容器卡片 | Android | P0 | 表单区域外层包裹半透明卡片（raisedSurface + glassStroke + 多层阴影 + 大圆角） |
| FR-4 | 品牌区域丰富 | Android | P0 | "映世"标题下方增加副标题，形成字重对比 |
| FR-6 | 连接设置入口视觉弱化 | Android | P2 | 连接设置入口颜色改为 textSecondary，字号缩小 |

**本轮重点**: 三个 FR 都修改 LoginScreen.kt 的布局结构，合并实施避免冲突。核心是建立表单区域的视觉层次：品牌标题（含副标题）→ 表单卡片容器（包裹输入框+按钮）→ 底部弱化连接设置。先做布局结构调整，再验证颜色 token 使用。

**前置条件**: 无

**实施顺序**:
1. FR-4: 品牌标题下方增加副标题（改动最小，先稳定）
2. FR-1: 表单区域包裹卡片容器（核心改动，注意与现有输入框样式兼容）
3. FR-6: 连接设置入口弱化（改动最小，收尾）
4. 编译验证: `gradlew.bat assembleDebug`

## Round 2: 背景精修与交互动效

**预估**: 大
**依赖**: Round 1（视觉基础就绪后再做动画和背景精修）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-2 | AUTH 背景 token 化 + memoryWash | Android | P0 | AuroraBackdrop AUTH variant 硬编码颜色改为 token 引用 + 引入 memoryWash |
| FR-7 | 极光背景微动画 | Android | P2 | 闪烁圆点 alpha 呼吸动画或辉光层缓变 |
| FR-3 | 表单状态切换动画 | Android | P0 | 密码框/验证码框切换、消息显隐、预设账号指示线等添加过渡动画 |

**本轮重点**: FR-2 和 FR-7 都修改 AuroraBackdrop.kt，合并实施。FR-2 是重构（token 化），FR-7 是新增（微动画），先重构再新增。FR-3 修改 LoginScreen.kt 的动画，涉及多个状态切换点，需逐个处理。本轮改动量最大，需特别注意：(1) token 化后视觉不退步；(2) 动画不导致布局抖动；(3) 所有动画遵循 rememberYingShiMotionEnabled()。

**前置条件**: Round 1 完成（表单卡片容器已就位，动画效果可在最终布局上验证）

**实施顺序**:
1. FR-2: AuroraBackdrop AUTH variant token 化 + memoryWash 引入
2. FR-7: 闪烁圆点/辉光层微动画（在 token 化基础上添加）
3. FR-3: LoginScreen 各状态切换动画（AnimatedVisibility / animateColorAsState）
4. 编译验证: `gradlew.bat assembleDebug`
5. 视觉回归: 确认其他 AuroraBackdrop variant 不受影响

## Round 3: 契约补齐与错误处理

**预估**: 小
**依赖**: 无强依赖，但放在最后可与前两轮改动隔离
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-5 | AUTH_ACCOUNT_LOCKED 错误码前端处理 | Both | P1 | Android 端增加锁定错误码的中文提示 + 按钮禁用；两端契约文档补齐 |

**本轮重点**: 改动集中在 LoginScreen.kt 的 handleActionError() 函数，增加 AUTH_ACCOUNT_LOCKED 分支。需要确定锁定提示文案和锁定期间的 UI 状态（按钮禁用 + 提示文案）。同时更新两端契约文档。改动范围小，但需确认服务端返回的错误响应格式（是否包含锁定剩余时间）。

**前置条件**: 确认 AuthService 中 AUTH_ACCOUNT_LOCKED 的响应格式（HTTP 429 + 错误码 + 消息）

**实施顺序**:
1. 确认服务端锁定响应格式（读取 AuthService.requireAccountNotLocked）
2. Android: handleActionError() 增加 AUTH_ACCOUNT_LOCKED 分支
3. Android: 锁定状态下按钮禁用逻辑
4. 两端契约文档补充 AUTH_ACCOUNT_LOCKED 说明
5. 编译验证: `gradlew.bat assembleDebug` + `mvnw.cmd compile`

## 风险与注意事项

| # | 风险 | 关联轮次 | 缓解措施 |
|---|------|---------|---------|
| 1 | AuroraBackdrop token 化后视觉偏差 | Round 2 | 修改前后截图对比；装饰细节保留硬编码；逐层替换而非一次性全改 |
| 2 | 动画引入后布局抖动 | Round 2 | AnimatedVisibility 使用 fade + slideInVertically(小位移)；避免影响按钮位置 |
| 3 | 表单卡片与输入框样式冲突 | Round 1 | 卡片仅作为外层 Column 包裹，不修改 YingShiTextField 组件 |
| 4 | AUTH_ACCOUNT_LOCKED 锁定时间获取 | Round 3 | 检查服务端响应是否包含 lockedUntil 时间；若无则使用通用文案"请 15 分钟后再试" |
| 5 | Round 2 改动量大 | Round 2 | 分步实施：先 token 化 → 再微动画 → 最后 LoginScreen 动画；每步编译验证 |
