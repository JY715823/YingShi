# 登录与会话 需求文档

> 版本: v1.0 | 日期: 2026-07-08 | 状态: 待确认

## 一、模块目标

在现有功能链路完整的基础上，按设计方案对齐登录页视觉品质（材质光影、情绪洗色、排版层次），补全交互过渡动画，修复 AUTH_ACCOUNT_LOCKED 错误码的前端处理缺口，使登录模块从"功能可用"提升到"成品可交付"状态。

## 二、功能需求

### FR-1: 表单容器卡片
**描述**: 在登录表单区域（输入框 + 按钮 + 预设账号）外层包裹一层半透明卡片容器，使用 raisedSurface 半透明底色（alpha ~0.88）、glassStroke 细边框（alpha ~0.5）、大圆角（radius.xl 28dp）、多层阴影（内阴影感 + 外阴影），使表单在极光背景上有明确的视觉承托层。可叠加一层极轻的 glowWash 水平渐变。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: 表单区域（从品牌标题下方到登录按钮）被一个半透明卡片包裹，与极光背景形成层次分离
- AC-2: 卡片使用 raisedSurface 底色（alpha 0.85-0.92），glassStroke 细边框，圆角 >= 24dp
- AC-3: 卡片有多层阴影效果，符合设计方案"多层阴影、微妙渐变、精致边线"要求
- AC-4: 所有颜色使用 YingShiThemeTokens，无硬编码颜色值
**涉及文件**: app/src/main/java/com/example/yingshi/feature/auth/LoginScreen.kt

### FR-2: AUTH 背景 token 化 + memoryWash 情绪洗色
**描述**: 将 YingShiAuroraBackdrop 的 AUTH variant 中 40+ 个硬编码颜色值改为引用 YingShiThemeTokens（appBackground、glowWash、memoryWash、sectionBackground 等）。同时在渐变底色中引入 memoryWash（#FFF1EE）做"进入共同空间"的温暖情绪洗色，替代当前偏冷的色调。装饰性细节（闪烁点、金色轨迹）可保留硬编码。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: AUTH variant 的底色渐变和主要辉光层使用 token 引用，硬编码颜色数量从 40+ 降至 15 以下（仅保留装饰细节）
- AC-2: 渐变底色中包含 memoryWash 色（#FFF1EE 或 token 引用），呈现温暖感
- AC-3: 整体视觉效果与当前一致或更好，不能出现明显色差退化
- AC-4: 其他 variant（HOME/PHOTOS/LIFE/ME/SHELL）不受影响
**涉及文件**: app/src/main/java/com/example/yingshi/ui/components/YingShiAuroraBackdrop.kt

### FR-3: 表单状态切换动画
**描述**: 为 LoginScreen 中所有状态切换添加过渡动画。包括：(1) 密码框与验证码框之间的切换使用 AnimatedVisibility 淡入淡出 + 轻微位移；(2) 消息/错误提示的出现和消失使用 AnimatedVisibility 淡入淡出；(3) 预设账号选中态指示线使用 animateColorAsState 平滑过渡；(4) 验证码操作区（重新发送/返回）使用 AnimatedVisibility。所有动画须遵循 rememberYingShiMotionEnabled() 设置。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: 密码框 -> 验证码框切换有淡入淡出 + 位移动画，时长 200-300ms
- AC-2: 消息/错误提示出现和消失有淡入淡出动画
- AC-3: 预设账号选中指示线颜色切换有过渡动画
- AC-4: 验证码操作区（重发/返回按钮）显隐有过渡动画
- AC-5: 系统"减少动画"设置开启时，所有动画退化为即时切换
- AC-6: 动画不导致布局抖动或按钮位置跳变
**涉及文件**: app/src/main/java/com/example/yingshi/feature/auth/LoginScreen.kt

### FR-4: 品牌区域丰富
**描述**: 在品牌标题"映世"下方增加一行品牌副标题（如"我们的共同空间"），使用 textSecondary 或 goldAccent 颜色，字号小于标题（bodyLarge 或 titleSmall），与主标题形成字重对比。主标题与副标题间距适当（4-8dp）。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: "映世"标题下方新增一行副标题文字
- AC-2: 副标题使用 textSecondary 或 goldAccent 颜色，字号明显小于主标题
- AC-3: 主标题与副标题有合理间距，视觉层次清晰
- AC-4: 颜色使用 YingShiThemeTokens，无硬编码
**涉及文件**: app/src/main/java/com/example/yingshi/feature/auth/LoginScreen.kt

### FR-5: AUTH_ACCOUNT_LOCKED 错误码前端处理
**描述**: Server 端已实现账号锁定机制（5 次失败锁 15 分钟，返回 AUTH_ACCOUNT_LOCKED），但 Android 端未处理该错误码，直接将英文原始消息透传给用户。需要：(1) Android 端在 handleActionError() 中增加 AUTH_ACCOUNT_LOCKED 分支，显示中文友好提示（如"账号已临时锁定，请 15 分钟后再试"）；(2) 锁定期间禁用登录按钮；(3) 同步更新两端契约文档，补充 AUTH_ACCOUNT_LOCKED 错误码说明。
**端**: Both
**优先级**: P1
**验收标准**:
- AC-1: 触发账号锁定时，Android 端显示中文提示（非英文原始消息）
- AC-2: 锁定状态下登录按钮保持禁用
- AC-3: 契约文档（两端 auth-api.md）补充 AUTH_ACCOUNT_LOCKED 错误码说明
- AC-4: 锁定解除后（15 分钟），用户可正常重试
**涉及文件**:
- Android: app/src/main/java/com/example/yingshi/feature/auth/LoginScreen.kt (handleActionError)
- Server docs: docs/contracts/auth-api.md (两端)

### FR-6: 连接设置入口视觉弱化
**描述**: 连接设置是低频操作入口，当前使用 titleAccent 颜色过于抢眼。改为 textSecondary 颜色、略小字号（labelMedium），降低视觉权重，使其"在但不抢眼"。
**端**: Android
**优先级**: P2
**验收标准**:
- AC-1: 连接设置入口使用 textSecondary 颜色（非 titleAccent）
- AC-2: 字号使用 labelMedium 或更小
- AC-3: 入口仍然可见可点击，功能不受影响
**涉及文件**: app/src/main/java/com/example/yingshi/feature/auth/LoginScreen.kt (ConnectionEntryLink)

### FR-7: 极光背景微动画
**描述**: 为 AUTH variant 的极光背景添加微弱的呼吸动画。对闪烁圆点添加 alpha 循环变化（周期 3-5 秒，alpha 在 0.3-0.8 之间缓变），或对辉光层添加极缓慢的缩放动画。须遵循 rememberYingShiMotionEnabled() 设置，动画减弱偏好下禁用。
**端**: Android
**优先级**: P2
**验收标准**:
- AC-1: 闪烁圆点或辉光层有微弱的呼吸/缓变动效
- AC-2: 动画周期 >= 3 秒，不造成视觉干扰
- AC-3: 系统"减少动画"设置开启时，动画退化为静态
- AC-4: 不影响登录页交互性能和流畅度
**涉及文件**: app/src/main/java/com/example/yingshi/ui/components/YingShiAuroraBackdrop.kt

## 三、非功能需求

### NFR-1: 动画可访问性
所有新增动画须遵循系统"减少动画"偏好设置（通过 rememberYingShiMotionEnabled()），开启时退化为即时切换或静态效果。

### NFR-2: 视觉不退步
AUTH 背景 token 化后，整体视觉效果须与当前一致或更好，不能因 token 替换导致色差退化。

### NFR-3: 文案中文化
所有用户可见的错误提示、状态文案须使用中文，与 App 整体语言一致。

### NFR-4: 编译通过
Android 端 gradlew.bat assembleDebug 通过，Server 端 mvnw.cmd compile 通过（如有 Server 改动）。

## 四、范围边界

### 在范围内
- 登录页视觉精修（容器卡片、背景 token 化、品牌区域、连接设置弱化）
- 登录页交互动画（状态切换、消息显隐、背景微动效）
- AUTH_ACCOUNT_LOCKED 错误码前端处理 + 契约文档补齐

### 不在范围内
- 注册 / 密码找回 / 第三方登录（既定 defer）
- JWT secret / CORS 生产配置（部署前处理）
- YingShiApp.kt 拆分（技术债，不在本模块范围）
- Android 端自动化测试补零（单独规划）
- allowBackup 安全加固（精修1 已完成）
- remembered-login 设备管理入口（双人场景不紧迫）

## 五、跨模块依赖

| 依赖模块 | 依赖方向 | 依赖内容 | 影响说明 |
|---------|---------|---------|---------|
| shell (AppShell) | 被依赖 | sessionVersion 驱动路由 | 本轮不涉及，无影响 |
| photos / me / notifications | 被依赖 | BackendAutoLoginManager.loginDefault() | 本轮不涉及，无影响 |
| ui/components (YingShiSurfaces) | 复用 | YingShiMistCard / YingShiTextField 等组件 | FR-1 可能复用现有组件，不修改 |
| ui/components (AuroraBackdrop) | 修改 | AUTH variant 背景 | FR-2/FR-7 直接修改，需回归其他 variant |
| design tokens | 复用 | YingShiThemeTokens 颜色系统 | FR-2 引入 token 引用，不修改 token 定义 |

## 六、数据模型变更

无。本轮不涉及数据库或数据模型变更。

## 七、风险清单

| # | 风险 | 严重度 | 缓解措施 |
|---|------|--------|---------|
| 1 | AuroraBackdrop AUTH variant token 化后视觉偏差 | 中 | 修改前后截图对比，确保色调不退步；装饰细节保留硬编码 |
| 2 | 动画引入后布局抖动或性能问题 | 低 | 使用 AnimatedVisibility 而非条件渲染；控制动画时长 200-300ms |
| 3 | 表单容器卡片与现有输入框样式冲突 | 低 | 卡片仅作为外层包裹，不修改 YingShiTextField 组件本身 |
| 4 | AUTH_ACCOUNT_LOCKED 锁定时间硬编码在前端 | 低 | 优先从服务端响应中读取锁定剩余时间，若无则使用通用提示 |
