## 三、FR-5 服务端: 批量删除端点

### 变更文件

| # | 文件 | 变更类型 | 说明 |
|---|------|---------|------|
| 1 | `UpdatePostMediaBatchRequest.java` | 新建 | DTO record，@NotEmpty + @NotBlank |

| 3 | `PostController.java` | 修改 | 新增 batchRemoveSmallAlbumMedia 端点 + import |

### 实施过程

1. 新建 `UpdatePostMediaBatchRequest.java`：record + jakarta.validation 注解，参考 AddPostMediaRequest 模式
2. PostService 新增 import + batchRemovePostMedia 方法：
   - requirePost 校验
   - validateDistinctIds 去重校验
   - 加载全部关系 + 校验 removeMediaIds 都属于本小相册
   - 防清空校验（DELETE_CONFLICT）
   - deleteAll + flush + 重排 sortOrder + 封面补偿
   - notifyContentUpdated
3. PostController 新增 import + batchRemoveSmallAlbumMedia 端点（PATCH /{smallAlbumId}/media-batch）
4. `mvnw.cmd compile` 验证通过

### 关键决策

- **路径**：采用 `/api/small-albums/{smallAlbumId}/media-batch`（与 PostController 现有约定一致，非需求文档的 `/api/posts/{postId}/media-batch`）
- **不创建 TrashItem**：编辑保存场景无需逐项撤销，批量删除仅删关系不入回收站
- **不新增 Repository 方法**：使用 findByLibraryIdAndPostIdOrderBySortOrderAsc + deleteAll + saveAll 组合

## 四、FR-5 Android: 批量删除优化

### 变更文件

| # | 文件 | 变更类型 | 说明 |
|---|------|---------|------|
| 1 | `PostDto.kt` | 修改 | 新增 UpdatePostMediaBatchRequestDto + typealias |
| 2 | `SmallAlbumApi.kt` | 修改 | 新增 updatePostMediaBatch 方法 + import |
| 3 | `Contracts.kt` | 修改 | PostRepository 接口新增 updatePostMediaBatch 抽象方法 |
| 4 | `RealRepositories.kt` | 修改 | RealPostRepository 新增实现 + import |
| 5 | `FakeRepositories.kt` | 修改 | FakePostRepositoryShell 新增 FAKE 实现 |
| 6 | `RealPostEditingViewModels.kt` | 修改 | save() 逐个删除循环改为一次批量请求 |

### 实施过程

1. PostDto.kt 新增 `UpdatePostMediaBatchRequestDto(removeMediaIds: List<String>)` + typealias `UpdateSmallAlbumMediaBatchRequestDto`
2. SmallAlbumApi.kt 新增 `@PATCH("api/small-albums/{smallAlbumId}/media-batch")` 方法
3. Contracts.kt PostRepository 接口新增 `updatePostMediaBatch(postId, removeMediaIds)` 抽象方法
4. RealRepositories.kt 新增 RealPostRepository 实现（runCatching + fold + ApiResult 模式）
5. FakeRepositories.kt 新增 FakePostRepositoryShell 实现（NOT_IMPLEMENTED，与现有 FAKE 风格一致）
6. RealPostEditingViewModels.kt save() 改造：
   - 原：`removedIds.forEach { mediaId -> RepositoryProvider.mediaRepository.deleteMediaFromPost(...) }`（N 次请求）
   - 新：`if (removedIds.isNotEmpty()) postRepository.updatePostMediaBatch(route.postId, removedIds)`（1 次请求）
7. `gradlew.bat assembleDebug` 验证通过

### 语义变化

- 原：逐个删除，首个失败记录但不中断（部分成功可能）
- 新：一次批量请求，全部成功或全部失败（@Transactional 原子性）

## 六、FR-7: 合并逻辑统一

### 变更文件

| # | 文件 | 变更类型 | 说明 |
|---|------|---------|------|
| 1 | `PostMediaMergeUtils.kt` | 新建 | 泛型共享合并函数 |
| 2 | `GearEditScreen.kt` | 修改 | 删除 mergeDraftPostMediaWithRepoAdditions，L146 调用改为共享函数 |
| 3 | `RealPostEditingViewModels.kt` | 修改 | 删除 mergeMediaDraftWithRemoteAdditions，L226 调用改为共享函数 |

### 实施过程

1. 新建 `PostMediaMergeUtils.kt`：泛型函数 `<T, U> mergeMediaDraftWithRemoteAdditions`，通过 `currentIdSelector`、`latestIdSelector`、`transformLatest` 三个 lambda 注入差异逻辑
2. GearEditScreen.kt：
   - L146 调用改为共享函数，`transformLatest = { it.toPostMediaListItem() }`
   - 删除原 `mergeDraftPostMediaWithRepoAdditions` 私有函数
3. RealPostEditingViewModels.kt：
   - L226 调用改为共享函数，`transformLatest = { it.copy(isCover = false) }`
   - 删除原 `mergeMediaDraftWithRemoteAdditions` 私有函数
4. `gradlew.bat assembleDebug` 验证通过

### 关键设计

- 泛型 `<T, U>` 支持跨类型合并（GearEditScreen 跨 PostMediaListItem ↔ ManagedPostMediaUiModel）
- `transformLatest` lambda 保留各自 isCover 语义差异
  - GearEditScreen: `toPostMediaListItem()` 不重置 isCover
  - RealPostEditingViewModels: `copy(isCover = false)` 强制清零封面标记
