## 二、FR-1 拆分边界分析

### 2.1 拆分文件规划

| # | 目标文件 | 预估行数 | 职责 | 目标行数 |
|---|---------|---------|------|---------|
| 1 | PostDetailScreen.kt（精简后） | ~1010 | 主入口 + 状态管理 + 布局骨架 | ≤800（需精简旧版组件） |
| 2 | SmallAlbumDetailHeader.kt | ~470 | 标题/所属头像/简介/时间/元信息/所属大相册 Chip | ~400 |
| 3 | SmallAlbumMediaGrid.kt | ~1390 | 媒体网格 + 密度缩放动画 + overlay 插值 | ~760（超目标但高内聚） |
| 4 | SmallAlbumAtmosphereBackdrop.kt | ~126 | 氛围背景多层渐变 | ~100 |
| 5 | SmallAlbumCommentSheets.kt | ~800 | 小相册评论 + 媒体评论 | ~500（超目标） |

**行数偏差说明**:
- SmallAlbumMediaGrid.kt（~1390 行）：密度缩放系统（SmallAlbumDensityTransitionStage + Animatable 进度驱动 + overlay 插值函数群）与媒体网格强耦合，共享 `densityMorphProgress`、`viewportBounds`、`itemBoundsByMediaId` 等状态，不可进一步拆分。
- SmallAlbumCommentSheets.kt（~800 行）：评论系统含小相册评论和媒体评论两套 sheet，各自含列表+输入+状态管理，内聚度高。
- PostDetailScreen.kt（~1010 行）：含主入口 PostDetailScreen + PostDetailScreenContent 状态管理骨架 + 部分旧版组件，需精简旧版组件（SmallAlbumMemoryPreviewStrip、SmallAlbumPreviewTile 等疑似死代码）以达到 ≤800 行。

### 2.2 共享状态分析（必须保留在主文件中）

密度缩放动画系统的核心状态（跨多个 Composable 共享）：
- `densityMorphProgress: Animatable<Float, AnimationVector1D>` — 密度缩放进度
- `SmallAlbumDensityTransitionStage`（IDLE/PREVIEW/COMMIT 三态）— 密度阶段
- `viewportBounds: Rect` — 视口边界
- `itemBoundsByMediaId: SnapshotStateMap<String, Rect>` — 各媒体项边界
- `selectionMode: MutableState<Boolean>` — 选择模式
- `selectedMediaIds: SnapshotStateList<String>` — 选中媒体集合

**结论**: 密度缩放状态必须保留在主文件 PostDetailScreen.kt 中，通过参数下传给 SmallAlbumMediaGrid.kt。

### 2.3 拆分风险点

| # | 风险 | 严重度 | 缓解措施 |
|---|------|--------|---------|
| 1 | 密度缩放 overlay 与媒体网格强耦合 | 高 | 密度缩放相关 Composable 和 overlay 插值函数群整体迁入 SmallAlbumMediaGrid.kt |
| 2 | 闭包依赖（内部 Composable 捕获外部状态） | 中 | 拆分时将捕获的状态显式参数化 |
| 3 | 旧版组件死代码（SmallAlbumMemoryPreviewStrip、SmallAlbumPreviewTile） | 低 | 调研调用方，确认无调用后删除以精简主文件 |
| 4 | import 依赖迁移遗漏 | 中 | 每拆分一个文件立即编译验证 |

### 2.4 拆分实施顺序

按依赖关系从底层到上层：
1. SmallAlbumAtmosphereBackdrop.kt — 最独立，无外部依赖
2. SmallAlbumCommentSheets.kt — 评论系统，依赖 CommentRepository
3. SmallAlbumDetailHeader.kt — 信息头，依赖 RemotePostDetail 模型
4. SmallAlbumMediaGrid.kt — 媒体网格，依赖密度缩放状态（参数化传入）
5. PostDetailScreen.kt — 精简为主入口 + 状态管理 + 布局骨架

每拆分一个文件后立即 `gradlew.bat assembleDebug` 编译验证。

### 3.4 participantUserIds 双重校验逻辑

**DTO 层**（CreatePostRequest）:
- `@NotNull`
- `@Size(min=1)` — 至少一个所属
- `@NotBlank` — 每个元素非空

**Service 层**（normalizeParticipantUserIds）:
- 空集合 -> 抛 `VALIDATION_ERROR`
- `LinkedHashSet` 去重保序
- 返回 `List<String>`

**UpdatePostRequest**:
- `participantUserIds` 无 `@NotNull`（null = 不更新）
- 非空时走相同校验
