## 四、模块精修总结

### 整体成果

**架构治理**：
- `PostDetailScreen.kt` 从 4352 行拆分为 5 个文件（771 + 688 + 2003 + 107 + 806 行）
- 创建页引入 `PostComposerViewModel`（485 行），结束无 ViewModel 状态
- 重复合并逻辑提取为 `PostMediaMergeUtils.kt` 泛型共享函数

**服务端**：
- 新建 `PostIntegrationTest`（22 个测试覆盖 8 端点 + 所属校验 + 批量删除 7 边界场景）
- 新增 `PATCH /api/posts/{postId}/media-batch` 批量删除端点，编辑保存从 N 次请求降为 1 次

**代码质量**：
- 18 处 `MaterialTheme.colorScheme` 全部替换为 YingShiThemeTokens
- 2 处编码损坏字符串清理
- `post-api.md` 补充 `participantUserIds` 文档

**视觉精修**：
- 详情页：信息卡玻璃容器 + 标题 24sp Bold + 简介融入背景 + 媒体卡片玻璃表面 + 缩放光晕 overlay + 同源氛围背景
- 创建页：玻璃预览卡片 + 头像芯片动效 + token 按钮
- 编辑页：按钮间距收紧 + 预览统一 + chips 光晕
- 小相册卡片：透明背景 + 深色遮罩 + Bold 文字层次 + 饱和金色张数

**Bug 修复**：
- 详情页无限加载：Success 分支数据转换加 try-catch 保护
- 批量删除后封面未同步：自动补偿逻辑
- 合并函数重复 id 边界：latestById.forEach 去重

### 关键教训
- **数据转换需要 try-catch 保护**：Repository 的 runCatching 只保护网络调用，后续的数据映射可能因异常数据崩溃
- **Surface 阴影在浅色背景上产生白色光晕**：透明卡片应同时去掉阴影
- **文件拆分用正则匹配 @Composable**：避免行号截取遗漏注解行
