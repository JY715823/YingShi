# 生活首页 需求文档

> 版本: v1.0 | 日期: 2026-07-17 | 状态: 已确认

## 一、模块目标

生活首页精修后达到：LifeConsoleScreen 有独立 ViewModel（从 1492 行瘦身）、LifeScreen 三张卡片展示动态摘要数据（今日痕迹媒体数/记账最近金额/聊天消息数）、路由管理用 sealed class 替代互斥 boolean、跨文件重复逻辑统一提取、时间 API 统一 java.time、问候语响应式更新、Widget Controller 拆分。

## 二、功能需求

### FR-1: LifeConsoleScreen 提取 ViewModel

**描述**: 当前 `LifeConsoleScreen.kt`（1492行）没有 ViewModel，所有状态（snapshot/history/loading/notice/pendingDelete 等）和业务逻辑（loadToday/loadHistory/uploadMedia/deleteMedia/bowelAdd/bowelRemove）全在 Composable 内用 `remember { mutableStateOf }` 管理。提取 `LifeConsoleViewModel`。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: 新建 `LifeConsoleViewModel.kt`，继承 `ViewModel`
- AC-2: 状态管理（snapshot/history/isLoading/notice/pendingDelete 等）移入 ViewModel，通过 StateFlow 暴露
- AC-3: 业务逻辑（loadToday/loadHistory/uploadMedia/deleteMedia/bowelAdd/bowelRemove）移入 ViewModel
- AC-4: LifeConsoleScreen Composable 只负责 UI 渲染，通过 `viewModel.uiState.collectAsState()` 获取状态
- AC-5: 跨零点自动刷新、SyncVersionTracker stale 刷新、ON_RESUME 刷新逻辑移入 ViewModel
- AC-6: 编译通过，功能行为不变

**涉及文件**:
- 新建 `app/src/main/java/com/example/yingshi/feature/life/LifeConsoleViewModel.kt`
- `app/src/main/java/com/example/yingshi/feature/life/LifeConsoleScreen.kt`

---

### FR-2: LifeScreen 卡片接入动态摘要数据

**描述**: 当前三张卡片是纯静态文本（"记账"/"聊天记录"/"今日痕迹"），信息密度全项目最低。接入动态摘要数据，让卡片展示实时信息。

**端**: Android

**优先级**: P0

**验收标准**:
- AC-1: 今日痕迹卡片显示当日媒体数量（如"今日 4 张"或"今天还没有痕迹"）
- AC-2: 记账卡片显示最近一笔金额或本月笔数（如"本月 23 笔"或"最近: -¥35 午餐"）
- AC-3: 聊天记录卡片显示最新消息数或未读数（如"128 条消息"或"3 条未读"）
- AC-4: 摘要数据从已有 API/Room 获取，不新增 Server 端点
- AC-5: 数据加载失败时卡片降级为静态文案，不影响导航功能
- AC-6: 编译通过

**涉及文件**:
- `app/src/main/java/com/example/yingshi/feature/life/LifeScreen.kt`
- 可能需要新建 `app/src/main/java/com/example/yingshi/feature/life/LifeSummaryViewModel.kt`（或在 LifeScreen 内用 produceState）

---

### FR-3: 路由管理 sealed class 化

**描述**: YingShiApp 中用 4 个互斥 boolean（ledgerRouteActive/lifeConsoleRouteActive/chatViewerRouteActive/...）控制生活模块路由，每次切换需手动重置其他 3 个，易出错。改为 sealed class。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: 新建 `sealed class LifeSubRoute { object Home; object Console; object Ledger; object Chat }`
- AC-2: YingShiApp 中 4 个 boolean 替换为单个 `LifeSubRoute` 状态
- AC-3: 所有路由切换逻辑（onOpenLedger/onOpenLifeConsole/onOpenChatViewer/onBack）更新为设置 LifeSubRoute
- AC-4: AppNavigationRequests 的外部触发（openLifeConsoleNonce 等）适配新路由
- AC-5: 编译通过，路由行为不变

**涉及文件**:
- `app/src/main/java/com/example/yingshi/app/YingShiApp.kt`（L1602-1648 路由分发）
- `app/src/main/java/com/example/yingshi/app/AppNavigationRequests.kt`

---

### FR-5: Calendar → java.time + 硬编码清理

**描述**: LifeScreen 用 `java.util.Calendar`，LifeConsoleScreen 用 `java.time`，不一致。时区 "Asia/Shanghai" 在 5 处硬编码。硬编码颜色值（LifeFramePalette 等）未走 Theme Token。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: LifeScreen 问候语计算改用 `LocalTime.now()` 和 `LocalDate.now()`
- AC-2: 时区 "Asia/Shanghai" 提取为 `LifeConsoleConstants.ZONE_ID` 常量
- AC-3: `LifeFramePalette` / `LifePersonGradient` / `LifeMealGradient` 硬编码颜色改为参数化或移入 Theme Token
- AC-4: 编译通过

**涉及文件**:
- `app/src/main/java/com/example/yingshi/feature/life/LifeScreen.kt`
- `app/src/main/java/com/example/yingshi/feature/life/LifeConsoleScreen.kt`
- 新建 `app/src/main/java/com/example/yingshi/feature/life/LifeConsoleConstants.kt`（或放入 LifeConsoleUtils.kt）

### FR-6: 问候语响应式更新

**描述**: 当前 `LaunchedEffect(Unit)` 只执行一次，跨时段不会刷新（如上午进入，到下午问候语不变）。改为 ON_RESUME 时重新计算。

**端**: Android

**优先级**: P1

**验收标准**:
- AC-1: 问候语在 LifeScreen 进入时计算
- AC-2: 从后台返回时（ON_RESUME）重新计算问候语
- AC-3: 跨时段（5点/12点/18点边界）自动切换
- AC-4: 编译通过

**涉及文件**:
- `app/src/main/java/com/example/yingshi/feature/life/LifeScreen.kt`

---

无数据模型变更。全部为 Android 端代码重构。
