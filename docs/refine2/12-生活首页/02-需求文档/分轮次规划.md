## Round 1: P0 架构升级

**预估**: 大
**依赖**: 无（首轮）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-1 | LifeConsoleScreen 提取 ViewModel | Android | P0 | 1492行瘦身，状态+业务逻辑移入 ViewModel |
| FR-2 | LifeScreen 卡片接入动态摘要数据 | Android | P0 | 三张卡片展示实时摘要（痕迹数/记账金额/聊天消息） |

**本轮重点**:
- **实施顺序**: FR-1 → FR-2
  1. FR-1 先做：新建 `LifeConsoleViewModel.kt`，将 snapshot/history/loading/notice/pendingDelete 等状态和 loadToday/loadHistory/uploadMedia/deleteMedia/bowelAdd/bowelRemove 等业务逻辑移入。LifeConsoleScreen 改为 collectAsState() 获取状态。跨零点刷新、SyncVersionTracker stale、ON_RESUME 刷新逻辑一并移入 ViewModel。
  2. FR-2 然后做：在 LifeScreen 中接入动态摘要数据。今日痕迹从 GET /api/life-console/today 获取媒体数量；记账从 Room 本地获取最近交易；聊天从 Room 本地获取消息数。异步加载，失败降级为静态文案。
- FR-1 改动面最大（1492行重构），需逐方法确认无遗漏
- FR-2 需要新增数据获取逻辑，但不新增 Server 端点

**前置条件**: 无

## Round 2: P1 代码质量

**预估**: 中
**依赖**: Round 1（FR-4 依赖 FR-1 拆分后的文件结构）
**包含需求**:

| FR编号 | 需求名称 | 端 | 优先级 | 简述 |
|--------|---------|-----|--------|------|
| FR-3 | 路由管理 sealed class 化 | Android | P1 | 4个boolean → LifeSubRoute sealed class |
| FR-4 | 跨文件重复逻辑提取 | Android | P1 | isVideo/乐观更新/URL工具/formatTime 统一 |
| FR-5 | Calendar→java.time + 硬编码清理 | Android | P1 | 时区常量+颜色Token化 |
| FR-6 | 问候语响应式更新 | Android | P1 | ON_RESUME 重新计算问候语 |

**本轮重点**:
- **实施顺序**: FR-6 → FR-5 → FR-4 → FR-3
  1. FR-6 先做：最小改动，LifeScreen 问候语改为 ON_RESUME 重新计算
  2. FR-5 然后做：Calendar→java.time + 时区常量 + 颜色清理
  3. FR-4 接着做：跨文件重复逻辑提取到 LifeConsoleUtils.kt
  4. FR-3 最后做：路由 sealed class 化，影响 YingShiApp 全局路由
- FR-3 改动影响面最大（YingShiApp 路由分发），需逐路由验证
- FR-4 涉及 5+ 文件，需全局搜索确认所有引用更新

**前置条件**: Round 1 完成
