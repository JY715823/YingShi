## 二、用户流程

### 流程1: 生活首页导航
用户点击底部导航"生活"Tab → LifeScreen 展示三张入口卡片（记账/聊天记录/今日痕迹）+ 时间问候 → 点击卡片 → YingShiApp 路由切换到对应子页面。
涉及: `LifeScreen.kt`, `YingShiApp.kt`

### 流程2: 今日痕迹完整流程
用户点击"今日痕迹"卡片 → LifeConsoleScreen 加载 GET /api/life-console/today → 展示4格媒体+排便记录 → 可上传媒体/删除媒体/加减排便 → 查看历史记录。
涉及: `LifeConsoleScreen.kt`, `LifeConsoleUploadBridge.kt`, `LifeConsoleService.java`

### 流程3: 推送→生活痕迹跳转
Server 生活痕迹变更 → FCM推送 life_console.changed → B设备系统通知栏 → 用户点击 → LifePushDispatchActivity → 解析 targetRoute → 打开对应媒体。
涉及: `PushNotificationService.java`, `YingShiFirebaseMessagingService.kt`, `LifePushDispatchActivity.kt`

## 三、数据流向

### 生活首页（纯导航）
LifeScreen 无数据请求。三张卡片为静态文本，通过 lambda 回调驱动路由切换。

### 今日痕迹（完整数据流）
```
Server LifeConsoleService.getToday()
  → 聚合用户/伴侣/媒体/排便数据
  → GET /api/life-console/today
  → Android LifeConsoleApi (Retrofit)
  → RealLifeConsoleRepository
  → LifeConsoleScreen Composable 状态
```

### 跨模块交互
- **同步系统**: SyncVersionTracker LIFE_CONSOLE 模块 → stale 驱动刷新
- **推送系统**: 生活痕迹变更 → FCM life_console.changed
- **回收站**: 删除媒体走 TrashService
- **Widget**: LifeConsoleWidgetProvider/Store 独立数据层
- **记账**: Room v4 本地 + POST /api/ledger/sync 增量同步
- **聊天**: Room v3 本地 + POST /api/chat/imported/sync 增量同步

## 七、代码质量评估

### 架构问题

| # | 问题 | 严重度 | 位置 | 说明 |
|---|------|--------|------|------|
| 1 | **LifeConsoleScreen 1492行无ViewModel** | 高 | LifeConsoleScreen.kt | 所有状态+业务逻辑在Composable内 |
| 2 | **LifeScreen 卡片纯静态无动态数据** | 中 | LifeScreen.kt | 信息密度全项目最低 |
| 3 | **路由管理用4个互斥boolean** | 中 | YingShiApp.kt | 每次切换需手动重置其他3个 |
| 4 | **跨文件重复逻辑** | 中 | 5+处 | isVideo/乐观更新/URL工具/formatTime |
| 5 | **Calendar vs java.time 混用** | 低 | LifeScreen vs LifeConsoleScreen | 不一致 |
| 6 | **硬编码时区(5处)** | 低 | 多处 | "Asia/Shanghai"应提取常量 |
| 7 | **硬编码颜色值** | 低 | LifeConsoleScreen | LifeFramePalette等未走Token |
| 8 | **问候语不随时间更新** | 低 | LifeScreen.kt L63 | LaunchedEffect(Unit)只执行一次 |
| 9 | **Widget Controller 618行** | 中 | LifeConsoleWidgetProvider | 可拆分 |
