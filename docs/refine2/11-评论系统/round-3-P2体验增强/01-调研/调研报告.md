## 一、FR-8: CommentInputBar 统一 TextFieldValue

### 当前状态

[CommentInputBar](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/CommentComponents.kt) (L64-169) 使用 `String` 管理输入状态：

- L76: `var value by rememberSaveable(stateKey) { mutableStateOf("") }`
- L126: `onValueChange = { value = it }` (String)
- L158-162: 发送时手动 trim → `onSend(trimmed)` → `value = ""`

**问题**: `CommentInteractionState` 中的 `editingDraft` 和 `selectedCommentValue` 已是 `TextFieldValue` 类型，但 CommentInputBar 使用 `String`，导致编辑模式需要手动转换。

### 调用方清单

| # | 调用方 | 文件 | 行号 | value 来源 |
|---|--------|------|------|-----------|
| 1 | RealCommentThreadContent (新建评论) | CommentComponents.kt | ~L860 | 无初始值 (String="") |
| 2 | RealCommentThreadContent (编辑评论) | CommentComponents.kt | ~L816 | `interactionState.editingDraft.text` (TextFieldValue.text) |
| 3 | FakeSmallAlbumCommentSheet | SmallAlbumCommentSheet.kt | ~L250 | 无初始值 (String="") |
| 4 | PhotoViewerCommentSheet | ViewerCommentSheet.kt | ~L103 | 无初始值 (String="") |

### 技术约束

- 编辑模式传 `editingDraft.text` 给 `onSend`，丢失了光标位置
- 需要新增 `value: TextFieldValue` 参数和 `onValueChange: (TextFieldValue) -> Unit` 参数
- 发送后需清空为 `TextFieldValue("")`
- 3 个调用方需要同步更新

## 二、FR-7: Popup 操作菜单动画

### 当前状态

[CommentInlineActionMenu](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/CommentComponents.kt) (L373-416) 是评论的长按操作菜单，包含"复制/选择/编辑/删除"四个操作项。

**触发方式** (L349-367):
- 通过 `showInlineActionMenu` 条件控制 `Popup` 的显示/隐藏
- `showInlineActionMenu = interactionState.actionCommentId == comment.id && !interactionState.showSelectedCommentNotice`
- 使用标准 `Popup` + `PopupProperties(focusable=true, dismissOnBackPress=true, dismissOnClickOutside=true)`

**当前无动画**: 菜单出现和消失是即时的，无过渡效果。

### 动画资源

- [YingShiMotion.kt](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/ui/components/YingShiMotion.kt) 已有 `rememberYingShiMotionEnabled()` 函数（L25-31），检查系统动画设置
- [Tokens.kt](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/ui/theme/Tokens.kt) L91: `floatingMillis: Int = 220`
- L117: `easing: Easing = FastOutSlowInEasing`
- `AnimatedVisibility` 是 Compose Foundation 的标准组件，可直接使用

### 技术约束

- 需使用 `AnimatedVisibility` + `fadeIn`/`scaleIn` + `fadeOut`/`scaleOut`
- 进入动画 ~150ms，退出动画 ~100ms
- 遵循 `rememberYingShiMotionEnabled()` 减少动画设置

## 三、FR-6: 评论列表分页

### 当前状态

[CommentThreadManager](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/feature/photos/CommentThreadManager.kt) (L31-54) `loadMediaComments` 只请求 page=1：

- L43: `commentRepository.getMediaComments(mediaId).toCommentListState()` — 无 page 参数

**数据层已支持分页**:
- [Contracts.kt](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/data/repository/Contracts.kt) L129-133: `getMediaComments(mediaId, page=1, size=20)`
- [CommentRepositoryModels.kt](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/data/model/CommentRepositoryModels.kt) L9: `CommentListState` 有 `hasMore: Boolean = false` 字段
- [RemoteModels.kt](file:///E:/Study/App/YingShi/app/src/main/java/com/example/yingshi/data/model/RemoteModels.kt) L47: `RemoteCommentPage` 有 `hasMore: Boolean`

**缺失**:
- `RealCommentThreadUiState` 没有 `hasMore` 字段
- `CommentThreadManager` 没有 `loadMoreMediaComments` 方法
- `RealCommentThreadContent` 使用 `LazyColumn` 列表，但没有滚动到底部加载更多的逻辑

### 参考实现

项目中已有分页加载示例（通知中心等），使用 `LazyColumn` + 检测最后一项可见性触发加载。

### 技术约束

- 需要在 `RealCommentThreadUiState` 添加 `hasMore: Boolean` 和 `currentPage: Int` 字段
- 需要在 `CommentThreadManager` 添加 `loadMoreMediaComments(mediaId)` 方法
- 需要在 `RealCommentThreadContent` 添加滚动到底部检测 + loading 指示器
- `toThreadUiState` 需要传递 `hasMore`
