## 二、用户流程

### 流程1: 查看小相册评论
用户在小相册详情页点击评论图标 → 打开底部评论弹窗（RealSmallAlbumCommentSheet）→ 加载评论列表（默认显示10条，超出折叠）→ 可展开查看全部。
涉及: `PostDetailScreen.kt`, `SmallAlbumCommentSheets.kt`, `CommentComponents.kt`, `RealPhotoViewModels.kt`

### 流程2: 查看媒体评论
用户在 Viewer 中点击评论预览/按钮 → 打开深色评论弹窗（PhotoViewerCommentSheet）→ 加载评论列表 → 可编辑/删除/复制/选择。
涉及: `PhotoViewerScreen.kt`, `ViewerCommentSheet.kt`, `ViewerOverlayChrome.kt`, `RealViewerCommentViewModel.kt`

### 流程3: 发送评论
用户在评论输入栏输入内容 → 点击发送 → API 创建评论 → 乐观添加到列表 → 成功后刷新 + 触发推送通知 + 通知 NotificationCenterLocalStore。
涉及: `CommentComponents.kt`(CommentInputBar), `RealPhotoViewModels.kt`/`RealViewerCommentViewModel.kt`, `CommentService.java`, `PushNotificationService.java`

### 流程4: 推送→评论跳转
A 发送评论 → Server 异步 FCM 推送 → B 点击通知 → MainActivity 解析深链接 → 打开小相册详情/Viewer → 自动打开评论弹窗 → 定位到目标评论（高亮2.4s）。
涉及: `PushNotificationService.java`, `MainActivity.kt`, `YingShiApp.kt`, `AppNavigationRequests.kt`

## 三、数据流向

### 评论读取
```
Server CommentRepository (active-only, partial index)
  → CommentController GET
  → Android CommentApi (Retrofit)
  → RealCommentRepository
  → PostDetailRealViewModel / RealViewerCommentViewModel
  → CommentListState → UI State
  → collectAsState() → CommentComponents
```

### 评论写入
```
CommentInputBar.onSend()
  → ViewModel.createComment()
  → CommentRepository → Server CommentController POST
  → CommentService.createComment() → DB
  → [afterCommit] PushNotificationService.notifyPhotoChanged() → FCM
  → [Success] Android: notifyRealBackendCommentChanged → RealBackendMutationBus
  → [Success] SyncVersionTracker.markLocalMutation
  → [Success] NotificationCenterLocalStore.pushCommentNotification
  → [Success] reload from API → update StateFlow
```

### 跨模块交互
- **通知系统**: NotificationService 直接读 CommentRepository 生成评论通知事件
- **推送系统**: CommentService 调用 PushNotificationService.notifyPhotoChanged
- **同步系统**: CommentRepository.findLatestUpdatedAtByLibraryId（方法存在但未被 Service 调用）
- **回收站**: 删除小相册/媒体时级联删除评论

## 七、代码质量评估

### 架构问题

| # | 问题 | 严重度 | 位置 | 说明 |
|---|------|--------|------|------|
| 1 | **评论交互状态大量重复** | 高 | RealCommentThreadContent / FakeSmallAlbumCommentSheet / PhotoViewerCommentSheet | 三处各管6-7个几乎相同的状态变量（actionCommentId, editingCommentId, editingDraft, selectedCommentId, pendingDeleteCommentId, selectedCommentValue），~200+行重复 |
| 2 | **SmallAlbumCommentSheets.kt 过大** | 高 | 806行 | 混合Fake/Real/Media/Summary 7个Composable |
| 3 | **RealPhotoViewModels.kt 过大** | 中 | 1452行，评论占~485行 | PostDetailRealViewModel 承担详情+全部评论管理 |
| 4 | **CommentGateway 硬编码走 Fake** | 中 | CommentGateway.kt L14-46 | 同步方法直接调FakeCommentRepository，REAL模式下Fake弹窗仍显示假数据 |
| 5 | **两个ViewModel评论逻辑重复** | 中 | RealViewerCommentViewModel vs PostDetailRealViewModel | ~200行 loadMediaComments/mutateMediaComments 高度相似 |
| 6 | **CommentInputBar 用 String 而非 TextFieldValue** | 低 | CommentComponents.kt L60-165 | 与编辑模式的 TextFieldValue 管理不一致 |
| 7 | **Popup 操作菜单无动画** | 低 | CommentComponents.kt L345-364 | 直接显示/消失 |
| 8 | **评论列表无分页** | 低 | 前端只请求 page=1，hasMore 字段返回但未使用 | 评论多时性能风险 |
| 9 | **中文字符串全部硬编码** | 低 | 多处 | "发送"/"复制"/"删除" 等散布各文件 |
| 10 | **两处时间格式化** | 低 | formatPostTime / formatViewerTime | 不同入口可能格式不一致 |
