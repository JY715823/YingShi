## 二、用户流程

### 流程1: 查看今日痕迹
用户在桌面看到Console小组件 → 显示吃饭(对方/自己)相框各一张最新照片+大便计数+账本按钮。数据来源：SharedPreferences本地快照(先渲染) → 后台GET /api/life-console/today拉新 → 存快照 → 重渲染 → 预热缩略图 → 三渲染。刷新触发：FCM life_console.changed / SyncVersionTracker stale检测(前台3s后台30s轮询) / 30min系统周期 / 手动点"刷新"。
涉及: LifeConsoleWidgetProvider.kt, LifeConsoleWidgetController, ConsoleWidgetBuilder.kt, LifeConsoleWidgetStore.kt, life_console_widget.xml

### 流程2: 从Widget上传照片
点"+"按钮 → WidgetMediaEntryActivity(透明中转页，Compose UI) → 相册选择(最多20张)/拍照/拍视频 → LifeConsoleUploadRuntime.enqueueWidgetUpload() → createToken(operationType=life_console, domain=life) → 上传(中转或MinIO直传+confirm) → addMedia(category, mediaIds) → 返回快照applySnapshot → widget即时刷新。上传前refreshAll(即时反馈)，失败回退refreshAll。拍照路径：createCaptureUri存cacheDir不进MediaStore；上传成功后延迟5s清理MIUI相机副本。
涉及: WidgetMediaEntryActivity.kt, LifeConsoleUploadBridge.kt, LifeConsoleUploadRuntime, WidgetPendingIntentFactory.kt

### 流程3: 大便快捷记录
点"+加号" → BOWEL_ADD广播 → Controller乐观更新本地快照(计数+1) → 渲染 → POST /api/life-console/bowel-events → 失败则restoreSnapshot回滚。"-减号"同理调DELETE latest。
涉及: LifeConsoleWidgetController, LifeConsoleWidgetStore.updateBowelOptimistically()

### 流程4: 推送到达与点击
对方操作 → 服务端事务提交后PushDispatchSupport.afterCommitAsync(虚拟线程) → FirebasePushMessageSender发data message(仅对方token，排除操作者) → 客户端YingShiFirebaseMessagingService收到life_console.changed → 三路并行：widget refreshAll + SyncVersionTracker即时轮询 + PushNotificationPresenter展示通知(actor自过滤+2min去重+渠道路由life:trace振动通道)。点击通知 → LifePushDispatchActivity → refreshAll + 按route解析目标媒体 → LifeMediaQuickViewerActivity快速查看。
涉及: PushNotificationService.java, LifeConsoleService.java, YingShiFirebaseMessagingService.kt, PushNotificationPresenter.kt, LifePushDispatchActivity.kt

### 流程5: 照片翻页
相框内"‹ ›"文字按钮 → SLOT_PREV/SLOT_NEXT广播 → Controller改SharedPreferences中index_<slot> → 重渲染。非RemoteViews集合控件，无过渡动画。
涉及: LifeConsoleWidgetController.handleReceive(), ConsoleWidgetBuilder.bindSlot()

## 三、数据流向

**上行（Widget→Server）**：Widget操作 → LifeConsoleUploadBridge/Controller → Retrofit API(UploadApi/LifeConsoleApi) → 服务端UploadService/LifeConsoleService → PostgreSQL(media/bowel_events/small_album_media) + MinIO(文件存储，domain=life前缀隔离)。

**下行（Server→Widget）**：三条路径汇聚 → ①FCM data message(life_console.changed) ②SyncVersionTracker轮询/api/sync/versions ③App内操作直接applySnapshot → 统一入口LifeConsoleWidgetProvider.refreshAll()/applySnapshot() → GET /api/life-console/today → RemoteLifeConsoleToday DTO(4 slot: personSelf/personPartner/mealSelf/mealPartner + bowelEvents + currentUser) → Gson序列化存SharedPreferences → RemoteViews渲染 → 缩略图HttpURLConnection+Bearer下载缓存。

**与模块13（今日足迹）的关系**：共享同一API(/api/life-console/today)、同一Repository(RealLifeConsoleRepository)、同一上传通道(LifeConsoleUploadBridge)、同一同步标记(SyncVersionTracker LIFE_CONSOLE)。但UI层完全独立：页面是Compose(LifeConsoleScreen)，Widget是RemoteViews；缓存也独立：页面用AppReadCacheStore，Widget用SharedPreferences快照——两套缓存可能不一致。

**服务端无Widget概念**：服务端仅通过operationType=LIFE_CONSOLE识别来源，职责为接受上传+抑制photos push+发送life变更推送。Widget渲染调度完全是客户端行为。

## 七、UI现状深度评估（用户反馈核心）

### 当前视觉画像

**配色**：主标题#2962FF(Material Blue A700电光蓝)、分区标签#00BFA5(Material Teal A700荧光青)、强调条#2979FF→#00BCD4→#00E676三色彩虹、大便数字#183B4B、次要文字#5F7D89。

**App品牌token对照**：appBackground #F1FBFD(极浅青白)、primaryContainer #BDEFFF(珍珠玉蓝)、sectionBackground #DFF5F4(淡薄荷)、raisedSurface #FFFFFC(暖白)、titleAccent #26313A(深石板)、goldAccent #9A6A2A(香槟金)、glassStroke #A9E5F2。

### 核心问题诊断

1. **色相冲突**：Widget的#2962FF/#00BFA5是Material Accent系高饱和色，与App粉彩体系饱和度差一个量级。品牌红线"不要饱和霓虹蓝紫"，widget恰好踩线。
2. **彩虹强调条**：蓝→青→绿三色渐变是典型开发者审美，与"安静、私密、可信"品牌气质背离。App内标题光晕用暖金#FFF4D9+冷蓝#AEEBFF双色柔光。
3. **缺失暖色**：App有香槟金+暖白作温度来源，widget全冷蓝冷青，像医疗/工具类App。
4. **大便板块直白**：116dp固定高度、34sp巨大数字、"大便"二字直接糊桌面，无美感包装。
5. **照片直角溢出**：位图未裁圆角，方角戳出圆角面板。
6. **文字按钮廉价**：+、−、‹、›、删全是文本符号，无图标无pressed反馈。
7. **无深色模式**：全部硬编码浅色，深色壁纸下背板发灰。
8. **信息密度失衡**：4x5塞标题+2相框+大便卡+账本，照片区域被严重挤压，主角最小。
9. **无情感化设计**：作为两人私密相册，无任何"成对/陪伴"视觉隐喻，长得像通用打卡工具。
10. **设计割裂**：WidgetMediaEntryActivity用珍珠玉蓝Compose主题，widget本体是另一套高饱和配色，点"+"经历视觉跳跃。

### 未充分利用的RemoteViews手段

- android:theme挂theme实现深浅色自动适配（未用）
- 预渲染圆角位图(Canvas+Path裁切)或setRoundRectRadius(API 31+)（未用）
- ColorStateList/state selector drawable按压反馈（未用）
- ViewFlipper/ViewSwitcher照片切换过渡（未用）
- previewImage mipmap低版本兜底（缺失）
- 多套尺寸布局(layout-v31/宽窄变体)（未用）

### 架构评价（可完整保留）

Provider/Controller/Builder/Store/PendingIntentFactory五层解耦清晰，乐观更新+回滚、先渲染后拉取、缩略图缓存、五路刷新——工程质量扎实。重构UI时骨架完整保留，只改Builder层渲染逻辑+XML资源。
