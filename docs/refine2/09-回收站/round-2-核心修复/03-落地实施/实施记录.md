## 一、Server 端变更

### 1. ObjectStorageService.java（修改）
**变更**: 新增 `listByPrefix(String prefix, String contains)` default 方法，返回指定前缀下所有对象 key。
```java
default List<String> listByPrefix(String prefix, String contains) {
    return List.of();
}
```

### 2. S3ObjectStorageService.java（修改）
**变更**: 实现 `listByPrefix`，使用 `ListObjectsV2Request` 分页列出对象并按 `contains` 过滤。
- 新增 imports: `ListObjectsV2Request`, `ListObjectsV2Response`, `S3Object`
- 支持分页（continuationToken 循环）

### 3. LocalObjectStorageService.java（修改）
**变更**: 实现 `listByPrefix`，使用 `Files.walk` 扫描本地目录。
- 新增 imports: `ArrayList`, `List`, `Stream`
- 使用 `rootPath.relativize(path)` 将绝对路径转为相对 object key
- 过滤 `.sha256` checksum sidecar 文件

### 4. LocalMediaStorageService.java（修改）
**变更**: `deleteRemoteStoredMediaFiles` 从只删 3 个固定对象改为按前缀批量删除所有派生对象。
- 先删原图 `sourceObjectKey`
- 用 `listByPrefix(previewPrefix + "/" + cacheKey, cacheKey)` 列出所有 preview/cover 变体并逐个删除

### 5. PostMediaRepository.java（修改）
**变更**: 新增 `existsByLibraryIdAndMediaId(String libraryId, String mediaId)` 方法，用于级联清理时检查媒体是否仍被其他 post 引用。

### 6. TrashService.java（修改，4处）
**变更1**: `purgeSmallAlbumDeleted` — 新增级联删子媒体 + MinIO + MEDIA_SYSTEM_DELETED trash_items
- 调用 `purgeMediaSystemDeletedItemsForSmallAlbum` (新增)
- 调用 `purgeSmallAlbumCascade` (新增)

**变更2**: `purgeLargeAlbumDeleted` — 同上，对每个子小相册执行完整级联

**变更3**: `restoreMediaSystemDeleted` 指纹冲突分支 — 迁移 post_media 关系和封面引用到已存在的活跃媒体
- 遍历 snapshot.relations()，用 `restoreRelationOrder` 在已存在媒体上重建关系
- 遍历 snapshot.coverPostIds()，恢复封面到已存在媒体

**新增方法**:
- `purgeMediaSystemDeletedItemsForSmallAlbum`: 查找并彻底删除属于指定小相册的 MEDIA_SYSTEM_DELETED trash items
- `purgeSmallAlbumCascade`: 级联删除小相册内所有未被其他 post 引用的媒体文件 + DB 记录 + 评论

### 7. TrashIntegrationTest.java（修改）
**新增 4 个测试用例**:
- `purgeSmallAlbumCascadesMediaDeletion`: 验证 purge 小相册后媒体文件被删除
- `purgeLargeAlbumCascadesMediaDeletion`: 验证 purge 大相册后所有子媒体文件被删除
- `purgeSmallAlbumKeepsMediaReferencedByOtherAlbums`: 验证媒体被其他小相册引用时不被删除
- `restoreMediaSystemDeletedWithFingerprintConflictMigratesRelations`: 验证指纹冲突时关系迁移到已存在媒体
