## 二、发现的 Bug

### BUG-1: pendingEntries 僵尸条目（P1，已修复）

**问题**: `RealTrashViewModels.kt` L114 的 `lastKnownPendingEntries` 更新条件为 `if (successPendingItems.isNotEmpty())`，当用户撤销/永久删除最后一条待清理项后，后端返回空列表，`lastKnownPendingEntries` 不被清空，UI 仍显示僵尸条目。

**根因**: 更新条件应基于"请求是否成功"而非"列表是否非空"。空列表是有效数据（表示已无待清理项），应更新缓存。

**修复**: 将条件从 `if (successPendingItems.isNotEmpty())` 改为 `if (pendingResult is ApiResult.Success)`，确保只要 pending 请求成功就更新（包括清空）。请求失败时保留旧值（缓存路径仍可用）。

**验证**: Android 单元测试 RealTrashNavigationTest 11/11 PASS。

### BUG-2: purge 路径未通知 SYSTEM_MEDIA（P2，已修复）

**问题**: `RealTrashListScreen.kt` 的 `purgePendingEntry` 只通知 TRASH/PHOTO_FEED/ALBUMS，未通知 SYSTEM_MEDIA。purge MEDIA_SYSTEM_DELETED 项同样会影响系统媒体页的导入状态。

**根因**: purge 和 restore 两条路径的 SyncModule 通知不一致。

**修复**: 在 `purgePendingEntry` 追加 `SyncVersionTracker.markLocalMutation(SyncModule.SYSTEM_MEDIA)`。

**验证**: Android 编译 + 单元测试 PASS。

### BUG-3: deleteRemoteStoredMediaFiles contains 过滤偏离计划（P2，已修复）

**问题**: `LocalMediaStorageService.java` L874-875 的 `listByPrefix(derivedPrefix, cacheKey)` 使用 `cacheKey`（无连字符）作为 contains 过滤，可能误匹配前缀相近的 mediaId。实施计划指定 `cacheKey + "-"`。

**根因**: 实现时未严格遵循计划，contains 过滤过于宽松。

**修复**: 将 prefix 改为 `previewDirectoryObjectKey(storagePath) + "/"`（不含 cacheKey），contains 改为 `cacheKey + "-"`，与本地模式的 `cacheKey + "-preview-v2-"` 模式一致。

**验证**: Server 集成测试 13/13 PASS。

### BUG-4: S3ObjectStorageService 使用 FQN 而非简单名（P2，已修复）

**问题**: `S3ObjectStorageService.java` L208 使用 `java.util.List` 和 `java.util.ArrayList` 全限定名，与项目风格不一致。

**根因**: 新增代码时遗漏 import。

**修复**: 添加 `import java.util.ArrayList;`，将 FQN 改为简单名 `List<String> result = new ArrayList<>();`。

**验证**: Server 编译 + 测试 PASS。

### BUG-5: 指纹冲突测试存在冗余请求（P2，已修复）

**问题**: `TrashIntegrationTest.java` L436-439 发送了一次 GET 请求赋值给 `detailResult` 但未使用，L441-445 又重新发送一次。

**根因**: 测试编写时的冗余代码。

**修复**: 删除冗余的第一次 GET 请求，保留带断言的请求。

**验证**: Server 集成测试 13/13 PASS。
