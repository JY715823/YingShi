## 二、必须测试的影响路径清单

### IA-1: PhotosRootScreen 签名变更不影响其他调用方
- 路径: PhotosRootScreen 新增可选参数 → 默认值兼容 → 其他调用方无需修改
- 测试: Grep 确认 PhotosRootScreen 的所有调用点

### IA-2: SyncModule 枚举新增不影响现有 when 分支
- 路径: SyncModule.SYSTEM_MEDIA 新增 → isStale/markRefreshed when 分支需补全 → 否则编译错误
- 测试: 编译验证 + Grep 确认所有 when(SyncModule) 分支

### IA-3: TrashService purge 级联不影响 MEDIA_REMOVED purge
- 路径: purgeSmallAlbumDeleted 增强 → MEDIA_REMOVED purge 仍是空实现 → 不受影响
- 测试: TrashIntegrationTest.moveToPendingCleanupAndPurge 回归

### IA-4: restoreMediaSystemDeleted 指纹冲突分支修改不影响无冲突路径
- 路径: 冲突分支增强 → 无冲突路径不变 → 不受影响
- 测试: TrashIntegrationTest.systemDeleteCreatesTrashItemAndRestoreWorks 回归

### IA-5: ObjectStorageService.listByPrefix 新方法不影响现有 delete
- 路径: 新增方法 → 现有 delete/exists/get 不变 → 不受影响
- 测试: 编译验证 + 现有 LocalObjectStorageServiceTest 回归

### IA-6: deleteRemoteStoredMediaFiles 修改影响所有 purge 路径
- 路径: purgeMediaSystemDeleted 调用 deleteStoredMediaFiles → deleteRemoteStoredMediaFiles 增强 → 清理更彻底
- 测试: TrashIntegrationTest.purgeDirectlyFromInTrash 回归 + 新增多尺寸变体测试

### IA-7: YingShiApp trashDetailRoute BackHandler 修改影响通知中心返回
- 路径: 去掉 restoreNotificationCenter() → 通知中心不再自动恢复 → 用户需手动进入通知中心
- 测试: 验证从通知进入回收站详情 → 返回 → 回到回收站列表（非通知中心）

### IA-8: RealTrashViewModels lastKnownPendingEntries 跨 refresh 保留
- 路径: 新增字段 → refresh 成功时更新 → 缓存路径使用 → pendingEntries 不丢失
- 测试: 单元测试验证 pendingEntries 跨缓存路径保留
