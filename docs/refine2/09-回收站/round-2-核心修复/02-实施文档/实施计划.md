#### 变更1: RealTrashViewModels.kt — 修复 pendingEntries 缓存丢失

**问题1**: L649-662 `CachedTrashList.toUiState()` 中 `pendingEntries = emptyList()` 硬编码

**修复方案**: 将 pendingEntries 持久化到缓存，并在 toUiState 中恢复。

但缓存层 `AppReadCacheStore.writeTrashList` 当前只存储 `items`。为最小化改动，采用以下策略：
- 不修改缓存存储格式（避免迁移问题）
- 在 ViewModel 中维护 `lastKnownPendingEntries` 字段，跨 refresh 保留 pending 数据
- `CachedTrashList.toUiState()` 接收 pendingEntries 参数

```kotlin

    pendingEntries: List<TrashPendingCleanupUiModel> = lastKnownPendingEntries,
    isOfflineReadOnly: Boolean = false,
    statusMessage: String? = null,
): RealTrashListUiState {
    // ...
    pendingEntries = pendingEntries,
}

// refresh() 成功路径更新 lastKnownPendingEntries
lastKnownPendingEntries = successPendingItems.map { ... }

// 缓存路径使用 lastKnownPendingEntries
_uiState.value = cachedList.toUiState(pendingEntries = lastKnownPendingEntries)
```

**问题2**: L118-135 主列表失败时 early-return 丢弃 pending 结果

#### 变更2: TrashService.java — purge 彻底性修复

**问题1**: `purgeSmallAlbumDeleted` (L511-517) 不删子媒体+MinIO

**修复**: 改为级联删除小相册内所有媒体的 media 记录 + MinIO 文件 + 关联的 MEDIA_SYSTEM_DELETED trash_items

```java
private void purgeSmallAlbumDeleted(TrashItemEntity item, String libraryId) {
    TrashSnapshotHelper.SmallAlbumDeletedSnapshot snapshot = snapshotHelper.readSmallAlbumDeletedSnapshot(item);
    String smallAlbumId = snapshot.smallAlbumId();
    
    // 1. 级联清理子 MEDIA_REMOVED trash_items（原有）
    purgeMediaRemovedItemsForSmallAlbum(libraryId, smallAlbumId);
    
    // 2. 级联清理子 MEDIA_SYSTEM_DELETED trash_items + 其对应媒体+MinIO（新增）
    purgeMediaSystemDeletedItemsForSmallAlbum(libraryId, smallAlbumId);
    
    // 3. 删除该小相册的所有 post_media 关系（原有）
    postMediaRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
    
    // 4. 删除该小相册的评论（原有）
    commentRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
    
    // 5. 删除小相册 post 记录（原有）
    postRepository.findByIdAndLibraryId(smallAlbumId, libraryId).ifPresent(postRepository::delete);
}
```

新增辅助方法 `purgeMediaSystemDeletedItemsForSmallAlbum`：
- 查询 `findByLibraryIdAndStateAndItemTypeAndSourcePostId(libraryId, IN_TRASH, MEDIA_SYSTEM_DELETED, smallAlbumId)`
- 对每个找到的 trash_item，调用 `purgeMediaSystemDeleted(item, libraryId)` 彻底删除媒体+MinIO+关系+评论
- 删除这些 trash_items

**问题2**: `purgeLargeAlbumDeleted` (L519-528) 不删子媒体+MinIO

**修复**: 对每个子小相册调用增强后的 `purgeSmallAlbumDeleted` 逻辑：

```java
private void purgeLargeAlbumDeleted(TrashItemEntity item, String libraryId) {
    TrashSnapshotHelper.LargeAlbumDeletedSnapshot snapshot = snapshotHelper.readLargeAlbumDeletedSnapshot(item);
    for (String smallAlbumId : snapshot.smallAlbumIds()) {
        // 复用 purgeSmallAlbumDeleted 的完整级联逻辑（新增调用）
        purgeSmallAlbumCascade(libraryId, smallAlbumId);
    }
    albumRepository.findByIdAndLibraryId(snapshot.albumId(), libraryId).ifPresent(albumRepository::delete);
}

// 抽取共用方法
private void purgeSmallAlbumCascade(String libraryId, String smallAlbumId) {
    purgeMediaRemovedItemsForSmallAlbum(libraryId, smallAlbumId);
    purgeMediaSystemDeletedItemsForSmallAlbum(libraryId, smallAlbumId);
    postMediaRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
    commentRepository.deleteByLibraryIdAndPostId(libraryId, smallAlbumId);
    postRepository.findByIdAndLibraryId(smallAlbumId, libraryId).ifPresent(postRepository::delete);
}
```

`purgeSmallAlbumDeleted` 也改为调用 `purgeSmallAlbumCascade`。

#### 变更3: LocalMediaStorageService.java — MinIO 彻底删除

**问题**: `deleteRemoteStoredMediaFiles` (L863-879) 只删 3 个固定对象

**修复**: 改为按 `previews/{yyyy}/{MM}/` 前缀 + cacheKey 前缀列出所有对象批量删除

```java
private List<String> deleteRemoteStoredMediaFiles(String storagePath, String cacheKey) {
    String sourceObjectKey = originalObjectKey(storagePath);
    if (sourceObjectKey == null) {
        return List.of();
    }
    List<String> deletedKeys = new java.util.ArrayList<>();
    
    // 1. 删除原图
    if (objectStorageService.delete(sourceObjectKey)) {
        deletedKeys.add(sourceObjectKey);
    }
    
    // 2. 列出 previews 目录下所有以 cacheKey 开头的对象并批量删除
    String previewPrefix = previewDirectoryObjectKey(storagePath);
    List<String> derivedKeys = objectStorageService.listByPrefix(previewPrefix + "/", cacheKey + "-");
    for (String objectKey : derivedKeys) {
        if (objectStorageService.delete(objectKey)) {
            deletedKeys.add(objectKey);
        }
    }
    return deletedKeys;
}
```

#### 变更1: TrashService.java — 指纹冲突分支关系迁移

**位置**: L476-486

**修复**: 冲突时不仅物理删除当前恢复的媒体，还要把原 snapshot 中的 post_media 关系迁移到已存在的媒体上，并恢复封面。

```java
if (existing.isPresent() && !existing.get().getId().equals(media.getId())) {
    MediaEntity existingMedia = existing.get();
    
    // 1. 把原 post_media 关系迁移到已存在的媒体
    for (TrashSnapshotHelper.MediaSystemRelationSnapshot relationSnapshot : snapshot.relations()) {
        postRepository.findByIdAndLibraryIdAndDeletedAtIsNull(relationSnapshot.postId(), libraryId)
                .ifPresent(post -> {
                    if (!postMediaRepository.existsByLibraryIdAndPostIdAndMediaId(libraryId, relationSnapshot.postId(), existingMedia.getId())) {
                        restoreRelationOrder(libraryId, relationSnapshot.postId(), existingMedia.getId(), relationSnapshot.sortOrder());
                    }
                });
    }
    
    // 2. 恢复封面到已存在的媒体
    for (String postId : snapshot.coverPostIds()) {
        postRepository.findByIdAndLibraryIdAndDeletedAtIsNull(postId, libraryId)
                .ifPresent(post -> {
                    if (post.getCoverMediaId() == null && postMediaRepository.existsByLibraryIdAndPostIdAndMediaId(libraryId, postId, existingMedia.getId())) {
                        post.setCoverMediaId(existingMedia.getId());
                        postRepository.save(post);
                    }
                });
    }
    
    // 3. 物理删除当前恢复的媒体（原有逻辑）
    localMediaStorageService.deleteStoredMediaFiles(media.getStoragePath(), media.getId());
    postMediaRepository.deleteByLibraryIdAndMediaId(libraryId, media.getId());
    commentRepository.deleteByLibraryIdAndMediaId(libraryId, media.getId());
    mediaRepository.delete(media);
    return;
}
```

#### 变更2: SyncVersionTracker.kt — 新增 SYSTEM_MEDIA 模块

```kotlin
enum class SyncModule {
    PHOTO_FEED,
    ALBUMS,
    TRASH,
    NOTIFICATIONS,
    LIFE_CONSOLE,
    SYSTEM_MEDIA,
}

data class SyncStaleState(
    val photoFeedStale: Boolean = false,
    val albumsStale: Boolean = false,
    val trashStale: Boolean = false,
    val notificationsStale: Boolean = false,
    val lifeConsoleStale: Boolean = false,
    val systemMediaStale: Boolean = false,
) {
    fun isStale(module: SyncModule): Boolean = when (module) {
        SyncModule.PHOTO_FEED -> photoFeedStale
        SyncModule.ALBUMS -> albumsStale
        SyncModule.TRASH -> trashStale
        SyncModule.NOTIFICATIONS -> notificationsStale
        SyncModule.LIFE_CONSOLE -> lifeConsoleStale
        SyncModule.SYSTEM_MEDIA -> systemMediaStale
    }
}
```
