## 三、发现的 Bug

### BUG-1: TC-004 首轮测量偏差导致 FR-1 AC-1 违规未被发现

**问题**: 首轮（阶段5 落地测试）使用 PowerShell `Measure-Object -Line` 测量文件行数。该方法统计的是换行符数量，当文件末行无换行符时不计入，导致行数被低估。

**根因**:
- `Measure-Object -Line` 统计换行符数量（`\n` 计数）
- `(Get-Content $_.FullName).Count` 统计数组元素数量（更准确）
- RealTrashListScreen.kt 末行无换行符，导致 `Measure-Object -Line` 返回 1195，而实际行数为 1221（差 26 行）
- 首轮误判 ListScreen.kt = 1195 行 ≤ 1200 → TC-004 PASS
- 实际 ListScreen.kt = 1221 行 > 1200 → AC-1 违规

**影响**: FR-1 AC-1（无单一文件超过 1200 行）实际未满足，但首轮测试报告误判为 PASS。

**修复**:
1. 将 `RealTrashPostTitleChip`(19行) + `RealTrashPostGridCard`(102行) 两个函数从 RealTrashListScreen.kt 迁移到 RealTrashShared.kt
2. 可见性从 `private` 改为 `internal`（跨文件调用需要）
3. 更新 RealTrashShared.kt 的 imports（添加 ExperimentalFoundationApi, combinedClickable, aspectRatio, clip）
4. 从 RealTrashListScreen.kt 删除这两个函数

**验证**:
- 行数重测（`(Get-Content).Count`）: ListScreen.kt = 1100 行 ≤ 1200 ✓，所有6个文件均 ≤ 1200 ✓
- 编译验证: `BUILD SUCCESSFUL in 31s`
- 跨文件引用验证: `RealTrashPostTitleChip` 在 ListScreen.kt L1095 被调用，迁移到 Shared.kt 后 internal 可见 ✓

**状态**: ✅ 已修复并重测 PASS
