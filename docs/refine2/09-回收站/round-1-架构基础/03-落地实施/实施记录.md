## 二、FR-2: RealTrashViewModels 架构改进

### 变更概要

删除 `RealTrashMemoryCache` private object 全局单例（跨VM UI状态LRU缓存），消除内存泄漏和多账号串号风险。两个ViewModel保持现有 `class : ViewModel() + StateFlow` 模式不变，改用磁盘缓存(AppReadCacheStore)兜底。

### 需求文档修正

需求文档FR-2原描述"object全局单例 + Compose mutableStateOf"与实际代码不符。实际两个ViewModel已是标准`class : ViewModel()` + `StateFlow`模式。真正问题是`RealTrashMemoryCache`(private object)跨VM全局缓存，其key不含userId但磁盘缓存按userId分桶，导致多账号切换时内存缓存串号。

### 变更文件清单

| # | 文件路径 | 端 | 变更类型 | 变更内容 |
|---|---------|-----|---------|---------|
| 1 | `feature/photos/RealTrashViewModels.kt` | Android | 修改 | 删除RealTrashMemoryCache object，6处引用更新 |

### 详细变更

**删除**: `RealTrashMemoryCache` object（原L47-81，35行），包含:
- `listStates`: LRU缓存(listStates上限20)
- `detailStates`: LRU缓存(detailStates上限50)
- `listKey()`、`readListState()`、`writeListState()`、`hasListState()`
- `readDetailState()`、`writeDetailState()`

**6处引用更新**:

| 位置 | 原代码 | 新代码 | 说明 |
|------|--------|--------|------|
| ListVM初始化 | `activeListKey = RealTrashMemoryCache.listKey(initialSelectedType)` | `activeListKey = initialSelectedType?.name ?: "ALL"` | 内联key计算 |
| ListVM初始化 | `RealTrashMemoryCache.readListState(initialSelectedType) ?: RealTrashListUiState(isLoading = true)` | `RealTrashListUiState(isLoading = true)` | 移除内存缓存读取 |
| ListVM.refresh() | `cachedState`/`hasCachedState` 变量 | 删除，保留`cachedList`磁盘缓存 | 简化缓存逻辑 |
| ListVM.refresh() | `shouldShowLoading = ... && !hasCachedState` | `shouldShowLoading = ... && cachedList == null` | 磁盘缓存兜底 |
| ListVM.refresh() | `RealTrashMemoryCache.writeListState(selectedType, nextState)` | 删除此行 | 不再写入内存缓存 |
| DetailVM初始化 | `RealTrashMemoryCache.readDetailState(route.entryId) ?: RealTrashDetailUiState(isLoading = true)` | `RealTrashDetailUiState(isLoading = true)` | 移除内存缓存读取 |
| DetailVM.loadDetail() | `RealTrashMemoryCache.writeDetailState(route.entryId, nextState)` | 删除此行 | 不再写入内存缓存 |
