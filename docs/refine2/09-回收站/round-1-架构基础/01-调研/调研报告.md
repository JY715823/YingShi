## 三、RealTrashViewModels.kt 架构（739 行）

**文件路径**: `app/src/main/java/com/example/yingshi/feature/photos/RealTrashViewModels.kt`

### 3.1 重要发现：需求文档描述与实际代码不符

需求文档 FR-2 描述"当前使用 object 全局单例 + Compose mutableStateOf，绕过 ViewModel 生命周期"，但**实际代码中两个 ViewModel 已是标准 `class : ViewModel()` + `StateFlow` 模式**：

```kotlin
class RealTrashListViewModel(
    private val initialSelectedType: TrashEntryType?,
    private val repository: TrashRepository = RepositoryProvider.trashRepository,
) : ViewModel() { ... }

class RealTrashDetailViewModel(
    private val route: TrashDetailRoute,
    private val repository: TrashRepository = RepositoryProvider.trashRepository,
) : ViewModel() { ... }
```

**真正的架构问题是**：
1. `RealTrashMemoryCache`（private object，47-81 行）是跨 VM 全局单例，持有 UI 状态 LRU 缓存
2. 两个 VM 直接静态调用 8 个外部 object 单例（AuthSessionManager、BackendAutoLoginManager、OfflineAccessManager、AppReadCacheStore、TrashActorHintStore、LocalSystemMediaBridgeRepository、notifyRealBackendContentChanged()、invalidateSystemMediaMetadataCache()）

### 3.2 RealTrashMemoryCache 问题分析

| 问题 | 严重度 | 说明 |
|------|--------|------|
| 内存泄漏 | 高 | object 生命周期 = 进程生命周期，VM 销毁后 UiState 仍残留；detailStates 上限 50 条强引用 |
| 多账号串号 | 高 | key 不含 userId，但磁盘缓存按 userId 分桶 — 切换账号会读到上一个账号的内存 UiState |
| 测试困难 | 中 | object 无法 mock/替换，单元测试间状态互相污染 |
| 数据契约混淆 | 中 | 缓存 UiState（含 statusMessage/errorMessage 瞬态文案）而非 Domain Model |

### 3.3 FR-2 实际工作内容调整

基于实际代码，FR-2 的工作调整为：
1. **删除 `RealTrashMemoryCache`**（private object，47-81 行）— 其缓存职责下沉到 Repository 或移除
2. **将列表内存缓存 key 加入 userId**（如保留缓存机制）
3. **保持两个 ViewModel 的 class + StateFlow 架构不变**（已是标准模式）
4. 不改动 VM 的外部调用方接口（`viewModel(factory = ...)` 调用点不变）

**风险评估**: 低。`RealTrashMemoryCache` 是 private object，文件外零引用，删除不影响外部。
