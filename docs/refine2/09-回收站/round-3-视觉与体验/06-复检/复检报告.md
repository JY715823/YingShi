## 三、发现并修复的 Bug

### BUG-1 [P3]: RealTrashShared.kt 5 个 unused imports
**问题**: RealTrashShared.kt 中 `AnimatedContent` / `fadeIn` / `fadeOut` / `togetherWith` / `yingShiClickable` 5 个 import 仅出现在 import 行，全文件无其他引用。
**根因**: Round 3 初版曾尝试在 Shared.kt 内用 AnimatedContent，后改用 Crossfade，遗留未清理的 import；yingShiClickable 是早期版本残留。
**修复**: 删除 5 个 unused imports（L3, L6-8, L48）。
**验证**: `grep -n "AnimatedContent\|fadeIn\|fadeOut\|togetherWith\|yingShiClickable" RealTrashShared.kt` 返回 0 行业务引用；编译 PASS。

### BUG-2 [P2]: formatPendingCleanupRemaining 死代码
**问题**: RealTrashShared.kt L200-209 的 `formatPendingCleanupRemaining(undoDeadlineMillis: Long): String` 函数全工程零调用（仅文档中有提及）。
**根因**: Round 3 倒计时改为 RealTrashCountdownBadge 后，原文本格式化函数变成死代码，未及时清理。
**修复**: 删除整个函数定义。
**验证**: `grep -r "formatPendingCleanupRemaining" YingShi/app/src` 仅返回 RealTrashShared.kt 的删除位置；编译 PASS。

### BUG-3 [P2]: RealTrashCountdownBadge 阈值偏离设计 + isWarning 死分支
**问题**: 
1. 原实现用 `ratio = remainingMillis / 24h`，阈值 `ratio < 0.2f`（≈4.8h）和 `ratio in 0.2f..0.5f`（4.8h~12h），与设计要求的 1h/6h 绝对时间不符。
2. `isWarning` 分支 gradient `listOf(colors.softGreenContainer, colors.glowWash)` 与 `else` 分支完全相同，等同死代码。
**根因**: 实现时用 ratio 简化计算，未对照设计文档核对阈值；isWarning gradient 复制粘贴 else 分支未差异化。
**修复**: 
1. 改为绝对毫秒阈值：`val oneHourMillis = 1L * 60L * 60L * 1000L; val sixHourMillis = 6L * 60L * 60L * 1000L; val isUrgent = remainingMillis <= oneHourMillis; val isWarning = remainingMillis in oneHourMillis..sixHourMillis`。
2. isWarning gradient 改为 `listOf(colors.goldAccent.copy(alpha = 0.20f), colors.glowWash)` 与 else 分支区分。
**验证**: 编译 PASS；阈值对照设计文档确认 1h/6h 正确；三档 gradient 各不相同。

### BUG-4 [P2]: formatCountdownRemaining 已过期分支缺失
**问题**: `formatCountdownRemaining` 当 `remainingMillis < 0`（已过期）时仍走 `coerceAtLeast(0L)` 分支显示 "即将过期"，应显示 "已过期"。
**根因**: 原实现用 `coerceAtLeast(0L)` 把负值钳为 0，导致已过期和即将过期两个状态合并显示。
**修复**: 在函数顶部增加 `if (remainingMillis <= 0L) return "已过期"`，移除 `coerceAtLeast` 钳位。
**验证**: 编译 PASS；逻辑核查：负值 → "已过期"；0 < r < 1min → "即将过期"；1min~1h → "剩余 Xm"；≥1h → "剩余 Xh Ym"。

### BUG-5 [P3]: RealTrashCountdownBadge safe 态 borderColor 使用 viewer token
**问题**: safe 态（剩余 > 6h）borderColor 使用 `colors.viewerOverlayBorder`，与 memory 主题不对齐。CountdownBadge 用于待清理场景（memory 域），应使用 memory token。
**根因**: 实现时复用了 viewer 边线 token，未区分场景。
**修复**: safe 态 borderColor 改为 `colors.memoryAccent.copy(alpha = 0.30f)`。
**验证**: 编译 PASS；三档 borderColor 分别为 destructive / goldAccent / memoryAccent，与 gradient 主题一致。

### BUG-6 [P3]: RealTrashListScreen.kt 2 个 unused imports
**问题**: `androidx.compose.foundation.clickable`（L12）和 `androidx.compose.foundation.layout.height`（L22）仅出现在 import 行。L300 的 `item.size.height` 是 `IntSize.height` 属性，非 layout modifier。
**根因**: AnimatedContent 引入后部分原 clickable 调用被移除；height modifier 在重构中不再使用。
**修复**: 删除 2 个 unused imports。
**验证**: `grep -n "clickable\|height" RealTrashListScreen.kt` 确认 `combinedClickable` 仍在用（L13, L791, L1103），`height` 仅剩 `item.size.height` 属性访问；编译 PASS。

### BUG-7 [P3 → 非阻塞]: AnimatedContent 切换 tab 丢失滚动位置
**问题**: `rememberLazyGridState()` 在 AnimatedContent content lambda 内部，切换分支时状态重建，回切后滚动位置重置到顶部。
**根因**: AnimatedContent 切换时旧 content 被销毁，对应的 remember 状态也随之丢失。
**评估**: **非回归** — 引入 AnimatedContent 前的 `when (selectedType)` 分支同样在内部 remember 状态，行为一致。本轮目标仅补切换动画（AC-3），缓存策略（AC-1/AC-2）已在 Round 1/2 满足。
**处理**: 记录为非阻塞发现，建议未来轮次将三个 gridState 提升至 AnimatedContent 外部以保持滚动位置。

### BUG-8 [P3]: RealTrashDetailScreen.kt 空 if 块
**问题**: L800-802 存在空 if 块 `if (detail.pendingCleanup != null) { // Pending cleanup is no longer exposed in the client UI. }`，仅含注释无代码体。
**根因**: Round 3 移除客户端 pendingCleanup UI 后，原 if 块变成空壳，未删除。
**修复**: 删除整个空 if 块。
**验证**: 编译 PASS；删除后 if-else 结构完整无破坏。

### BUG-9 [P3 → 审查通过]: RealTrashDetailTopBar fallback 分支未传 onRestore/onRemove
**问题**: RealTrashDetailScreen.kt L145-150 fallback "detail" 分支调用 RealTrashDetailTopBar 时未传 onRestore/onRemove。
**根因分析**: 经核查 RealTrashDetailTopBar 实现（RealTrashShared.kt L793, L801），`onRestore`/`onRemove` 是可选参数（默认 null），当为 null 时通过 `if (onRestore != null)` / `if (onRemove != null)` 守卫不渲染按钮。
**结论**: **非 bug** — fallback 分支用于 detail 为 null/loading/error 时显示占位信息，此时无具体条目可恢复/移除，不渲染操作按钮是正确行为。
**处理**: 审查通过，无需修改。

### BUG-10 [P3 → 审查通过]: BoxWithConstraints Pager 高度边界
**问题**: BoxWithConstraints 计算的 Pager 高度在极端 aspectRatio（< 0.5 或 > 2.5）时的边界行为。
**根因分析**: 代码已用 `coerceIn(0.5f, 2.5f)` 钳位 aspectRatio，并用 `coerceIn(240.dp, 520.dp)` 钳位最终高度，双重保护。
**结论**: 审查通过，无需修改。

### BUG-11 [P3 → 审查通过]: 回调连接
**问题**: RealTrashDetailTopBar 的 onRestore/onRemove 是否正确连接到 viewModel。
**根因分析**: 经核查 RealTrashDetailScreen.kt，三类详情页均正确传递 `onRestore = { viewModel.restore { ... } }` 和 `onRemove = { viewModel.remove(...) }`。
**结论**: 审查通过，无需修改。

### BUG-12 [P3 → 审查通过]: LaunchedEffect 重复重置 showCommentPreview
**问题**: RealTrashViewer.kt L255-256 的 LaunchedEffect 中重复重置 showCommentPreview，remember key 已自动重置。
**根因分析**: 经核查，该 LaunchedEffect 监听 mediaItem 变化做副作用清理，重置 showCommentPreview 是显式防御性编程，不会导致错误。
**结论**: 非阻塞，审查通过。如需优化可在未来轮次移除冗余重置。
