### 2.3 CountdownBadge 阈值逻辑（Round 3 修复后）

文件：`RealTrashShared.kt:621-686`

| 档位 | 条件（remainingMillis） | gradientColors | borderColor | textColor |
|------|----------------------|----------------|------------|-----------|
| isUrgent | `<= oneHourMillis`（≤ 3,600,000ms，含负数） | [memoryContainer, memoryWash] | destructive.copy(alpha=0.44f) | destructive |
| isWarning | `in oneHourMillis..sixHourMillis`（3,600,000..21,600,000，含两端） | [goldAccent.copy(alpha=0.20f), glowWash] | goldAccent.copy(alpha=0.34f) | titleAccent |
| safe | `> sixHourMillis`（> 21,600,000ms） | [softGreenContainer, glowWash] | memoryAccent.copy(alpha=0.30f) | titleAccent |

**关键边界**：when 先判 isUrgent 再判 isWarning，因此 `remainingMillis == oneHourMillis` 落入 isUrgent（warning 的 in 虽含下界但被 urgent 抢先）。实际生效边界：urgent = `(-∞, 1h]`；warning = `(1h, 6h]`；safe = `(6h, +∞)`。

**建议提取纯函数**：
```kotlin
enum class CountdownSeverity { URGENT, WARNING, SAFE }
internal fun countdownSeverity(remainingMillis: Long): CountdownSeverity
```
提取后阈值边界可独立单测，颜色映射仍由 Composable 处理。

### 4.3 测试策略总结

**核心思路**：
1. Repository 层用 fake：手写 `FakeTrashRepository : TrashRepository`（不用 MockK）
2. ViewModel 直接构造：绕过 factory，`RealTrashListViewModel(initialSelectedType = ..., trashRepository = fakeRepo)`
3. 协程测试：引入 kotlinx-coroutines-test，用 runTest + StandardTestDispatcher + MainDispatcherRule
4. 单例副作用处理：不 mock 单例，设计测试用例使其不触发单例的敏感路径（fake repo 返回 Success 时不进入 BackendAutoLoginManager.loginDefault 分支）

- **P0（必做）**：纯函数单测（14 组共 90+ 用例）+ ViewModel mutation 方法行为测试（restore/move/purge/undo 的成功 + 离线拦截 + 空列表早返回 + 部分失败）

### 8.4 可选提取（countdownSeverity 纯函数）

```kotlin
// RealTrashShared.kt
enum class CountdownSeverity { URGENT, WARNING, SAFE }
internal fun countdownSeverity(remainingMillis: Long): CountdownSeverity {
    val oneHourMillis = 1L * 60L * 60L * 1000L
    val sixHourMillis = 6L * 60L * 60L * 1000L
    return when {
        remainingMillis <= oneHourMillis -> CountdownSeverity.URGENT
        remainingMillis <= sixHourMillis -> CountdownSeverity.WARNING
        else -> CountdownSeverity.SAFE
    }
}
```
RealTrashCountdownBadge 内联逻辑改为调用 `countdownSeverity(remainingMillis)`，便于独立单测。
