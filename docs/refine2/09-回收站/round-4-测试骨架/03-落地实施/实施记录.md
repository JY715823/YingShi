## 二、关键实施细节

### 2.1 RealTrashShared.kt 修改

**countdownSeverity 提取**：将 RealTrashCountdownBadge 中的 severity 判定逻辑提取为独立纯函数，便于单测。阈值从 Round 3 的 ratio(0.2/0.5) 改为绝对时间 1h/6h 毫秒值。

```kotlin
internal enum class CountdownSeverity { URGENT, WARNING, SAFE }
internal fun countdownSeverity(remainingMillis: Long): CountdownSeverity { ... }
```

**realTrashGridPostTitle 修复**：原代码 `?:` 只处理 null 不处理空串，当 `sourcePostTitle = ""` 时返回空串而非回退。修复为 `?.takeIf { it.isNotBlank() }`。

**formatCountdownRemaining 可见性**：从 `private` 改为 `internal`，使测试模块可访问。同时确保 `已过期` 分支（Round 3 已修复）。

### 2.2 测试基础设施搭建

**依赖引入**：
- `kotlinx-coroutines-test 1.10.1`：提供 `runTest`、`StandardTestDispatcher`、`UnconfinedTestDispatcher`、`TestScope`
- `turbine 1.1.0`：Flow 测试工具（本轮已引入，实际未使用，为后续轮次预留）

**FakeTrashRepository 设计**：
- 每个 suspend 方法的返回值可独立配置
- 记录每次调用的入参（trashItemId），供测试 verify
- 支持 `restoreResultsById` / `moveOutResultsById` / `purgeResultsById` 按 id 返回不同结果（用于部分失败场景）
- `reset()` 清除所有调用记录

**MainDispatcherRule 设计**：
- 继承 `TestWatcher`，在 `starting` 时 `Dispatchers.setMain(dispatcher)`，在 `finished` 时 `Dispatchers.resetMain()`
- 默认使用 `StandardTestDispatcher`，ViewModel 测试使用 `UnconfinedTestDispatcher` 让协程立即执行
- 改为 `public` 可见性以支持 `@Rule @JvmField` 注解

### 2.3 ViewModel 测试策略

**AuthSessionManager 处理**：
- `@Before` 中调用 `AuthSessionManager.saveTokens(validTokens())` 模拟已登录状态
- 不设置 `currentUserSnapshot`，使 `readCachedList` / `persistTrashList` 返回 null（绕过 AppReadCacheStore）
- `@After` 中调用 `AuthSessionManager.clearTokensPreservingReadCache()` 清理

**协程时序处理**：
- 使用 `UnconfinedTestDispatcher` 让 `viewModelScope.launch` 立即执行
- `withContext(Dispatchers.IO)` 在 refresh() 中仅返回 null（getCurrentUserSnapshot 为 null），通过 `Thread.sleep(200)` 等待 IO 完成

**测试覆盖**：
- AC-1 (分类切换/恢复/移出/purge)：RealTrashListViewModelTest 13 用例 + RealTrashDetailViewModelTest 6 用例
- AC-2 (待清理倒计时/过期判断)：RealTrashSharedLogicTest 中 formatCountdownRemaining(11) + countdownSeverity(8)
- AC-3 (测试全部 PASS)：125 个新测试全部 PASS
