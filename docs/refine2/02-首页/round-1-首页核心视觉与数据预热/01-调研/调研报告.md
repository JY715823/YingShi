## 五、FR-5 首页数据预热现状

### 核心结论
首页当前**纯读缓存、零主动拉取**。照片缓存仅在用户进入"照片"Tab 后由 RealPhotoFeedViewModel 写入；通知缓存仅在用户打开"通知中心"后写入。首次启动进入首页时缓存为空，照片卡片显示"0 张/未缓存"，铃铛角标为 0。

### 数据聚合层（HomeSummary.kt）
- `rememberHomeUiState()` (L83-188) 订阅三个版本号: sessionVersion + changeVersion + offlineAccessState
- 照片缓存读取: `AppReadCacheStore.readPhotoFeed(userId)?.payload?.items.orEmpty()` (L201)
- 通知缓存读取: `AppReadCacheStore.readNotifications(userId)?.payload?.items.orEmpty()` (L209)
- **无任何主动拉取逻辑**，唯一 LaunchedEffect (L128-131) 仅做账本 seed

### 缓存层（AppReadCacheStore.kt）
- `readPhotoFeed` (L122-128) / `readNotifications` (L186-192): 纯文件 I/O
- `changeVersion` (L79): 写入成功后自增 (L390)，HomeSummary 通过 remember key 监听
- **无"刷新"或"拉取"API**，拉取逻辑全在 ViewModel/Screen 层

### 缓存填充时机（关键缺口）
- 照片缓存写入: 仅 `RealPhotoFeedViewModel.persistFeed()` — **只在照片 Tab 实例化**
- 通知缓存写入: 仅 `NotificationCenterScreen` (L274) — **用户点铃铛才触发**
- **启动后首页可见时，无任何照片/通知拉取触发点**

### Repository 拉取方法（现成可用）
- 照片: `MediaRepository.getMediaFeedPage(cursor, pageSize=60): ApiResult<RemoteMediaFeedPage>` (Contracts.kt:49-52)
- 通知: `NotificationRepository.getNotifications(limit=100): ApiResult<List<RemoteNotification>>` (Contracts.kt:147-149)
- 两者返回类型可直接喂给 `AppReadCacheStore.writePhotoFeed / writeNotifications`

### FR-5 实施方案决策
**放置位置**: HomeScreen.kt 新增 `LaunchedEffect(uiState.currentUser?.userId)` (L74 之后)
**避免重复**: 缓存存在性检查 `readPhotoFeed(userId) == null` / `readNotifications(userId) == null`
**静默失败**: `runCatching { ... }.onFailure { }`，不改变全局只读态，不显示 Toast
**不阻塞渲染**: LaunchedEffect 异步，首页先显示空态，写入缓存后 changeVersion 自增触发重组
**无需修改其他文件**: HomeSummary.kt / AppReadCacheStore.kt / RepositoryProvider.kt / YingShiApp.kt 均无需改动

## 六、设计系统约束

### YingShiThemeTokens 颜色 token（26 字段）
- **可用 token**: appBackground, sectionBackground, raisedSurface, primaryContainer, titleAccent, softGreenContainer, goldAccent, memoryAccent, memoryWash, dividerSoft, glassStroke, glowWash, textPrimary, textSecondary
- **不可改**: 26 个核心 token 的 Hex 值、主色调珍珠玉蓝、使用规则
- **允许**: 新增 token、`.copy(alpha=0.xf)` 派生

### shimmer 可复用实现参照
`YingShiSurfaces.kt` L425-484 的 `YingShiPrimaryMistButton` shimmer sweep:
- 周期 3500ms, LinearEasing, RepeatMode.Restart
- 颜色: `Transparent → White@0.18 → Transparent` linearGradient
- **FR-2 需新建可复用 shimmer Modifier**（建议放 YingShiMotion.kt），对齐此 spec

### rememberYingShiMotionEnabled (YingShiMotion.kt L19-26)
- 读 `followSystemReducedMotion` + `ValueAnimator.areAnimatorsEnabled()`
- 约定: 每个 Composable 顶部调用一次，透传给动画 Modifier
- HomeScreen.kt L67 已调用，但 **HomeNotificationBellButton 未消费**（FR-3 需补）

### yingShiSoftReveal (YingShiMotion.kt L52-81)
- alpha + scale + translationY 三个 animateFloatAsState
- duration: 220ms, FastOutSlowInEasing
- **不支持 staggered delay**（FR-6 在 Round 2 处理）

## 十一、调研结论

1. **FR-1 照片卡片**: 替换 L233 关键压暗遮罩为 `titleAccent.copy(alpha)`，增强磨砂玻璃质感（多层阴影/精致边框），fallback 渐变保留
2. **FR-2 账本卡片**: Hero 暖色/白底改 token 派生，新增 shimmer Modifier（YingShiMotion.kt），Recent 区降低 alpha
3. **FR-3 通知铃铛**: 新增呼吸光晕动画（memoryWash 基色），按钮底色/角标边框改 token 派生，角标位置/比例优化
4. **FR-5 数据预热**: HomeScreen.kt 新增 LaunchedEffect，并行拉取照片+通知，缓存存在性守卫，runCatching 静默失败
5. **需新增**: YingShiMotion.kt 新增 `Modifier.yingShiShimmerSweep()` 可复用 shimmer
6. **不改**: HomeSummary.kt / AppReadCacheStore.kt / RepositoryProvider.kt / YingShiAuroraBackdrop.kt
