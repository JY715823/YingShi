## 三、数据流影响分析

### 3.1 FR-5 数据流变化

**变更前**:
```
用户进入首页
  → rememberHomeUiState()
    → AppReadCacheStore.readPhotoFeed(userId) → null (首次)
    → AppReadCacheStore.readNotifications(userId) → null (首次)
  → 首页显示空态
  → 用户手动进入照片页/通知页 → 触发拉取 → 写入缓存
  → 返回首页 → changeVersion 变化 → 重组显示数据
```

**变更后**:
```
用户进入首页
  → rememberHomeUiState()
    → AppReadCacheStore.readPhotoFeed(userId) → null (首次)
    → AppReadCacheStore.readNotifications(userId) → null (首次)
  → 首页显示空态（先渲染）
  → LaunchedEffect 启动（异步，不阻塞）
    → 并行拉取照片 feed + 通知
    → 写入 AppReadCacheStore
    → changeVersion 自增
    → rememberHomeUiState 重组
  → 首页自动更新显示数据（3秒内）
```

**数据流安全性**:
- LaunchedEffect key 为 `uiState.currentUser?.userId`，用户切换时重新触发
- `readPhotoFeed == null` 守卫确保已有缓存不重复拉取
- `runCatching` 静默失败，不中断首页
- `coroutineScope { launch{}; launch{} }` 并行拉取，互不阻塞

### 3.2 视觉变更数据流（FR-1/2/3）

**无数据流变化**。FR-1/2/3 均为纯视觉改动，不涉及数据读取、状态管理或事件传递。所有改动在 Composable 渲染层内闭合。

## 五、风险评估

### 5.1 高风险项（无）

本轮无高风险项。所有改动均在 HomeScreen.kt 内部组件闭合，不涉及跨模块接口变更。

### 5.2 中风险项

| # | 风险 | 概率 | 影响 | 缓解 |
|---|------|------|------|------|
| 1 | FR-5 预热与照片页/通知页的刷新逻辑重复拉取 | 中 | 低 | `readPhotoFeed == null` 守卫；首次预热后缓存已有，后续进入子页面不会重复 |
| 2 | FR-5 并行拉取在网络差时长时间占用 IO | 低 | 中 | `runCatching` 包裹，但无超时控制 — 可接受（首次预热仅一次） |
| 3 | FR-3 breathTransition 在 hasUnread 切换时重组开销 | 低 | 低 | `if (hasUnread && motionEnabled)` 条件创建，false 时不实例化 |

### 5.3 低风险项

| # | 风险 | 缓解 |
|---|------|------|
| 1 | FR-1 遮罩 5 色渐变在低端机渲染开销 | Compose 渐变有缓存，5 色 vs 3 色差异可忽略 |
| 2 | FR-2 shimmer 与 HomeLedgerCard 背景渐变叠加 | shimmer alpha 0.18，叠加效果柔和 |
| 3 | FR-2 Recent alpha 降低后文字可读性 | 0.56 仍高于 0.50 阈值，文字 titleAccent 对比度足够 |
| 4 | import 冲突 | 新增 import 均为独立符号，无重名 |
