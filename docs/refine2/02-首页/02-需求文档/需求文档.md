# 首页 需求文档

> 版本: v1.0 | 日期: 2026-07-08 | 状态: 待确认

## 一、模块目标

在现有两卡结构（照片 + 账本）功能完整的基础上，按设计方案对齐首页视觉品质（磨砂玻璃材质、丝绸渐变光泽、精致排版层次），修复首页首次打开数据空白的预热问题，使首页从"功能可用"提升到"成品门厅"状态。

## 二、功能需求

### FR-1: 照片卡片视觉升级
**描述**: 提升最近照片卡片的材质感和精致度。卡片增加磨砂玻璃质感（更明显的半透明 + 多层阴影），4 格拼贴的 pane 间距和圆角更精致，渐变遮罩更柔和自然，卡片边框从单一 glassStroke 改为更精致的多层边线效果。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: 照片卡片有磨砂玻璃质感，视觉上与极光背景形成明显的层次分离
- AC-2: 拼贴 pane 之间的间距统一（当前 10dp），圆角一致（当前 24dp），边框精致
- AC-3: 卡片遮罩渐变从硬切改为柔和过渡，不出现明显的色带分界
- AC-4: 所有颜色使用 YingShiThemeTokens，硬编码遮罩色改为 token 或 token 派生
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomePhotoCard, HomePhotoCollage, HomePhotoPane)

### FR-2: 账本卡片视觉层级强化
**描述**: 强化账本信号卡的三层视觉区分度。Hero 月支出区增加丝绸渐变光泽材质感，最近一笔区用更轻的承托（降低 alpha），整体卡片增加微妙的光泽扫过效果（与登录页按钮 shimmer 一致的设计语言）。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: Hero 月支出区有明显的材质感（丝绸渐变光泽），与标题行和最近一笔区形成清晰的视觉层次
- AC-2: 最近一笔区的背景 alpha 降低，视觉上轻于 Hero 区
- AC-3: 卡片整体有微妙的光泽扫过效果（shimmer），周期 3-5 秒
- AC-4: 账本卡片圆角（当前 30dp）和边框精致度与照片卡片保持一致的设计语言
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomeLedgerCard, HomeLedgerHeroSignal, HomeLedgerRecentSignal)

### FR-3: 通知铃铛精修
**描述**: 精修通知铃铛的视觉细节。图标样式更精致，角标位置和比例优化，有未读时增加微弱的呼吸光晕效果（与登录页设计语言一致）。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: 铃铛图标在有/无未读时有明确的视觉区分
- AC-2: 角标位置在铃铛右上角，比例协调（不遮挡图标主体）
- AC-3: 有未读时铃铛周围有微弱的 memoryWash 呼吸光晕，周期 2-3 秒
- AC-4: 角标数字 99+ 封顶，文字居中，背景 memoryAccent
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomeNotificationBellButton)

### FR-4: 首页背景 HOME variant 增强
**描述**: 增强 AuroraBackdrop HOME variant 的极光层次感。增加极光带的视觉丰富度，闪烁粒子增加呼吸动画（与登录页 AUTH variant 一致），整体色调更温暖有"归家"感。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: HOME variant 的极光带比当前更有层次感（至少 2 条可辨别的极光曲线）
- AC-2: 闪烁粒子有微弱的呼吸动画（alpha 缓变），周期 >= 3 秒
- AC-3: 整体色调偏暖，memoryWash 暖色在渐变中可感知
- AC-4: 其他 variant（AUTH/PHOTOS/LIFE/ME/SHELL）不受影响
**涉及文件**: app/src/main/java/com/example/yingshi/ui/components/YingShiAuroraBackdrop.kt

### FR-5: 首页数据预热
**描述**: 修复首页首次打开数据空白的问题。当前首页依赖 AppReadCacheStore 读缓存，但缓存只在用户访问照片页/通知页时才被填充。需要在 App 启动后（或首页首次显示时）自动触发照片流和通知的拉取，使首页首次打开就能看到数据。
**端**: Android
**优先级**: P0
**验收标准**:
- AC-1: 首次打开 App 进入首页后，照片卡片在 3 秒内显示最近照片（而非空态）
- AC-2: 首次打开 App 进入首页后，通知铃铛角标正确显示未读数
- AC-3: 数据预热不阻塞首页渲染，首页先显示骨架/空态，数据到达后自然更新
- AC-4: 预热逻辑不重复拉取（已有缓存时跳过）
- AC-5: 预热失败不影响首页正常使用（静默失败，用户可手动下拉刷新或进入子页面触发）
**涉及文件**:
- app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt 或 HomeSummary.kt
- app/src/main/java/com/example/yingshi/app/YingShiApp.kt（启动触发点）
- 可能涉及: AppReadCacheStore.kt, RepositoryProvider

### FR-6: 卡片入场动画增强
**描述**: 首页卡片入场使用 staggered reveal 动画。照片卡片先入场，账本卡片延迟 100-150ms 入场，状态药丸和铃铛也有轻微延迟。所有动画遵循 rememberYingShiMotionEnabled()。
**端**: Android
**优先级**: P1
**验收标准**:
- AC-1: 照片卡片入场有淡入 + 轻微上移动画
- AC-2: 账本卡片比照片卡片延迟 100-150ms 入场
- AC-3: 铃铛和状态药丸有轻微延迟入场
- AC-4: 系统"减少动画"设置开启时，所有动画退化为即时显示
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt

### FR-7: 协作人圆点交互优化
**描述**: 协作人筛选圆点的选中/未选中切换增加颜色过渡动画（animateColorAsState），选中态增加微弱的光晕效果（glassStroke 外圈）。
**端**: Android
**优先级**: P1
**验收标准**:
- AC-1: 圆点选中/未选中切换有颜色过渡动画，时长 200ms
- AC-2: 选中态圆点有微弱的 glassStroke 外圈光晕
- AC-3: 遵循 motionEnabled 设置
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomeCollaboratorDot)

### FR-8: 账本筛选 chip 视觉精修
**描述**: 账本筛选 chip 增加更精致的选中态视觉，下拉标记从 "▾" 改为更优雅的图标。
**端**: Android
**优先级**: P1
**验收标准**:
- AC-1: chip 选中态有明确的视觉区分（背景色/边框变化）
- AC-2: 下拉标记使用 Material Icon（如 Icons.Rounded.ExpandMore）替代文字 "▾"
- AC-3: chip 有多账本时可点击，单账本时视觉弱化（不可点击态）
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomeBookFilterChip)

### FR-9: 首页硬编码颜色 token 化
**描述**: 将首页中约 10 个硬编码装饰色纳入 token 体系或改为 token 派生。包括：照片遮罩蓝灰、账本渐变薄荷/暖橙、Hero 暖色、拼贴 fallback 渐变色等。
**端**: Android
**优先级**: P2
**验收标准**:
- AC-1: 照片卡片遮罩色改为 token 派生（如 titleAccent.copy(alpha)）
- AC-2: 账本卡片渐变薄荷/暖橙改为 sectionBackground/memoryWash 的 token 派生
- AC-3: Hero 暖色改为 memoryWash 或 goldAccent 的 token 派生
- AC-4: 拼贴 fallback 渐变色保留硬编码（属于装饰细节，与 AUTH variant 金线同理）
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt

### FR-10: 空态视觉精修
**描述**: 无照片/无账本时的空态更有设计感。当前空态比较朴素（纯文字或简单渐变），改为有质感的轻空态（如极轻的图标轮廓 + 柔和文案）。
**端**: Android
**优先级**: P2
**验收标准**:
- AC-1: 无照片时拼贴区域显示有质感的空态（非纯白/纯渐变）
- AC-2: 无账本记录时显示轻空态文案，不出现大报错
- AC-3: 空态颜色使用 token，无硬编码
**涉及文件**: app/src/main/java/com/example/yingshi/feature/home/HomeScreen.kt (HomePhotoPane, HomeLedgerRecentSignal)

## 三、非功能需求

### NFR-1: 动画可访问性
所有新增动画须遵循系统"减少动画"偏好设置（通过 rememberYingShiMotionEnabled()），开启时退化为即时显示。

### NFR-2: 视觉不退步
视觉精修后，首页整体效果须与当前一致或更好，不能因改动导致布局错乱或信息丢失。

### NFR-3: 数据预热不阻塞
首页数据预热不能阻塞首页渲染，必须异步执行，首页先显示骨架/空态。

### NFR-4: 编译通过
Android 端 gradlew.bat assembleDebug 通过。

## 四、范围边界

### 在范围内
- 首页视觉精修（照片卡片、账本卡片、铃铛、背景、动画、空态）
- 首页数据预热（启动后自动拉取照片/通知数据）
- 硬编码颜色 token 化

### 不在范围内
- 新增后端接口
- 首页接入聊天/今日痕迹/生活摘要
- 改写照片/通知/账本模块主流程
- 底部导航精修（属于 shell 模块）

## 五、跨模块依赖

| 依赖模块 | 依赖方向 | 依赖内容 | 影响说明 |
|---------|---------|---------|---------|
| photos | 被依赖 | 照片缓存、缩略图组件 | FR-5 需触发照片流拉取，复用现有 Repository |
| notifications | 被依赖 | 通知缓存 | FR-5 需触发通知拉取，复用现有 Repository |
| ledger | 被依赖 | Room 账本数据 | 首页已有独立 LedgerRepository(NoOp)，不受影响 |
| shell (AppShell) | 被依赖 | 底部导航、路由 | FR-5 可能在 YingShiApp 启动时触发，需注意路由时机 |

## 六、数据模型变更

无。

## 七、风险清单

| # | 风险 | 严重度 | 缓解措施 |
|---|------|--------|---------|
| 1 | 数据预热与现有缓存刷新机制冲突 | 中 | 预热逻辑检查 changeVersion，已有缓存时跳过；使用独立的 LaunchedEffect |
| 2 | 首页视觉改动影响小屏密度 | 低 | 保持现有间距和尺寸，只改颜色和材质效果 |
| 3 | shimmer 动画影响性能 | 低 | 仅在可见时运行，遵循 motionEnabled |
| 4 | 数据预热在网络不可用时无限重试 | 低 | 仅尝试一次，失败后静默，用户可手动触发 |
