## 二、用户流程

### 流程1: 正常态首页
用户打开 App → 进入首页 → 看到顶部「映世」+ 通知铃铛（有未读时显示红色角标）→ 下方大「最近照片」卡片（4 格拼贴 + 协作人筛选 + 时间统计）→ 再下方「账本信号」卡片（月支出大数字 + 最近一笔交易）→ 点击照片卡片跳转到照片页，点击账本卡片跳转到记账，点击铃铛打开通知中心。

涉及: `HomeScreen.kt`, `HomeSummary.kt`, `YingShiApp.kt`, `AppReadCacheStore.kt`

### 流程2: 缓存只读态
网络断开 → OfflineAccessManager 进入只读模式 → 首页顶部显示"缓存只读"药丸（memoryAccent 红色文字）→ 照片和账本数据仍从本地缓存/Room 读取 → 首页结构不变，仅多一个轻提示。

涉及: `OfflineAccessManager.kt`, `HomeStatusPill`

### 流程3: 通知回流
用户在首页看到铃铛角标 → 点击进入通知中心 → 标记已读 → 返回首页 → AppReadCacheStore.changeVersion 自增 → 首页重新聚合 → 角标消失。

涉及: `AppReadCacheStore.kt`, `HomeNotificationBellButton`

### 流程4: 协作人筛选
用户点击"我"或"TA"圆点 → 切换照片筛选 → 照片拼贴重新聚合 → 只显示选中用户上传的照片。

涉及: `HomeCollaboratorDot`, `toggleCollaboratorSelection()`

### 流程5: 账本筛选
用户点击账本筛选 chip → 弹出 LedgerBookPickerSheet → 选择账本 → 月支出和最近一笔重新聚合。

涉及: `HomeBookFilterChip`, `LedgerBookPickerSheet`

## 三、数据流向

### 首页数据聚合架构

```
HomeScreen (Composable)
  → rememberHomeUiState()
    → AuthSessionManager.getCurrentUserSnapshot() → 当前用户
    → AppReadCacheStore.readPhotoFeed(userId) → 照片缓存 → 按协作人筛选 → take(5) → 4格拼贴
    → AppReadCacheStore.readNotifications(userId) → 通知缓存 → count(!isRead) → 角标
    → AppReadCacheStore.changeVersion → 缓存变更触发重组
    → OfflineAccessManager.state → 只读状态
    → LedgerRepository (NoOp sync) → observeBooks() + observeTransactions() → 月支出 + 最近一笔
    → LedgerPreferencesStore → 默认账本
  → HomeUiState (data class)
    → HomeRecentPhotosSummary (totalCount, tiles, latestAt)
    → HomeLedgerSummary (monthlyExpenseCents, recentTransaction, bookName)
    → unreadNotificationCount
    → isReadOnly
```

### 跨模块依赖

| 模块 | 依赖方向 | 依赖内容 | 影响说明 |
|------|---------|---------|---------|
| photos | 被依赖 | 照片缓存、协作人模型、缩略图组件 | 首页复用照片缓存，不修改照片模块 |
| ledger | 被依赖 | Room 账本数据、账本选择弹窗 | 首页创建独立 LedgerRepository(NoOp sync)，不改账本模块 |
| notifications | 被依赖 | 通知缓存 | 首页从读缓存统计未读数，不改通知模块 |
| shell (AppShell) | 被依赖 | 底部导航、路由调度 | 首页是 4 个根目的地之一 |
| auth | 被依赖 | currentUserSnapshot、sessionVersion | 首页按当前用户维度读缓存 |
