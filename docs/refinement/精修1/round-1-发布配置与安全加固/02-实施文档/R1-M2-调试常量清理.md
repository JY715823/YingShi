# R1-M2: 调试常量清理 实施文档

## 一、目标

将 `BackendAutoLoginManager.kt` 中硬编码的默认账号密码从顶层 `const val` 迁移到 `BuildConfig`，确保 release APK 反编译后找不到敏感信息。

## 二、涉及文件清单

| 文件 | 端 | 改动类型 | 说明 |
|------|-----|---------|------|
| `app/build.gradle.kts` | Android | 修改 | 添加 buildConfigField（邮箱全 buildType、密码仅 debug） |
| `BackendAutoLoginManager.kt` | Android | 修改 | 移除 const val，改用 BuildConfig |
| `LoginScreen.kt` | Android | 修改 | import 改为 BuildConfig 引用 |

## 三、配置级实施方案

### 3.1 build.gradle.kts — defaultConfig 添加 BuildConfig 字段

在 `defaultConfig {}` 块内添加（所有 buildType 可用）：

```kotlin
buildConfigField("String", "DEFAULT_PRIMARY_ACCOUNT", "\"1085060329@qq.com\"")
buildConfigField("String", "DEFAULT_SECONDARY_ACCOUNT", "\"2926315047@qq.com\"")
```

在 `debug {}` buildType 块内添加（仅 debug 可用）：

```kotlin
buildConfigField("String", "DEFAULT_TEMP_PASSWORD", "\"123456\"")
```

在 `release {}` buildType 块内添加：

```kotlin
buildConfigField("String", "DEFAULT_TEMP_PASSWORD", "\"\"")
```

**设计决策**：
- 邮箱地址保留在所有 buildType 中——它们是 UI 预填值（账号 A/B 选择器），非安全敏感信息
- 密码仅 debug 有效，release 为空字符串——防止密码暴露在 release 代码中
- 未来如需从 release 中完全移除邮箱地址，可改为 `if (BuildConfig.DEBUG)` 判断

### 3.2 BackendAutoLoginManager.kt — 修改

**删除**：
- L30 `const val DEFAULT_PRIMARY_ACCOUNT = "1085060329@qq.com"`
- L31 `const val DEFAULT_SECONDARY_ACCOUNT = "2926315047@qq.com"`
- L32 `const val DEFAULT_TEMP_PASSWORD = "123456"`

**替换为**：
```kotlin
// 从 BuildConfig 获取默认值
val DEFAULT_PRIMARY_ACCOUNT: String get() = com.example.yingshi.BuildConfig.DEFAULT_PRIMARY_ACCOUNT
val DEFAULT_SECONDARY_ACCOUNT: String get() = com.example.yingshi.BuildConfig.DEFAULT_SECONDARY_ACCOUNT
val DEFAULT_TEMP_PASSWORD: String get() = com.example.yingshi.BuildConfig.DEFAULT_TEMP_PASSWORD
```

**注意**：不能再用 `const val`（需要编译期常量），改为普通 `val` + getter。BackendAutoLoginManager 内的 `DEFAULT_DEMO_ACCOUNT` 等别名保持引用 `DEFAULT_PRIMARY_ACCOUNT` 不变。

**影响分析**：
- `BackendAutoLoginUiState` 的 `account: String = DEFAULT_PRIMARY_ACCOUNT` 默认值从编译期常量变为运行期 getter——功能等价
- `MutableStateFlow(BackendAutoLoginUiState(account = DEFAULT_PRIMARY_ACCOUNT))` —— 功能等价
- `BackendAutoLoginManager.DEFAULT_DEMO_ACCOUNT` 等——功能等价（引用链：const → val getter → BuildConfig）

### 3.3 LoginScreen.kt — 修改

**修改 import**：
```kotlin
// 删除
import com.example.yingshi.data.remote.auth.DEFAULT_PRIMARY_ACCOUNT
import com.example.yingshi.data.remote.auth.DEFAULT_SECONDARY_ACCOUNT
import com.example.yingshi.data.remote.auth.DEFAULT_TEMP_PASSWORD

// 替换为（无需显式 import，直接引用全限定名或在文件头 import BuildConfig）
import com.example.yingshi.BuildConfig
```

**修改引用点**：

| 行号 | 原代码 | 新代码 |
|------|--------|--------|
| L133 | `DEFAULT_PRIMARY_ACCOUNT` | `BuildConfig.DEFAULT_PRIMARY_ACCOUNT` |
| L135 | `DEFAULT_TEMP_PASSWORD` | `BuildConfig.DEFAULT_TEMP_PASSWORD` |
| L496 | `DEFAULT_TEMP_PASSWORD` | `BuildConfig.DEFAULT_TEMP_PASSWORD` |
| L734 | `DEFAULT_PRIMARY_ACCOUNT to "账号 A"` | `BuildConfig.DEFAULT_PRIMARY_ACCOUNT to "账号 A"` |
| L735 | `DEFAULT_SECONDARY_ACCOUNT to "账号 B"` | `BuildConfig.DEFAULT_SECONDARY_ACCOUNT to "账号 B"` |

**L734-735 账号选择器**：release 构建中邮箱不为空（保留了邮箱在 defaultConfig），所以选择器仍正常工作。如果未来需要 release 中也隐藏邮箱，需在此处添加 `.filter { it.first.isNotBlank() }` 过滤。
