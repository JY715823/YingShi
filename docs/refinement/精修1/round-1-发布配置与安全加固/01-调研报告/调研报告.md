#### proguard-rules.pro

默认 Android Studio 模板，**零自定义规则**。所有 keep 规则均被注释掉。若启用 `isMinifyEnabled=true`，以下库将因反射/JNI 被混淆而崩溃：
- Retrofit 2.11（接口方法名被改 → HTTP 请求全部失败）
- Gson（DTO 字段名被改 → JSON 解析全部失败）
- Room 2.8.2（Entity/DAO 类被移除 → 数据库操作崩溃）
- Firebase Messaging（Service 类被移除 → 推送接收失败）
- SilkDecoder（JNI 方法名被改 → 语音解码崩溃）
- Compose（runtime 类被混淆 → UI 崩溃）
- Media3（ExoPlayer 内部反射 → 视频播放失败）

## 三、跨模块影响评估

| 改动 | 影响的模块 | 影响程度 |
|------|-----------|---------|
| ProGuard 规则 | 所有网络请求（Retrofit）、数据库（Room）、推送（FCM） | **高** — 规则不完整将导致 release 崩溃 |

| allowBackup=false | 应用数据备份 | **低** — 不影响功能 |

| V24 孤儿审计 | 数据库迁移链 | **高** — 直接影响服务启动 |

## 四、风险与注意事项

1. **ProGuard 规则风险**：启用 `isMinifyEnabled=true` 后，若 keep 规则不完整，release APK 可能在运行时崩溃（而非编译期）。必须在 Round 1 完成后做一次完整的 release 构建 + 功能冒烟测试。
2. **签名密钥安全**：生成的 `.jks` 文件一旦丢失，无法更新已发布的 APK。需妥善保管（建议备份到安全位置）。
3. **LoginScreen 账号选择器**：release 构建中邮箱常量为空时，L734-735 的账号切换器列表将显示空条目。需在代码中处理空值情况。
4. **data_extraction_rules.xml 缺失**：manifest 引用但文件不存在，需创建空文件或移除引用。
5. **CORS dev 兼容性**：修改默认 CORS 行为后，需确保 dev profile 下 localhost 仍可正常访问。
6. **V24 孤儿数据量**：若生产库有大量孤儿数据，需人工决策是软修复（SET NULL）还是硬修复（DELETE）。建议先审计再决定。
